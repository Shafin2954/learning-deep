## Bengali embeddings in practice

An **embedding** turns a sentence into a list of numbers, chosen so that sentences with similar
meaning get similar lists. Once text is numbers, "how alike are these two sentences?" becomes a
quick calculation.

F8 taught you what embeddings are; this chapter is the Bengali-specific practice — the
models, the pooling, and the two places embeddings win you points: as a **cheap strong
baseline** for classification, and as the **retrieval engine** of **RAG** — retrieval-augmented
generation, where you look up relevant passages and hand them to a generator (ch. 12).

> **Picture it:** a huge map where every sentence is a pin. ঢাকা বাংলাদেশের রাজধানী। and a
> question about the capital are pinned close together; a sentence about machine learning
> is pinned far away. Similarity search is "find the pins nearest to mine".

## Sentence embeddings: one vector per document

The plain idea: a model gives you one vector per token, but you want one vector for the whole
sentence, so you average the token vectors.

A transformer produces one contextual vector per token (F8, F12). For similarity and retrieval
you need one vector per *sentence or document*. You get it by **pooling** the token vectors —
combining many vectors into one — usually **mean pooling** over the real (non-padding) tokens,
sometimes the `[CLS]` token. Sentence-embedding models (the `sentence-transformers` family) are
encoders fine-tuned specifically so that mean-pooled vectors of similar sentences have high
**cosine similarity** (a score from -1 to 1 for how closely two vectors point in the same
direction). That fine-tuning is why you use them instead of pooling a raw BERT.

### Mean pooling over the attention mask

**Padding** tokens are filler added so every sentence in a batch has the same length. They carry
no meaning, so they must not take part in the average.

Pool only over real tokens — never include padding tokens, or your vectors are polluted:

$$
\hat{v} = \frac{\sum_{t=1}^{T} m_t \, h_t}{\sum_{t=1}^{T} m_t}
$$

where $m_t \in \{0, 1\}$ is the attention mask and $h_t$ is the token vector.

> **In plain words:**
> - $T$ is the number of token slots, real plus padding.
> - $m_t$ is 1 for a real token and 0 for padding.
> - The top adds up only the real token vectors (padding is multiplied by 0); the bottom
>   counts the real tokens. Their ratio is the plain average of the real tokens, $\hat{v}$.

```python
import numpy as np
np.random.seed(0)
def mean_pool(token_vecs, attention_mask):
    m = attention_mask[:, None]                      # (T,1)
    return (token_vecs * m).sum(0) / np.clip(m.sum(), 1, None)

tok_vecs = np.random.randn(6, 384)                   # 6 tokens, 2 are padding
mask     = np.array([1,1,1,1,0,0])
sent_vec = mean_pool(tok_vecs, mask)
print("sentence vector shape:", sent_vec.shape)      # (384,) — padding ignored
```

```output
sentence vector shape: (384,)
```

The 6 token vectors of length 384 became one vector of length 384, and the mask
`[1,1,1,1,0,0]` made sure only the first 4 tokens counted. The `np.clip(..., 1, None)` guards
against dividing by zero for an all-padding row.

> **Watch out:** `token_vecs.mean(0)` looks like the same thing but divides by 6 and mixes in the
> 2 padding vectors. In a batch, shorter sentences have more padding, so their vectors shrink
> towards the padding vector and similarity scores quietly go wrong.

## Which embedding models for Bengali

Not every embedding model has seen much Bengali. Choose one that has, and then check it on
your own Bengali examples.

- **Multilingual, strong, general:** **LaBSE** (109 languages, built for cross-lingual
  similarity), **multilingual-E5** (`intfloat/multilingual-e5-*`, excellent retrieval, uses
  `"query:"`/`"passage:"` prefixes), **BGE-M3** (multilingual, dense + sparse + multi-vector).
- **Bengali / Indic specific:** L3Cube Bengali SBERT, IndicSBERT (AI4Bharat).
- **Rule:** prefer models with real Bengali coverage and **evaluate on your own Bengali pairs** —
  English benchmark rankings do not transfer to Bengali. **Cross-lingual** models (LaBSE, E5),
  which place a sentence and its translation close together, are especially useful for
  code-mixed Bengali text.

## Bengali-specific gotchas

Four habits keep your Bengali embeddings honest; each one links back to an earlier chapter.

1. **Normalize text first** (ch. 2) — un-normalized variants embed inconsistently.
2. **Watch fertility/length** (ch. 3) — long Bengali inputs may exceed the encoder's max length
   and silently truncate the tail.
3. **Respect model-specific prompt prefixes** — E5 wants `"query:"` / `"passage:"`.
4. **Mean-pool over the attention mask**, not over padding.

> **Watch out:** forgetting the E5 prefixes does not raise an error. The model still returns
> vectors; they are just worse at retrieval, and you only notice through a lower score.

## Bengali sentence embeddings and retrieval (RUN-LOCALLY)

The plain idea: embed three short Bengali documents and one question, then rank the documents
by how close each vector is to the question's vector.

The real retrieval demo uses `sentence-transformers` — run this on your own machine:

```python
# Real Bengali sentence embeddings + retrieval (run locally).
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("intfloat/multilingual-e5-base")   # strong multilingual

docs = ["ঢাকা বাংলাদেশের রাজধানী।",
        "পদ্মা সেতু একটি বড় অবকাঠামো।",
        "মেশিন লার্নিং কৃত্রিম বুদ্ধিমত্তার একটি শাখা।"]
query = "বাংলাদেশের রাজধানী কোনটি?"

# E5 convention: prefix passages and queries.
doc_emb = model.encode(["passage: " + d for d in docs], normalize_embeddings=True)
q_emb   = model.encode("query: " + query,               normalize_embeddings=True)

scores = doc_emb @ q_emb            # cosine (already normalized) = one matmul
order  = np.argsort(scores)[::-1]
for r in order:
    print(f"{scores[r]:+.3f}  {docs[r]}")
# Top hit should be the Dhaka sentence — semantic match across different wording.
```

```output
+0.869  ঢাকা বাংলাদেশের রাজধানী।
+0.745  পদ্মা সেতু একটি বড় অবকাঠামো।
+0.691  মেশিন লার্নিং কৃত্রিম বুদ্ধিমত্তার একটি শাখা।
```

The Dhaka sentence wins with `+0.869`, even though the question uses different words (কোনটি,
a question form) than the document. Look at the other two lines too: the unrelated
machine-learning sentence still scores `+0.691`. E5 scores sit in a narrow, high band, so the
*order* carries the information, not the raw value.

> **Watch out:** do not pick a fixed threshold like "keep anything above 0.5" for E5. Here every
> document clears it, including the irrelevant one. Use top-$k$, or tune a threshold on your
> own validation pairs.

## Two high-value competition uses

Embeddings pay off twice: as a fast classifier baseline, and as the search step of RAG.

### 1. The embedding baseline

Embed each training text with a **frozen** sentence model (its weights are never updated), then
train a tiny classifier (logistic regression / linear head) on those vectors. No fine-tuning,
trains in seconds, and on small Bengali datasets it is often *shockingly* competitive — sometimes
beating a fine-tuned LLM (fewer parameters to overfit, F6). Always build this baseline first
(ch. 17); it sets the bar everything else must clear.

> **Picture it:** the embedding model is a seasoned librarian who has already sorted every book
> onto shelves by topic. Your classifier only has to learn which shelves mean "positive" and
> which mean "negative", a far easier job than learning to read.

### 2. Retrieval for RAG (ch. 12)

Embed your knowledge chunks once, embed the query, return the top-$k$ by cosine. This is the "R"
that grounds a generative answer. For retrieval over many documents, use **FAISS** locally or
**pgvector** — which is just an efficient approximate version of the same cosine search.

Cosine similarity (F8): normalize vectors, take dot products as one matrix multiply —
$$
\mathrm{sim}(q, d_i) = \frac{q \cdot d_i}{\|q\|\,\|d_i\|}
$$

> **In plain words:** multiply the query $q$ and a document $d_i$ entry by entry and add up (the
> dot product), then divide by both lengths. If you first scale every vector to length 1, the
> denominator is 1 and the score is the dot product alone, so one matrix multiply scores every
> document at once. That is why the demo passed `normalize_embeddings=True`.

## Recap in plain words

- An embedding is a vector that places similar meanings close together.
- A sentence vector is the average of its real token vectors; padding must be masked out.
- Pick embedding models with real Bengali coverage (LaBSE, multilingual-E5, BGE-M3, Indic SBERTs) and test them on your own pairs.
- Normalize text, mind the max length, and use the model's prefixes (E5: `query:` / `passage:`).
- In the E5 demo the right document ranked first (0.869), but an unrelated one still scored 0.691, so rank rather than threshold.
- A linear classifier on frozen embeddings is the baseline every fancier model must beat.

## Try it Yourself

This is the embedding baseline in miniature: random vectors stand in for frozen sentence
embeddings, and a softmax classifier is trained on them with 400 steps of gradient descent.

```python
import numpy as np
np.random.seed(0)

# The embedding BASELINE in miniature: linear classifier on frozen embeddings.
# (Random 'embeddings' here just to show the mechanics — swap in real ones.)
N, d, C = 300, 32, 3
E = np.random.randn(N, d)                              # frozen sentence embeddings
W_true = np.random.randn(d, C); y = (E @ W_true).argmax(1)

def softmax(z): z=z-z.max(-1,keepdims=True); e=np.exp(z); return e/e.sum(-1,keepdims=True)
W = np.random.randn(d, C)*0.01; b = np.zeros(C); lr = 0.1
for _ in range(400):
    p = softmax(E @ W + b); p[np.arange(N), y] -= 1; p /= N
    W -= lr*(E.T @ p); b -= lr*p.sum(0)
print("baseline accuracy:", round(float(((E@W+b).argmax(1)==y).mean()), 3))
# On real frozen Bengali embeddings this same 10-line baseline is your bar to beat.
```

```output
baseline accuracy: 0.98
```

The classifier gets 0.98 of the 300 examples right. That is high because the labels were built
from a linear rule over these exact vectors, so a linear model can recover them; on real
embeddings expect lower numbers. The point is the size of the recipe: about ten lines, no GPU.

Variation to try: halve the iterations to 200 or set `lr = 0.01` and watch the accuracy drop;
then raise `C` to 10 classes.

## Exercise

Build `embed_and_retrieve(query, docs, model, k=3)` that (1) normalizes Bengali text
(ch. 2), (2) encodes with correct prefixes, (3) returns the top-k docs by cosine via a
single matmul. Then, separately, build the embedding *baseline* classifier for a
classification task and record its score — that number is the floor your fine-tuned
model (ch. 8–9) must beat to justify its cost.

> **Hint:** Reuse F8's vectorized `top_k`: normalize all doc embeddings once, normalize the
> query, one matmul gives every cosine score, `argsort` for the top-k. For the baseline, frozen
> embeddings + `LogisticRegression` (sklearn) is enough — keep it dumb and fast; its job
> is to set the bar, not to win.

```python
import unicodedata
import numpy as np

def embed_and_retrieve(query, docs, model, k=3):
    norm = lambda t: unicodedata.normalize("NFC", t)          # (1) ch. 2
    D = model.encode(["passage: " + norm(d) for d in docs], normalize_embeddings=True)
    q = model.encode("query: " + norm(query), normalize_embeddings=True)   # (2) prefixes
    scores = D @ q                                             # (3) one matmul
    top = np.argsort(scores)[::-1][:k]
    return [(round(float(scores[i]), 3), docs[i]) for i in top]

for hit in embed_and_retrieve("পদ্মা নদীর উপর সেতু", docs, model, k=2):
    print(hit)
```

```output
(0.851, 'পদ্মা সেতু একটি বড় অবকাঠামো।')
(0.762, 'ঢাকা বাংলাদেশের রাজধানী।')
```

The query পদ্মা নদীর উপর সেতু ("a bridge over the Padma river") shares only one word with the
Padma Bridge document, yet it ranks first at 0.851, ahead of the Dhaka sentence at 0.762. The
solution reuses `docs` and `model` from the RUN-LOCALLY cell above, since every block on the
page shares one session. For the baseline half, swap the random `E` in Try it Yourself for
`model.encode(...)` vectors of your training texts.
