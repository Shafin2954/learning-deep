## Before any model, there is the text

A computer does not store "letters". It stores numbers, and Bengali letters are stored as
small groups of numbers that do not line up one-to-one with what your eye sees. Every
Bengali model you will ever train sits on top of those numbers, so this chapter teaches you
to read them.

Bengali text is not what your code thinks it is. Most Bengali NLP bugs are born here,
silently, and show up later as a mysteriously low score. So we start at the bottom.

Bengali is an **abugida** (alphasyllabary) — a writing system where each consonant symbol
already carries a vowel sound — not an **alphabet**, where consonants and vowels are
separate letters of equal standing. Each consonant carries an **inherent vowel** — the
vowel you hear without anything being written for it — here অ, the "ô" sound. You don't
write the vowel; it's assumed. To change or remove it, you attach marks. This single fact
explains most of the script's behavior.

> **Picture it:** every consonant arrives wearing a default hat (the "ô" sound). A vowel
> sign swaps the hat for a different one; the virama (below) takes the hat off so the
> consonant can lean on the next one. English letters never wear hats, which is why tools
> built for English get confused.

## A character you see is not a character Python counts

The plain idea: one "letter" on screen can be several numbers in memory, and Python counts
the numbers, not the letters.

What a human reads as one unit is a **grapheme cluster** — the smallest piece of text a
reader perceives as one written symbol. Python's `len()` counts **Unicode code points** —
the individual numbered entries in the Unicode table (written `U+` plus a hex number) —
which can be several per cluster. Take ক্ষমা ("forgiveness"):

- Humans see 2 units: ক্ষ and মা.
- Python sees 5 code points: ক + ্ + ষ + ম + া.

The ্ (U+09CD) is *virama* / *hasanta* — the "kill the inherent vowel and join" mark.
ক + ্ + ষ fuse into the **conjunct** ক্ষ (kṣa) — two or more consonants drawn as one
merged shape. Conjuncts (যুক্তাক্ষর) are the defining feature of the script and the reason
naive character-level processing, truncation, and "count the letters" logic all break. If
you slice a string by code point, you can cut a grapheme in half and produce garbage.

The code below prints each layer: the raw code points, their official Unicode names, and
the grapheme clusters found by the `\X` pattern ("one whole grapheme") of the third-party
`regex` module.

```python
import regex          # the third-party `regex` module — supports \X. NOT stdlib `re`.
import unicodedata

word = "ক্ষমা"   # "forgiveness"

print("string         :", word)
print("len() codepoints:", len(word))                         # 5
print("code points    :", [f"U+{ord(c):04X}" for c in word])
print("names          :", [unicodedata.name(c) for c in word])

# What a human actually sees: grapheme clusters via \X
graphemes = regex.findall(r"\X", word)
print("graphemes      :", graphemes, "->", len(graphemes))    # ['ক্ষ', 'মা'] -> 2

# Same look, different bytes:
a = "নো"                              # single o-kar  (U+09CB)
b = "ন" + "ে" + "া"         # e-kar + aa-kar (U+09C7 U+09BE)
print("\nidentical on screen:", a, b, "| a == b ?", a == b)   # False!
print("a:", [f"U+{ord(c):04X}" for c in a])
print("b:", [f"U+{ord(c):04X}" for c in b])
```

```output
string         : ক্ষমা
len() codepoints: 5
code points    : ['U+0995', 'U+09CD', 'U+09B7', 'U+09AE', 'U+09BE']
names          : ['BENGALI LETTER KA', 'BENGALI SIGN VIRAMA', 'BENGALI LETTER SSA', 'BENGALI LETTER MA', 'BENGALI VOWEL SIGN AA']
graphemes      : ['ক্ষ', 'মা'] -> 2

identical on screen: নো নো | a == b ? False
a: ['U+09A8', 'U+09CB']
b: ['U+09A8', 'U+09C7', 'U+09BE']
```

Read the second line: `len()` says 5, while the `graphemes` line says 2 (`['ক্ষ', 'মা']`).
The `names` line shows the hidden helper: `BENGALI SIGN VIRAMA` sits between KA and SSA and
glues them into one shape. In the second half, both strings print as নো, yet `a == b` is
`False`, because `a` is 2 code points (`U+09A8 U+09CB`) and `b` is 3 (`U+09A8 U+09C7 U+09BE`).

`len("ক্ষমা") == 5`, but the word has 2 letters — and two visually identical strings
can be unequal.

> **Watch out:** the standard-library `re` module does not understand `\X`. You need
> `import regex` (a separate package). With plain `re`, `\X` raises an error instead of
> finding graphemes.

## Vowel signs attach to consonants

In plain words: a vowel at the start of a word gets its own full letter, but a vowel after a
consonant shrinks into a small mark stuck onto that consonant.

**Independent vowels** (অ আ ই ঈ উ...) — full vowel letters that stand alone — are used at the
start of a word. Everywhere else, a vowel is a **sign** (also called a *kar* or *matra*) — a
mark attached to a consonant: ক + া → কা, ক + ি → কি. The sign can render to the *left* of
the consonant (ি) even though it comes *after* it in memory. Visual order $\neq$ logical
order. Never reason about Bengali from how it looks.

> **Picture it:** memory is the order you *say* the sounds (k, then i). The screen is a
> painter who is allowed to place the i-mark wherever it looks best, even in front.
> Your code reads memory, not the painting.

> **Watch out:** if you reverse a Bengali string or search for "the character before X"
> using what you see on screen, you will get the wrong code point. Always print the code
> points when in doubt.

## The same-looking text can be different bytes

The plain idea: the computer can store one visible letter in more than one way, and to the
computer those two ways are different text.

The "o-kar" ো can be stored as one code point (U+09CB) or as two (e-kar U+09C7 +
aa-kar U+09BE). They render identically and read identically — but `==` says they're
different, your tokenizer splits them differently, and your model sees two different
inputs. Multiply this across thousands of training rows and your signal blurs. The fix is
*normalization* (next chapter), but you can't fix what you can't see, so first: learn to
look at the code points.

> **Picture it:** two people spell the same name, one as "Mohammad", one as "Muhammad". A
> human knows it is one person; a strict database sees two customers. Your model is the
> strict database.

Two invisible troublemakers also live here:

- **ZWNJ** (U+200C, zero-width non-joiner) and **ZWJ** (U+200D, zero-width joiner)
  control whether a conjunct *displays* as joined or split. They carry no sound, take no
  space, and quietly differ between data sources.
- The **nukta** (U+09BC) — a small dot under a letter — turns ড/ঢ/য into ড়/ঢ়/য় — and those
  can each be either a single precomposed code point *or* base + nukta. Same letter, two
  encodings.

The Bengali **block** — the range of Unicode numbers reserved for the script — is
U+0980–U+09FF. Digits are ০–৯ (U+09E6–U+09EF) — your model will not treat "৫" and "5" as
the same number unless you make it. Sentence end is the *daṛi* "।" (U+0964), not a period.

> **Watch out:** ZWNJ and ZWJ are invisible in every editor. Two rows of your dataset can
> look letter-for-letter equal and still fail an exact-match check because one has a
> hidden U+200C. Print `[f"U+{ord(c):04X}" for c in s]` whenever two "equal" strings
> disagree.

### The Unicode block layout

The Bengali digits are a small sub-range inside the Bengali block:

$$
\underbrace{\text{U+0980–U+09FF}}_{\text{Bengali block}}
\quad\supset\quad
\underbrace{\text{U+09E6–U+09EF}}_{\text{Bengali digits ০–৯}}
$$

> **In plain words:** every Bengali code point lives between U+0980 and U+09FF, and inside
> that range the ten slots from U+09E6 to U+09EF are the digits ০ to ৯. The $\supset$ sign
> means "contains". A quick range test `0x0980 <= ord(c) <= 0x09FF` tells you whether a
> character is Bengali at all.

The key rule: **operate on graphemes, normalize early, and inspect code points when
anything looks "fine but wrong."** This is the cheapest score you'll ever buy.

## Recap in plain words

- Bengali consonants carry a built-in "ô" vowel; marks change or remove it.
- `len()` counts code points, not the letters a reader sees; use `regex` and `\X` to count graphemes.
- The virama ্ glues consonants into conjuncts such as ক্ষ, so one visible letter can be 3 or more code points.
- A vowel sign can be drawn to the left of its consonant while being stored after it.
- The same visible text (নো, য়) can have more than one code-point spelling, and `==` treats them as different.
- ZWNJ/ZWJ are invisible, and Bengali digits ০–৯ are different code points from 0–9.

## Try it Yourself

The loop below prints, for five words, the code-point count next to the grapheme count and
the clusters themselves. Guess each grapheme count before you run it.

```python
import regex, unicodedata

# Try your own words. Predict the grapheme count BEFORE running.
for word in ["বাংলা", "জ্ঞান", "স্ত্রী", "কম্পিউটার", "৫টি"]:
    cps = len(word)
    graphemes = regex.findall(r"\X", word)
    print(f"{word:12s} | codepoints={cps:2d} | graphemes={len(graphemes)} {graphemes}")

# Inspect any character's identity:
ch = "ৎ"          # try changing this
print("\n", ch, "=", unicodedata.name(ch), f"(U+{ord(ch):04X})")
```

```output
বাংলা        | codepoints= 5 | graphemes=2 ['বাং', 'লা']
জ্ঞান        | codepoints= 5 | graphemes=2 ['জ্ঞা', 'ন']
স্ত্রী       | codepoints= 6 | graphemes=1 ['স্ত্রী']
কম্পিউটার    | codepoints= 9 | graphemes=5 ['ক', 'ম্পি', 'উ', 'টা', 'র']
৫টি          | codepoints= 3 | graphemes=2 ['৫', 'টি']

 ৎ = BENGALI LETTER KHANDA TA (U+09CE)
```

Look at স্ত্রী: 6 code points, but only 1 grapheme, because two viramas chain three
consonants (স, ত, র) plus the ী sign into a single shape. কম্পিউটার goes from 9 code points
down to 5 graphemes. ৫টি shows a Bengali digit is its own grapheme. The last line prints the
official name of ৎ, `BENGALI LETTER KHANDA TA`, at U+09CE.

Notice জ্ঞান: জ + ্ + ঞ forms জ্ঞ (a conjunct whose sound, "gg/ggæ", isn't obvious from
its parts) — a perfect example of why you can't decompose meaning from shape.

Variation to try: add a word you build by hand with a stray ZWNJ, such as `"ক্‌ষ"`, and
see how the grapheme count changes compared with `"ক্ষ"`.

## Exercise

Write `safe_truncate(text, n)` that returns the first `n` **grapheme clusters** of a
Bengali string (not code points), so you never cut a conjunct or detach a vowel sign.

> **Hint:** split the text into clusters with `regex.findall(r"\X", text)`, keep the first
> `n` items of that list, then join them back into a string.

<details>
<summary>Solution</summary>

```python
import regex

def safe_truncate(text, n):
    graphemes = regex.findall(r"\X", text)
    return "".join(graphemes[:n])

print(safe_truncate("কম্পিউটার বিজ্ঞান", 5))   # keeps clusters whole
# Compare the naive, broken version:
print("কম্পিউটার বিজ্ঞান"[:5])                 # may end mid-conjunct
```

Why it matters: truncating model inputs/outputs, building char features, or displaying
previews — all must respect grapheme boundaries.

Running it, `safe_truncate(..., 5)` returns the whole word কম্পিউটার (5 graphemes, 9 code
points), while the naive `[:5]` returns only কম্পি. The two "5"s count different things.
In this case the naive cut happens to land on a cluster edge; try `[:3]` and you get কম্,
which ends on a dangling virama, a broken letter no Bengali reader would write.
</details>
