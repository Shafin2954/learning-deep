## Why tree models work well for time series

A decision tree learns rules like "if last week was high and it's December, predict high".
Gradient boosting stacks hundreds of small trees, each fixing the mistakes of the ones before
it. That lets it learn combinations of clues a straight-line model cannot.

LightGBM and XGBoost naturally capture nonlinear interactions between lags — e.g.,
"when lag_7 is high AND month is December, the value spikes." Linear models can't express
this without explicit interaction terms. Trees also handle mixed feature types (lags,
calendars, categorical IDs) without scaling.

An **interaction** is when the effect of one feature depends on another. **LightGBM** and
**XGBoost** are two popular, fast gradient-boosting libraries. **Scaling** means rescaling
features to similar ranges; trees only ask "is this feature above a threshold?", so the units
don't matter.

> **Picture it:** a team of tutors marking a practice exam. The first tutor gives rough
> feedback. The second only looks at what the first got wrong, the third at what is still
> wrong, and so on. Each one is weak alone; together they get very precise.

The lag-feature framework from ch. 7 works directly: build the feature matrix, then
replace Ridge with LightGBM.

> **Watch out:** trees cannot extrapolate. A tree's prediction is always an average of training
> targets, so it can never forecast a value above the highest one it has seen. On a strongly
> trending series, model the change (difference) or remove the trend first, or the forecasts
> flatten out at the old maximum.

## Multi-step forecasting strategies

A model trained to predict "tomorrow" doesn't directly tell you "next Thursday". You can train
a separate model for each day ahead, reuse one model by feeding its own guesses back in, or
train one model that outputs all days at once.

When you need $h > 1$ step ahead you have three options:

- **Direct**: train $h$ separate models, $\hat{y}_{t+k} = f_k(\text{features}_t)$ for $k=1,\ldots,h$.
  No error accumulation; higher training cost; each model specializes.
- **Recursive**: train one model for 1-step-ahead; at inference, use $\hat{y}_{t+1}$ as
  `lag_1` to predict $\hat{y}_{t+2}$, and so on. Simple; accumulates errors for long horizons.
- **MIMO** (multi-input multi-output): one model outputs all $h$ values simultaneously.

**Error accumulation** means the recursive model's day-2 forecast is built on its own day-1
guess, so a day-1 mistake gets baked into day 2, then day 3, like a photocopy of a photocopy.

> **Picture it:** giving directions. Direct: you write separate instructions for each turn,
> each from the starting point. Recursive: you say "go to the next corner, then ask again" —
> one wrong turn early and every later step is off.

For horizons up to ~12, direct is the most reliable in practice.

## LightGBM with early stopping

Boosting keeps adding trees, and after a while new trees start memorising noise. **Early
stopping** watches the error on a validation set and stops when it hasn't improved for a while.

The split has three parts, in time order: 80% to train, the next 10% to **validate** (to decide
when to stop), the final 10% to **test** (touched once, at the end). `early_stopping(50)` stops
if 50 rounds pass without a better validation MAE and keeps the best round.

```python
import numpy as np
import pandas as pd
import lightgbm as lgb

rng = np.random.default_rng(42)
idx = pd.date_range('2016-01-01', periods=730, freq='D')
t   = np.arange(730)
y   = (100 + 0.08*t
       + 12*np.sin(2*np.pi*t/365.25)
       + 8*np.sin(2*np.pi*t/7)
       + rng.normal(0, 3, 730))
series = pd.Series(y, index=idx)

# Feature engineering (from ch. 7)
df = pd.DataFrame({'y': series})
for lag in [1, 2, 3, 7, 14, 28]:
    df[f'lag_{lag}'] = df['y'].shift(lag)
df['roll_mean_7']  = df['y'].shift(1).rolling(7).mean()
df['roll_std_7']   = df['y'].shift(1).rolling(7).std()
df['month_sin']    = np.sin(2*np.pi*df.index.month / 12)
df['month_cos']    = np.cos(2*np.pi*df.index.month / 12)
df['dow_sin']      = np.sin(2*np.pi*df.index.dayofweek / 7)
df['dow_cos']      = np.cos(2*np.pi*df.index.dayofweek / 7)
df = df.dropna()

# Time-ordered split: 80% train, 10% val, 10% test
n = len(df)
tr_end = int(n*0.8); val_end = int(n*0.9)
X = df.drop('y', axis=1).values; y_arr = df['y'].values

X_tr, y_tr   = X[:tr_end],  y_arr[:tr_end]
X_val, y_val = X[tr_end:val_end], y_arr[tr_end:val_end]
X_te, y_te   = X[val_end:], y_arr[val_end:]

dtrain = lgb.Dataset(X_tr,  y_tr)
dval   = lgb.Dataset(X_val, y_val, reference=dtrain)

params = {
    'objective': 'regression', 'metric': 'mae',
    'num_leaves': 31, 'learning_rate': 0.05,
    'min_child_samples': 10, 'verbose': -1,
}
model = lgb.train(
    params, dtrain, num_boost_round=500,
    valid_sets=[dval],
    callbacks=[lgb.early_stopping(50, verbose=False), lgb.log_evaluation(-1)],
)
preds = model.predict(X_te)
mae   = np.mean(np.abs(y_te - preds))
naive = np.mean(np.abs(np.diff(y_te)))
print(f"Best iteration: {model.best_iteration}")
print(f"Test MAE:  {mae:.3f}")
print(f"Naive MAE: {naive:.3f}")
print(f"MASE:      {mae/naive:.3f}")
```

```output
Best iteration: 70
Test MAE:  3.759
Naive MAE: 5.057
MASE:      0.743
```

Early stopping kept round 70 of the 500 allowed: after that, the validation MAE stopped
improving. On the test set the MAE is 3.759 against a naive 5.057, so MASE is 0.743 —
LightGBM's errors are about 74% of the naive ones.

That is a real gain, but not a huge one. The noise std is 3, so even a perfect model would have
an MAE near $3 \times 0.8 = 2.4$. On this data a plain Ridge regression with the same features
reaches an MAE of about 2.51: the series is built from sine waves and a straight trend, which a
linear model on lags captures almost exactly, while trees approximate every smooth curve with
steps.

> **Watch out:** gradient boosting is not automatically better. On smooth, nearly linear series
> a linear model on good features often wins. Backtest both (ch. 6) before choosing.

## Feature importance

After training, you can ask the model which clues it leaned on most. LightGBM's default answer
counts how often each feature was used to split a tree.

```python
import numpy as np
import pandas as pd
import lightgbm as lgb

rng = np.random.default_rng(42)
idx = pd.date_range('2016-01-01', periods=730, freq='D')
t   = np.arange(730)
y   = (100 + 0.08*t + 12*np.sin(2*np.pi*t/365.25)
       + 8*np.sin(2*np.pi*t/7) + rng.normal(0, 3, 730))
series = pd.Series(y, index=idx)

df = pd.DataFrame({'y': series})
feature_names = []
for lag in [1, 2, 3, 7, 14, 28]:
    df[f'lag_{lag}'] = df['y'].shift(lag)
    feature_names.append(f'lag_{lag}')
df['roll_mean_7'] = df['y'].shift(1).rolling(7).mean()
df['roll_std_7']  = df['y'].shift(1).rolling(7).std()
df['month_sin']   = np.sin(2*np.pi*df.index.month/12)
df['month_cos']   = np.cos(2*np.pi*df.index.month/12)
df['dow_sin']     = np.sin(2*np.pi*df.index.dayofweek/7)
df['dow_cos']     = np.cos(2*np.pi*df.index.dayofweek/7)
feature_names += ['roll_mean_7','roll_std_7','month_sin','month_cos','dow_sin','dow_cos']
df = df.dropna()

X = df[feature_names].values; y_arr = df['y'].values
model = lgb.LGBMRegressor(n_estimators=200, learning_rate=0.05, verbose=-1)
model.fit(X, y_arr)

imp = sorted(zip(feature_names, model.feature_importances_), key=lambda x: -x[1])
for name, score in imp[:6]:
    print(f"  {name:<16} {score:>5}")
```

```output
  roll_std_7         694
  lag_1              652
  lag_7              628
  lag_28             549
  lag_2              541
  lag_3              527
```

The top feature by this count is `roll_std_7` (694 splits), then `lag_1` (652) and `lag_7`
(628). That does not mean the rolling std is the most useful feature. The default
`feature_importances_` is **split importance**: the number of times a feature appears in a
split. Continuous, noisy features offer many slightly different thresholds, so trees keep
reaching for them to make small refinements.

Switch to **gain importance** — how much each feature's splits reduced the error,
`model.booster_.feature_importance('gain')` — and the picture changes: `lag_7` comes first
by a wide margin (about 1.30 million), then `lag_14` (0.39 million) and `roll_mean_7`
(0.09 million). With gain, `lag_7` dominates — the strong weekly cycle means last week's
same-weekday value is the best single predictor. The rolling mean and day-of-week signals
follow.

> **Watch out:** split counts reward features that are used often, not features that matter.
> Use gain importance, or better, permutation importance on held-out data, before you drop or
> keep features based on importance.

## Recap in plain words

- Gradient boosting adds many small trees, each correcting the last, and learns interactions between lags and calendar features.
- Trees cannot predict outside the range of training targets, so handle trends before you fit.
- Multi-step forecasts can be direct (one model per horizon), recursive (feed predictions back) or MIMO (all horizons at once).
- Early stopping on a time-ordered validation set picks the number of trees.
- Split-count importance is biased toward noisy continuous features; gain importance is a better first look.

## Try it Yourself

```python
import numpy as np
import pandas as pd
import lightgbm as lgb

rng = np.random.default_rng(10)
idx = pd.date_range('2018-01-01', periods=365*3, freq='D')
t   = np.arange(len(idx))
y   = 80 + 0.06*t + 15*np.sin(2*np.pi*t/7) + rng.normal(0, 2, len(t))
series = pd.Series(y, index=idx)

df = pd.DataFrame({'y': series})
for lag in [1,7,14]: df[f'lag_{lag}'] = df['y'].shift(lag)
df['roll_mean_7'] = df['y'].shift(1).rolling(7).mean()
df['dow_sin'] = np.sin(2*np.pi*df.index.dayofweek/7)
df['dow_cos'] = np.cos(2*np.pi*df.index.dayofweek/7)
df = df.dropna()

n = len(df); X = df.drop('y',axis=1).values; y_arr = df['y'].values
split = int(n*0.85)
model = lgb.LGBMRegressor(n_estimators=300, learning_rate=0.05, verbose=-1)
model.fit(X[:split], y_arr[:split])
preds = model.predict(X[split:])
mae = np.mean(np.abs(y_arr[split:] - preds))
print(f"Test MAE: {mae:.3f}  (naive: {np.mean(np.abs(np.diff(y_arr[split:]))):.3f})")
```

```output
Test MAE: 3.665  (naive: 8.478)
```

LightGBM's MAE is 3.665 against the naive 8.478 — less than half. Naive suffers here because
the weekly wave is large ($\pm 15$): yesterday is a poor guess for today. The model is still well
above the noise floor of about 1.6 (noise std 2), partly because this series trends upward for
three years: about a quarter of the test values (the last 15% of days) lie above the training maximum,
which trees cannot reach.

Try removing the trend (`0.0*t`) and re-run: the MAE drops to about 1.72, right at the noise floor. Then
try modelling the change instead: target `y - lag_1` and add `lag_1` back after predicting.

## Exercise

Implement the recursive multi-step strategy for 4-step-ahead forecasting: train one model
for 1-step-ahead, then iteratively feed predictions as lag features. Compare MAE at each
horizon h=1,2,3,4 vs the direct strategy (four separate models).

> **Hint:** for the direct strategy, pair each feature row at time $t$ with the target
> $y_{t+h}$ using `df['y'].shift(-h)`. For the recursive strategy, predict one step, write the
> prediction into a copy of the series, rebuild the lags, and repeat four times.

```python
import numpy as np
import pandas as pd
import lightgbm as lgb

rng = np.random.default_rng(0)
idx = pd.date_range('2020-01-01', periods=500, freq='D')
t   = np.arange(500)
y   = 100 + 0.05*t + 10*np.sin(2*np.pi*t/7) + rng.normal(0,2,500)
series = pd.Series(y, index=idx)

def make_df(series, lags=[1,2,3,7]):
    df = pd.DataFrame({'y': series})
    for l in lags: df[f'lag_{l}'] = df['y'].shift(l)
    df = df.dropna()
    return df

df = make_df(series)
n  = len(df); split = 400
feat_cols = [c for c in df.columns if c != 'y']
X, y_arr  = df[feat_cols].values, df['y'].values

# Direct: train one model per horizon
direct_maes = []
for h in range(1, 5):
    Xh = df[feat_cols].iloc[:split]
    yh = df['y'].shift(-h).dropna()
    n_common = min(len(Xh), len(yh))
    m = lgb.LGBMRegressor(n_estimators=150, verbose=-1)
    m.fit(Xh.values[:n_common], yh.values[:n_common])
    preds = m.predict(X[split:])
    actual = y_arr[split+h:] if split+h < len(y_arr) else y_arr[split:]
    direct_maes.append(np.mean(np.abs(actual[:len(preds)] - preds[:len(actual)])))

print("Direct strategy MAE by horizon:", [f"{v:.3f}" for v in direct_maes])
```

The solution implements the direct half. Running it prints MAEs of 5.823, 7.219, 5.805 and
2.831 for $h = 1, 2, 3, 4$ — not the steady rise you might expect. Two details explain it.
First, row $t$'s features are lags of $y_t$ (so $y_{t-1}$, $y_{t-2}$, $y_{t-3}$, $y_{t-7}$),
and $y_t$ itself is not a feature, so even "$h = 1$" forecasts two steps past the newest value
used. Second, the series has a 7-day cycle: for $h = 4$ the target $y_{t+4}$ falls on the
same weekday as the feature $y_{t-3}$, an almost perfect clue, so $h = 4$ is the easiest
horizon. Adding $y_t$ (a `lag_0` column) to the features would fix the first issue.

For the recursive half: fit one model on $h = 1$, predict $\hat{y}_{t+1}$, append it to the
series as if it were real, rebuild the four lag features, predict $\hat{y}_{t+2}$, and repeat.
Its errors usually grow with $h$ as guesses feed on guesses; the direct models avoid that
by training on real targets at each horizon.
