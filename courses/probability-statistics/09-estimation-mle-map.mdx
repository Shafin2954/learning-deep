## Maximum Likelihood Estimation

You have data and a family of possible explanations (say, "a Normal with some mean and
spread"). **Maximum likelihood** picks the explanation under which your actual data would
have been most likely to appear. It's the single most common way models are fitted.

Given data $x_1,\ldots,x_n$ drawn i.i.d. from $p(x;\theta)$, the **maximum likelihood estimator** is:

$$
\hat\theta_{\text{MLE}} = \arg\max_\theta \prod_{i=1}^n p(x_i;\theta) = \arg\max_\theta \sum_{i=1}^n \log p(x_i;\theta)
$$

The log converts the product to a sum, making optimization tractable. The log-likelihood $\ell(\theta) = \sum_i \log p(x_i;\theta)$ is what you actually maximize.

> **In plain words:** $\theta$ is the knob setting (the parameters). For each setting, score
> how probable the whole dataset is — the product of each point's probability. Turn the knob
> to the highest score. Taking logs changes the score but not which setting wins, and sums
> are far easier to differentiate (and don't underflow to zero like a product of 1000 small
> numbers would).

> **Picture it:** you find a footprint and ask "which shoe size makes this print most
> likely?". You don't ask which size is most common in the population — that's the prior,
> and MAP (below) brings it in.

### Analytic MLE for the Normal

For simple models you can solve "slope of the log-likelihood = 0" with algebra and get a
formula.

Set $\partial\ell/\partial\mu = 0$ and $\partial\ell/\partial\sigma^2 = 0$:

$$
\hat\mu = \bar{x} = \frac{1}{n}\sum_i x_i, \qquad \hat\sigma^2 = \frac{1}{n}\sum_i (x_i - \bar{x})^2
$$

Note: the MLE variance uses $1/n$ (biased), not the sample variance $1/(n-1)$.

> **In plain words:** the best-fitting Normal has its mean at the sample average and its
> variance at the average squared distance from it. The $1/n$ version is slightly too small on
> average because the data are measured from their *own* average, which sits closer to them
> than the true mean does; $1/(n-1)$ corrects that (**Bessel's correction**).

```python
import numpy as np

rng = np.random.default_rng(0)
true_mu, true_sigma = 5.0, 2.0
n = 200
x = rng.normal(true_mu, true_sigma, n)

# Analytic MLE
mu_hat    = x.mean()
sigma_hat = x.std(ddof=0)     # MLE: divide by n
sigma_unb = x.std(ddof=1)     # Unbiased: divide by n-1

print(f"True: mu={true_mu}, sigma={true_sigma}")
print(f"MLE:  mu={mu_hat:.4f}, sigma={sigma_hat:.4f}")
print(f"Unbiased sigma (ddof=1): {sigma_unb:.4f}")
print(f"MLE bias in sigma: {sigma_hat - true_sigma:.4f}  (small for large n)")
```

```output
True: mu=5.0, sigma=2.0
MLE:  mu=5.0305, sigma=1.9224
Unbiased sigma (ddof=1): 1.9272
MLE bias in sigma: -0.0776  (small for large n)
```

With 200 points the estimates land near the truth: mean 5.03 and $\sigma$ 1.92. The last line
is labelled "bias", but most of that $-0.08$ is ordinary sampling luck — the true bias of the
$1/n$ estimator at $n = 200$ is only about $-0.005$. The two $\sigma$ estimates differ only in
the third decimal; the $n$ vs $n - 1$ distinction matters for small samples.

### Analytic MLE for Poisson and Exponential

For Poisson: $\ell(\lambda) = \sum_i (x_i \log\lambda - \lambda - \log x_i!)$. Setting $\partial\ell/\partial\lambda=0$ gives $\hat\lambda = \bar{x}$.

For Exponential: $\ell(\lambda) = n\log\lambda - \lambda\sum_i x_i$. Setting to zero gives $\hat\lambda = 1/\bar{x}$.

Both answers match intuition: the Poisson's $\lambda$ *is* its mean, so estimate it with the
sample mean; the Exponential's mean is $1/\lambda$, so invert the sample mean.

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(1)

# Poisson MLE
lam_true = 4.0
x_pois = rng.poisson(lam_true, 500)
lam_hat = x_pois.mean()
print(f"Poisson MLE: lambda_hat = x_bar = {lam_hat:.4f}  (true: {lam_true})")

# Exponential MLE
lam_exp_true = 0.5   # mean = 2
x_exp = rng.exponential(1/lam_exp_true, 500)
lam_exp_hat = 1 / x_exp.mean()
print(f"Exponential MLE: lambda_hat = 1/x_bar = {lam_exp_hat:.4f}  (true: {lam_exp_true})")
```

```output
Poisson MLE: lambda_hat = x_bar = 3.9580  (true: 4.0)
Exponential MLE: lambda_hat = 1/x_bar = 0.5120  (true: 0.5)
```

Both estimates are within a few percent of the true rates from 500 observations each.

## Numerical MLE

When no closed form exists, minimize the **negative log-likelihood** numerically.

Optimizers are built to *minimize*, so you flip the sign: maximizing $\ell$ is the same as
minimizing $-\ell$. It's the gradient-free cousin of ch. 9 of Math & Optimization.

```python
import numpy as np
from scipy import optimize, stats

rng = np.random.default_rng(2)
# Generate data from a Gamma(shape=3, scale=2) distribution
alpha_true, beta_true = 3.0, 2.0
x = rng.gamma(alpha_true, beta_true, 300)

def neg_log_lik(params, data):
    alpha, beta = params
    if alpha <= 0 or beta <= 0:
        return np.inf
    return -np.sum(stats.gamma.logpdf(data, a=alpha, scale=beta))

result = optimize.minimize(
    neg_log_lik, x0=[2.0, 1.5], args=(x,),
    method='Nelder-Mead',
    options={'xatol': 1e-8, 'fatol': 1e-8}
)
alpha_hat, beta_hat = result.x
print(f"Gamma MLE:  alpha={alpha_hat:.4f}  beta={beta_hat:.4f}")
print(f"True:       alpha={alpha_true}     beta={beta_true}")
print(f"Optimization converged: {result.success}")
```

```output
Gamma MLE:  alpha=2.7741  beta=2.0652
True:       alpha=3.0     beta=2.0
Optimization converged: True
```

**Nelder–Mead** (a method that only needs function values, no gradients) found
$\alpha \approx 2.77$ and $\beta \approx 2.07$ from 300 points; the truth is 3 and 2. The shape
estimate is the less precise of the two — the Gamma's shape and scale trade off against each
other (a higher shape with a lower scale gives a similar mean), so the likelihood surface is
a long, shallow ridge in that direction.

> **Watch out:** the code returns `np.inf` for negative parameters — a crude way to keep the
> search in the allowed region. A cleaner trick (used in the Try it Yourself) is to optimize
> $\log\sigma$ instead of $\sigma$, so every value the optimizer tries is valid.

## MAP estimation

**MAP** is maximum likelihood plus a "common sense" term: before seeing data you had some
belief about plausible parameter values (the **prior**), and MAP picks the value that best
balances the data's opinion with that belief.

**Maximum A Posteriori (MAP)** adds a log-prior term:

$$
\hat\theta_{\text{MAP}} = \arg\max_\theta \left[\sum_i \log p(x_i|\theta) + \log p(\theta)\right]
$$

MAP is equivalent to MLE with regularization. A Gaussian prior on $\theta$ corresponds to L2 regularization; a Laplace prior corresponds to L1.

> **In plain words:** by Bayes (ch. 1), posterior $\propto$ likelihood × prior; logs turn that
> into likelihood term + prior term. A Gaussian prior's log is $-\theta^2/(2\tau^2)$ — exactly
> an L2 penalty. A **Laplace** prior (a pointed, two-sided exponential) gives
> $-|\theta|/b$ — an L1 penalty. Every regularized model is secretly a MAP estimate.

### Beta-Binomial conjugacy

For $k$ successes in $n$ Bernoulli trials with a $\text{Beta}(\alpha,\beta)$ prior:

$$
\hat p_{\text{MAP}} = \frac{k + \alpha - 1}{n + \alpha + \beta - 2}, \qquad \hat p_{\text{MLE}} = \frac{k}{n}
$$

> **In plain words:** the prior acts like extra pretend flips — $\alpha - 1$ pretend heads
> and $\beta - 1$ pretend tails — added to your real ones before taking the fraction.

```python
import numpy as np
from scipy import stats

# Small sample: 2 heads in 5 flips
n, k = 5, 2

# MLE
p_mle = k / n
print(f"MLE: p = {k}/{n} = {p_mle:.4f}")

# MAP with different priors
priors = [
    (1, 1, "Beta(1,1) = Uniform"),
    (2, 2, "Beta(2,2) = Weak symmetric"),
    (5, 5, "Beta(5,5) = Strong prior toward 0.5"),
]

for alpha, beta, label in priors:
    p_map = (k + alpha - 1) / (n + alpha + beta - 2)
    print(f"MAP {label:<35}: {p_map:.4f}")
```

```output
MLE: p = 2/5 = 0.4000
MAP Beta(1,1) = Uniform                : 0.4000
MAP Beta(2,2) = Weak symmetric         : 0.4286
MAP Beta(5,5) = Strong prior toward 0.5: 0.4615
```

With only 5 flips, the prior matters. Beta(1,1) adds zero pretend flips, so MAP equals the MLE
(0.4). Beta(2,2) adds one pretend head and one tail: $3/7 = 0.4286$. Beta(5,5) adds four of
each: $6/13 = 0.4615$, pulled noticeably toward 0.5.

Beta(1,1) is the flat (non-informative) prior — MAP reduces to MLE. Stronger priors pull the estimate toward the prior mean (0.5), a form of Bayesian regularization.

## Properties of MLE

With enough data, maximum likelihood is about as good as an estimator can be: it homes in on
the truth, its errors are bell-shaped, and no reasonable competitor has smaller errors.

MLE is **consistent** ($\hat\theta_n \to \theta$), **asymptotically Normal** ($\sqrt{n}(\hat\theta-\theta)\to N(0,I(\theta)^{-1})$), and **asymptotically efficient** (achieves Cramér-Rao bound).

> **In plain words:** $I(\theta)$, the **Fisher information**, measures how sharply peaked the
> log-likelihood is around the truth — a sharp peak means the data pin $\theta$ down tightly.
> The **Cramér–Rao bound** says no unbiased estimator can have variance below
> $1/(n I(\theta))$, and the MLE reaches it as $n$ grows.

```python
import numpy as np

rng = np.random.default_rng(3)
true_lam = 3.0
ns = [10, 50, 200, 1000]

print(f"MLE of Poisson lambda (true={true_lam})")
print(f"{'n':<8}  {'mean(lam_hat)':<16}  {'std(lam_hat)':<14}  {'theory SE'}")
for n in ns:
    lam_hats = rng.poisson(true_lam, (5000, n)).mean(axis=1)
    se_theory = np.sqrt(true_lam / n)
    print(f"{n:<8}  {lam_hats.mean():<16.4f}  {lam_hats.std():<14.4f}  {se_theory:.4f}")
```

```output
MLE of Poisson lambda (true=3.0)
n         mean(lam_hat)     std(lam_hat)    theory SE
10        3.0047            0.5492          0.5477
50        3.0008            0.2454          0.2449
200       3.0018            0.1215          0.1225
1000      2.9997            0.0544          0.0548
```

For the Poisson, $I(\lambda) = 1/\lambda$, so the theory says the MLE's standard error is
$\sqrt{\lambda/n}$. Across 5000 simulated datasets per row, the measured spread of
$\hat\lambda$ matches that formula at every sample size (0.549 vs 0.548 at $n = 10$; 0.054 vs
0.055 at $n = 1000$), and the average estimate stays at 3 — consistent and efficient, as
promised.

## Recap in plain words

- MLE: choose the parameters that make the observed data most probable; in practice,
  maximize the log-likelihood.
- Closed forms exist for simple models (Normal: sample mean and $1/n$ variance; Poisson:
  $\bar{x}$; Exponential: $1/\bar{x}$); otherwise minimize the negative log-likelihood
  numerically.
- MAP adds a log-prior: Gaussian prior = L2 penalty, Laplace prior = L1 penalty.
- With a Beta prior, the prior acts like pretend flips added to the data.
- MLE is consistent, asymptotically Normal, and asymptotically efficient (Cramér–Rao).

## Try it Yourself

```python
import numpy as np
from scipy import optimize, stats

rng = np.random.default_rng(42)
# Fit a Normal via both analytic and numerical MLE; verify they agree
mu_true, sigma_true = 7.0, 3.0
x = rng.normal(mu_true, sigma_true, 150)

# Analytic
mu_analytic    = x.mean()
sigma_analytic = x.std(ddof=0)

# Numerical
def neg_ll(params):
    mu, log_s = params
    return -np.sum(stats.norm.logpdf(x, loc=mu, scale=np.exp(log_s)))

res = optimize.minimize(neg_ll, x0=[x.mean(), np.log(x.std())], method='BFGS')
mu_num, sigma_num = res.x[0], np.exp(res.x[1])

print(f"True:      mu={mu_true},  sigma={sigma_true}")
print(f"Analytic:  mu={mu_analytic:.4f}  sigma={sigma_analytic:.4f}")
print(f"Numerical: mu={mu_num:.4f}  sigma={sigma_num:.4f}")
print(f"Max abs diff: {max(abs(mu_analytic-mu_num), abs(sigma_analytic-sigma_num)):.2e}")
```

```output
True:      mu=7.0,  sigma=3.0
Analytic:  mu=6.8482  sigma=2.5587
Numerical: mu=6.8482  sigma=2.5587
Max abs diff: 0.00e+00
```

The numerical answer matches the analytic one exactly — partly because the optimizer was
*started* at the analytic answer, so it had nothing to do. Optimizing $\log\sigma$ keeps
$\sigma = e^{\log\sigma}$ positive automatically. Try starting from `x0=[0.0, 0.0]` and check
the two still agree to many decimals.

## Exercise

You observe 100 coin flips: 63 heads, 37 tails. (1) Compute the MLE for $p$. (2) Compute the MAP estimate with a $\text{Beta}(2,2)$ prior. (3) Which estimate is larger, and why?

> **Hint:** Beta(2,2) means one pretend head and one pretend tail. Which way does adding
> those push a fraction that's above 0.5?

<details>
<summary>Solution</summary>

```python
import numpy as np
from scipy import stats

n, k = 100, 63

# MLE
p_mle = k / n

# MAP with Beta(2,2) prior
alpha, beta = 2, 2
p_map = (k + alpha - 1) / (n + alpha + beta - 2)

print(f"MLE:  p = {k}/{n} = {p_mle:.4f}")
print(f"MAP:  p = ({k}+{alpha}-1)/({n}+{alpha}+{beta}-2) = {p_map:.4f}")
print(f"MLE > MAP because the prior pulls toward 0.5 (shrinkage)")

# Posterior distribution for visualization
posterior = stats.beta(alpha + k, beta + (n - k))
print(f"\nPosterior 95% CI: [{posterior.ppf(0.025):.4f}, {posterior.ppf(0.975):.4f}]")
```

The MLE (0.63) is larger because the Beta(2,2) prior places weight near 0.5, pulling the MAP estimate (0.626) slightly toward the prior mean. With 100 observations the difference is small — data dominate the prior.
As $n$ grows, the two pretend flips matter less and less, and MAP and MLE converge.
