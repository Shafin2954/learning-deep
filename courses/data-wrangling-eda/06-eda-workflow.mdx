## EDA is hypothesis generation

**Exploratory Data Analysis (EDA)** is getting to know a dataset before you model it: how
big it is, what is missing, what each column looks like, and which columns move together.
The goal is not pretty charts. The goal is a list of facts and hunches that tell you what to
clean, what to transform, and what to test.

Exploratory Data Analysis is not about making charts — it's about building a mental model of
the data that informs every modelling decision. Work through these five steps in order, and
document what you find at each step. Undocumented EDA is wasted EDA.

1. **Shape and dtypes** — how many rows, columns, and what types?
2. **Missing values** — which columns, how much, any pattern?
3. **Univariate distributions** — shape, skew, outliers, cardinality.
4. **Bivariate relationships** — numeric×numeric, numeric×categorical, categorical×categorical.
5. **Multivariate** — pairplot, heatmap, conditional patterns.

**Univariate** means one column at a time, **bivariate** two at a time, and
**multivariate** many at once. **Cardinality** is the number of distinct values a column
has.

> **Picture it:** a doctor's check-up. First height and weight (shape), then what is missing
> from your file, then each vital sign on its own, then how pairs relate ("blood pressure
> rises with age"), and only then the whole picture. Skipping to the whole picture first is
> how things get missed.

## Step 1: Shape and dtypes

Count the rows and columns and check each column's type. Wrong types (numbers stored as
text, IDs stored as numbers) are the first thing to fix.

```python
import pandas as pd
import numpy as np

rng = np.random.default_rng(0)
n = 500

df = pd.DataFrame({
    'age':       rng.integers(18, 75, n).astype(np.int32),
    'income':    rng.exponential(40_000, n).astype(np.float64),
    'score':     np.clip(rng.normal(700, 80, n), 300, 850).astype(np.float64),
    'region':    rng.choice(['North', 'South', 'East', 'West'], n),
    'product':   rng.choice(['Basic', 'Pro', 'Enterprise'], n, p=[0.5, 0.35, 0.15]),
    'churned':   rng.integers(0, 2, n).astype(np.int8),
})
# Plant some missing values
df.loc[rng.random(n) < 0.05, 'income'] = np.nan
df.loc[rng.random(n) < 0.08, 'score']  = np.nan

print(df.shape)
print(df.dtypes)
print(f"\nMemory: {df.memory_usage(deep=True).sum() / 1024:.1f} KB")
```

```output
(500, 6)
age          int32
income     float64
score      float64
region         str
product        str
churned       int8
dtype: object

Memory: 22.9 KB
```

500 rows and 6 columns. `region` and `product` are text (`str`), `churned` is a small
`int8` (it only holds 0 or 1), and the whole table uses about 23 KB. Already you know
`churned` is the likely target and two columns will need encoding (ch. 9).

## Step 2: Missing values

Next, count the blanks per column and turn them into percentages, so "19 missing" becomes
"3.8% missing" — a number you can compare across columns.

```python
import pandas as pd
import numpy as np

rng = np.random.default_rng(0)
n = 500
df = pd.DataFrame({
    'age':    rng.integers(18, 75, n).astype(np.int32),
    'income': np.where(rng.random(n) < 0.05, np.nan, rng.exponential(40_000, n)),
    'score':  np.where(rng.random(n) < 0.08, np.nan, np.clip(rng.normal(700, 80, n), 300, 850)),
    'region': rng.choice(['North', 'South', 'East', 'West'], n),
    'churned': rng.integers(0, 2, n).astype(np.int8),
})

miss = df.isnull().sum()
miss_pct = (miss / len(df) * 100).round(1)
summary = pd.DataFrame({'missing': miss, 'pct': miss_pct})
print(summary[summary['missing'] > 0])
```

```output
        missing  pct
income       19  3.8
score        43  8.6
```

Only two columns have gaps: `income` with 19 (3.8%) and `score` with 43 (8.6%) — close to
the 5% and 8% planted. The summary shows only columns with at least one blank, so a wide
table stays readable. Next you would check *why* they are missing (ch. 4).

## Step 3: Univariate distributions

Look at each column by itself. For numbers: where is the middle, how wide is the spread,
is it lopsided, are there extremes? For categories: how many of each?

A **distribution** is the pattern of how often each value occurs. **Skew** measures how
lopsided it is: 0 for symmetric, positive when a long tail stretches to the right.

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(1)
n = 500
income = rng.exponential(40_000, n).astype(np.float64)
product = rng.choice(['Basic', 'Pro', 'Enterprise'], n, p=[0.5, 0.35, 0.15])

fig, axes = plt.subplots(1, 3, figsize=(14, 3))

# Numeric: histogram with KDE
axes[0].hist(income, bins=30, color='steelblue', alpha=0.7, edgecolor='white')
axes[0].set_title('income (right-skewed)')
axes[0].set_xlabel('income')

# Numeric: box plot
axes[1].boxplot(income, vert=False)
axes[1].set_title('income box plot')
axes[1].set_xlabel('income')

# Categorical: count plot
cats, counts = np.unique(product, return_counts=True)
axes[2].barh(cats, counts, color=['steelblue', 'tomato', 'seagreen'])
axes[2].set_title('product distribution')
axes[2].set_xlabel('count')

fig.tight_layout()
plt.show()

print(f"income skew: {pd.Series(income).skew():.2f}")
print(f"product counts:\n{pd.Series(product).value_counts()}")
```

```output
income skew: 2.22
product counts:
Basic         243
Pro           168
Enterprise     89
Name: count, dtype: int64
```

The skew of 2.22 says income has a long right tail — a few people earn far more than the
rest (an exponential distribution has skew 2 in theory). In the product counts, Basic
leads with 243, then Pro with 168, and Enterprise trails with 89.

Right-skewed income ($\text{skew} > 1$) is a signal to consider log-transforming before
feeding to linear models. Enterprise customers are rare (89 of 500, about 18%) — flag for
class-imbalance consideration.

> **Picture it:** a right-skewed income histogram is a playground slide seen from the side:
> a tall ladder of ordinary incomes on the left, and a long slope trailing off to the right
> where the few very high earners sit.

## Step 4: Bivariate relationships

Now look at pairs of columns. The right tool depends on the pair's types: a scatter plot
and correlation for two numbers, grouped box plots for a number and a category, and a
contingency table for two categories.

### Numeric × numeric

The **correlation** (Pearson's $r$, ch. 7) is a number from -1 to 1 that says how close two
columns are to lying on a straight line together: 1 is a perfect rising line, 0 is no line.

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(2)
n = 500
age    = rng.integers(18, 70, n).astype(np.float64)
income = 20_000 + 800 * age + rng.normal(0, 10_000, n)
score  = np.clip(600 + 0.5 * age - 0.0001 * income + rng.normal(0, 40, n), 300, 850)

df = pd.DataFrame({'age': age, 'income': income, 'score': score})

fig, axes = plt.subplots(1, 2, figsize=(10, 4))
axes[0].scatter(df['age'], df['income'], alpha=0.3, s=15)
axes[0].set_xlabel('age'); axes[0].set_ylabel('income')
axes[0].set_title('age vs income (positive trend)')

axes[1].scatter(df['income'], df['score'], alpha=0.3, s=15, color='tomato')
axes[1].set_xlabel('income'); axes[1].set_ylabel('score')
axes[1].set_title('income vs score (weak)')

fig.tight_layout()
plt.show()
print(df.corr().round(2))
```

```output
         age  income  score
age     1.00    0.79   0.12
income  0.79    1.00   0.07
score   0.12    0.07   1.00
```

`age` and `income` correlate at 0.79 — a strong rising trend, as the formula built in
(`800 * age`). `score` barely relates to either: 0.12 with age and 0.07 with income. The
formula gives score a *negative* direct link to income (`- 0.0001 * income`), yet the
correlation is positive: income rides along with age, and age pushes score up. That
indirect path outweighs the small direct one.

> **Watch out:** a correlation between two columns mixes direct and indirect effects. To
> isolate one effect, you need a model that holds the other columns fixed — not a
> correlation table.

### Numeric × categorical

To compare a number across groups, compute summary statistics per group and draw one box
plot per group side by side.

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(3)
n = 500
product = rng.choice(['Basic', 'Pro', 'Enterprise'], n, p=[0.5, 0.35, 0.15])
income  = np.where(
    product == 'Enterprise', rng.normal(90_000, 20_000, n),
    np.where(product == 'Pro', rng.normal(55_000, 15_000, n),
             rng.normal(35_000, 10_000, n))
)
df = pd.DataFrame({'product': product, 'income': income})

fig, ax = plt.subplots(figsize=(6, 4))
groups = [df[df['product'] == p]['income'].dropna().values for p in ['Basic', 'Pro', 'Enterprise']]
ax.boxplot(groups, tick_labels=['Basic', 'Pro', 'Enterprise'])
ax.set_ylabel('income')
ax.set_title('Income by product tier')
plt.show()

print(df.groupby('product')['income'].agg(['mean', 'median', 'std']).round(0))
```

```output
               mean   median      std
product
Basic       35785.0  34782.0  10145.0
Enterprise  91137.0  92319.0  18079.0
Pro         53015.0  53471.0  14049.0
```

The groups are clearly separated: Basic averages about 35,800, Pro about 53,000, and
Enterprise about 91,100. In each tier the mean and median are close, so the groups are
roughly symmetric. Enterprise's standard deviation (18,079) is the widest, a sign of more
varied customers in that tier.

## Step 5: Contingency tables for categorical × categorical

A **contingency table** (or **crosstab**) counts how many rows fall in each combination of
two categories — region by product here. Dividing each row by its total turns counts into
shares you can compare.

```python
import pandas as pd
import numpy as np

rng = np.random.default_rng(4)
n = 500
region  = rng.choice(['North', 'South', 'East', 'West'], n)
product = rng.choice(['Basic', 'Pro', 'Enterprise'], n, p=[0.5, 0.35, 0.15])
df = pd.DataFrame({'region': region, 'product': product})

# Contingency table: raw counts
ct = pd.crosstab(df['region'], df['product'])
print("Raw counts:")
print(ct)

# Normalised by row: proportion within each region
ct_norm = pd.crosstab(df['region'], df['product'], normalize='index').round(3)
print("\nRow-normalised (proportion within region):")
print(ct_norm)
```

```output
Raw counts:
product  Basic  Enterprise  Pro
region
East        54          26   45
North       59          18   43
South       56          19   45
West        73          12   50

Row-normalised (proportion within region):
product  Basic  Enterprise    Pro
region
East     0.432       0.208  0.360
North    0.492       0.150  0.358
South    0.467       0.158  0.375
West     0.541       0.089  0.370
```

Row-normalised tables reveal differences in distribution across groups. Here the
differences look striking at first: East has 20.8% Enterprise customers and West only
8.9%. But this data was generated with region and product *independent* — the gaps are
pure sampling noise. A chi-square test of independence on these counts gives $p \approx
0.24$, far from significant (see the Probability & Statistics course for the test).

> **Watch out:** with a few hundred rows split into 12 cells, some cells hold only 12 to 26
> rows, and percentages jump by several points on a handful of customers. Before you report
> "West buys less Enterprise", test it.

## Recap in plain words

- EDA builds a written list of facts and hunches about the data before any model.
- Go in order: shape and types, missing values, one column at a time, pairs, then many.
- Skew above 1 suggests a log transform; rare categories suggest class imbalance.
- Pick the pair tool by type: correlation for number-number, grouped box plots for
  number-category, crosstabs for category-category.
- Differences in small groups can be noise — check them with a test before believing them.

## Try it Yourself

This runs all five steps on a small customer table where churn is defined as spending
under 40.

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(7)
n = 400
tenure  = rng.integers(1, 120, n).astype(np.float64)
spend   = 20 + 0.5 * tenure + rng.exponential(30, n)
segment = rng.choice(['A', 'B', 'C'], n, p=[0.4, 0.4, 0.2])
churned = (spend < 40).astype(np.int8)

df = pd.DataFrame({'tenure': tenure, 'spend': spend,
                   'segment': segment, 'churned': churned})

# Step 1-2: shape and missing
print("Shape:", df.shape)
print("Missing:\n", df.isnull().sum())

# Step 3: numeric distributions
fig, axes = plt.subplots(1, 2, figsize=(10, 3))
axes[0].hist(df['tenure'], bins=20, color='steelblue', edgecolor='white')
axes[0].set_title('Tenure distribution')
axes[1].hist(df['spend'], bins=30, color='tomato', edgecolor='white')
axes[1].set_title('Spend distribution (right-skew?)')
plt.tight_layout(); plt.show()

# Step 4: bivariate scatter
print("\nCorrelation spend vs tenure:", df['spend'].corr(df['tenure']).round(3))

# Step 5: contingency
print("\nChurn by segment:")
print(pd.crosstab(df['segment'], df['churned'], normalize='index').round(3))
```

```output
Shape: (400, 4)
Missing:
 tenure     0
spend      0
segment    0
churned    0
dtype: int64

Correlation spend vs tenure: 0.436

Churn by segment:
churned      0      1
segment
A        0.904  0.096
B        0.966  0.034
C        0.923  0.077
```

No missing values, and spend correlates with tenure at 0.436 — positive, as the formula
`0.5 * tenure` built in. The churn table shows 9.6%, 3.4%, and 7.7% churn across segments
A, B, C, but segment was assigned at random, so this spread is noise again (a chi-square
test gives $p \approx 0.09$). The real churn driver is spend, which you would find by
comparing spend across `churned` values. Try `df.groupby('churned')['spend'].mean()` and
see how far apart the two groups are.

## Exercise

Simulate a DataFrame: 600 rows, columns `temperature` (Normal 20, 5), `humidity` (Beta(2,5)×100),
`city` (choice of 4 cities), `demand` (positive linear function of temperature + noise).
Produce: (1) a printed missing-value summary, (2) a histogram of `demand`, (3) a box plot of
`demand` by `city`, (4) a correlation table for the numeric columns.

> **Hint:** build `temperature` first as its own array so `demand` can use it, then put
> everything in one `DataFrame`. For the box plot, collect one array per city in a list.

<details>
<summary>Solution</summary>

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt

rng = np.random.default_rng(0)
n = 600
cities = ['Oslo', 'Cairo', 'Berlin', 'Tokyo']
temp   = rng.normal(20, 5, n).astype(np.float64)
df = pd.DataFrame({
    'temperature': temp,
    'humidity':    (rng.beta(2, 5, n) * 100).astype(np.float64),
    'city':        rng.choice(cities, n),
    'demand':      (200 + 8 * temp + rng.normal(0, 20, n)).astype(np.float64),
})

# 1) Missing summary
print("Missing:\n", df.isnull().sum())

# 2) Demand histogram
fig, axes = plt.subplots(1, 2, figsize=(10, 4))
axes[0].hist(df['demand'], bins=25, color='steelblue', edgecolor='white')
axes[0].set_title('Demand distribution')

# 3) Box plot by city
city_groups = [df[df['city'] == c]['demand'].values for c in cities]
axes[1].boxplot(city_groups, tick_labels=cities)
axes[1].set_title('Demand by city')

plt.tight_layout()
plt.show()

# 4) Correlation table
print("\nCorrelation matrix:")
print(df[['temperature', 'humidity', 'demand']].corr().round(3))
```

Temperature and demand should show strong positive correlation (~0.89); humidity and demand
near zero. City box plots should show similar medians (city was random here) — a real dataset
would show geographic differences. Running it confirms this: temperature and demand
correlate at 0.894, humidity and demand at -0.003. The strength comes from the signal-to-noise
ratio: `8 * temp` has a spread of 40 against noise of 20.
