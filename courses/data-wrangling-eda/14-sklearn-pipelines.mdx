## Why you need Pipelines

A **Pipeline** bundles every preparation step and the model into one object, so that
"learn from the training data, then apply to new data" happens the same way every time,
for every step, without you having to remember it. It is the practical cure for the
preprocessing leakage of ch. 12.

Any transformation that computes statistics from the data (mean, variance, category counts,
target means) must be fit on training data only and then applied to test data. If you apply
these transformations outside a Pipeline — even carefully — you will eventually forget to do
it correctly inside a CV loop, and you'll get leakage. Pipelines make the correct behaviour
automatic.

A `Pipeline` is a sequence of `(name, estimator)` pairs. During `fit`, it calls
`fit_transform` on every step except the last (which gets `fit`). During `predict` or
`transform`, it calls `transform` on every step except the last (which gets `predict`).

(An **estimator** is any scikit-learn object with a `fit` method: a model, a scaler, an
imputer. A **transformer** is an estimator that also has `transform`.)

> **Picture it:** an assembly line in a factory. Each station does one job — fill holes,
> resize, paint — and the line is set up once using sample parts (the training data).
> After that, every new part goes through the same stations in the same order, with the
> settings left exactly as they were.

## Basic Pipeline

The simplest Pipeline chains steps for all columns at once: fill the blanks, scale, then
classify.

```python
import numpy as np
import pandas as pd
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split, cross_val_score

rng = np.random.default_rng(0)
n = 500
X = rng.normal(0, 1, (n, 4)).astype(np.float64)
X[rng.random((n, 4)) < 0.1] = np.nan   # 10% missing
y = (X[:, 0] + X[:, 1] + rng.normal(0, 0.5, n) > 0).astype(np.int8)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=0)

pipe = Pipeline([
    ('impute', SimpleImputer(strategy='mean')),
    ('scale',  StandardScaler()),
    ('clf',    LogisticRegression(max_iter=500)),
])
pipe.fit(X_train, y_train)

print(f"Train accuracy: {pipe.score(X_train, y_train):.4f}")
print(f"Test  accuracy: {pipe.score(X_test,  y_test):.4f}")

# CV on full pipeline — no leakage
auc = cross_val_score(pipe, X, y, cv=5, scoring='roc_auc').mean()
print(f"CV AUC (5-fold): {auc:.4f}")
```

```output
Train accuracy: 0.8575
Test  accuracy: 0.7900
CV AUC (5-fold): 0.9197
```

Train accuracy is 0.8575 and test accuracy 0.7900 — a gap worth noting, but on 100 test
rows a few misclassified rows move accuracy by several points. The CV AUC of 0.9197 comes
from calling `cross_val_score` on the *whole* pipeline, so every fold re-fits the imputer
and the scaler on its own training part.

The imputer mean is computed only on each training fold; the same transform is applied to
the val fold — entirely automated by Pipeline.

> **Watch out:** pass the *pipeline* to `cross_val_score`, not a model plus pre-scaled data.
> If you scale `X` first and then cross-validate only the model, the leak of ch. 12 is back.

## ColumnTransformer — different transforms per column

Numbers and categories need different preparation: numbers get filled and scaled,
categories get filled and one-hot encoded. A **ColumnTransformer** sends each group of
columns down its own mini-pipeline and glues the results back together side by side.

Real datasets have mixed types: some columns need imputing then scaling, others need imputing
then one-hot encoding, and tree models may need no scaling at all.

`ColumnTransformer` applies a different `Pipeline` (or single transformer) to each subset of
columns and horizontally concatenates the results.

> **Picture it:** a sorting office. Letters go to one desk, parcels to another; each desk
> handles its own kind, and everything is loaded onto the same truck at the end.

```python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split, cross_val_score

rng = np.random.default_rng(1)
n = 600
df = pd.DataFrame({
    'age':     rng.normal(40, 10, n).astype(np.float64),
    'income':  rng.exponential(50_000, n).astype(np.float64),
    'region':  rng.choice(['North', 'South', 'East', 'West'], n),
    'product': rng.choice(['Basic', 'Pro', 'Enterprise'], n),
})
# Plant missing values
df.loc[rng.random(n) < 0.1, 'age'] = np.nan
df.loc[rng.random(n) < 0.08, 'region'] = np.nan

y = ((df['income'].fillna(df['income'].median()) > 40_000) &
     (df['age'].fillna(40) < 50)).astype(np.int8)

X_train, X_test, y_train, y_test = train_test_split(df, y, test_size=0.2, random_state=0)

# Numeric branch: impute median → scale
num_pipeline = Pipeline([
    ('impute', SimpleImputer(strategy='median')),
    ('scale',  StandardScaler()),
])

# Categorical branch: impute most-frequent → one-hot
cat_pipeline = Pipeline([
    ('impute', SimpleImputer(strategy='most_frequent')),
    ('ohe',   OneHotEncoder(drop='first', sparse_output=False, handle_unknown='ignore')),
])

preprocessor = ColumnTransformer([
    ('num', num_pipeline, ['age', 'income']),
    ('cat', cat_pipeline, ['region', 'product']),
])

full_pipe = Pipeline([
    ('prep', preprocessor),
    ('clf',  LogisticRegression(max_iter=1000)),
])

full_pipe.fit(X_train, y_train)
print(f"Test accuracy:      {full_pipe.score(X_test, y_test):.4f}")

cv_auc = cross_val_score(full_pipe, df, y, cv=5, scoring='roc_auc').mean()
print(f"CV AUC (5-fold):    {cv_auc:.4f}")
```

```output
Test accuracy:      0.9000
CV AUC (5-fold):    0.9595
```

Test accuracy is 0.9000 and the 5-fold CV AUC is 0.9595. (`pipe.score` reports
*accuracy* for a classifier; AUC needs `scoring='roc_auc'` as in the CV call.) The single
`full_pipe` object holds both branches, so fitting it once fitted all four columns'
preparation steps on the training rows only.

> **Watch out:** `handle_unknown='ignore'` matters. Without it, a category that appears
> only in the test set — a new region, say — makes `transform` raise an error. With it, that
> row gets zeros in all the region columns.

## Inspecting pipeline internals

You can open up a fitted pipeline and read what each step learned. That is how you
*prove* nothing was fitted on test data.

Verifying that transformers were fit only on training data is easy — check their learned
parameters:

```python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.impute import SimpleImputer
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(2)
n = 500
df = pd.DataFrame({'age': rng.normal(40, 10, n).astype(np.float64),
                   'income': rng.normal(50_000, 15_000, n).astype(np.float64)})
X_train, X_test = train_test_split(df, test_size=0.2, random_state=0)

prep = ColumnTransformer([
    ('num', Pipeline([
        ('imp', SimpleImputer(strategy='mean')),
        ('sc',  StandardScaler()),
    ]), ['age', 'income']),
])

prep.fit(X_train)

# Imputer statistics — must match train, not full dataset
imp = prep.named_transformers_['num'].named_steps['imp']
sc  = prep.named_transformers_['num'].named_steps['sc']

print(f"Imputer means:  age={imp.statistics_[0]:.2f}, income={imp.statistics_[1]:.2f}")
print(f"True train means: age={X_train['age'].mean():.2f}, income={X_train['income'].mean():.2f}")
print(f"Scaler means:   age={sc.mean_[0]:.2f}, income={sc.mean_[1]:.2f}")
print("Match train means:", abs(imp.statistics_ - [X_train['age'].mean(), X_train['income'].mean()]).max() < 1e-6)
```

```output
Imputer means:  age=39.25, income=50674.56
True train means: age=39.25, income=50674.56
Scaler means:   age=39.25, income=50674.56
Match train means: True
```

The imputer's means (age 39.25, income 50674.56), the scaler's means, and the training
set's own means are identical, and the check prints `True`. The test rows never touched
the fitted statistics. `named_transformers_` reaches into the ColumnTransformer and
`named_steps` reaches into a Pipeline, each by the names you gave the steps.

## Custom transformers

When no built-in step does what you need, you can write your own — a small class with a
`fit` method that learns and a `transform` method that applies.

When you need a transform that sklearn doesn't provide, subclass `BaseEstimator` and
`TransformerMixin`. The `fit` method learns parameters; `transform` applies them.
(`TransformerMixin` gives you `fit_transform` for free; `BaseEstimator` gives you
`get_params`, which cloning in CV needs.)

```python
import numpy as np
from sklearn.base import BaseEstimator, TransformerMixin
from sklearn.pipeline import Pipeline
from sklearn.model_selection import train_test_split

class LogTransformer(BaseEstimator, TransformerMixin):
    """Apply log(1+x) to all columns."""

    def fit(self, X, y=None):
        self.min_ = np.min(X, axis=0)  # learned attrs end in _
        return self

    def transform(self, X):
        X = np.asarray(X, dtype=np.float64)
        if np.any(X < 0):
            raise ValueError("LogTransformer requires non-negative input")
        return np.log1p(X)

rng = np.random.default_rng(3)
n = 300
X = rng.exponential(100, (n, 2)).astype(np.float64)
X_train, X_test = train_test_split(X, test_size=0.2, random_state=0)

pipe = Pipeline([
    ('log', LogTransformer()),
])
X_train_log = pipe.fit_transform(X_train)
X_test_log  = pipe.transform(X_test)

print(f"Original mean:    {X_train.mean():.1f}")
print(f"After log:        {X_train_log.mean():.3f}")
print(f"Test transformed: {X_test_log.mean():.3f}")
```

```output
Original mean:    105.5
After log:        4.129
Test transformed: 4.125
```

The training values average 105.5 before the transform and 4.129 after — the log
squeezed values in the hundreds down to about 4 to 5. The test set gives a similar 4.125,
transformed with the same object.

> **Watch out:** scikit-learn decides whether a step has been fitted by looking for
> attributes whose names *end* in an underscore, like `min_`. Name a learned attribute
> `self._min` (leading underscore) instead, and `pipe.transform` raises `NotFittedError`
> even after a successful `fit`. Also: never set learned attributes in `__init__`.

## Recap in plain words

- A Pipeline chains preparation steps and a model, and always fits them on training data
  only.
- Cross-validate the whole pipeline, so every fold re-learns every step.
- A ColumnTransformer sends numeric and categorical columns down separate branches.
- `named_transformers_` and `named_steps` let you read what each fitted step learned.
- Custom steps need `fit` and `transform`, and learned attributes ending in `_`.

## Try it Yourself

This is the full recipe on a churn-style table: two numeric and two categorical columns,
a ColumnTransformer, and a random forest, scored with stratified 5-fold CV.

```python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import cross_val_score, StratifiedKFold

rng = np.random.default_rng(4)
n = 800
df = pd.DataFrame({
    'tenure':  rng.normal(24, 12, n).astype(np.float64),
    'spend':   rng.exponential(500, n).astype(np.float64),
    'plan':    rng.choice(['basic', 'standard', 'premium'], n),
    'country': rng.choice(['BD', 'IN', 'PK', 'LK'], n),
})
df.loc[rng.random(n) < 0.12, 'tenure'] = np.nan
y = ((df['tenure'].fillna(24) > 24) & (df['spend'] > 300)).astype(np.int8)

preproc = ColumnTransformer([
    ('num', Pipeline([('imp', SimpleImputer(strategy='median')),
                      ('sc',  StandardScaler())]),
     ['tenure', 'spend']),
    ('cat', Pipeline([('imp', SimpleImputer(strategy='most_frequent')),
                      ('ohe', OneHotEncoder(drop='first', sparse_output=False))]),
     ['plan', 'country']),
])

pipe = Pipeline([('prep', preproc), ('clf', RandomForestClassifier(n_estimators=50, random_state=0))])
cv = StratifiedKFold(5, shuffle=True, random_state=0)
aucs = cross_val_score(pipe, df, y, cv=cv, scoring='roc_auc')
print(f"CV AUC: {aucs.mean():.4f} ± {aucs.std():.4f}")
```

```output
CV AUC: 0.9995 ± 0.0006
```

The CV AUC is 0.9995 $\pm$ 0.0006 — nearly perfect. That is not leakage: the target is an
exact rule on two columns (`tenure > 24` and `spend > 300`) with no noise, and a random
forest finds those two thresholds easily. The only imperfection comes from the 12% of
`tenure` values that were blank. Try adding noise to the label — flip 10% of `y` at random
with `y = np.where(rng.random(n) < 0.1, 1 - y, y)` — and see how far the AUC falls.

## Exercise

Build a Pipeline for a regression problem: `ColumnTransformer` with a numeric branch
(`SimpleImputer` + `StandardScaler`) and a categorical branch (`SimpleImputer` +

> **Hint:** copy the `preproc` block from the Try-it, swap the classifier for `Ridge()`, and
> use `scoring='neg_root_mean_squared_error'`. scikit-learn negates error scores so that
> "higher is better" everywhere — flip the sign back before printing.

```python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.linear_model import Ridge
from sklearn.model_selection import cross_val_score, KFold

rng = np.random.default_rng(0)
n = 500
df = pd.DataFrame({
    'size':   rng.normal(80, 20, n).astype(np.float64),
    'rooms':  rng.integers(1, 6, n).astype(np.float64),
    'city':   rng.choice(['oslo', 'berlin', 'tokyo', 'cairo'], n),
})
df.loc[rng.random(n) < 0.1, 'size'] = np.nan
y = 200_000 + 2500 * df['size'].fillna(80) + 20_000 * df['rooms'] + rng.normal(0, 15_000, n)

preproc = ColumnTransformer([
    ('num', Pipeline([('imp', SimpleImputer(strategy='median')),
                      ('sc',  StandardScaler())]),
     ['size', 'rooms']),
    ('cat', Pipeline([('imp', SimpleImputer(strategy='most_frequent')),
                      ('ohe', OneHotEncoder(drop='first', sparse_output=False))]),
     ['city']),
])

pipe = Pipeline([('prep', preproc), ('reg', Ridge())])
rmses = cross_val_score(pipe, df, y, cv=KFold(5, shuffle=True, random_state=0),
                        scoring='neg_root_mean_squared_error')
print(f"CV RMSE: {(-rmses).mean():.0f} ± {rmses.std():.0f}")
```

A complete Pipeline ensures every preprocessing step is re-fit on each training fold.
Checking the `named_steps` of the fitted pipeline would confirm the imputer's `statistics_`
match the training-fold mean/median — not the full-dataset statistic. When run, the CV RMSE
is about 15,314 (spread 782 across folds), right at the 15,000 noise level built into `y`:
the model has found all the structure there is, and the rest is noise no model can remove.

## Under the Trench

Rare and advanced topics you should at least know the name of. You won't need them daily,
but you'll stop being surprised when you meet them.

- **Adversarial validation** — train a binary classifier to predict whether a sample is from train or test; AUC significantly above 0.5 means the distributions differ; use it to identify which features are leaking or drifted. (You met it in ch. 13.)
- **Target/leave-one-out encoding with CV folds** — for each training fold, compute target mean per category using only the OTHER folds; prevents the target from leaking into the categorical feature representation. (The out-of-fold encoding of ch. 9.)
- **Weight of evidence & information value (IV)** — $\text{WoE} = \log(P(\text{event}|cat)/P(\text{non-event}|cat))$; IV $= \sum \text{WoE} \times (P_e - P_{ne})$; IV > 0.3 signals strong predictor; used heavily in credit scoring. In plain words: WoE says how much more common the event is in a category than the non-event, on a log scale; IV adds this up over categories into one "how predictive" score.
- **Entity/record linkage & fuzzy joins** — match records without a clean foreign key; Jaccard similarity on token sets, Levenshtein edit distance, blocking (only compare records sharing first letter) to scale. (Levenshtein distance counts the single-letter edits needed to turn one string into another.)
- **Imbalanced data: SMOTE family vs class weights** — SMOTE synthesises new minority samples in feature space via interpolation; Borderline-SMOTE focuses on boundary; class weights adjust the loss instead of sampling; SMOTE helps tree models, weights help logistic/SVM. Resample only inside the training folds, or the synthetic rows leak into validation.
- **Great Expectations / data contracts** — define expectations (non-null, value range, regex pattern) as test suites that run in CI; catch schema drift before it corrupts downstream models. (CI — continuous integration — runs the checks automatically on every change.)
- **Feature stores & training/serving skew** — if a feature is computed differently at training time (using historical data) vs serving time (using real-time data), predictions degrade silently; feature stores enforce identical computation both ways.
