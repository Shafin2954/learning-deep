## Why outliers demand investigation, not deletion

An **outlier** is a value that sits far away from the rest — a 200 in a column where
almost everything is between 30 and 70. Some outliers are mistakes; some are the most
important rows in the dataset. Finding them is easy; deciding what they *are* is the real
work.

An outlier is any observation that deviates markedly from the bulk of the data. Before acting,
you need to know *why* it's there:

- **Measurement error** (sensor glitch, data entry typo): fix or remove.
- **Legitimate rare event** (a billion-dollar transaction in a payment dataset): keep.
- **Distribution mismatch** (wrong units in one column): fix at the source.

Deleting outliers without understanding them corrupts the model's view of the real world.

> **Picture it:** a smoke alarm going off. It might be a burnt toast (a harmless glitch) or a
> real fire (the thing you most need to know about). Ripping the alarm off the wall every
> time it beeps is the "delete all outliers" strategy.

## IQR-based fences

The plain idea: find the middle half of the data, measure how wide it is, and call anything
that lands far outside that band suspicious. Because the middle half ignores the extremes,
the extremes cannot drag the band around.

The **quartiles** split sorted data into four equal parts: **Q1** is the value 25% of the way
up and **Q3** the value 75% of the way up. The interquartile range (IQR = Q3 − Q1) is robust
to outliers by definition, so using it to detect outliers avoids the circularity of
mean-based methods. **Robust** means a few wild values barely change it.

- **Mild outlier:** $x < Q1 - 1.5 \cdot \text{IQR}$ or $x > Q3 + 1.5 \cdot \text{IQR}$.
- **Extreme outlier:** $x < Q1 - 3 \cdot \text{IQR}$ or $x > Q3 + 3 \cdot \text{IQR}$.

These limits are called **fences**: points beyond them are flagged.

```python
import pandas as pd
import numpy as np

rng = np.random.default_rng(0)
n = 300
data = rng.normal(50, 10, n).astype(np.float64)

# Plant 5 outliers
data[[10, 50, 100, 200, 250]] = [150, -30, 200, -50, 180]

s = pd.Series(data)
Q1, Q3 = s.quantile(0.25), s.quantile(0.75)
IQR = Q3 - Q1
lower = Q1 - 1.5 * IQR
upper = Q3 + 1.5 * IQR

outliers = s[(s < lower) | (s > upper)]
print(f"Q1={Q1:.1f}, Q3={Q3:.1f}, IQR={IQR:.1f}")
print(f"Fences: [{lower:.1f}, {upper:.1f}]")
print(f"Outliers detected ({len(outliers)}): {outliers.values}")
```

```output
Q1=42.7, Q3=57.0, IQR=14.4
Fences: [21.1, 78.6]
Outliers detected (8): [150.         -30.         200.         -50.          80.66036739
  18.93663199 180.          20.63954554]
```

The middle half spans 42.7 to 57.0 (IQR 14.4), so the fences sit at 21.1 and 78.6. All 5
planted values were caught — 150, -30, 200, -50, 180 — but so were 3 ordinary points:
80.66, 18.94, and 20.64. Those are honest draws from the normal distribution's tails.

> **Watch out:** the 1.5-IQR rule flags about 0.7% of perfectly normal data. In 300 rows
> that is around 2 false alarms; in a million rows it is about 7,000. Flagged does not mean
> wrong.

## Z-score and its weakness

A **z-score** says how many standard deviations a value is from the mean. The problem: the
mean and standard deviation are themselves pulled toward the outliers, so the ruler you
measure with is bent by the thing you are measuring.

The z-score $z = (x - \mu) / \sigma$ is corrupted by the very outliers you're trying to detect:
the mean and std shift toward them, making extreme values look less extreme.

```python
import numpy as np

rng = np.random.default_rng(1)
data = rng.normal(50, 10, 300).astype(np.float64)
data[[0, 1]] = [500, 600]   # heavy outliers

z = (data - data.mean()) / data.std()
print(f"True outlier z-scores: {z[0]:.2f}, {z[1]:.2f}")
print(f"Threshold |z| > 3 catches them: {(abs(z) > 3).sum()} observations")
print(f"Mean shifted to: {data.mean():.1f} (true: ~50)")
print(f"Std inflated to: {data.std():.1f} (true: ~10)")
```

```output
True outlier z-scores: 10.66, 13.04
Threshold |z| > 3 catches them: 2 observations
Mean shifted to: 52.3 (true: ~50)
Std inflated to: 42.0 (true: ~10)
```

Two values out of 300 inflated the standard deviation from about 10 to 42.0 and moved the
mean from about 50 to 52.3. Here $|z| > 3$ still catches both, but look at how much they
shrank: measured with the true spread, 500 sits $(500 - 50)/10 = 45$ standard deviations
out. With the inflated spread it scores only 10.66.

With heavy enough outliers the z-score threshold may miss them because the std inflates so
much that even extreme values look like they're within 3 std of the mean. This
**masking** gets worse with more outliers or fewer rows: with many outliers, each one
props up the spread that hides the others.

> **Watch out:** in a sample of $n$ points, no z-score can exceed $(n-1)/\sqrt{n}$ (using
> the sample standard deviation, as pandas does) or $\sqrt{n-1}$ (using NumPy's default).
> With 10 rows those caps are 2.85 and 3.0, so the $|z| > 3$ rule can never flag anything.

### Modified z-score — robust alternative

The fix is to build the ruler from robust pieces: the median instead of the mean, and the
median distance from the median instead of the standard deviation.

Replace mean with median and std with MAD (median absolute deviation):

$$
\tilde{z}_i = \frac{0.6745 \cdot (x_i - \tilde{x})}{\text{MAD}}
$$

where $\text{MAD} = \text{median}|x_i - \tilde{x}|$ and 0.6745 makes the scale consistent
with the standard deviation for normal data.

> **In plain words:**
> - $\tilde{x}$ is the median of the data.
> - $x_i - \tilde{x}$ is how far point $i$ is from the median.
> - **MAD** (median absolute deviation) is the typical such distance, taken with a median so
>   the outliers can't inflate it.
> - Multiplying by 0.6745 rescales it so that, on normal data, $\tilde{z}_i$ reads like an
>   ordinary z-score. The usual cut-off is $|\tilde{z}_i| > 3.5$.

```python
import numpy as np

rng = np.random.default_rng(2)
data = rng.normal(50, 10, 300).astype(np.float64)
data[[0, 1]] = [500, 600]

median = np.median(data)
mad = np.median(np.abs(data - median))
mz = 0.6745 * (data - median) / mad

print(f"Median: {median:.1f}, MAD: {mad:.1f}")
print(f"Modified z-scores of outliers: {mz[0]:.1f}, {mz[1]:.1f}")
print(f"|mz| > 3.5 detects: {(np.abs(mz) > 3.5).sum()} outliers")
```

```output
Median: 49.3, MAD: 7.3
Modified z-scores of outliers: 41.5, 50.8
|mz| > 3.5 detects: 2 outliers
```

The median (49.3) and MAD (7.3) look like the clean data's centre and spread — the two
planted values did not move them. Measured with that ruler, the outliers score 41.5 and
50.8, close to their "true" distance, and the $3.5$ cut-off flags exactly those 2.

The modified z-score is unaffected by the outliers themselves.

## Isolation Forest — multivariate detection

Some outliers are only strange as a *combination*: a 2-metre-tall person is unusual, and a
40-kg adult is unusual, but a 2-metre, 40-kg adult is far stranger than either. Checking
one column at a time can miss that.

For multivariate data, the **Isolation Forest** isolates anomalies by recursively
random-splitting features. Outliers are isolated with fewer splits (shorter path length).

> **Picture it:** a game of "guess who" with random yes/no questions such as "is x above
> 2.3?". A loner standing in an empty corner is singled out after two or three questions; a
> person in the middle of the crowd needs many. The forest plays the game hundreds of times
> and flags whoever gets singled out fastest on average.

```python
import numpy as np
import pandas as pd
from sklearn.ensemble import IsolationForest

rng = np.random.default_rng(3)
n = 300
X = pd.DataFrame({
    'x': rng.normal(0, 1, n).astype(np.float64),
    'y': rng.normal(0, 1, n).astype(np.float64),
})
# Plant 10 outliers in a corner the IQR won't catch well
X.loc[:9, 'x'] = rng.uniform(5, 8, 10)
X.loc[:9, 'y'] = rng.uniform(5, 8, 10)

iso = IsolationForest(n_estimators=100, contamination=0.05, random_state=0)
X['is_outlier'] = iso.fit_predict(X[['x', 'y']]) == -1

print(f"Outliers found: {X['is_outlier'].sum()}")
print("True positives (planted):", X.loc[:9, 'is_outlier'].sum(), "/ 10")
```

```output
Outliers found: 15
True positives (planted): 10 / 10
```

All 10 planted corner points were flagged (10 / 10). The forest flagged 15 in total because
`contamination=0.05` tells it to flag 5% of 300 rows — so 5 ordinary points were flagged
to fill the quota.

> **Watch out:** `contamination` is your guess of the outlier share, and the model flags
> exactly that share. Set it too high and you get false alarms; too low and real outliers
> slip through. It is a decision, not something the model learns.

## Treatment options

Once a value is flagged and investigated, you can cap it, delete it, mark it, or leave it
alone. Each choice changes your statistics differently.

Once you've identified outliers, choose from four approaches — and record your reasoning:

| Action | When |
|--------|------|
| **Clip** to fence | Known-valid range exists; values beyond it are errors |
| **Remove** row | Strong evidence of recording error; small fraction |
| **Flag** as feature | Outlier may carry signal (fraud, failure) |
| **Leave** as-is | Tree models handle them; removing introduces bias |

**Clipping** (also called **capping** or **winsorizing**) replaces each value beyond a fence
with the fence value itself.

```python
import pandas as pd
import numpy as np

rng = np.random.default_rng(4)
s = pd.Series(rng.normal(100, 15, 500).astype(np.float64))
s.iloc[[5, 20, 100]] = [500, -200, 800]   # planted errors

Q1, Q3 = s.quantile(0.25), s.quantile(0.75)
IQR = Q3 - Q1
lower, upper = Q1 - 1.5 * IQR, Q3 + 1.5 * IQR

# Option 1: clip
s_clip = s.clip(lower, upper)

# Option 2: remove
s_drop = s[(s >= lower) & (s <= upper)]

print(f"Original  — mean: {s.mean():.1f}, std: {s.std():.1f}, n={len(s)}")
print(f"Clipped   — mean: {s_clip.mean():.1f}, std: {s_clip.std():.1f}, n={len(s_clip)}")
print(f"Removed   — mean: {s_drop.mean():.1f}, std: {s_drop.std():.1f}, n={len(s_drop)}")
```

```output
Original  — mean: 101.7, std: 41.3, n=500
Clipped   — mean: 100.2, std: 15.4, n=500
Removed   — mean: 100.4, std: 14.8, n=494
```

Three bad values pushed the standard deviation from about 15 to 41.3. Clipping kept all 500
rows and brought it back to 15.4; removing dropped 6 rows (the 3 planted errors plus 3
natural tail points) and gave 14.8.

Clipping preserves sample size; removing reduces it. Both recover the true std
$\approx 15$.

## Recap in plain words

- Investigate every outlier: typo, real rare event, or units mix-up each need a different
  fix.
- IQR fences use the middle half of the data, so the outliers can't move them.
- Plain z-scores are distorted by the outliers they hunt; use the modified z-score with the
  median and MAD.
- Isolation Forest finds rows that are odd as a combination of columns, and flags exactly
  the `contamination` share you ask for.
- Clip to keep rows, remove for confirmed errors, flag when the oddness itself is a signal.

## Try it Yourself

Eight "bot" rows with huge revenue *and* huge session counts are planted in 400 normal
rows. You compare a one-column IQR check with a two-column Isolation Forest.

```python
import pandas as pd
import numpy as np
from sklearn.ensemble import IsolationForest

rng = np.random.default_rng(10)
n = 400
df = pd.DataFrame({
    'revenue':   rng.normal(1000, 200, n).astype(np.float64),
    'sessions':  rng.normal(50, 10, n).astype(np.float64),
})
# Plant outliers: 8 very high revenue + high sessions (bots?)
df.loc[:7, 'revenue']  = rng.uniform(5000, 8000, 8)
df.loc[:7, 'sessions'] = rng.uniform(500, 900, 8)

# IQR on revenue alone
Q1, Q3 = df['revenue'].quantile(0.25), df['revenue'].quantile(0.75)
IQR = Q3 - Q1
iqr_flag = (df['revenue'] < Q1 - 1.5*IQR) | (df['revenue'] > Q3 + 1.5*IQR)

# Isolation Forest on both columns
iso = IsolationForest(contamination=0.03, random_state=0)
iso_flag = iso.fit_predict(df) == -1

print(f"IQR detected: {iqr_flag.sum()} outliers, TP: {iqr_flag[:8].sum()}/8")
print(f"IsoForest detected: {iso_flag.sum()} outliers, TP: {iso_flag[:8].sum()}/8")
```

```output
IQR detected: 14 outliers, TP: 8/8
IsoForest detected: 12 outliers, TP: 8/8
```

Both methods caught all 8 bots (`TP: 8/8`, where **TP** — true positives — counts real
outliers correctly flagged). The difference is in false alarms: IQR flagged 14 rows, so 6
normal ones; the forest flagged 12 (its 3% quota), so 4 normal ones. Try making the bots
subtler — revenue around 1,600 and sessions around 90, each only mildly high — and watch
which method keeps finding them.

import pandas as pd
import numpy as np

rng = np.random.default_rng(0)
s = pd.Series(rng.normal(60_000, 8_000, 500).astype(np.float64))
s.iloc[[0, 1, 2, 3]] = [500_000, -10_000, 999_999, -5_000]

# (a) IQR
Q1, Q3 = s.quantile(0.25), s.quantile(0.75)
IQR = Q3 - Q1
lower, upper = Q1 - 1.5 * IQR, Q3 + 1.5 * IQR
iqr_out = (s < lower) | (s > upper)

# (b) Modified z-score
med = np.median(s)
mad = np.median(np.abs(s - med))
mz = 0.6745 * (s - med) / mad
mz_out = np.abs(mz) > 3.5
print(f"Modified z-score detected: {mz_out.sum()}")

# (c) Clip
s_clipped = s.clip(lower, upper)

Both IQR and modified z-score catch all 4 planted outliers — and more: when run, IQR
flags 10 values and the modified z-score 6, the extras being genuine tail salaries.

before to 59810 / 8221 after. The key insight: always investigate *why* values are extreme
before deciding on treatment — here 6 of IQR's 10 flags are real people.
