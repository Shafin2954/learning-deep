## Why measurement scales matter

Before you compute anything on a column, ask one question: *what kind of thing does this
number measure?* The answer decides which maths makes sense. A ZIP code is written with
digits, but averaging ZIP codes gives you a number that means nothing. Averaging
temperatures gives you a real, useful number.

The operations you can legally perform on a variable depend on what kind of thing it
measures. Averaging a list of ZIP codes is nonsense; averaging temperatures is not. The
four **measurement scales** — the four "kinds" a variable can be — are **nominal, ordinal,
interval, ratio**. They tell you exactly which arithmetic operations are valid, which
visualizations apply, and which ML model assumptions are reasonable.

> **Picture it:** the four scales are a ladder. Each rung keeps every power of the rung
> below and adds one new one. Nominal can only say "same or different". Ordinal adds
> "bigger or smaller". Interval adds "by how much". Ratio adds "how many times as much".

## The four scales

Each scale below comes with examples, the operations it allows, and a short demo of the
legal operations in pandas.

### Nominal — categories with no order

A **nominal** variable is a name tag: it tells you which group a row belongs to, and
nothing more. Values are labels only. No ranking, no distance.

Examples: country, product category, blood type, species.

Legal operations: `==`, `!=`, `count`, `mode`. Nothing else. (The **mode** is the most
common value.)

```python
import pandas as pd

s = pd.Series(['cat', 'dog', 'cat', 'bird', 'dog', 'cat'])
print(s.value_counts())               # legal: count
print("mode:", s.mode()[0])           # legal: mode
# s.mean()  ← illegal: meaningless
```

```output
cat     3
dog     2
bird    1
Name: count, dtype: int64
mode: cat
```

`value_counts` shows `cat` 3 times, `dog` 2 times, `bird` once, and the mode is `cat` —
the only two summaries a nominal column can honestly give you. There is no "average
animal".

You encode nominal variables as **one-hot** (ch. 9) for most models — one 0/1 column per
category, so no category looks "bigger" than another. Order-insensitive.

> **Watch out:** if you label-encode a nominal column as `cat=0, dog=1, bird=2`, a linear
> model reads "bird is twice as much as dog". That order is invented, and the model will
> happily learn from it.

### Ordinal — categories with a meaningful order

An **ordinal** variable is a ranking: you know first from second, but not *how far* apart
they are. Values have a rank, but the gaps between ranks are not guaranteed to be equal.

Examples: education level (high school < bachelor < master < PhD), satisfaction score
(1–5 stars), cancer stage (I < II < III < IV).

Legal operations: all nominal ops, plus `<`, `>`, `median`, `rank`.

> **Picture it:** finishing places in a race. 1st beat 2nd, and 2nd beat 3rd — but 1st may
> have won by a centimetre and 2nd by a whole lap. The places tell you the order, not the
> gaps.

```python
import pandas as pd

edu = pd.Categorical(
    ['bachelor', 'high_school', 'phd', 'master', 'bachelor'],
    categories=['high_school', 'bachelor', 'master', 'phd'],
    ordered=True,
)
s = pd.Series(edu)
print(s.min(), s.max())      # legal: order-based min/max
print(s.sort_values().values)
# s.mean()  ← technically illegal, but widely abused for Likert scales
```

```output
high_school phd
['high_school', 'bachelor', 'bachelor', 'master', 'phd']
Categories (4, str): ['high_school' < 'bachelor' < 'master' < 'phd']
```

The first line shows `min` = `high_school` and `max` = `phd`. pandas did not sort these
alphabetically (that would put `bachelor` first); it used the order you declared in
`categories`. The last line prints that order with `<` signs: an **ordered categorical**
— a pandas column that knows its categories have a ranking.

Encoding ordinal variables: use integer codes that preserve the order (ch. 9), not one-hot.

### Interval — ordered with equal gaps, but no true zero

An **interval** variable is a number line where steps are equal, but "zero" is an
arbitrary point someone picked. Equal numeric differences are meaningful; ratios are not.

Examples: temperature in °C (20°C is not "twice as hot" as 10°C), calendar year, IQ score.

Legal operations: all ordinal ops, plus `mean`, `std`, `+`, `-`. NOT division/ratios.

> **Picture it:** a ruler whose 0 mark was drawn in a random place. The distance between 3
> and 5 is still 2 marks, but "5 is 1.67 times 3" only describes where someone drew the 0.

```python
import numpy as np

# Celsius: 0°C is not "no temperature"
temps_c = np.array([0.0, 10.0, 20.0, 30.0])
print("mean:", temps_c.mean())
print("std :", temps_c.std().round(2))

# Converting to Kelvin makes it a ratio scale (true zero)
temps_k = temps_c + 273.15
print("ratio meaningful in K:", temps_k[2] / temps_k[0])   # 293.15/273.15 ≈ 1.073
```

```output
mean: 15.0
std : 11.18
ratio meaningful in K: 1.0732198425773385
```

The mean (15.0) and standard deviation (11.18) are fine for Celsius. But the ratio of
20°C to 0°C would be a division by zero — a sign Celsius has no real zero. In Kelvin,
where 0 means "no heat at all", the same pair gives $293.15 / 273.15 \approx 1.073$: 20°C
holds about 7% more heat energy than 0°C, not "infinitely more".

### Ratio — ordered, equal gaps, and a true absolute zero

A **ratio** variable has a real zero that means "none of it". That is what makes "twice as
much" true. The most powerful scale. All arithmetic is valid.

Examples: height, weight, age, income, distance, duration, count.

Legal operations: everything, including ratios (`income_A / income_B` is meaningful).

```python
import numpy as np

incomes = np.array([30_000, 60_000, 90_000], dtype=np.float64)
print("mean:", incomes.mean())
print("ratio (second vs first):", incomes[1] / incomes[0])  # 2.0 — meaningful
print("log transform meaningful:", np.log(incomes).round(2)) # compress skew
```

```output
mean: 60000.0
ratio (second vs first): 2.0
log transform meaningful: [10.31 11.   11.41]
```

The second line says 60,000 / 30,000 = 2.0, and that really means "earns twice as much".
The log values 10.31, 11.0, 11.41 are evenly spaced *in ratio*: each step multiplies
income, so the log squeezes a long right tail into a shorter one (ch. 11).

Log transforms are valid only for ratio-scale variables. Taking `log(temperature_C)` is
invalid because $\log(0) = -\infty$ at 0°C, and negative Celsius temperatures have no real
logarithm at all (NumPy returns `nan`).

> **Watch out:** "ratio scale" does not mean "every value is positive". Income can be 0,
> and $\log(0) = -\infty$. That is why skewed counts and money get `np.log1p` — which
> computes $\log(1 + x)$ — rather than a plain log.

## Statistical dtype vs measurement scale

A column's **dtype** — the storage type pandas uses for it — tells you how the computer
saves the values, not what they mean. You have to keep track of the meaning yourself.

pandas dtypes (`int64`, `float64`, `object`, `category`) describe storage, not semantics.
A column of integers can be nominal (ZIP code), ordinal (rank), or ratio (count).
A `category` dtype does not mean "nominal" — it means "limited set of values stored
efficiently" (it can be ordered or unordered).

```python
import pandas as pd

df = pd.DataFrame({
    'zip_code':   [1200, 1300, 1100, 1200],   # nominal — stored as int64, don't average
    'rating':     [3, 1, 4, 2],               # ordinal — int64, but only rank-ops valid
    'age':        [25, 32, 28, 41],           # ratio  — int64, all ops valid
    'edu':        pd.Categorical(
                      ['bachelor', 'phd', 'master', 'bachelor'],
                      categories=['high_school', 'bachelor', 'master', 'phd'],
                      ordered=True),
})
print(df.dtypes)
```

```output
zip_code       int64
rating         int64
age            int64
edu         category
dtype: object
```

Three of the four columns print `int64` — ZIP code, rating, and age look identical to
pandas. Only `edu` shows `category`, and that is because you told pandas so.

`zip_code` and `age` have the same dtype but completely different semantics. You must track
measurement scale separately from dtype — it determines every downstream decision.

> **Picture it:** a dtype is the shape of the box; the scale is what is inside it. A shoebox
> can hold shoes, letters, or a cat. The box will not tell you which.

## Identifying scale in practice

When a new dataset lands, a quick first clue is how many **distinct values** (`nunique`)
each column has compared with the row count.

```python
import pandas as pd
import numpy as np

rng = np.random.default_rng(0)
df = pd.DataFrame({
    'user_id':    rng.integers(1000, 9999, 100),   # nominal
    'click_rank': rng.integers(1, 6, 100),          # ordinal (1=top click)
    'revenue':    rng.exponential(50, 100).round(2),# ratio
    'temp_c':     rng.normal(25, 5, 100).round(1), # interval
    'category':   rng.choice(['A', 'B', 'C'], 100), # nominal
})

# What stats are valid for each?
for col in df.columns:
    nuniq = df[col].nunique()
    print(f"{col:<12} nuniq={nuniq:<4} dtype={str(df[col].dtype):<8}")
```

```output
user_id      nuniq=100  dtype=int64
click_rank   nuniq=5    dtype=int64
revenue      nuniq=100  dtype=float64
temp_c       nuniq=78   dtype=float64
category     nuniq=3    dtype=str
```

`click_rank` has only 5 distinct values in 100 rows and `category` only 3: both are small,
fixed sets, which hints at nominal or ordinal. `revenue` has 100 distinct values out of 100
and `temp_c` has 78, so they behave like continuous numbers. Note `user_id`: 100 distinct
values, `int64` — it *looks* continuous, yet it is a nominal label.

Low `nunique` relative to row count is a signal of nominal/ordinal. High cardinality
with continuous values is interval or ratio. But only domain knowledge confirms which.

> **Watch out:** in recent pandas a text column prints its dtype as `str` (older versions
> print `object`). Either way, the dtype says "text", not "nominal" — a text column of
> `'low' / 'medium' / 'high'` is ordinal.

## Recap in plain words

- The four scales are nominal (names), ordinal (rankings), interval (equal steps, fake
  zero), and ratio (equal steps, real zero).
- Each scale allows every operation of the one below it, plus one more.
- Means need at least interval; ratios and logs need ratio scale.
- The dtype only says how the values are stored — integers can still be nominal.
- Nominal columns get one-hot codes; ordinal columns get order-preserving integer codes.

## Try it Yourself

This experiment looks at the most common grey area: 1–5 star ratings, which are ordinal
but get averaged all the time.

```python
import pandas as pd

# A real ambiguity: Likert-scale ratings (1–5 stars)
# Ordinal by definition, but researchers routinely compute means
ratings = pd.Series([4, 5, 3, 4, 1, 5, 4, 2, 5, 4])

# Ordinal-valid stats
print("median (ordinal):", ratings.median())
print("mode   (ordinal):", ratings.mode()[0])

# Mean is technically invalid but widely used — note the caveat
print("mean   (abused) :", ratings.mean())

# At least check: does treating it as interval change your conclusion?
print("high satisfaction (>=4):", (ratings >= 4).mean().round(2))
```

```output
median (ordinal): 4.0
mode   (ordinal): 4
mean   (abused) : 3.7
high satisfaction (>=4): 0.7
```

The median and mode are both 4, while the "abused" mean is 3.7. The last line says 70% of
ratings are 4 or 5. Here the mean and median tell the same story ("mostly happy"), so the
shortcut is harmless. Try replacing two of the 4s with 1s: the median stays at 4, but the
mean drops — that gap is how you spot when treating ranks as numbers starts to mislead.

## Exercise

Given a dataset with columns: `customer_id`, `age`, `city`, `monthly_spend`, `satisfaction`
(1–5), `subscription_tier` (bronze < silver < gold). For each column:

1. Identify the measurement scale.
2. State what summary statistics are valid.
3. Identify what encoding you would use for an ML model.

> **Hint:** for each column ask "does zero mean none?", "can I say bigger/smaller?", and
> "is it only a label?" — in that order. An ID is a label even when it is a number.

<details>
<summary>Solution</summary>

| Column | Scale | Valid stats | Encoding |
|--------|-------|-------------|----------|
| `customer_id` | Nominal | count, mode | drop (it's an ID) |
| `age` | Ratio | all | standardize or as-is |
| `city` | Nominal | count, mode | one-hot or target encoding |
| `monthly_spend` | Ratio | all (log-transform if skewed) | standardize / log |
| `satisfaction` | Ordinal | median, mode (mean debatable) | ordinal integer codes |
| `subscription_tier` | Ordinal | median, mode | ordinal codes (0=bronze,1=silver,2=gold) |

```python
import pandas as pd

df = pd.DataFrame({
    'subscription_tier': pd.Categorical(
        ['silver', 'bronze', 'gold', 'silver'],
        categories=['bronze', 'silver', 'gold'], ordered=True),
})
df['tier_code'] = df['subscription_tier'].cat.codes   # 0, 1, 2
print(df)
```

Ordinal codes preserve the rank information that one-hot would destroy. One-hot treats
bronze and gold as equally different from silver, which is wrong for an ordered variable.
`.cat.codes` numbers the categories in the order you declared, so `silver` becomes 1,
`bronze` 0, and `gold` 2 — not in alphabetical order.
</details>
