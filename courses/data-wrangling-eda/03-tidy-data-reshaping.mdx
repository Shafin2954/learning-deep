## What tidy data is

**Tidy data** is a table laid out so that every fact has exactly one obvious place: one
column per kind of measurement, one row per thing measured. Most data tools assume this
layout, so getting your table into it first makes everything after it easier.

Hadley Wickham's 2014 paper defined three rules for "tidy" data:

1. **Each variable has its own column.**
2. **Each observation has its own row.**
3. **Each type of observational unit forms its own table.**

Here a **variable** is one kind of quantity (sales, month, age), an **observation** is one
measured instance (alpha's sales in January), and an **observational unit** is the kind of
thing being described (customers, orders, products).

Violations of these rules cause almost every reshape bug in data work. When data is tidy,
groupby, pivot, and join all work without manual index gymnastics.

> **Picture it:** a tidy table is a stack of identical index cards. Each card (row) is one
> observation, and every card has the same labelled boxes (columns) in the same place. An
> untidy table is a card where someone wrote three months' sales into one box and the
> month names into the box labels.

## Common untidy patterns and their fixes

Untidy data comes in a handful of recurring shapes. Learn to spot these four, and the fix
is nearly always `melt` (wide to long), `str.split` (one column to many), or `pivot` (long
to wide).

### Pattern 1 — Column headers are values, not variable names

The months are values of a "month" variable, but they appear as column names.

```python
import pandas as pd

wide = pd.DataFrame({
    'product': ['alpha', 'beta', 'gamma'],
    'jan':     [100, 200, 150],
    'feb':     [110, 190, 160],
    'mar':     [120, 210, 140],
})
print("untidy (wide):")
print(wide)

# Fix: melt — move column names into a 'month' variable
long = wide.melt(id_vars='product', var_name='month', value_name='sales')
print("\ntidy (long):")
print(long.sort_values(['product', 'month']).reset_index(drop=True))
```

```output
untidy (wide):
  product  jan  feb  mar
0   alpha  100  110  120
1    beta  200  190  210
2   gamma  150  160  140

tidy (long):
  product month  sales
0   alpha   feb    110
1   alpha   jan    100
2   alpha   mar    120
3    beta   feb    190
4    beta   jan    200
5    beta   mar    210
6   gamma   feb    160
7   gamma   jan    150
8   gamma   mar    140
```

The wide table had 3 rows and 4 columns; the tidy table has 9 rows (3 products times 3
months) and 3 columns. Each row is now one fact: "alpha sold 110 in feb". **`melt`** is
the pandas tool that turns column names into values of a new column (`month` here) and
their cells into another (`sales`).

> **Watch out:** the months come out as `feb, jan, mar` because sorting text is
> alphabetical. If calendar order matters, convert `month` to an ordered categorical
> (ch. 1) before sorting.

### Pattern 2 — Multiple variables in one column

A single `"age_sex"` column encodes two variables: age group and sex.

```python
import pandas as pd

df = pd.DataFrame({
    'region':  ['north', 'north', 'south'],
    'age_sex': ['25_M', '30_F', '25_M'],
    'count':   [120, 95, 200],
})

# Fix: split the compound column
df[['age', 'sex']] = df['age_sex'].str.split('_', expand=True)
df['age'] = df['age'].astype(int)
df = df.drop(columns='age_sex')
print(df)
```

```output
  region  count  age sex
0  north    120   25   M
1  north     95   30   F
2  south    200   25   M
```

`'25_M'` split at the underscore into `age = 25` and `sex = M`. `expand=True` asks for the
pieces as separate columns, and `astype(int)` turns `'25'` from text into a number so you
can compare or average ages.

### Pattern 3 — One variable across multiple columns

Systolic and diastolic blood pressure are a single "blood pressure" measurement stored in
two columns — they should become two rows (keyed by `measurement_type`).

```python
import pandas as pd

df = pd.DataFrame({
    'patient': [1, 2, 3],
    'systolic': [120, 130, 115],
    'diastolic': [80, 85, 75],
})

# Both pressure readings are the SAME variable (blood pressure) with different types
tidy = df.melt(id_vars='patient',
               value_vars=['systolic', 'diastolic'],
               var_name='measurement', value_name='mmhg')
print(tidy.sort_values(['patient', 'measurement']).reset_index(drop=True))
```

```output
   patient measurement  mmhg
0        1   diastolic    80
1        1    systolic   120
2        2   diastolic    85
3        2    systolic   130
4        3   diastolic    75
5        3    systolic   115
```

Three patients times two readings became six rows, and the reading type now lives in the
`measurement` column. That layout lets you group by `measurement` or plot both readings
with one call.

> **Watch out:** "what is one variable?" depends on the question. If you want a
> per-patient ratio like systolic / diastolic, the wide layout (two columns) is the tidy one
> for that job. Tidy is a choice made for an analysis, not a fixed property of the data.

### Pattern 4 — Observations split across rows

When a single "observation" is stored in two or more rows, you need to pivot from long
to wide to combine them.

```python
import pandas as pd

long = pd.DataFrame({
    'id':    [1, 1, 2, 2],
    'key':   ['name', 'age', 'name', 'age'],
    'value': ['alice', '25', 'bob', '32'],
})

wide = long.pivot(index='id', columns='key', values='value').reset_index()
wide.columns.name = None
wide['age'] = wide['age'].astype(int)
print(wide)
```

```output
   id  age   name
0   1   25  alice
1   2   32    bob
```

Each `id` had two rows — one for `name`, one for `age`. **`pivot`** turned the `key`
values into column names, so person 1 is now one row: `age 25, name alice`. The
`astype(int)` was needed because the `value` column mixed names and numbers, so every
value arrived as text.

> **Picture it:** this "key/value" layout is a form torn into strips, one answer per strip.
> `pivot` tapes the strips back into one form per person.

## Reshaping with `stack` and `unstack`

`stack` folds columns down into the row labels, making the table taller; `unstack` does the
reverse. They work on the row and column *labels* (the index) rather than on ordinary
columns.

When you already have a MultiIndex, `stack`/`unstack` are faster than pivot/melt:

```python
import pandas as pd

df = pd.DataFrame({
    'jan': [10, 20], 'feb': [11, 21], 'mar': [12, 22]
}, index=['A', 'B'])
df.index.name = 'product'

# stack: columns → inner row level
long = df.stack()
long.index.names = ['product', 'month']
print(long)
```

```output
product  month
A        jan      10
         feb      11
         mar      12
B        jan      20
         feb      21
         mar      22
dtype: int64
```

The result is a Series with a two-level row label (a **MultiIndex**): `product` on the
outside, `month` inside. Product `A` appears once with its three months listed beneath it.
`long.unstack()` would rebuild the original 2-by-3 table.

## Recap in plain words

- Tidy means one column per variable, one row per observation, one table per kind of thing.
- Month names (or any values) used as column headers get `melt`-ed into a column.
- Two facts packed into one string get split with `str.split(..., expand=True)`.
- One observation spread over several rows gets `pivot`-ed back into one row.
- `stack` and `unstack` do the same reshaping on index levels.
- What counts as "one variable" depends on the analysis you are about to run.

## Try it Yourself

This table has the classic double problem: values in headers (`q1`, `q2`) *and* two
variables packed into each header (subject and quarter).

```python
import pandas as pd

# A real-world-style untidy table: one row per student, multiple test scores
untidy = pd.DataFrame({
    'student': ['alice', 'bob', 'carol'],
    'math_q1': [85, 70, 90],
    'math_q2': [88, 72, 87],
    'english_q1': [78, 85, 80],
    'english_q2': [80, 83, 82],
})

# Tidy it: separate subject and quarter
tidy = untidy.melt(id_vars='student', var_name='subject_quarter', value_name='score')
tidy[['subject', 'quarter']] = tidy['subject_quarter'].str.rsplit('_', n=1, expand=True)
tidy = tidy.drop(columns='subject_quarter').sort_values(['student','subject','quarter']).reset_index(drop=True)
print(tidy.head(8))

# Verify: per-student mean score per subject
print(tidy.groupby(['student', 'subject'])['score'].mean())
```

```output
  student  score  subject quarter
0   alice     78  english      q1
1   alice     80  english      q2
2   alice     85     math      q1
3   alice     88     math      q2
4     bob     85  english      q1
5     bob     83  english      q2
6     bob     70     math      q1
7     bob     72     math      q2
student  subject
alice    english    79.0
         math       86.5
bob      english    84.0
         math       71.0
carol    english    81.0
         math       88.5
Name: score, dtype: float64
```

`melt` turned the 4 score columns into 12 rows, and `rsplit('_', n=1)` split
`math_q1` into `math` and `q1` — splitting from the right, once, so a subject with an
underscore in its name would survive. The group means check the reshape: alice's math
average is $(85 + 88)/2 = 86.5$, matching her original two scores. Try adding a
`science_q1` column and confirm the rest of the code still works without changes.

## Exercise

You have a DataFrame where each row records one transaction with columns
`user_id`, `item_bought`, `item_price`. The same user may appear multiple times.
Reshape it into a wide "user-item matrix" where rows are users, columns are items,
and values are the prices (or 0 if the user never bought that item).

> **Hint:** `pivot` refuses duplicate (row, column) pairs, but a user can buy the same
> item twice. `pivot_table` with an `aggfunc` and `fill_value` handles both problems.

<details>
<summary>Solution</summary>

```python
import pandas as pd

df = pd.DataFrame({
    'user_id':   [1, 1, 2, 3, 2, 1],
    'item':      ['A', 'B', 'A', 'C', 'B', 'C'],
    'price':     [10, 20, 10, 30, 20, 30],
})

# pivot_table handles duplicate (user, item) pairs (e.g. if a user buys the same item twice)
matrix = df.pivot_table(
    index='user_id', columns='item', values='price',
    aggfunc='sum', fill_value=0,
)
matrix.columns.name = None
print(matrix)
```

This is the "user-item matrix" used in collaborative filtering (see the Recommender
Systems course). Tidy format is the input; the wide pivot is the model's input format.
The solution names the columns `item` and `price` for brevity. `fill_value=0` writes 0
where a user never bought an item — user 3 bought only `C`, so their `A` and `B` cells are
0 — and `aggfunc='sum'` adds up repeat purchases instead of raising an error.
</details>
