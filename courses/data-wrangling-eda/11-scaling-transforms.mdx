## When scaling matters — and when it doesn't

**Scaling** changes the units of a column so that all columns sit on a similar range, like
converting prices in cents and prices in millions to the same kind of number. Some models
compare columns by size and get fooled by big units; others only ask "bigger or smaller?"
and don't care.

Scaling makes features commensurable (on the same numerical scale). Models that use
distance or gradient descent are scale-sensitive; tree models are not.

| Model type | Needs scaling? |
|------------|----------------|
| Linear/logistic regression | Yes — coefficients have different units |
| SVM, k-NN | Yes — distance is distorted by different scales |
| PCA | Yes — variance is dominated by large-scale features |
| Neural networks | Yes — gradient updates depend on scale |
| Decision trees, Random Forest, XGBoost | No — splits are rank-based |

> **Picture it:** measuring how "close" two houses are using price in dollars and number
> of bedrooms. A $1,000 price difference swamps a 3-bedroom difference, purely because
> dollars are small units. Scaling puts both on a "how unusual is this?" footing, so a
> distance-based model listens to both.

## StandardScaler — zero mean, unit variance

**Standardising** shifts a column so its average is 0, then stretches it so its standard
deviation is 1. The result is a z-score (ch. 5): "how many standard deviations from the
average".

$$
z = \frac{x - \mu}{\sigma}
$$

> **In plain words:** subtract the column's mean $\mu$, then divide by its standard
> deviation $\sigma$. A value of $z = 2$ means "two standard deviations above average",
> whatever the original units were.

Assumes the feature is roughly Gaussian. Sensitive to outliers because $\mu$ and $\sigma$ are
sensitive to outliers.

```python
import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(0)
n = 500
X = rng.normal(50, 10, (n, 3)).astype(np.float64)
X[:, 1] *= 100      # feature 1 has scale ~1000
X[:, 2] += 5000     # feature 2 has large offset

X_train, X_test = train_test_split(X, test_size=0.2, random_state=0)

scaler = StandardScaler()
scaler.fit(X_train)
X_train_sc = scaler.transform(X_train)
X_test_sc  = scaler.transform(X_test)

print("Train stats after scaling:")
print(f"  mean:  {X_train_sc.mean(axis=0).round(3)}")
print(f"  std:   {X_train_sc.std(axis=0).round(3)}")
print(f"\nScaler mean (from train): {scaler.mean_.round(1)}")
print(f"Scaler std  (from train): {scaler.scale_.round(1)}")
```

```output
Train stats after scaling:
  mean:  [-0. -0. -0.]
  std:   [1. 1. 1.]

Scaler mean (from train): [  48.7 5090.6 5049.9]
Scaler std  (from train): [  9.7 922.   10.5]
```

After scaling, every column has mean 0 and standard deviation 1 on the training data (the
`-0.` is a tiny negative rounding error). The scaler stored what it learned: column 1's
mean of 5090.6 and standard deviation of 922.0, column 2's offset of about 5050. Those
very different units are now gone.

## MinMaxScaler — maps to [0, 1]

**Min-max scaling** squeezes a column so its smallest value becomes 0 and its largest
becomes 1, keeping everything else in proportion between them.

$$
z = \frac{x - x_{\min}}{x_{\max} - x_{\min}}
$$

> **In plain words:** how far is $x$ from the minimum, as a fraction of the whole range
> from minimum to maximum? The minimum maps to 0, the maximum to 1.

Extreme outliers compress the rest of the values to a narrow band. Use only when you know the
feature has hard bounds and no outliers.

```python
import numpy as np
from sklearn.preprocessing import MinMaxScaler
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(1)
n = 500
data = rng.normal(0, 1, n).astype(np.float64)
data[0] = 100   # one extreme outlier

X_train, X_test = train_test_split(data.reshape(-1, 1), test_size=0.2, random_state=0)

mms = MinMaxScaler()
mms.fit(X_train)
X_sc = mms.transform(X_train)

print(f"Without outlier — max normal value maps to: {mms.transform([[3.5]])[0,0]:.3f}")
print(f"Entire normal range compressed to: [{X_sc[X_sc < mms.transform([[100]])[0,0]].max():.3f}]")
print(f"95% of data in range: [{X_sc.min():.3f}, {np.percentile(X_sc, 95):.3f}]")
print(f"Outlier maps to: {mms.transform([[100.0]])[0,0]:.3f}")
```

```output
Without outlier — max normal value maps to: 0.060
Entire normal range compressed to: [0.057]
95% of data in range: [0.000, 0.041]
Outlier maps to: 1.000
```

The printed labels are terse, so read them this way: a fairly extreme normal value (3.5)
maps to only 0.060; the largest non-outlier training value maps to 0.057; 95% of the data
lands between 0.000 and 0.041; and the outlier at 100 takes the value 1.000.

The single outlier at 100 claims the entire [0, 1] range; the actual data cluster in [0, 0.06].
This is why MinMaxScaler is dangerous with outliers.

> **Picture it:** zooming a photo out until the one person standing far away fits into
> the frame — everyone else shrinks to a dot in the corner.

## RobustScaler — IQR-based, outlier-resistant

**Robust scaling** uses the median as the centre and the width of the middle half of the
data (the **IQR**, ch. 5) as the ruler. Outliers sit outside the middle half, so they
can't move either.

$$
z = \frac{x - Q_2}{Q_3 - Q_1}
$$

> **In plain words:** $Q_2$ is the median, and $Q_3 - Q_1$ is the interquartile range.
> Subtract the median, divide by the IQR.

Uses the median and IQR instead of mean and std, so outliers don't distort the centering or
scaling.

```python
import numpy as np
from sklearn.preprocessing import StandardScaler, RobustScaler
import matplotlib.pyplot as plt

rng = np.random.default_rng(2)
n = 500
data = rng.normal(0, 1, n).astype(np.float64)
data[[0, 1, 2]] = [50, -40, 80]   # 3 heavy outliers

X = data.reshape(-1, 1)
X_std    = StandardScaler().fit_transform(X).ravel()
X_robust = RobustScaler().fit_transform(X).ravel()

fig, axes = plt.subplots(1, 2, figsize=(10, 3))
for ax, vals, title in zip(axes,
                            [X_std, X_robust],
                            ['StandardScaler', 'RobustScaler']):
    ax.hist(vals[np.abs(vals) < 5], bins=40, edgecolor='white', color='steelblue')
    ax.set_title(title)
    ax.set_xlabel('scaled value')
plt.tight_layout(); plt.show()

# Bulk data statistics
bulk = np.abs(data) < 10    # the 497 non-outlier points (raw std ≈ 1)
print(f"StandardScaler bulk std:  {X_std[bulk].std():.3f}")
print(f"RobustScaler   bulk std:  {X_robust[bulk].std():.3f}")
```

```output
StandardScaler bulk std:  0.216
RobustScaler   bulk std:  0.703
```

StandardScaler compresses the bulk of the data into a narrow range (std 0.216, where the
raw bulk has std about 1) because the 3 extreme values inflated the computed std from about
1 to about 4.7. RobustScaler keeps the correct spread: its 0.703 is close to what you get
on clean normal data. Why not exactly 1? For a normal distribution the IQR is about 1.35
standard deviations, so dividing by the IQR gives a standard deviation of about
$1 / 1.35 \approx 0.74$ — the outliers had nothing to do with it.

> **Watch out:** RobustScaler does not *remove* outliers. The point at 80 is still about
> 59 units out after scaling. It only stops them from distorting how everything *else* is
> scaled.

## PowerTransformer — make distributions more Gaussian

Scalers only shift and stretch; they never change a distribution's *shape*. A **power
transform** (ch. 8) bends the shape itself — pulling in a long tail so the column looks
more like a bell curve.

```python
import numpy as np
import pandas as pd
from sklearn.preprocessing import PowerTransformer
import matplotlib.pyplot as plt

rng = np.random.default_rng(3)
n = 800
income  = rng.exponential(40_000, n).astype(np.float64)  # right-skewed
expenses = (income * 0.4 - 5000 + rng.normal(0, 3000, n)).astype(np.float64)

X = np.column_stack([income, expenses])
pt = PowerTransformer(method='yeo-johnson')
X_pt = pt.fit_transform(X)

fig, axes = plt.subplots(2, 2, figsize=(10, 5))
for i, (name, before, after) in enumerate([
    ('income',   income,   X_pt[:, 0]),
    ('expenses', expenses, X_pt[:, 1]),
]):
    axes[i, 0].hist(before, bins=40, edgecolor='white', color='steelblue')
    axes[i, 0].set_title(f'{name} — original (skew={pd.Series(before).skew():.2f})')
    axes[i, 1].hist(after, bins=40, edgecolor='white', color='tomato')
    axes[i, 1].set_title(f'{name} — transformed (skew={pd.Series(after).skew():.2f})')

plt.tight_layout(); plt.show()
print(f"income  λ: {pt.lambdas_[0]:.3f}")
print(f"expenses λ: {pt.lambdas_[1]:.3f}")
```

```output
income  λ: 0.282
expenses λ: 0.921
```

Yeo-Johnson picked a separate $\lambda$ for each column. Income got 0.282 — a strong
bend, close to a log — because it is heavily right-skewed (skew 1.63 in the plot titles;
-0.05 after). Expenses is almost as skewed (1.54) but got 0.921, barely a bend. The reason
is its negative values (the `- 5000` shift): Yeo-Johnson bends negative values with the
power $2 - \lambda$, so a strong bend for the positive side would warp the negative side.
The fit compromises, and expenses still has skew 0.46 afterwards.

> **Watch out:** Yeo-Johnson is not unit-free. The same expenses column measured in
> thousands gets $\lambda = 0.666$ instead of 0.921. Scale columns to a sensible unit
> before fitting it (`PowerTransformer` standardises only the *output*).

## QuantileTransformer

The most aggressive option ignores the values' spacing altogether and keeps only their
order: the smallest value maps to the lowest slot of a target bell curve, the median to
its middle, and so on. The **empirical CDF** used here is "what fraction of the data is
below this value".

Maps any distribution to a uniform or normal output by applying the empirical CDF. The most
robust transform — immune to any shape, including bimodal and heavy-tailed distributions.
The trade-off: it can distort relationships between features.

```python
import numpy as np
from sklearn.preprocessing import QuantileTransformer

rng = np.random.default_rng(4)
n = 1000
# Bimodal: mixture of two Gaussians
x = np.concatenate([rng.normal(-3, 1, n//2), rng.normal(3, 1, n//2)]).astype(np.float64)

qt = QuantileTransformer(output_distribution='normal', random_state=0)
x_qt = qt.fit_transform(x.reshape(-1, 1)).ravel()

import pandas as pd
print(f"Original — mean: {x.mean():.2f}, std: {x.std():.2f}, skew: {pd.Series(x).skew():.2f}")
print(f"Quantile — mean: {x_qt.mean():.2f}, std: {x_qt.std():.2f}, skew: {pd.Series(x_qt).skew():.2f}")
```

```output
Original — mean: -0.01, std: 3.15, skew: 0.00
Quantile — mean: 0.00, std: 1.02, skew: 0.00
```

Mean and skew look the same before and after (both about 0), but the shapes are completely
different. The original had two humps at -3 and +3 (a **bimodal** distribution) with
standard deviation 3.15. The output is a single bell with standard deviation 1.02. The two
humps were merged — the gap between them, which may carry real meaning, is gone.

> **Watch out:** summary numbers like mean, std and skew can match while the shapes differ
> completely. Always look at a histogram after a transform.

## The golden rule: fit on train, transform both

A scaler *learns* numbers (a mean, a standard deviation) when you `fit` it. Those numbers
must come from training data only; the test set is then converted with the training
numbers, as if it were brand-new data arriving later.

```python
import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(5)
X = rng.normal(100, 20, (500, 3)).astype(np.float64)
X_train, X_test = train_test_split(X, test_size=0.2, random_state=0)

scaler = StandardScaler()
scaler.fit(X_train)           # only train — NO test data here

X_train_sc = scaler.transform(X_train)
X_test_sc  = scaler.transform(X_test)   # same scaler parameters

print("Test mean (should be ~0, not exact 0 — that's expected):")
print(X_test_sc.mean(axis=0).round(3))
print("Test std (should be ~1, slight deviation because test != train):")
print(X_test_sc.std(axis=0).round(3))
```

```output
Test mean (should be ~0, not exact 0 — that's expected):
[ 0.219  0.14  -0.233]
Test std (should be ~1, slight deviation because test != train):
[1.035 1.035 0.982]
```

The test means are 0.219, 0.14 and -0.233 — not 0 — and the test standard deviations are
around 1.0 but not exactly. That is the honest picture: 100 test rows never match 400
training rows perfectly.

The test set deviates slightly from 0/1 — that's correct. If you fit on the full dataset,
the combined data would have mean exactly 0 and std exactly 1, and the test set's own
numbers would have shaped the scaler — that is leakage.

## Recap in plain words

- Distance- and gradient-based models need scaling; tree models don't.
- StandardScaler gives mean 0 and std 1, but outliers inflate the std and squash the rest.
- MinMaxScaler maps to [0, 1] and is wrecked by a single outlier.
- RobustScaler uses the median and IQR, so outliers can't distort it.
- PowerTransformer and QuantileTransformer change the *shape*, not only the scale.
- Fit every scaler on training data only, then transform both sets.

## Try it Yourself

Here a right-skewed column with 10 huge outliers goes through RobustScaler and
PowerTransformer, and you compare the skew afterwards.

```python
import numpy as np
from sklearn.preprocessing import RobustScaler, PowerTransformer
from sklearn.model_selection import train_test_split
import pandas as pd

rng = np.random.default_rng(6)
n = 600
X = np.column_stack([
    rng.exponential(1000, n),    # right-skewed with potential outliers
    rng.normal(50, 5, n),
]).astype(np.float64)
X[rng.choice(n, 10, replace=False), 0] = rng.uniform(50_000, 100_000, 10)  # outliers

X_train, X_test = train_test_split(X, test_size=0.2, random_state=0)

# Compare RobustScaler vs PowerTransformer
rob = RobustScaler()
pt  = PowerTransformer(method='yeo-johnson')

X_train_rob = rob.fit_transform(X_train)
X_train_pt  = pt.fit_transform(X_train)

for name, Xsc in [('RobustScaler', X_train_rob), ('PowerTransformer', X_train_pt)]:
    skew0 = pd.Series(Xsc[:, 0]).skew()
    print(f"{name}: feature0 skew={skew0:.3f}")
```

```output
RobustScaler: feature0 skew=7.884
PowerTransformer: feature0 skew=0.025
```

RobustScaler leaves the skew at 7.884: shifting and dividing can't change a shape. The
Yeo-Johnson transform brings it to 0.025, nearly symmetric. So scaling and transforming do
different jobs. Try running RobustScaler *after* the PowerTransformer — a common recipe
when a column is both skewed and outlier-heavy.

## Exercise

Given features `age` (Normal), `salary` (log-normal), and `score` (0-100, bounded), apply:
(a) StandardScaler to `age`, (b) PowerTransformer to `salary`, (c) MinMaxScaler to `score`.
Use a Pipeline with ColumnTransformer. Verify no leakage by fitting on train only.

> **Hint:** a `ColumnTransformer` takes a list of `(name, transformer, columns)` triples.
> After `pipe.fit`, reach the fitted scaler via
> `pipe.named_steps['prep'].named_transformers_['std']`.

<details>
<summary>Solution</summary>

```python
import numpy as np
import pandas as pd
from sklearn.preprocessing import StandardScaler, PowerTransformer, MinMaxScaler
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.model_selection import train_test_split
from sklearn.linear_model import Ridge

rng = np.random.default_rng(0)
n = 400
df = pd.DataFrame({
    'age':    rng.normal(40, 10, n).astype(np.float64),
    'salary': np.exp(rng.normal(11, 0.5, n)).astype(np.float64),
    'score':  np.clip(rng.normal(60, 15, n), 0, 100).astype(np.float64),
})
target = df['age'] * 0.5 + np.log(df['salary']) * 0.3 + rng.normal(0, 5, n)

X_train, X_test, y_train, y_test = train_test_split(df, target, test_size=0.2, random_state=0)

preproc = ColumnTransformer([
    ('std', StandardScaler(),    ['age']),
    ('pt',  PowerTransformer(),  ['salary']),
    ('mms', MinMaxScaler(),      ['score']),
])

pipe = Pipeline([('prep', preproc), ('model', Ridge())])
pipe.fit(X_train, y_train)

print(f"Train R²: {pipe.score(X_train, y_train):.3f}")
print(f"Test  R²: {pipe.score(X_test,  y_test):.3f}")

# Verify: StandardScaler was fit on train only
ss = pipe.named_steps['prep'].named_transformers_['std']
print(f"\nScaler mean (from train): {ss.mean_[0]:.2f}")
print(f"True train mean age:       {X_train['age'].mean():.2f}")
```

The scaler mean matches the training mean exactly — proof that fitting happened only on
training data. The ColumnTransformer applies the correct transform per column without any
test-data contamination. When run, both means print 39.82, and train and test R² are close
(0.502 and 0.506) — the R² is modest only because the target has large noise
(standard deviation 5) on purpose.
