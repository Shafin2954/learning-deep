## Leakage is silent model poisoning

**Data leakage** is when your model gets to peek at the answer during training or
evaluation — through a column it should not have, or through test rows that slipped into
training. It scores brilliantly in your notebook and then fails on real new data, where no
peeking is possible.

Data leakage occurs when information from outside the legitimate training signal bleeds into
your model's features or evaluation. The result: CV scores look fantastic, holdout scores
disappoint, and production performance is even worse. Leakage is not always obvious —
here are the four main types.

(**CV** — cross-validation — scores a model by training and testing it on several
different splits of the data; a **holdout** set is data kept aside and used only once, at
the end.)

> **Picture it:** a student who saw the exam paper the night before. Their mock-exam score
> is perfect, and it tells you nothing about how they will do on a paper they haven't
> seen.

## Type 1 — Target leakage

**Target leakage** is a feature that secretly contains the answer, because it was
recorded *after* the outcome happened.

A feature that is computed *from* or *conditional on* the target value.

Classic example: predicting loan default. If one feature is `amount_recovered_from_default`
— a value that only exists when someone has already defaulted — it is a direct copy of the
target for the positive class.

```python
import pandas as pd
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

rng = np.random.default_rng(0)
n = 1000
df = pd.DataFrame({
    'credit_score':  rng.normal(650, 80, n).astype(np.float64),
    'income':        rng.exponential(50_000, n).astype(np.float64),
    'defaulted':     (rng.random(n) < 0.15).astype(np.int8),
})
# Leaking feature: only non-zero if defaulted
df['recovery_amount'] = df['defaulted'] * rng.exponential(5000, n)

X_leak = df[['credit_score', 'income', 'recovery_amount']].values
X_clean = df[['credit_score', 'income']].values
y = df['defaulted'].values

clf = LogisticRegression(max_iter=1000)
score_leak  = cross_val_score(clf, X_leak,  y, cv=5, scoring='roc_auc').mean()
score_clean = cross_val_score(clf, X_clean, y, cv=5, scoring='roc_auc').mean()

print(f"AUC with leaking feature:  {score_leak:.4f}  ← too good to be true")
print(f"AUC without it:            {score_clean:.4f}  ← honest")
```

```output
AUC with leaking feature:  1.0000  ← too good to be true
AUC without it:            0.5457  ← honest
```

With the leaking column, AUC is a perfect 1.0000; without it, 0.5457 — barely above the
0.5 of random guessing, since defaults were assigned at random in this simulation. (**AUC**
is the chance that the model ranks a random positive above a random negative: 0.5 is a coin
flip, 1.0 is perfect.)

`recovery_amount` is literally a function of `defaulted`. An AUC of exactly 1.0000 means
the model memorised the label through the leaking feature: any row with
`recovery_amount > 0` is a default.

**How to kill it:** Ask, for each feature: "Would I know this value at the moment of
prediction?" If the answer is no, drop it.

## Type 2 — Temporal leakage

**Temporal leakage** happens when the model trains on rows from the future and is tested on
rows from the past — the opposite of how it will be used.

Using future information to predict the past. Arises whenever a time-ordered dataset is
shuffled before splitting.

> **Picture it:** forecasting yesterday's weather after reading today's newspaper. Of
> course you get it right.

```python
import pandas as pd
import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(1)
n = 1000
t = np.arange(n, dtype=np.float64)
# Trend + signal: tomorrow's feature is today's future
y = 0.5 * t + rng.normal(0, 5, n)

# Build a 3-day lag feature — CORRECT (uses past values)
df = pd.DataFrame({'t': t, 'y': y})
df['lag3'] = df['y'].shift(3)
df = df.dropna()

# WRONG: random split ignores time order — test rows appear in train windows
Xr = df[['t', 'lag3']].values
yr = df['y'].values
X_tr, X_te, y_tr, y_te = train_test_split(Xr, yr, test_size=0.2, random_state=0)
model_random = LinearRegression().fit(X_tr, y_tr)

# CORRECT: temporal split — all test rows are in the future
split = int(len(df) * 0.8)
X_tr2, X_te2 = df[['t', 'lag3']].values[:split], df[['t', 'lag3']].values[split:]
y_tr2, y_te2 = df['y'].values[:split],            df['y'].values[split:]
model_time = LinearRegression().fit(X_tr2, y_tr2)

print(f"Random split R²: {model_random.score(X_te, y_te):.4f}  ← optimistic (future in train)")
print(f"Temporal split R²: {model_time.score(X_te2, y_te2):.4f}  ← honest")
```

```output
Random split R²: 0.9986  ← optimistic (future in train)
Temporal split R²: 0.9707  ← honest
```

The random split scores R² = 0.9986; the temporal split 0.9707. (**R²** is the share of
the target's variation the model explains: 1 is perfect.) With a random split, every test
day has training days on both sides of it, so the model only has to *interpolate*. With the
temporal split it must *extrapolate* into 200 days it has never seen — the real job of a
forecast. Both scores are high here because the trend is very regular; on real data the
gap is usually much wider.

> **Watch out:** lag features built with `shift()` are safe only if every row's lag points
> backwards in time. Sort by time first, and compute lags per entity (with `groupby`) when
> several users or stores share one table.

## Type 3 — Preprocessing leakage

**Preprocessing leakage** is when a cleaning or selection step learns from all the rows —
including the ones you will later test on — before the split.

Fitting a scaler, imputer, or encoder on the *full* dataset before splitting, so the test
set's statistics contaminate the training-set transform.

The demo uses **feature selection** — keeping the columns that look most related to the
target — because it shows the effect most clearly.

```python
import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.pipeline import Pipeline

rng = np.random.default_rng(2)
n = 400
X = rng.normal(0, 1, (n, 1000)).astype(np.float64)   # 1000 pure-noise features
y = (rng.random(n) < 0.5).astype(np.int8)   # pure noise — true AUC should be 0.5

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)

# WRONG: scale and keep the 20 "best" features using ALL rows, then cross-validate
X_scaled_all = StandardScaler().fit_transform(X)   # uses entire X including test folds!
X_sel_all = SelectKBest(f_classif, k=20).fit_transform(X_scaled_all, y)  # uses test labels!
score_leaky = cross_val_score(LogisticRegression(max_iter=500), X_sel_all, y,
                               cv=cv, scoring='roc_auc').mean()

# CORRECT: Pipeline — scaler and selector are fit only on each training fold
pipe = Pipeline([('sc', StandardScaler()),
                 ('sel', SelectKBest(f_classif, k=20)),
                 ('clf', LogisticRegression(max_iter=500))])
score_clean = cross_val_score(pipe, X, y, cv=cv, scoring='roc_auc').mean()

print(f"AUC with preprocessing leakage: {score_leaky:.4f}  ← inflated on pure noise!")
print(f"AUC with Pipeline (correct):    {score_clean:.4f}  ← near 0.5 as expected")
```

```output
AUC with preprocessing leakage: 0.7628  ← inflated on pure noise!
AUC with Pipeline (correct):    0.5383  ← near 0.5 as expected
```

Every feature is pure noise and the labels are coin flips, so the honest AUC is 0.5. The
leaky version reports 0.7628. The Pipeline reports 0.5383 — near 0.5, as it should be.

The 0.22 AUC gap comes from the selection step. Picking the 20 columns that best match `y`
*on all 400 rows* found columns that match the test folds' labels by chance, and the model
then "predicted" that chance. The scaler alone contributes almost nothing here: standardising
with the full-data mean and std shifts every row the same way. In real data with imputers
and target encoders (ch. 4, ch. 9) the inflation can be much larger. **Always use sklearn
Pipelines** so every transformer is fit only on the training fold.

> **Watch out:** "I'll pick features first, then cross-validate" is the most common
> version of this leak. Feature selection is part of the model and belongs inside the
> Pipeline.

## Type 4 — Group leakage

**Group leakage** happens when rows from the same person (or store, or patient) land in
both the training and the test set. The model recognises the person instead of learning
anything that would work for a stranger.

The same entity (patient, user, store) appears in both train and test. The model
memorises per-entity patterns instead of learning generalisable features.

```python
import pandas as pd
import numpy as np
from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import cross_val_score, GroupKFold, KFold

rng = np.random.default_rng(3)
n_users = 50
obs_per_user = 20
n = n_users * obs_per_user

user_ids   = np.repeat(np.arange(n_users), obs_per_user)
user_effect = rng.normal(0, 5, n_users)[user_ids]   # per-user baseline
X = rng.normal(0, 1, (n, 5)).astype(np.float64)
X[:, :2] = rng.normal(0, 1, (n_users, 2))[user_ids]  # 2 user-level columns (e.g. age, signup year)
y = user_effect + rng.normal(0, 1, n)               # target = user effect + noise
model = RandomForestRegressor(n_estimators=100, random_state=0)

# WRONG: regular KFold — same user in train and test
score_kf = cross_val_score(model, X, y,
                            cv=KFold(5, shuffle=True, random_state=0),
                            scoring='r2').mean()

# CORRECT: GroupKFold — each user in exactly one fold
score_gkf = cross_val_score(model, X, y,
                             cv=GroupKFold(n_splits=5), groups=user_ids,
                             scoring='r2').mean()

print(f"KFold R²      (group leakage): {score_kf:.4f}  ← inflated by memorised user effects")
print(f"GroupKFold R² (correct):       {score_gkf:.4f}  ← honest — features have no real signal")
```

```output
KFold R²      (group leakage): 0.9533  ← inflated by memorised user effects
GroupKFold R² (correct):       -1.5139  ← honest — features have no real signal
```

The features have zero signal — the only structure is per-user. Two columns are constant
for each user (like an age or a signup year), which lets the random forest *recognise* a
user. KFold sees the same user in both train and test, so it memorises the user effect and
reports R² = 0.9533. GroupKFold puts each user in exactly one fold, so every test user is a
stranger: R² = -1.5139, worse than predicting the average. (A negative R² means the model's
errors are larger than those of always guessing the mean.)

> **Picture it:** a teacher who learns each student's handwriting. They grade old students
> perfectly by recognising the writing — and are lost when a new class arrives.

## How to systematically find leakage

Leaks rarely announce themselves. These five checks catch most of them.

1. **Review feature provenance:** for each feature, trace how it was computed and when the
   value would be available in production.
2. **Suspicious performance:** AUC > 0.99 on a hard problem usually means leakage.
3. **Feature importance check:** if a feature that *should not* carry signal has very high
   importance, investigate it.
4. **Train/test score gap:** if CV score >> holdout score, leakage in preprocessing is likely.
5. **Adversarial validation (ch. 13):** if a model can classify train vs test better than
   chance, the distributions differ — which often points to a leaking feature.

(**Provenance** is where a value came from and when it was recorded.)

## Recap in plain words

- Leakage means the model saw information it won't have when it is used for real.
- Target leakage: a feature recorded after the outcome — ask "would I know this at
  prediction time?".
- Temporal leakage: split time-ordered data by time, never at random.
- Preprocessing leakage: fit every scaler, imputer, encoder and selector inside a Pipeline.
- Group leakage: keep all rows of one person in the same fold with `GroupKFold`.
- A score that looks too good usually is.

## Try it Yourself

This repeats the preprocessing comparison with 50 noise features and *only* a scaler — no
feature selection.

```python
import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.pipeline import Pipeline

rng = np.random.default_rng(0)
n = 600
# 50 features, all noise — true AUC = 0.5
X = rng.normal(0, 1, (n, 50)).astype(np.float64)
y = (rng.random(n) < 0.5).astype(np.int8)

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)

# Leaky: fit scaler on full X
X_sc_leaky = StandardScaler().fit_transform(X)
auc_leaky = cross_val_score(LogisticRegression(max_iter=300),
                             X_sc_leaky, y, cv=cv, scoring='roc_auc').mean()

# Clean: Pipeline
pipe = Pipeline([('sc', StandardScaler()),
                 ('clf', LogisticRegression(max_iter=300))])
auc_clean = cross_val_score(pipe, X, y, cv=cv, scoring='roc_auc').mean()

print(f"Leaky AUC (50 noise features): {auc_leaky:.4f}")
print(f"Clean AUC (pipeline):          {auc_clean:.4f}")
```

```output
Leaky AUC (50 noise features): 0.4711
Clean AUC (pipeline):          0.4711
```

Both AUCs are 0.4711, identical to four decimals. This is the honest finding: on its own, a
full-data StandardScaler barely leaks, because it moves every row by the same amount. (The
0.47 instead of 0.5 is chance: 600 rows of noise.) Now try the version that does leak: add
`from sklearn.feature_selection import SelectKBest` and put
`SelectKBest(k=5)` in front of the scaler — once on the full `X` before cross-validation,
and once inside the Pipeline. The leaky number rises to about 0.56 while the Pipeline
stays at about 0.49. With only 50 candidate columns the leak is smaller than in the
1000-column demo above — the more columns you choose from, the more chance matches there
are to find.

## Exercise

Write a function `detect_target_leak(df, feature_cols, target_col, threshold=0.95)` that:
(a) trains a logistic regression using each feature alone,
(b) computes AUC via 5-fold CV,
(c) returns the names of features with AUC > threshold (likely target leaks).
Test it on a DataFrame where one feature is directly computed from the target.

> **Hint:** loop over the columns, pass `df[[col]]` (double brackets keep it 2-D) to
> `cross_val_score(..., scoring='roc_auc')`, and wrap the model in a Pipeline with a
> scaler so even this check is leak-free.

```python
import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

def detect_target_leak(df, feature_cols, target_col, threshold=0.95):
    y = df[target_col].values
    suspicious = []
    for col in feature_cols:
        pipe = Pipeline([('sc', StandardScaler()),
                         ('clf', LogisticRegression(max_iter=500))])
        auc = cross_val_score(pipe, df[[col]].values, y,
                              cv=5, scoring='roc_auc').mean()
        if auc > threshold:
            suspicious.append((col, auc))
    return suspicious

rng = np.random.default_rng(0)
n = 500
df = pd.DataFrame({
    'feature_a': rng.normal(0, 1, n),
    'feature_b': rng.normal(0, 1, n),
    'defaulted':  (rng.random(n) < 0.2).astype(np.int8),
})
# Plant a leaking feature
df['leak_col'] = df['defaulted'] * rng.exponential(1000, n)

leaks = detect_target_leak(df, ['feature_a', 'feature_b', 'leak_col'], 'defaulted')
print("Detected leaks:", leaks)
```

`leak_col` should be flagged with AUC > 0.99; `feature_a` and `feature_b` should report
near-0.5. This pattern — checking each feature's solo AUC — is a quick first-pass screen
for target leakage in any dataset. When run, the function returns only `leak_col`, with
AUC 1.0. A solo-AUC screen only catches leaks that work on their own; a leak hidden in a
combination of columns needs the provenance review above.
