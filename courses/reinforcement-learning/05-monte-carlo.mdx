## Learning Without a Model

When you don't have the rulebook, you play. Monte Carlo learning means: play many complete
games, write down what you scored from each situation, and average.

Dynamic programming required the transition dynamics $p(s',r|s,a)$. Monte Carlo methods need
nothing of the sort — they learn purely from experience: complete episodes of interaction.
You run the agent, observe the sequence of states, actions, and rewards, and then use the
actual returns to update value estimates. The name **Monte Carlo** (after the casino) is used
for any method that estimates an answer by averaging random samples.

The trade-off: MC can only update after a complete episode, so it doesn't work for continuing
tasks. But it can handle any environment you can simulate, even one with complex stochastic
dynamics you'd never be able to write down as a model.

> **Picture it:** estimating how long your commute takes. DP would need a map with every
> traffic light's timing. Monte Carlo just drives to work 100 times with a stopwatch and
> averages. It never needs the map — but it only learns anything once each trip is over.

## First-Visit MC Prediction

**Prediction** means estimating how good states are under a fixed policy (no improving yet).
The Monte Carlo recipe: every time you visit a state, remember the total reward that followed;
the average of those totals is the state's value.

You want to estimate $v_\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]$. The return from time $t$
is $G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots$ over the rest of the episode.

**First-visit MC**: on each episode, for each state $s$, find the *first* time it appears.
Compute $G_t$ from that point. Average over all episodes.

$$
V(s) \leftarrow V(s) + \alpha\bigl(G_t - V(s)\bigr)
$$

> **In plain words:** nudge your estimate $V(s)$ toward the return $G_t$ you actually got,
> by a fraction $\alpha$ of the gap. Same "old + step × error" shape as the bandit update in
> ch. 2 — but now the target is a whole episode's return instead of one reward.

Using $\alpha = 1/N(s)$ gives the sample mean. Using a fixed small $\alpha$ tracks
non-stationary problems. Here $N(s)$ counts how many episodes have visited $s$ so far.

The example uses **Blackjack**: you are dealt cards and try to get a sum close to 21 without
going over ("busting"). The state is a triple (your sum, the dealer's visible card, whether you
hold a **usable ace** — an ace you can count as 11 without busting). The reward is $+1$ for a
win, $-1$ for a loss, 0 for a draw, all at the end. The fixed policy: hit (take a card) until
your sum is 20 or more, then stick.

```python
import numpy as np
import gymnasium as gym

env = gym.make("Blackjack-v1", sab=True)
env.reset(seed=0)  # seed the deck once; later resets continue the stream

def generate_episode(env, policy):
    """Returns list of (state, action, reward)."""
    episode = []
    state, _ = env.reset()
    done = False
    while not done:
        action = policy(state)
        next_state, reward, terminated, truncated, _ = env.step(action)
        episode.append((state, action, reward))
        state = next_state
        done = terminated or truncated
    return episode

def simple_policy(state):
    """Stick (0) if sum >= 20, else hit (1)."""
    player_sum, _, _ = state
    return 0 if player_sum >= 20 else 1

# First-visit MC prediction
returns_sum = {}
returns_count = {}
V = {}

n_episodes = 100_000
for ep in range(n_episodes):
    episode = generate_episode(env, simple_policy)
    G = 0
    visited = set()
    for t in reversed(range(len(episode))):
        state, action, reward = episode[t]
        G = reward + G  # gamma=1 for Blackjack
        if state not in visited:
            visited.add(state)
            returns_sum[state] = returns_sum.get(state, 0) + G
            returns_count[state] = returns_count.get(state, 0) + 1
            V[state] = returns_sum[state] / returns_count[state]

# Show value for usable-ace states with dealer showing 2
print("V(player_sum, dealer=2, usable_ace=True):")
for ps in range(12, 22):
    key = (ps, 2, True)
    val = V.get(key, float('nan'))
    print(f"  player={ps}: {val:.3f}")
```

```output
V(player_sum, dealer=2, usable_ace=True):
  player=12: -0.176
  player=13: -0.109
  player=14: -0.299
  player=15: -0.339
  player=16: -0.361
  player=17: -0.422
  player=18: -0.415
  player=19: -0.379
  player=20: 0.683
  player=21: 0.975
```

Read the column from top to bottom. Sums 12 through 19 are all negative, between $-0.109$ and
$-0.422$: this policy keeps hitting on those sums and often busts. Then the jump: 20 is worth
0.683 and 21 is worth 0.975, because those are the only sums where the policy sticks. A value
of 0.683 means wins minus losses equals 68.3% of games — for example about 80% wins and 12%
losses.

Values do not rise smoothly with player sum: they jump at 20, where this policy switches from
hitting to sticking. With a usable ace, 20 has an expected outcome of $+0.683$ per game against a
dealer showing 2 — strongly favourable, but not a sure win.

> **Watch out:** the code walks each episode *backwards*, so that `G = reward + G` builds the
> return from the end. A state's "first visit" is then the last time the backward loop sees
> it — which is why the code checks `visited` as it goes. Here $\gamma = 1$, so no discounting
> appears.

## MC Control: ε-Soft Policy

**Control** means finding a good policy, not only scoring a fixed one. The catch: if you
always do what currently looks best, you never learn about the alternatives. So you keep a
little randomness in every state.

To find the optimal policy without a model, you need to explore. The **ε-soft** approach makes
every action available with at least probability $\varepsilon/|A|$ (where $|A|$ is the number
of actions), but assigns most probability to the current best action:

$$
\pi(a|s) = \begin{cases}
1 - \varepsilon + \varepsilon/|A| & \text{if } a = \arg\max_{a'} Q(s,a') \\
\varepsilon/|A| & \text{otherwise}
\end{cases}
$$

> **In plain words:** with $\varepsilon = 0.1$ and two actions, the best-looking action is
> picked with probability $1 - 0.1 + 0.05 = 0.95$, and the other with probability 0.05. Every
> action keeps a small, non-zero chance, so its value keeps getting updated.

Here the agent learns $Q(s, a)$ — the action value from ch. 3 — instead of $V(s)$. Without a
model you cannot look one step ahead to compare actions, so you need values for each action
directly.

```python
from collections import defaultdict

env = gym.make("Blackjack-v1", sab=True)
env.reset(seed=0)
env.action_space.seed(0)
np.random.seed(0)

Q = defaultdict(lambda: np.zeros(2))  # 2 actions: stick=0, hit=1
N = defaultdict(lambda: np.zeros(2))
epsilon = 0.1

def epsilon_greedy(state, eps=epsilon):
    if np.random.random() < eps:
        return env.action_space.sample()
    return int(np.argmax(Q[state]))

n_episodes = 300_000
for ep in range(n_episodes):
    episode = []
    state, _ = env.reset()
    done = False
    while not done:
        action = epsilon_greedy(state)
        next_state, reward, terminated, truncated, _ = env.step(action)
        episode.append((state, action, reward))
        state = next_state
        done = terminated or truncated

    G = 0
    visited = set()
    for t in reversed(range(len(episode))):
        state, action, reward = episode[t]
        G = reward + G
        sa = (state, action)
        if sa not in visited:
            visited.add(sa)
            N[state][action] += 1
            Q[state][action] += (G - Q[state][action]) / N[state][action]

# Show optimal action for no-usable-ace states
print("Optimal action (0=stick, 1=hit) — no usable ace, dealer=6:")
for ps in range(12, 22):
    key = (ps, 6, False)
    action = np.argmax(Q[key])
    print(f"  player={ps}: {'hit' if action else 'stick'}")
```

```output
Optimal action (0=stick, 1=hit) — no usable ace, dealer=6:
  player=12: stick
  player=13: stick
  player=14: stick
  player=15: stick
  player=16: stick
  player=17: stick
  player=18: stick
  player=19: stick
  player=20: stick
  player=21: stick
```

All ten lines say `stick`: with the dealer showing 6, the learned policy never takes a card
from 12 upward.

With dealer showing 6 (a "bust card"), the learnt policy matches basic strategy, which sticks on
every sum from 12 upward against a 6, because the dealer is likely to bust. Six is the dealer's
worst card: the dealer must keep hitting below 17, and from 6 that often goes over 21.

> **Watch out:** states that are rarely visited get few updates, so their learned action can
> be noise. Check the visit counts in `N` before trusting the policy in an unusual state.

### Exploring Starts vs ε-Soft

Another way to make sure every action gets tried: start each episode from a random situation
with a random first move.

An alternative to ε-soft is **exploring starts**: guarantee every (state, action) pair has
nonzero probability of being the start of an episode. This allows a fully greedy policy but
requires control over the environment's start distribution — impossible in real settings.
ε-soft is the practical default.

## Importance Sampling for Off-Policy MC

Sometimes you want to learn about one way of playing while actually playing a different way —
for example, learn the greedy strategy from a cautious player's games. You fix the mismatch by
re-weighting each game by how much more (or less) likely it was under the strategy you care
about.

To learn about a **target policy** $\pi$ (the one you want to evaluate) while following a
**behavior policy** $b$ (the one that generates the data) — which must cover $\pi$:
$\pi(a|s) > 0 \Rightarrow b(a|s) > 0$ — multiply returns by the importance sampling ratio. This
is called **off-policy** learning: the data comes "off" a different policy.

$$
\rho_{t:T-1} = \prod_{k=t}^{T-1} \frac{\pi(A_k|S_k)}{b(A_k|S_k)}
$$

> **In plain words:** for each step from $t$ to the end $T-1$, divide "how likely the target
> policy was to take that action" by "how likely the behavior policy was to take it", and
> multiply all those ratios together. If $\pi$ would have taken these actions twice as often
> as $b$ did, the episode counts double.

Ordinary IS: $V(s) \leftarrow \frac{\sum \rho G}{\text{count}}$ — unbiased but high variance.
Weighted IS: $V(s) \leftarrow \frac{\sum \rho G}{\sum \rho}$ — biased but much lower variance in
practice, and the bias vanishes asymptotically. **Unbiased** means right on average;
**variance** measures how far a single estimate can swing.

> **Watch out:** the ratio is a product over the whole episode, so it can explode. Ten steps
> where $\pi$ is twice as likely as $b$ give a weight of $2^{10} = 1024$ — one episode then
> dominates the average. That is why weighted IS is preferred, and why a step where $\pi$ would
> never act (ratio 0) wipes out the rest of the episode.

## Recap in plain words

- Monte Carlo learns values by averaging the returns of complete episodes; no model needed.
- First-visit MC counts only the first time a state appears in each episode.
- Learning $Q(s, a)$ lets you pick the best action without a model.
- An $\varepsilon$-soft policy keeps every action possible, so exploration never stops.
- MC must wait until the episode ends before it can update anything.
- Importance sampling re-weights episodes to learn about a policy you are not following.

## Try it Yourself

```python
import numpy as np
import gymnasium as gym
from collections import defaultdict

# Train MC control on Blackjack for 200,000 episodes with epsilon=0.1
# Then evaluate the greedy policy for 10,000 episodes and report win rate

env = gym.make("Blackjack-v1", sab=True)
env.reset(seed=1)
env.action_space.seed(1)
np.random.seed(1)
Q = defaultdict(lambda: np.zeros(2))
N = defaultdict(lambda: np.zeros(2))
epsilon = 0.1

for ep in range(200_000):
    episode = []
    state, _ = env.reset()
    done = False
    while not done:
        action = int(np.argmax(Q[state])) if np.random.random() > epsilon else env.action_space.sample()
        next_state, reward, terminated, truncated, _ = env.step(action)
        episode.append((state, action, reward))
        state = next_state
        done = terminated or truncated
    G = 0
    visited = set()
    for t in reversed(range(len(episode))):
        s, a, r = episode[t]
        G = r + G
        if (s, a) not in visited:
            visited.add((s, a))
            N[s][a] += 1
            Q[s][a] += (G - Q[s][a]) / N[s][a]

# Evaluate greedy policy
wins = draws = losses = 0
for _ in range(10_000):
    state, _ = env.reset()
    done = False
    while not done:
        action = int(np.argmax(Q[state]))
        state, reward, terminated, truncated, _ = env.step(action)
        done = terminated or truncated
    if reward > 0:
        wins += 1
    elif reward == 0:
        draws += 1
    else:
        losses += 1

print(f"Win rate: {wins/100:.1f}%  Draw: {draws/100:.1f}%  Loss: {losses/100:.1f}%")
```

```output
Win rate: 43.0%  Draw: 9.0%  Loss: 48.0%
```

The learned greedy policy wins 43.0%, draws 9.0%, and loses 48.0% of 10,000 hands. Losing more
often than winning is normal: in Blackjack the house has an edge even against perfect basic
strategy (which wins about 43% and loses about 49%). So this learner is already close to the
best a player can do.

Try training for 20,000 episodes instead of 200,000 and compare the win rate, or set
`epsilon = 0.3` to see how heavier exploration during training changes the result.

## Exercise

Implement **every-visit** MC prediction (not first-visit) on the same Blackjack environment.
After 100,000 episodes, compare the value estimates for states (18, 6, False) and (20, 10, False)
between first-visit and every-visit MC. Are they different? Why or why not in the limit?

> **Hint:** before coding, ask whether a Blackjack state can appear twice in one episode. Every
> card you take changes your sum or your ace status.

```python
import numpy as np
import gymnasium as gym

env = gym.make("Blackjack-v1", sab=True)
env.reset(seed=0)  # same deck stream as the first-visit run above

def simple_policy(state):
    return 0 if state[0] >= 20 else 1

# Every-visit MC
returns_sum_ev = {}
returns_count_ev = {}

for ep in range(100_000):
    episode = []
    state, _ = env.reset()
    done = False
    while not done:
        action = simple_policy(state)
        ns, reward, terminated, truncated, _ = env.step(action)
        episode.append((state, action, reward))
        state = ns
        done = terminated or truncated
    G = 0
    for t in reversed(range(len(episode))):
        s, a, r = episode[t]
        G = r + G
        # Every visit: update even if s was seen before
        returns_sum_ev[s] = returns_sum_ev.get(s, 0) + G
        returns_count_ev[s] = returns_count_ev.get(s, 0) + 1

for key in [(18, 6, False), (20, 10, False)]:
    ev = returns_sum_ev.get(key, 0) / max(returns_count_ev.get(key, 1), 1)
    print(f"Every-visit V{key} = {ev:.4f}")
```

This prints $V(18, 6, \text{False}) = -0.7093$ and $V(20, 10, \text{False}) = 0.4437$ — exactly
the same values the first-visit loop from the first example gives on the same seeded deck. In
the limit, first-visit and every-visit MC both converge to the true $v_\pi(s)$. In general the
difference is variance, not bias: every-visit uses more updates per episode, but those updates
are correlated within episodes (and every-visit is slightly biased for finite samples). For
Blackjack, each state appears at most once per episode anyway, so the two methods are not just
nearly identical here — they do the very same updates.
</details>
