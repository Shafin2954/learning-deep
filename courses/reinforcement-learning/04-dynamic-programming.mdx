## Why DP Needs a Model

If you have the full rulebook of the world — exactly where every move can take you and what it
pays — you don't need to play to learn. You can sit down and compute the best strategy with
pencil and paper (or a loop).

Dynamic programming computes optimal policies by sweeping the Bellman equations (ch. 3) over the
entire state space. **Dynamic programming** (DP) means solving a big problem by reusing answers
to smaller overlapping pieces — here, reusing the values of next states. Unlike the methods
ahead, it requires the transition dynamics $p(s',r|s,a)$ — the probability of landing in $s'$
with reward $r$ after taking action $a$ in state $s$. When you have this model, DP is exact and
fast. When you don't, you need Monte Carlo or TD (ch. 5, ch. 6).

The key idea: the value of a state depends on the values of its successors, which depend on
their successors. DP breaks this circularity by iterating until the values stop changing.

> **Picture it:** a town where each house's "distance to the station" is one more than its
> closest neighbour's. Nobody knows their number at first. Everyone writes down a guess, then
> repeatedly looks at the neighbours' guesses and corrects their own. After a few rounds the
> numbers stop changing, and every house knows its true distance.

## Policy Evaluation

First question: how good is a given strategy? Policy evaluation scores a fixed policy by
computing the value of every state under it.

Given a fixed policy $\pi$, compute $v_\pi(s)$ for every state. The Bellman expectation
equation tells you what $v_\pi$ must satisfy:

$$
v_\pi(s) = \sum_a \pi(a|s) \sum_{s',r} p(s',r|s,a)\bigl[r + \gamma v_\pi(s')\bigr]
$$

> **In plain words:** the value of state $s$ is the average, over the actions the policy picks
> and the outcomes the world produces, of "reward now + $\gamma$ times the value of the next
> state". The same equation as ch. 3.

You can't solve this analytically for large state spaces, but you can iterate: start with
$V(s)=0$ everywhere, then sweep all states applying the right-hand side. Repeat until
$\max_s |V(s) - V_{old}(s)| < \theta$. The threshold $\theta$ (Greek "theta", here $10^{-6}$)
is your definition of "stopped changing": the biggest change in any state during the last sweep.

The gridworld below pays $+1$ for stepping into the goal (state 15, bottom-right) and 0 for
every other step, with $\gamma = 0.9$. So a state's value is roughly "0.9 to the power of how
long it takes to reach the goal", averaged over the random wandering.

```python
import numpy as np

# 4x4 gridworld: states 0..15, goal=15 (reward +1 for entering it)
# Actions: 0=up, 1=down, 2=left, 3=right
# Simple random policy (uniform over valid actions)
# Transitions: deterministic, stay at boundary

n_states = 16
gamma = 0.9
theta = 1e-6

def get_transitions(state, action):
    """Returns list of (prob, next_state, reward)."""
    row, col = divmod(state, 4)
    moves = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    dr, dc = moves[action]
    nr, nc = row + dr, col + dc
    if 0 <= nr < 4 and 0 <= nc < 4:
        next_state = nr * 4 + nc
    else:
        next_state = state
    reward = 1.0 if next_state == 15 else 0.0
    return [(1.0, next_state, reward)]

# Uniform random policy
pi = np.ones((n_states, 4)) / 4

V = np.zeros(n_states)
for iteration in range(1000):
    delta = 0
    for s in range(n_states - 1):  # skip terminal
        v_old = V[s]
        V[s] = sum(
            pi[s, a] * sum(
                p * (r + gamma * V[s_])
                for p, s_, r in get_transitions(s, a)
            )
            for a in range(4)
        )
        delta = max(delta, abs(V[s] - v_old))
    if delta < theta:
        print(f"Converged after {iteration + 1} iterations")
        break

print("Value function (random policy):")
print(V.reshape(4, 4).round(3))
```

```output
Converged after 57 iterations
Value function (random policy):
[[0.071 0.087 0.114 0.139]
 [0.087 0.114 0.167 0.226]
 [0.114 0.167 0.287 0.471]
 [0.139 0.226 0.471 0.   ]]
```

57 sweeps to settle. Values grow from 0.071 in the far corner (top-left) to 0.471 next to the
goal — the two neighbours of the goal, (2, 3) and (3, 2), tie at 0.471 by symmetry. Even next to
the goal the value is under 0.5, because a random walker steps into the goal only one time in
four and often wanders off.

The states nearest the goal (row 3, col 2 and row 2, col 3) have the highest value under the
random policy. The terminal state 15 is 0 because it's **absorbing** — once you are there the
episode is over, so there is no future reward.

> **Watch out:** this loop updates `V[s]` in place, so later states in the same sweep already use
> this sweep's new values. That is the "Gauss–Seidel" style and it converges faster than keeping
> a separate copy of the old values. Both versions reach the same answer.

## Policy Improvement

Second question: once you know how good each state is under your current strategy, can you do
better? Yes — in every state, switch to the action that looks best one step ahead.

Once you have $v_\pi$, you can improve the policy greedily: pick the action that maximizes the
expected return using the one-step Bellman lookahead.

$$
\pi'(s) = \arg\max_a \sum_{s',r} p(s',r|s,a)\bigl[r + \gamma v_\pi(s')\bigr]
$$

> **In plain words:** the new policy $\pi'$ ("pi prime") picks, in each state, the action with
> the best "reward now + discounted value of where you land", using the values of the *old*
> policy. You trust your current scores, and act on them.

The policy improvement theorem guarantees $v_{\pi'} \geq v_\pi$ everywhere (strictly better
unless $\pi$ was already optimal). Alternate evaluation and improvement until convergence —
this is **policy iteration**.

> **Picture it:** a sports coach. Watch the team play a full season with the current playbook
> (evaluation). Then, for every situation, rewrite the play that would have worked best
> (improvement). Next season, play the new book and watch again. Each new playbook is at least
> as good, and when a rewrite changes nothing, you are done.

```python
def policy_eval(pi, gamma=0.9, theta=1e-6):
    V = np.zeros(n_states)
    while True:
        delta = 0
        for s in range(n_states - 1):
            v_old = V[s]
            V[s] = sum(
                pi[s, a] * sum(p * (r + gamma * V[s_])
                               for p, s_, r in get_transitions(s, a))
                for a in range(4)
            )
            delta = max(delta, abs(V[s] - v_old))
        if delta < theta:
            return V

def policy_improve(V, gamma=0.9):
    pi = np.zeros((n_states, 4))
    for s in range(n_states - 1):
        q = [sum(p * (r + gamma * V[s_]) for p, s_, r in get_transitions(s, a))
             for a in range(4)]
        best = np.argmax(q)
        pi[s, best] = 1.0
    pi[15] = 0.25  # terminal: arbitrary
    return pi

# Policy iteration
pi = np.ones((n_states, 4)) / 4
for k in range(100):
    V = policy_eval(pi)
    pi_new = policy_improve(V)
    if np.allclose(pi_new, pi):
        print(f"Policy stable after {k + 1} improvement steps")
        break
    pi = pi_new

symbols = {0: "↑", 1: "↓", 2: "←", 3: "→"}
print("Optimal policy:")
for row in range(4):
    print(" ".join(symbols[np.argmax(pi[row*4+col])] for col in range(4)))
```

```output
Policy stable after 3 improvement steps
Optimal policy:
↓ ↓ ↓ ↓
↓ ↓ ↓ ↓
↓ ↓ ↓ ↓
→ → → ↑
```

Three improvement steps, and the policy stopped changing. Every non-goal state points down, and
the bottom row points right: the shortest route to the goal from anywhere. Moving right and
moving down are equally good in most cells, and `np.argmax` breaks the tie by taking the lower
index (down = 1 comes before right = 3). The `↑` in the bottom-right corner is the terminal
state's arbitrary entry; it never gets used.

Three sweeps of evaluation and improvement find the optimal policy. The arrows steer every state
toward the goal at state 15 (G).

## Value Iteration

Policy iteration waits for a full, careful evaluation before improving. Value iteration is
impatient: it improves after every single sweep, by taking the best action directly inside
the update.

Policy iteration evaluates the policy to convergence each sweep. Value iteration skips full
evaluation and applies the Bellman *optimality* equation directly — it's essentially one step of
policy evaluation per improvement cycle:

$$
V(s) \leftarrow \max_a \sum_{s',r} p(s',r|s,a)\bigl[r + \gamma V(s')\bigr]
$$

> **In plain words:** for every state, set its value to the best over actions of "reward now +
> discounted value of where you land". The arrow $\leftarrow$ means "overwrite with". Repeat
> until nothing moves.

```python
V = np.zeros(n_states)
for iteration in range(1000):
    delta = 0
    for s in range(n_states - 1):
        v_old = V[s]
        V[s] = max(
            sum(p * (r + gamma * V[s_]) for p, s_, r in get_transitions(s, a))
            for a in range(4)
        )
        delta = max(delta, abs(V[s] - v_old))
    if delta < theta:
        print(f"Value iteration converged after {iteration + 1} sweeps")
        break

print("Optimal value function:")
print(V.reshape(4, 4).round(3))
```

```output
Value iteration converged after 7 sweeps
Optimal value function:
[[0.59  0.656 0.729 0.81 ]
 [0.656 0.729 0.81  0.9  ]
 [0.729 0.81  0.9   1.   ]
 [0.81  0.9   1.    0.   ]]
```

Only 7 sweeps. The values are exact powers of 0.9: the states next to the goal are worth 1.0
(one step, reward 1), two steps away 0.9, then 0.81, 0.729, 0.656, and the far corner 0.59
$\approx 0.9^5$ — six steps from the goal. Each sweep pushes the correct values one more step
outward from the goal.

Value iteration converged in 7 sweeps here. Policy iteration needed 3 cycles whose evaluations
took 57, 7, and 7 sweeps — 71 sweeps in total. The first evaluation is the slow one: it scores the
random policy, which wanders. For small grids the difference is minor; policy iteration can win
on larger problems because it needs very few improvement steps, each of which is costly.

> **Watch out:** value iteration's intermediate `V` is not the value of any particular policy —
> it is a moving target that only becomes meaningful at convergence. To get the policy, run one
> greedy step (the formula for $\pi'$ above) on the final `V`.

### Asynchronous DP

You don't have to update states in neat full passes. Any order works, as long as no state is
ignored forever.

Standard DP sweeps all states in a fixed order each iteration. **Asynchronous DP** updates states
in any order — even one at a time — and still converges as long as every state gets updated
infinitely often. This lets you prioritize "important" states (high TD error — a big gap between
a state's value and its one-step update, ch. 6) and skip unchanged regions, which matters for
very large MDPs.

## Recap in plain words

- DP computes the best policy from a known model, without playing a single episode.
- Policy evaluation repeats the Bellman expectation update until values change by less than $\theta$.
- Policy improvement switches each state to the action that looks best one step ahead; it never makes things worse.
- Policy iteration alternates the two; here it took 3 cycles (71 evaluation sweeps).
- Value iteration folds the "best action" into every update; here it took 7 sweeps.
- With $\gamma = 0.9$ and a +1 goal, optimal values are powers of 0.9, one per step of distance.

## Try it Yourself

The same value iteration on a $5 \times 5$ grid with a wall in the middle (state 12). A **wall**
here is a cell you cannot enter: moving into it leaves you where you were.

```python
import numpy as np

# 5x5 gridworld with a wall at (2,2)
# Modify the get_transitions function to block state 12 (row 2, col 2)
# Then run value iteration and print the resulting policy

n_states = 25
gamma = 0.95
theta = 1e-6
WALL = 12  # state 12 is a wall — agent bounces back

def get_transitions_5x5(state, action):
    if state == WALL:
        return [(1.0, state, 0.0)]
    row, col = divmod(state, 5)
    moves = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    dr, dc = moves[action]
    nr, nc = row + dr, col + dc
    if 0 <= nr < 5 and 0 <= nc < 5:
        next_state = nr * 5 + nc
        if next_state == WALL:
            next_state = state  # bounce off wall
    else:
        next_state = state
    reward = 1.0 if next_state == 24 else 0.0
    return [(1.0, next_state, reward)]

V = np.zeros(n_states)
for _ in range(2000):
    delta = 0
    for s in range(n_states - 1):
        if s == WALL:
            continue
        v_old = V[s]
        V[s] = max(
            sum(p * (r + gamma * V[s_])
                for p, s_, r in get_transitions_5x5(s, a))
            for a in range(4)
        )
        delta = max(delta, abs(V[s] - v_old))
    if delta < theta:
        break

symbols = ["↑", "↓", "←", "→"]
print("Optimal policy (W=wall, G=goal):")
for row in range(5):
    line = []
    for col in range(5):
        s = row * 5 + col
        if s == WALL:
            line.append("W")
        elif s == 24:
            line.append("G")
        else:
            q = [sum(p * (r + gamma * V[s_])
                     for p, s_, r in get_transitions_5x5(s, a))
                 for a in range(4)]
            line.append(symbols[np.argmax(q)])
    print(" ".join(line))
```

```output
Optimal policy (W=wall, G=goal):
↓ ↓ ↓ ↓ ↓
↓ ↓ → ↓ ↓
↓ ↓ W ↓ ↓
↓ ↓ ↓ ↓ ↓
→ → → → G
```

Look at the second row: the cell just above the wall shows `→` instead of `↓`, because moving
down would bump into the wall and waste a step. Everywhere else the policy is the same "down,
then right along the bottom row" route as before. Moving the wall to `WALL = 22` (bottom row)
forces the bottom-row route to detour — try it, and also try `gamma = 0.5` to see the values
shrink much faster with distance.

reward. Run policy iteration and print the optimal value function and policy. Does the agent now
avoid the top row?

> **Hint:** the goal is in the bottom-right corner. Ask yourself whether the shortest route from
> any state ever steps *into* row 0 before you predict a change.

```python
import numpy as np

n_states = 25
gamma = 0.95
theta = 1e-8
WALL = 12
GOAL = 24

def get_transitions_penalty(state, action):
    if state == WALL or state == GOAL:
        return [(1.0, state, 0.0)]
    row, col = divmod(state, 5)
    moves = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    dr, dc = moves[action]
    nr, nc = row + dr, col + dc
    if 0 <= nr < 5 and 0 <= nc < 5:
        next_state = nr * 5 + nc
        if next_state == WALL:
            next_state = state
    else:
        next_state = state
    nr2, _ = divmod(next_state, 5)
    reward = (1.0 if next_state == GOAL else 0.0) + (-0.5 if nr2 == 0 else 0.0)
    return [(1.0, next_state, reward)]

def policy_eval_5x5(pi):
    V = np.zeros(n_states)
    while True:
        delta = 0
        for s in range(n_states):
            if s in (WALL, GOAL):
                continue
            v_old = V[s]
            V[s] = sum(
                pi[s, a] * sum(p * (r + gamma * V[s_])
                               for p, s_, r in get_transitions_penalty(s, a))
                for a in range(4)
            )
            delta = max(delta, abs(V[s] - v_old))
        if delta < theta:
            return V

pi = np.ones((n_states, 4)) / 4
for k in range(200):
    V = policy_eval_5x5(pi)
    pi_new = np.zeros((n_states, 4))
    stable = True
    for s in range(n_states):
        if s in (WALL, GOAL):
            pi_new[s] = 0.25
            continue
        q = [sum(p * (r + gamma * V[s_])
                 for p, s_, r in get_transitions_penalty(s, a))
             for a in range(4)]
        best = np.argmax(q)
        pi_new[s, best] = 1.0
        if best != np.argmax(pi[s]):
            stable = False
    pi = pi_new
    if stable:
        print(f"Converged after {k+1} improvement steps")
        break

symbols = ["↑", "↓", "←", "→"]
print("Policy with top-row penalty:")
for row in range(5):
    line = []
    for col in range(5):
        s = row * 5 + col
        if s == WALL:
            line.append("W")
        elif s == GOAL:
            line.append("G")
        else:
            line.append(symbols[np.argmax(pi[s])])
    print(" ".join(line))
```

The printed policy is identical to the no-penalty policy from Try it Yourself, and it converges
after 3 improvement steps. The agent avoids row 0 — but it already did: the penalty is charged
only for stepping *into* row 0, and no optimal route from any state ever moves up, so states in
row 1 keep pointing down or sideways. The penalty changes nothing here. To see the penalty
reshape the value landscape, put the goal in the top row (for example `GOAL = 2`): then routes
must decide how long they can stay out of the penalty zone. Add
`print(V.reshape(5, 5).round(3))` to show the value function the exercise asks for.
