## The agent-environment loop

Reinforcement learning is learning by trial and error: you try something, the world tells you
how well it went, and you slowly figure out what to do. Nobody hands you the right answers —
you only get a score.

Reinforcement learning is the problem of learning to act. An **agent** (the learner and
decision-maker — the program you write) observes a **state** $S_t$ (a snapshot of the situation
at time step $t$), takes an **action** $A_t$ (one of the moves it is allowed to make), and
receives a **reward** $R_{t+1}$ (a single number saying how good that step was) along with a
new state $S_{t+1}$ from the **environment** (everything outside the agent: the game, the robot's
physics, the market). This loop repeats until the episode ends or indefinitely.

The diagram is simple: Agent → Action → Environment → (State, Reward) → Agent.

> **Picture it:** training a dog. The dog (agent) sees the room and your hand signal (state),
> does something — sits, jumps, barks (action) — and you give a treat or nothing (reward).
> The dog never reads a rulebook; it learns which actions earn treats in which situations.
> Where the analogy breaks: a dog gets a treat right away, while RL rewards often arrive many
> steps after the action that earned them.

Every RL algorithm is a different answer to the same question: given the history of states,
actions, and rewards you've seen, what action should you take next?

Notice the reward is labelled $R_{t+1}$, not $R_t$: it is the consequence of acting at time
$t$, so it arrives one tick later, together with $S_{t+1}$. The rule the agent uses to choose
actions is called its **policy** — later chapters are all about finding a good one.

> **Watch out:** RL is not supervised learning. In supervised learning every example comes
> with the correct label. Here the agent is never told the best action — only how much reward
> its own choice produced — and its choices change which data it sees next.

## The reward hypothesis

The idea: whatever you want the agent to do, you can turn it into "collect as many points as
possible over time". The art is in choosing the points.

The reward hypothesis is RL's central assumption: every goal can be expressed as the
maximization of expected **cumulative reward** (the total of all rewards added up over time,
not only the next one). Winning a game, controlling a robot, managing a portfolio — all of
these reduce to a scalar signal the agent should maximize.

The **return** $G_t$ is the total discounted reward from time $t$:

$$
G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}
$$

> **In plain words:** the return is "everything you will collect from now on", where each
> reward further in the future is multiplied by one more factor of $\gamma$.
> - $G_t$ — the return, counted from time step $t$ onward.
> - $R_{t+k+1}$ — the reward that arrives $k+1$ steps from now.
> - $\gamma$ — the discount factor (Greek "gamma"), a number between 0 and 1.
> - $\gamma^k$ — the shrink factor: a reward $k$ steps away counts $\gamma^k$ as much.

The **discount factor** $\gamma \in [0, 1)$ controls how much the agent values future rewards.
$\gamma = 0$ makes the agent myopic (only immediate reward). $\gamma \to 1$ makes it
far-sighted. Most practical settings use $\gamma = 0.99$.

Concrete numbers help. With $\gamma = 0.99$ and a reward of 1 every step forever, the return is
$1 + 0.99 + 0.99^2 + \cdots = 1/(1-0.99) = 100$. A reward 100 steps away still counts
$0.99^{100} \approx 0.37$ as much as one right now. With $\gamma = 0.9$ the same reward would
count only $0.9^{100} \approx 0.00003$ — practically invisible.

> **Picture it:** money in the bank, run backwards. A dollar promised next year is worth a bit
> less than a dollar today, because you might never get it. $\gamma$ is "how much a promise
> one step away is worth today".

### Episodic vs continuing tasks

Some tasks have a finish line and some never stop; that changes how you add up rewards.

**Episodic tasks** have a natural end (a game ends, a robot reaches the goal). Return is the sum
of rewards in the episode. One run from start to finish is called an **episode**.

**Continuing tasks** go on forever (stock trading, process control). You need discounting to
keep the return finite.

> **Watch out:** with $\gamma = 1$ in a continuing task that pays +1 every step, the return is
> $1 + 1 + 1 + \cdots$, which is infinite. Every policy then looks equally "infinitely good",
> and comparing them stops making sense. Discounting with $\gamma < 1$ fixes that.

## The Markov property

The plain idea: if you know where things stand right now, knowing how you got here adds
nothing. The present already contains everything useful about the past.

The **Markov property** says the current state $S_t$ is sufficient to predict the future — you
don't need the full history. Formally:

$$
P(S_{t+1} | S_t, A_t, S_{t-1}, A_{t-1}, \ldots) = P(S_{t+1} | S_t, A_t)
$$

> **In plain words:** the chance of landing in the next state, given the whole history of
> states and actions, equals the chance given only the current state and action. The vertical
> bar "|" reads "given". The left side remembers everything; the right side remembers only
> "now" — and they are equal.

If the state fully captures the relevant history, the process is **Markov**. This is an
assumption — raw pixel frames from Atari technically need frame stacking to be approximately
Markov (velocity isn't visible in a single frame).

> **Picture it:** a chess position is Markov. If someone shows you the board mid-game, you can
> pick the best move without knowing which moves led there. A single photo of a thrown ball is
> not Markov: you can see where the ball is, but not whether it is going up or coming down.
> Stacking two photos (frame stacking) reveals the direction.

## The gymnasium API

Every RL environment needs the same few buttons: "start over", "do this action", and "what can
I see / what can I do". A shared API means your agent code works on any environment.

`gymnasium` (the maintained fork of OpenAI gym) provides a standard interface for RL
environments. The **observation space** describes what the agent sees each step, and the
**action space** describes which actions are legal.

```python
import gymnasium as gym

env = gym.make("CartPole-v1")
obs, info = env.reset(seed=42)
print("Observation space:", env.observation_space)
print("Action space:     ", env.action_space)
print("Initial obs shape:", obs.shape)
```

```output
Observation space: Box([-4.8               -inf -0.41887903        -inf], [4.8               inf 0.41887903        inf], (4,), float32)
Action space:      Discrete(2)
Initial obs shape: (4,)
```

Read the first line from left to right. `Box(low, high, (4,), float32)` means four real
numbers, each bounded below by the first list and above by the second: cart position in
$[-4.8, 4.8]$, pole angle in about $[-0.42, 0.42]$ radians (24 degrees), and two velocities
with no hard limit (`inf`). `Discrete(2)` means exactly two actions, numbered 0 and 1.

CartPole's observation is `[cart_pos, cart_vel, pole_angle, pole_angular_vel]`. Actions are 0
(push left) or 1 (push right).

> **Picture it:** balancing a broomstick upright on your palm. You can only move your hand
> left or right. The four numbers are where your hand is, how fast it moves, how far the
> broom leans, and how fast it is tipping.

### Running a random policy

The simplest possible agent ignores what it sees and picks actions at random. It is a useful
baseline: any learning agent must beat it.

```python
import gymnasium as gym
import numpy as np

env = gym.make("CartPole-v1")
env.action_space.seed(0)  # reproducible random actions
total_rewards = []

for episode in range(10):
    obs, _ = env.reset(seed=episode)
    total_reward = 0
    done = False
    while not done:
        action = env.action_space.sample()  # random action
        obs, reward, terminated, truncated, info = env.step(action)
        total_reward += reward
        done = terminated or truncated
    total_rewards.append(total_reward)

print(f"Mean reward (random): {np.mean(total_rewards):.1f} ± {np.std(total_rewards):.1f}")
print(f"Max possible:         500")
```

```output
Mean reward (random): 25.6 ± 15.2
Max possible:         500
```

Ten random episodes average 25.6 steps, with a large spread (standard deviation 15.2) — some
episodes die almost at once, others survive a while by luck. Seeding `reset` and the action
space makes these exact numbers reproducible; change a seed and you get a different mix.

A random policy lasts only about 26 steps before the pole falls. A trained agent achieves 500
(the episode cap). That gap is what learning must close.

> **Watch out:** `env.reset()` without a seed and `env.action_space.sample()` without
> `env.action_space.seed(...)` give different results on every run. When you compare two
> algorithms, fix the seeds, or you may be comparing luck.

### The step loop in detail

Each call to `step` moves the world forward one tick and hands back five things. It is worth
looking at them one at a time.

```python
import gymnasium as gym

env = gym.make("CartPole-v1")
obs, _ = env.reset(seed=0)
env.action_space.seed(0)

for t in range(5):
    action = env.action_space.sample()
    next_obs, reward, terminated, truncated, info = env.step(action)
    print(f"t={t}  action={action}  reward={reward:.0f}  terminated={terminated}")
    obs = next_obs
    if terminated or truncated:
        break
```

```output
t=0  action=1  reward=1  terminated=False
t=1  action=1  reward=1  terminated=False
t=2  action=1  reward=1  terminated=False
t=3  action=0  reward=1  terminated=False
t=4  action=0  reward=1  terminated=False
```

Every line shows `reward=1`: CartPole pays +1 for each step the pole stays up, so the return of
an episode is its length. `terminated=False` on all five lines means the pole had not fallen
yet after five random pushes.

Each step gives reward +1 for staying upright. `terminated=True` means the pole fell or the cart
left bounds. The other flag, `truncated=True`, means the episode was cut off by a time limit
(500 steps for CartPole-v1) rather than by failure.

> **Watch out:** `terminated` and `truncated` mean different things. A terminated episode
> truly ended — there is no future reward. A truncated one was stopped by a clock, and the
> future would have continued. Later algorithms (ch. 6, ch. 9) treat the two differently when
> they estimate future reward.

## State, action, and reward design

Whoever builds the environment decides what the agent sees, what it can do, and what earns
points. A badly chosen reward teaches the wrong lesson perfectly.

The environment you interact with defines the MDP (the formal model of the problem, ch. 3). As a
practitioner you sometimes design the reward signal (**reward shaping** — adding extra reward
to guide the agent), which is tricky — reward what you actually want, not a proxy that the
agent can exploit.

Classic pitfall: reward a cleaning robot for *seeing* dirt as clean, and it learns to close its
eyes.

> **Picture it:** paying a student per page written instead of per idea understood. You get
> very long essays. The agent is not lazy or sneaky — it optimizes exactly the number you gave
> it, and nothing else.

> **Watch out:** when a trained agent does something strange, first check the reward. It is
> usually doing what you rewarded, not what you meant. This failure has a name: **reward
> hacking**.

## Recap in plain words

- An agent sees a state, picks an action, and gets a reward and a new state back — over and over.
- The goal is the return: the sum of future rewards, each shrunk by $\gamma$ per step of delay.
- $\gamma$ near 0 cares only about now; $\gamma$ near 1 plans far ahead; 0.99 is the usual choice.
- The Markov property means the current state is enough to decide; frame stacking can restore it.
- `gymnasium` gives every environment the same `reset` / `step` interface and labelled spaces.
- A random agent survives about 26 steps in CartPole; 500 is the cap a learned agent can reach.
- The agent maximizes the reward you wrote, so write the reward you actually want.

## Try it Yourself

```python
import gymnasium as gym
import numpy as np

# Try a right-biased policy and compare to random
env = gym.make("CartPole-v1")

def right_biased_policy(obs):
    # Always push right — terrible, but instructive
    return 1

rewards = []
for i in range(20):
    obs, _ = env.reset(seed=i)
    total, done = 0, False
    while not done:
        action = right_biased_policy(obs)
        obs, r, terminated, truncated, _ = env.step(action)
        total += r
        done = terminated or truncated
    rewards.append(total)

print(f"Right-only policy: mean={np.mean(rewards):.1f}, std={np.std(rewards):.1f}")
```

```output
Right-only policy: mean=9.3, std=0.6
```

Always pushing right lasts only 9.3 steps on average — far worse than random (about 26). The
cart accelerates right, the pole tips left, and nothing ever corrects it. The tiny spread (0.6)
shows the failure is almost the same every time: a fixed policy plus small random starting
positions gives nearly identical episodes.

Try changing `right_biased_policy` to alternate actions (`return t % 2` with a step counter),
or to push left when the cart position `obs[0]` is positive. Which simple rule survives longest?

## Exercise

Implement an **angle-based heuristic**: if the pole angle (index 2 of observation) is positive,
push right; otherwise push left. Run 20 episodes and report mean reward. Does this simple rule
beat random?

> **Hint:** a positive angle means the pole leans right. To catch a falling broom, you move
> your hand under it — in the direction it is falling.

<details>
<summary>Solution</summary>

```python
import gymnasium as gym
import numpy as np

env = gym.make("CartPole-v1")

def angle_policy(obs):
    return 1 if obs[2] > 0 else 0  # push in direction pole is falling

rewards = []
for i in range(20):
    obs, _ = env.reset(seed=i)
    total, done = 0, False
    while not done:
        action = angle_policy(obs)
        obs, r, terminated, truncated, _ = env.step(action)
        total += r
        done = terminated or truncated
    rewards.append(total)

print(f"Angle policy: mean={np.mean(rewards):.1f}, std={np.std(rewards):.1f}")
```

On seeds 0–19 this heuristic averages 40.9 steps (std 7.4) — clearly better than random (about
26) but far below a trained agent (500). The pole angle alone doesn't capture cart position
drift, which eventually causes failure: each correction pushes the cart a little further in
one direction until it leaves the track or the pole swings too fast to save. Adding the angular
velocity `obs[3]` to the rule (push in the direction of `obs[2] + obs[3]`) averages 491.7 on
the same 20 seeds — knowing which way the pole is *moving* matters more than where it is.
</details>
