## The bandit problem

You face a row of slot machines and want to win as much as possible. Every pull teaches you a
little about one machine — but every pull spent learning is a pull not spent on the machine
you already think is best.

A **k-armed bandit** is an RL problem with one state: you pick one of $k$ actions ("arms"),
receive a reward, repeat. No state transitions, no episodes — just the pure explore-exploit
dilemma. To **explore** means trying an action to learn about it; to **exploit** means
choosing the action that currently looks best.

Think of $k$ slot machines. Each has an unknown reward distribution. You want to maximize total
reward over $N$ pulls. Pull the same good arm forever (exploit), and you miss better arms you
haven't tried. Try every arm equally (explore), and you waste pulls on known bad arms.

> **Picture it:** choosing a restaurant in a new city. Going back to the one decent place you
> found is exploiting. Trying a new one is exploring — it might be awful, or it might be your
> new favourite. If you never try anything new you can't find the best place; if you always
> try something new you eat a lot of bad dinners.

The **true action value** is $q_*(a) = \mathbb{E}[R_t | A_t = a]$. You don't know it; you
estimate it from samples. Here $\mathbb{E}$ means **expected value** — the long-run average
you would see if you pulled arm $a$ forever.

## Sample-average estimation

The most natural guess for how good an arm is: the average of the rewards it has paid so far.

After taking action $a$ a total of $N_t(a)$ times with observed rewards $R_1, R_2, \ldots$:

$$
Q_t(a) = \frac{\text{sum of rewards when } a \text{ was taken}}{N_t(a)}
$$

> **In plain words:** your estimate $Q_t(a)$ for arm $a$ at time $t$ is the total reward you
> got from that arm divided by how many times you pulled it — a plain average.

The incremental update — process one reward at a time without storing history:

$$
Q_{n+1}(a) = Q_n(a) + \frac{1}{n}\bigl(R_n - Q_n(a)\bigr)
$$

> **In plain words:** to update an average after the $n$-th reward, take the old average and
> move it a fraction $1/n$ of the way toward the new reward. If the average is 2.0 after 4
> pulls and the 5th pull pays 3.0, the new average is $2.0 + \frac{1}{5}(3.0 - 2.0) = 2.2$ —
> exactly the same as re-averaging all five numbers.

This is the general form: new estimate = old estimate + step size times (target minus old estimate).
The "target" here is the observed reward $R_n$. The difference $R_n - Q_n(a)$ is the **error**
— how surprised you were. You will see this exact shape in almost every algorithm in this
course (ch. 5, ch. 6, ch. 9).

### Non-stationary environments

If the machines change their payouts over time, old rewards are stale news, and you want your
estimate to lean on recent ones.

If the true action values drift over time, you want recent rewards to count more. Replace $1/n$
with a constant step size $\alpha$:

$$
Q_{n+1}(a) = Q_n(a) + \alpha\bigl(R_n - Q_n(a)\bigr)
$$

> **In plain words:** same update, but the step size $\alpha$ (Greek "alpha", for example 0.1)
> never shrinks. Each new reward always moves the estimate 10% of the way toward it, so the
> estimate keeps following the arm as it changes.

This is an **exponential recency-weighted average**: $Q_{n+1} = (1-\alpha)^n Q_1 + \sum_{i=1}^n \alpha(1-\alpha)^{n-i} R_i$.

Reading that formula: the reward from $n-i$ steps ago carries weight $\alpha(1-\alpha)^{n-i}$.
With $\alpha = 0.1$, the latest reward gets weight 0.1, the one before 0.09, then 0.081, and so
on — each older reward counts 10% less. The starting guess $Q_1$ fades away as $(1-\alpha)^n$.

> **Watch out:** a constant $\alpha$ never fully settles down — the estimate keeps jiggling
> around the true value. That is the price of being able to follow change. With $1/n$ the
> estimate converges, but it becomes slower and slower to react.

## ε-Greedy exploration

The easy fix for "never trying anything new": flip a weighted coin before each pull, and once
in a while pick at random.

**Greedy**: always pick $A_t = \arg\max_a Q_t(a)$. You never explore, so you lock onto the first
arm that looks good. ($\arg\max_a$ means "the arm $a$ that makes the value largest".)

**$\varepsilon$-Greedy**: with probability $\varepsilon$, pick a random arm; otherwise pick greedily. The
Greek letter $\varepsilon$ ("epsilon") is the exploration rate, for example 0.1 = explore one
pull in ten.

```python
import numpy as np

class Bandit:
    def __init__(self, k=10, seed=0):
        rng = np.random.default_rng(seed)
        self.q_true = rng.normal(0, 1, k)  # true values
        self.k = k
    def pull(self, action, rng):
        return rng.normal(self.q_true[action], 1.0)

def epsilon_greedy(bandit, eps, steps, seed=1):
    rng = np.random.default_rng(seed)
    Q = np.zeros(bandit.k)
    N = np.zeros(bandit.k, dtype=int)
    rewards = []
    for _ in range(steps):
        if rng.random() < eps:
            a = rng.integers(bandit.k)
        else:
            a = np.argmax(Q)
        r = bandit.pull(a, rng)
        N[a] += 1
        Q[a] += (r - Q[a]) / N[a]
        rewards.append(r)
    return np.array(rewards)

bandit = Bandit(k=10)
r_greedy = epsilon_greedy(bandit, eps=0.0, steps=1000)
r_01    = epsilon_greedy(bandit, eps=0.1, steps=1000)

print(f"ε=0.0 (greedy): mean reward = {r_greedy.mean():.3f}")
print(f"ε=0.1:         mean reward = {r_01.mean():.3f}")
print(f"Best possible:              {bandit.q_true.max():.3f}")
```

```output
ε=0.0 (greedy): mean reward = 0.622
ε=0.1:         mean reward = 1.063
Best possible:              1.304
```

Look at the three numbers. Pure greedy averages 0.622 per pull; $\varepsilon = 0.1$ averages
1.063; the best arm is worth 1.304 per pull. Greedy got stuck on a mediocre arm after a few
lucky early rewards. Exploration recovered most of the gap, and the remaining gap comes from
the 10% of pulls that are still spent at random, plus the early learning phase.

Pure greedy locked onto a suboptimal arm early. $\varepsilon = 0.1$ keeps exploring and converges closer to
the best arm.

> **Watch out:** `np.argmax` breaks ties by picking the lowest index. At the start every $Q$ is
> 0, so greedy always tries arm 0 first. With tiny problems this bias can matter; some code
> breaks ties at random instead.

## Optimistic initial values

A sneaky way to make a greedy agent explore: start out believing every arm is amazing. Each
arm it tries then disappoints it, so it moves on to the next untried one.

Set $Q_0(a) = 5$ for all arms (optimistically high). The greedy agent is forced to explore
because every arm disappoints the first time it's tried. This only works for stationary problems
— optimism fades as estimates converge.

> **Picture it:** a food critic who assumes every restaurant deserves five stars until proven
> otherwise. The first visit lowers each one's score, so the critic keeps going to places
> still sitting at five stars — until every place has been tried.

You will run this idea yourself in Try it Yourself below.

## Upper Confidence Bound (UCB)

Better than exploring at random: explore the arms you know least about. An arm tried only twice
might be great; an arm tried 500 times is a known quantity.

$\varepsilon$-greedy explores randomly. **UCB** explores *intelligently* — prefer arms that are either good
or uncertain:

$$
A_t = \arg\max_a \left[ Q_t(a) + c\sqrt{\frac{\ln t}{N_t(a)}} \right]
$$

> **In plain words:** score each arm as "how good it looks" plus "how unsure I am about it",
> and pick the top score.
> - $Q_t(a)$ — the current average reward of arm $a$.
> - $N_t(a)$ — how many times arm $a$ has been pulled; more pulls means a smaller bonus.
> - $\ln t$ — the natural log of the total number of pulls so far; it grows slowly, so an
>   ignored arm's bonus creeps up until it gets another try.
> - $c$ — how much weight the uncertainty bonus gets.

The bonus term grows with $\ln t$ (so all arms get tried eventually) and shrinks with $N_t(a)$
(so frequently tried arms get less bonus). $c$ controls the confidence level.

> **Picture it:** an error bar around each arm's average. UCB picks the arm whose error bar
> reaches highest — the arm that *could* still be the best, given what you have seen. Pulling
> an arm shrinks its error bar.

```python
def ucb(bandit, c, steps, seed=1):
    rng = np.random.default_rng(seed)
    Q = np.zeros(bandit.k)
    N = np.zeros(bandit.k, dtype=int)
    rewards = []
    for t in range(1, steps + 1):
        # Try each arm once before UCB kicks in
        untried = np.where(N == 0)[0]
        if len(untried):
            a = untried[0]
        else:
            ucb_vals = Q + c * np.sqrt(np.log(t) / N)
            a = np.argmax(ucb_vals)
        r = bandit.pull(a, rng)
        N[a] += 1
        Q[a] += (r - Q[a]) / N[a]
        rewards.append(r)
    return np.array(rewards)

r_ucb = ucb(bandit, c=1.0, steps=1000)
print(f"UCB (c=1): mean reward = {r_ucb.mean():.3f}")
print(f"ε=0.1:     mean reward = {r_01.mean():.3f}")
```

```output
UCB (c=1): mean reward = 1.172
ε=0.1:     mean reward = 1.063
```

With $c = 1$, UCB averages 1.172 per pull against 1.063 for $\varepsilon$-greedy on the same
bandit — and 1.304 is the ceiling. UCB wastes fewer pulls because it stops trying arms once
their averages are well known and clearly bad.

UCB usually outperforms $\varepsilon$-greedy on stationary problems because it directs exploration toward
high-uncertainty arms. A **stationary** problem is one where the arms' payouts never change.

> **Watch out:** the result depends on $c$. On this exact bandit, $c = 2$ explores too much in
> 1000 pulls and scores 1.040 — slightly *worse* than $\varepsilon$-greedy. $c = 0.5$ scores
> 1.217. Treat $c$ as a knob to tune, not a constant.

### Cumulative regret

**Regret** is a scoreboard of lost reward: how much more you would have earned by always pulling
the best arm.

**Regret** measures the cost of not always picking the best arm: $\text{Regret}_T = \sum_{t=1}^T \bigl[q_*(a^*) - q_*(A_t)\bigr]$.
Here $a^*$ is the best arm and $T$ the number of pulls; each term is the value you gave up on
step $t$.

UCB achieves $O(\log T)$ regret — optimal asymptotically. $\varepsilon$-greedy incurs $O(\varepsilon T)$
linear regret because it always wastes $\varepsilon$ fraction of steps on random arms. **$O(\log
T)$** means total regret grows like the logarithm of the number of pulls: 10 times more pulls
adds only a fixed amount of extra regret. **Linear** regret keeps growing at the same rate
forever.

```python
best = bandit.q_true.max()
# simplified illustration: regret measured against observed (noisy) rewards
cumulative_regret_eps = np.cumsum(best - r_01)
cumulative_regret_ucb = np.cumsum(best - r_ucb)

print(f"Total regret ε=0.1: {cumulative_regret_eps[-1]:.1f}")
print(f"Total regret UCB:   {cumulative_regret_ucb[-1]:.1f}")
```

```output
Total regret ε=0.1: 241.2
Total regret UCB:   131.6
```

Over 1000 pulls, $\varepsilon$-greedy gave up about 241 units of reward and UCB about 132 —
roughly half as much. This code uses the observed rewards $R_t$ instead of the true values
$q_*(A_t)$, so it is a noisy stand-in for regret (single lucky pulls can even make a term
negative). It is a simplified illustration of the same idea.

## Thompson sampling

Another way to balance the two: for each arm, keep a whole range of beliefs about how good it
might be, draw one guess from each range, and play the arm whose guess came out highest.

A Bayesian alternative: maintain a $\mathrm{Beta}(\alpha, \beta)$ posterior over each arm's
success probability; at each step, sample from each posterior and pick the arm with the highest
sample. Naturally balances exploration and exploitation through posterior uncertainty. Often
the best-performing algorithm in practice. A **posterior** is your updated belief after seeing
data (Probability & Statistics covers Bayesian updating); the **Beta** distribution is a
standard way to describe a belief about a probability between 0 and 1. Here $\alpha$ and
$\beta$ are its two parameters, not the step size from above: roughly "wins + 1" and
"losses + 1".

> **Picture it:** an arm with few pulls has a wide, blurry belief, so its random draw sometimes
> comes out very high and it gets tried. An arm with many pulls has a sharp belief, and its
> draws stay close to its true value. Uncertainty itself creates exploration.

## Recap in plain words

- A bandit is RL with one state: pick an arm, get a reward, learn, repeat.
- An arm's value is estimated by a running average: old estimate + step size times (reward minus old estimate).
- A shrinking step $1/n$ gives the exact average; a constant $\alpha$ follows payouts that change.
- Greedy gets stuck; $\varepsilon$-greedy explores at random a fixed fraction of the time.
- Optimistic starting values make even a greedy agent try every arm once.
- UCB explores the arms it is least sure about; tune its $c$ (here $c = 1$ beat $c = 2$).
- Regret counts the reward lost by not always pulling the best arm.

## Try it Yourself

```python
import numpy as np

class Bandit:
    def __init__(self, k=10, seed=0):
        rng = np.random.default_rng(seed)
        self.q_true = rng.normal(0, 1, k)
        self.k = k
    def pull(self, action, rng):
        return rng.normal(self.q_true[action], 1.0)

bandit = Bandit(k=10, seed=42)
rng = np.random.default_rng(7)

# Optimistic initial values
Q = np.full(bandit.k, 5.0)  # optimistic start
N = np.zeros(bandit.k, dtype=int)
rewards = []
for _ in range(500):
    a = np.argmax(Q)
    r = bandit.pull(a, rng)
    N[a] += 1
    Q[a] += (r - Q[a]) / N[a]
    rewards.append(r)

print(f"Optimistic greedy: mean={np.mean(rewards):.3f}")
print(f"Arms tried: {np.sum(N > 0)}/{bandit.k}")
```

```output
Optimistic greedy: mean=0.590
Arms tried: 10/10
```

The second line shows optimism worked as promised: all 10 arms got tried. But the mean is only
0.590, while this bandit's best arm (seed 42) is worth 0.94. Why? With the $1/n$ step size, the
first pull of an arm *replaces* the optimistic 5.0 entirely ($n = 1$ means "move 100% of the
way"). So after one pull per arm the agent is a plain greedy agent judging each arm on a single
noisy sample — and it settled on the arm worth 0.75 for 485 of the 500 pulls.

Try changing the update to a constant step `Q[a] += 0.1 * (r - Q[a])`. The optimism then
fades over several pulls, the agent tries arms repeatedly, and it finds the 0.94 arm (at the
cost of a lower average over the first 500 pulls, about 0.36, because it explores longer).

## Exercise

Implement a **non-stationary bandit** where the true action values drift by adding Gaussian
noise at each step. Compare $\varepsilon$-greedy with $1/n$ step size vs constant $\alpha=0.1$ step size
over 10000 steps. Which handles drift better?

> **Hint:** after a few thousand pulls, $1/n$ is a tiny number — new rewards barely move the
> estimate. Measure performance only on the last part of the run, when the arms have drifted
> far from where they started.

<details>
<summary>Solution</summary>

```python
import numpy as np

class NonStationaryBandit:
    def __init__(self, k=10, seed=0):
        rng = np.random.default_rng(seed)
        self.q_true = rng.normal(0, 1, k)
        self.k = k
        self.rng = rng
    def pull(self, action):
        reward = self.rng.normal(self.q_true[action], 1.0)
        self.q_true += self.rng.normal(0, 0.05, self.k)  # drift
        return reward

def run(alpha_type, steps=10000, eps=0.1, seed=1):
    bandit = NonStationaryBandit(seed=0)
    rng = np.random.default_rng(seed)
    Q = np.zeros(bandit.k)
    N = np.zeros(bandit.k, dtype=int)
    rewards = []
    for t in range(1, steps+1):
        a = rng.integers(bandit.k) if rng.random() < eps else np.argmax(Q)
        r = bandit.pull(a)
        N[a] += 1
        alpha = 0.1 if alpha_type == 'const' else 1/N[a]
        Q[a] += alpha * (r - Q[a])
        rewards.append(r)
    return np.mean(rewards[-2500:])  # last 2500 to measure tracking

print(f"1/n step:     {run('sample'):.3f}")
print(f"α=0.1 const: {run('const'):.3f}")
```

On this run the sample average scores 3.156 per pull over the last 2500 steps, the constant step
size 4.949. Constant step size tracks the drifting optimum far better because it keeps weighting
recent data more than old data. Sample average forgets nothing, so old (now wrong) estimates
pollute $Q$. Note the drift has to be big enough to matter: with noise of 0.01 per step over
2000 steps, the best arm never changes and both methods print the same number.
</details>
