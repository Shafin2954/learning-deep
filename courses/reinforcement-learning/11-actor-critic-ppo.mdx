## Online Actor-Critic

REINFORCE waits for the episode to end before updating. Actor-critic methods update at every
step: the **critic** $V_w(s)$ provides a bootstrapped estimate of the advantage, replacing
the Monte Carlo return $G_t$ with a TD signal.

One-step actor-critic:
- **Critic update**: $w \leftarrow w + \alpha_w \delta_t \nabla_w V_w(S_t)$, where $\delta_t = R_{t+1} + \gamma V_w(S_{t+1}) - V_w(S_t)$.
- **Actor update**: $\theta \leftarrow \theta + \alpha_\theta \delta_t \nabla_\theta \log \pi_\theta(A_t|S_t)$.

The TD error $\delta_t$ is an unbiased estimate of the advantage $A_t = Q(s,a) - V(s)$
under the current policy. Using it in the actor update reduces variance vs MC returns without
introducing bias (relative to the true gradient, which uses $Q$).

## A2C: Synchronous Advantage Actor-Critic

A2C runs multiple environments in parallel (synchronous workers), averages their gradients,
then updates once. This reduces variance further: the gradient estimate is based on $N$
independent trajectories instead of 1.

The advantage estimator at step $t$ (for a rollout of length $T$):

$$
\hat{A}_t = R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{T-t} V_w(S_{T}) - V_w(S_t)
$$

No `gymnasium` is required: the block below re-implements CartPole's physics in numpy behind the
same `reset`/`step` interface, so the training loops are what you would write for `gym.make("CartPole-v1")`.

```python
import torch
import torch.nn as nn
import torch.optim as optim
import numpy as np
torch.set_num_threads(1)
torch.manual_seed(0)

class CartPole:
    """CartPole-v1 dynamics (Euler integration, tau=0.02) in plain numpy, gymnasium-style API."""
    obs_dim, n_actions = 4, 2
    def __init__(self, seed=0):
        self.rng = np.random.default_rng(seed)
    def reset(self, seed=None):
        if seed is not None:
            self.rng = np.random.default_rng(seed)
        self.s = self.rng.uniform(-0.05, 0.05, 4)
        self.t = 0
        return self.s.copy(), {}
    def sample_action(self):
        return int(self.rng.integers(self.n_actions))
    def step(self, a):
        x, xd, th, thd = self.s
        f = 10.0 if a == 1 else -10.0
        c, sn = np.cos(th), np.sin(th)
        tmp = (f + 0.05 * thd**2 * sn) / 1.1
        thacc = (9.8 * sn - c * tmp) / (0.5 * (4 / 3 - 0.1 * c**2 / 1.1))
        xacc = tmp - 0.05 * thacc * c / 1.1
        self.s = np.array([x + 0.02 * xd, xd + 0.02 * xacc, th + 0.02 * thd, thd + 0.02 * thacc])
        self.t += 1
        terminated = bool(abs(self.s[0]) > 2.4 or abs(self.s[2]) > 0.2095)
        return self.s.copy(), 1.0, terminated, self.t >= 500, {}

class ActorCriticNet(nn.Module):
    def __init__(self, obs_dim, n_actions):
        super().__init__()
        self.shared = nn.Sequential(nn.Linear(obs_dim, 128), nn.ReLU())
        self.actor  = nn.Linear(128, n_actions)
        self.critic = nn.Linear(128, 1)

    def forward(self, x):
        h = self.shared(x)
        dist  = torch.distributions.Categorical(logits=self.actor(h))
        value = self.critic(h).squeeze(-1)
        return dist, value

# Single-env actor-critic (simplified A2C): update every 32 steps, bootstrapping from V(s)
env = CartPole(seed=0)
net = ActorCriticNet(4, 2)
optimizer = optim.Adam(net.parameters(), lr=5e-4)
gamma, n_steps = 0.99, 32
ep_rewards, ep_r = [], 0.0
obs, _ = env.reset()

for update in range(940):           # about 30,000 environment steps
    log_probs, values, entropies, rewards, ended = [], [], [], [], []
    for _ in range(n_steps):
        dist, value = net(torch.FloatTensor(obs))
        action = dist.sample()
        obs, r, terminated, truncated, _ = env.step(action.item())
        log_probs.append(dist.log_prob(action))
        values.append(value)
        entropies.append(dist.entropy())
        rewards.append(r)
        ended.append(float(terminated or truncated))
        ep_r += r
        if terminated or truncated:
            ep_rewards.append(ep_r)
            ep_r = 0.0
            obs, _ = env.reset()

    # Bootstrap from the state after the rollout
    with torch.no_grad():
        G = net(torch.FloatTensor(obs))[1].item() * (1 - ended[-1])
    returns = []
    for r, d in zip(reversed(rewards), reversed(ended)):
        G = r + gamma * G * (1 - d)
        returns.insert(0, G)

    returns     = torch.FloatTensor(returns)
    values_t    = torch.stack(values)
    log_probs_t = torch.stack(log_probs)
    advantages  = returns - values_t.detach()

    actor_loss  = -(log_probs_t * advantages).mean()
    critic_loss = nn.MSELoss()(values_t, returns)
    entropy     = torch.stack(entropies).mean()
    loss = actor_loss + 0.5 * critic_loss - 0.01 * entropy

    optimizer.zero_grad()
    loss.backward()
    nn.utils.clip_grad_norm_(net.parameters(), 0.5)
    optimizer.step()

    if update % 200 == 0 or update == 939:
        print(f"Update {update:4d} ({(update + 1) * n_steps:5d} steps): "
              f"episodes={len(ep_rewards):3d}  avg(last 20 eps)={np.mean(ep_rewards[-20:]) if ep_rewards else 0:.0f}")
```

With one environment and 32-step rollouts the 20-episode average climbs from about 20 to about 120 over

gradients, which is exactly why A2C uses many parallel environments. Expect the curve to wobble
from run to run.

## PPO: Proximal Policy Optimisation

A2C takes a gradient step in the direction that increases returns — but large steps can
collapse the policy. PPO constrains the policy update by clipping the probability ratio.

Define the ratio $r_t(\theta) = \pi_\theta(a_t|s_t) / \pi_{\theta_{\text{old}}}(a_t|s_t)$.
The clipped surrogate objective:

$$
L^{CLIP}(\theta) = \mathbb{E}_t\!\left[\min\!\left(r_t(\theta)\hat{A}_t,\; \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right)\right]
$$

If the advantage is positive (action was better than average): clip prevents $r_t$ from
exceeding $1+\epsilon$, capping the benefit of taking the same good action again.
If the advantage is negative: clip prevents $r_t$ from going below $1-\epsilon$, capping
the cost of taking the bad action.

The resulting updates are bounded — PPO can't take a step so large that it breaks the policy.

### Generalised Advantage Estimation (GAE)

GAE interpolates between TD(0) and MC advantage estimates using $\lambda$:

$$
\hat{A}_t^{GAE} = \sum_{l=0}^{T-t} (\gamma\lambda)^l \delta_{t+l}, \quad \delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

At $\lambda=0$: one-step TD advantage (low variance, high bias). At $\lambda=1$: MC advantage
(low bias, high variance). In practice $\lambda \in [0.9, 0.97]$ works well.

```python
class PPONet(nn.Module):
    def __init__(self, obs_dim, n_actions):
        super().__init__()
        self.shared = nn.Sequential(nn.Linear(obs_dim,256),nn.Tanh(),nn.Linear(256,256),nn.Tanh())
        self.actor  = nn.Linear(256, n_actions)
        self.critic = nn.Linear(256, 1)
    def forward(self, x):
        h = self.shared(x)
        return torch.distributions.Categorical(logits=self.actor(h)), self.critic(h).squeeze(-1)

env = CartPole(seed=1)
net = PPONet(4, 2)
optimizer = optim.Adam(net.parameters(), lr=1e-3)

# PPO hyperparameters
gamma, lam = 0.99, 0.95
clip_eps = 0.2
n_epochs = 8
n_steps  = 256  # rollout length

ep_rewards = []
obs, _ = env.reset()   # the environment persists across rollouts
ep_r = 0.0

for iteration in range(100):
    # Collect rollout
    obs_buf, act_buf, logp_buf, val_buf, rew_buf, done_buf = [], [], [], [], [], []
    for _ in range(n_steps):
        with torch.no_grad():
            dist, val = net(torch.FloatTensor(obs))
        action = dist.sample()
        nobs, r, terminated, truncated, _ = env.step(action.item())
        done = terminated or truncated
        obs_buf.append(obs)
        act_buf.append(action.item())
        logp_buf.append(dist.log_prob(action).item())
        val_buf.append(val.item())
        rew_buf.append(r)
        done_buf.append(float(done))
        ep_r += r
        obs = nobs
        if done:
            ep_rewards.append(ep_r)
            ep_r = 0.0
            obs, _ = env.reset()

    # GAE computation
    with torch.no_grad():
        _, last_val = net(torch.FloatTensor(obs))
    advantages = np.zeros(n_steps)
    gae = 0.0
    vals_ext = val_buf + [last_val.item()]
    for t in reversed(range(n_steps)):
        delta = rew_buf[t] + gamma * vals_ext[t+1] * (1-done_buf[t]) - vals_ext[t]
        gae = delta + gamma * lam * (1-done_buf[t]) * gae
        advantages[t] = gae
    returns = advantages + np.array(val_buf)

    # Tensors
    obs_t  = torch.FloatTensor(np.array(obs_buf))
    act_t  = torch.LongTensor(act_buf)
    logp_t = torch.FloatTensor(logp_buf)
    adv_t  = torch.FloatTensor(advantages)
    ret_t  = torch.FloatTensor(returns)
    adv_t  = (adv_t - adv_t.mean()) / (adv_t.std() + 1e-8)

    # PPO update
    for _ in range(n_epochs):
        dist, values = net(obs_t)
        new_logp = dist.log_prob(act_t)
        ratio = (new_logp - logp_t).exp()
        surr1 = ratio * adv_t
        surr2 = ratio.clamp(1-clip_eps, 1+clip_eps) * adv_t
        actor_loss  = -torch.min(surr1, surr2).mean()
        critic_loss = nn.MSELoss()(values, ret_t)
        entropy     = dist.entropy().mean()
        loss = actor_loss + 0.5 * critic_loss - 0.01 * entropy
        optimizer.zero_grad()
        loss.backward()
        nn.utils.clip_grad_norm_(net.parameters(), 0.5)
        optimizer.step()

    if iteration % 20 == 0 and ep_rewards:
        print(f"Iter {iteration:3d}: avg reward (last 10 eps) = {np.mean(ep_rewards[-10:]):.0f}")

```

```output
Iter   0: avg reward (last 10 eps) = 20
Iter  20: avg reward (last 10 eps) = 86
Iter  40: avg reward (last 10 eps) = 108
Iter  60: avg reward (last 10 eps) = 102
Iter  80: avg reward (last 10 eps) = 105
```

In this budget (100 iterations of 256 steps, about 25,000 environment steps) PPO's 10-episode average
rises quickly from about 20 to above 100 within 20 to 40 iterations, then plateaus near 100 rather than
reaching the 500 cap; a bigger budget, a larger rollout, or tuned hyperparameters would be needed for
that. The point to take away is the mechanism: the clipped ratio lets you take 8 gradient epochs on
the same rollout without the policy being pushed arbitrarily far from the one that collected the data.

## Try it Yourself

```python
# PPO as a function, so we can vary GAE lambda and the entropy coefficient.
# (Reuses CartPole and PPONet from earlier on this page.)
def ppo(lam=0.95, ent_coef=lambda it, n: 0.01, iters=40, seed=0, n_steps=256, gamma=0.99, clip_eps=0.2):
    torch.manual_seed(seed)
    env = CartPole(seed=seed)
    net = PPONet(4, 2)
    opt = optim.Adam(net.parameters(), lr=1e-3)
    ep_rewards, curve = [], []
    obs, _ = env.reset()
    ep_r = 0.0
    for it in range(iters):
        O, A, LP, V, R, D = [], [], [], [], [], []
        for _ in range(n_steps):
            with torch.no_grad():
                dist, val = net(torch.FloatTensor(obs))
            a = dist.sample()
            nobs, r, term, trunc, _ = env.step(a.item())
            done = term or trunc
            O.append(obs); A.append(a.item()); LP.append(dist.log_prob(a).item())
            V.append(val.item()); R.append(r); D.append(float(done))
            ep_r += r; obs = nobs
            if done:
                ep_rewards.append(ep_r); ep_r = 0.0; obs, _ = env.reset()
        with torch.no_grad():
            last_v = net(torch.FloatTensor(obs))[1].item()
        adv, gae, vext = np.zeros(n_steps), 0.0, V + [last_v]
        for t in reversed(range(n_steps)):
            delta = R[t] + gamma * vext[t + 1] * (1 - D[t]) - vext[t]
            gae = delta + gamma * lam * (1 - D[t]) * gae
            adv[t] = gae
        ret = torch.FloatTensor(adv + np.array(V))
        adv = torch.FloatTensor(adv)
        adv = (adv - adv.mean()) / (adv.std() + 1e-8)
        O, A, LP = torch.FloatTensor(np.array(O)), torch.LongTensor(A), torch.FloatTensor(LP)
        for _ in range(8):
            dist, vals = net(O)
            ratio = (dist.log_prob(A) - LP).exp()
            actor = -torch.min(ratio * adv, ratio.clamp(1 - clip_eps, 1 + clip_eps) * adv).mean()
            loss = actor + 0.5 * nn.MSELoss()(vals, ret) - ent_coef(it, iters) * dist.entropy().mean()
            opt.zero_grad(); loss.backward()
            nn.utils.clip_grad_norm_(net.parameters(), 0.5); opt.step()
        curve.append(np.mean(ep_rewards[-10:]) if ep_rewards else 0.0)
    return curve

for lam in (0.0, 0.95, 1.0):
    curve = ppo(lam=lam)
    print(f"GAE lambda={lam:4.2f}: avg reward (last 10 eps) at iter 20 = {curve[20]:5.1f}, at iter 39 = {curve[-1]:5.1f}")
```

```output
GAE lambda=0.00: avg reward (last 10 eps) at iter 20 =  59.0, at iter 39 = 158.7
GAE lambda=0.95: avg reward (last 10 eps) at iter 20 =  68.1, at iter 39 =  84.4
GAE lambda=1.00: avg reward (last 10 eps) at iter 20 =  26.5, at iter 39 =  62.0
```

Here $\lambda=0$ (one-step TD advantage) happened to learn fastest on this seed, ahead of
$\lambda=0.95$ and $1$, which is the opposite of the usual rule of thumb that intermediate $\lambda$ wins.
That is the nature of a single seed over 40 iterations: low-variance, biased advantages pay off early
when the critic is learning quickly. Try other values of `lam`, more `iters`, or more seeds, and look
for large, consistent gaps rather than small ones.

## Exercise

Add an **entropy schedule** to PPO: start with entropy coefficient 0.05 and decay to 0.001
over training. This encourages exploration early and exploitation later. Using the `ppo` function
above, compare the first iteration at which the 10-episode average reaches 100 against a fixed
entropy coefficient of 0.01, over 2 seeds.

```python
def first_iter_reaching(curve, target=100):
    hits = [i for i, v in enumerate(curve) if v >= target]
    return hits[0] if hits else None

schedule = lambda it, n: max(0.001, 0.05 * (1 - it / n))
fixed    = lambda it, n: 0.01

for name, fn in [("fixed 0.01", fixed), ("schedule 0.05 -> 0.001", schedule)]:
    firsts = [first_iter_reaching(ppo(ent_coef=fn, iters=40, seed=seed)) for seed in range(2)]
    print(f"{name:24s}: first iteration with avg >= 100 per seed = {firsts}")
```

```output
fixed 0.01              : first iteration with avg >= 100 per seed = [None, None]
schedule 0.05 -> 0.001  : first iteration with avg >= 100 per seed = [None, 36]
```

Read the result with care: two seeds is too few to separate the two settings unless the gap is
large. The idea is that a large early entropy bonus keeps the policy stochastic while the critic is
still poor, and the decay lets it sharpen later; whether that wins depends on the task and seed.
