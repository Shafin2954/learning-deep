## What pandas adds to NumPy

pandas is NumPy with name tags. Every row and every column gets a label, so you can say
"the score for alice" instead of "the number in slot 2", and pandas keeps the labels
attached to the numbers wherever they go.

NumPy's ndarray is great for homogeneous numerical arrays. Real data is heterogeneous
(mixed types): one column of integers, one of strings, one of dates, with named columns and
meaningful row labels. pandas wraps NumPy arrays in a layer of **labeled axes** called the
**Index**.

> **Picture it:** a NumPy array is a grid of unlabeled boxes. A pandas DataFrame is a
> spreadsheet: the same grid, plus a header row naming each column and a first column
> naming each row. Sort or filter the sheet and the names travel with their rows.

Three objects do essentially everything in pandas:

- **Index** — an immutable array of labels for rows or columns.
- **Series** — a 1-D labeled array (`index` + `values`).
- **DataFrame** — a 2-D table (`row index` + `column index` + one Series per column).

## Series — the labeled 1-D array

A **Series** is one column of a spreadsheet: a list of values, each with a label next to
it. If you don't give labels, pandas numbers the rows 0, 1, 2, …

```python
import pandas as pd

# Integer values with a default RangeIndex
s = pd.Series([10, 20, 30], name='score')
print(s)
```

```output
0    10
1    20
2    30
Name: score, dtype: int64
```

The left column (`0 1 2`) is the index — here the default **RangeIndex**, which is just row
numbers. The right column is the data. `Name: score` is the Series' name, and `dtype: int64`
is the NumPy dtype of the values underneath.

```python
import pandas as pd

# Custom index — can be any hashable type
s = pd.Series([10, 20, 30], index=['alice', 'bob', 'carol'], name='score')
print(s)
print("dtype  :", s.dtype)
print("values :", s.values)    # plain NumPy array
print("index  :", s.index.tolist())
```

```output
alice    10
bob      20
carol    30
Name: score, dtype: int64
dtype  : int64
values : [10 20 30]
index  : ['alice', 'bob', 'carol']
```

Same values, but now each one is labelled with a person. `s.values` shows the plain NumPy
array hiding inside, and `s.index` shows the labels, stored separately.

You can access values by label (`s['bob']`) or by integer position (`s.iloc[1]`). The
former uses the index; the latter ignores it. That distinction becomes critical in ch. 5.

### Index alignment — the killer feature

**Alignment** means pandas matches values up by their labels before doing any arithmetic,
the way you'd match two receipts line by line by item name, not by which line it's on.

When you add two Series, pandas aligns on the **index**, not on position.

```python
import pandas as pd

a = pd.Series([1, 2, 3], index=['x', 'y', 'z'])
b = pd.Series([10, 20, 30], index=['y', 'z', 'w'])

print(a + b)
```

```output
w     NaN
x     NaN
y    12.0
z    23.0
dtype: float64
```

Labels that exist in both: summed. Labels that appear in only one: `NaN`. This is what
makes pandas safe for misaligned data — you can't accidentally add a value for 'alice' to
a value for 'bob'. The dtype widened to float64 to accommodate NaN (NumPy int64 has no NaN).
**NaN** ("not a number") is the floating-point marker pandas uses for "missing".

Check it in the output: `y` is `2 + 10 = 12` and `z` is `3 + 20 = 23` — the numbers that
share a label, even though they sat at different positions. `x` only exists in `a` and `w`
only in `b`, so each gets `NaN`. Notice the result is also sorted by label.

> **Watch out:** if you meant "add position by position", alignment will quietly give you
> NaNs instead. Use `a.values + b.values` (or reset both indexes) when positions, not
> labels, are what match.

## DataFrame — the labeled 2-D table

A **DataFrame** is the whole spreadsheet: several Series glued side by side, all sharing
the same row labels.

```python
import pandas as pd

df = pd.DataFrame({
    'name':  ['alice', 'bob', 'carol'],
    'score': [88, 75, 92],
    'grade': ['B', 'C', 'A'],
})
print(df)
print()
print("dtypes:\n", df.dtypes)
```

```output
    name  score grade
0  alice     88     B
1    bob     75     C
2  carol     92     A

dtypes:
 name       str
score    int64
grade      str
dtype: object
```

Each column has its own dtype. `score` is `int64`; `name` and `grade` hold text and show
`str` — pandas 3 (what this kernel runs) gives text columns a dedicated string dtype. Older
pandas versions printed `object` here, a catch-all for "arbitrary Python objects".

Each column is a **Series** sharing the same row index. `df['score']` returns the Series for
that column. `df[['score', 'grade']]` returns a new DataFrame with two columns.

### Accessing columns and the column index

```python
import pandas as pd

df = pd.DataFrame({'a': [1, 2, 3], 'b': [4, 5, 6]})

print(df.columns.tolist())         # ['a', 'b']
print(df['a'])                     # Series
print(type(df[['a']]))             # DataFrame (double brackets)
```

```output
['a', 'b']
0    1
1    2
2    3
Name: a, dtype: int64
<class 'pandas.DataFrame'>
```

`df['a']` (single string) → Series. `df[['a']]` (list) → DataFrame. This inconsistency is
one of the oldest pandas gotchas; keep it in mind.

> **In plain words:** one pair of brackets with a name asks for *the column itself*. Two
> pairs of brackets ask for *a table made of these columns* — which happens to contain one
> column.

## The Index object

The Index is the list of labels — the row names (or the column names). pandas guards it
carefully because every alignment and every look-up depends on it.

An Index is **immutable** (you can't assign to a single label — `df.index[0] = 'q'` raises
an error) and is backed by a **hash table** — the same trick a Python `dict` uses — so a
label look-up is O(1): constant time, however many rows there are. (The Index object itself
is not hashable; it's the labels inside that get hashed.) It's not just column names — it's
the row identifier that makes alignment work.

```python
import pandas as pd

df = pd.DataFrame({'x': [10, 20, 30]}, index=['a', 'b', 'c'])
print("index  :", df.index.tolist())
print("columns:", df.columns.tolist())

# Reset index — moves the index into a column
df2 = df.reset_index()
print(df2)

# Set a column as the index
df3 = df2.set_index('index')
print(df3)
```

```output
index  : ['a', 'b', 'c']
columns: ['x']
  index   x
0     a  10
1     b  20
2     c  30
        x
index
a      10
b      20
c      30
```

Follow the labels: `reset_index()` turned the row labels `a, b, c` into an ordinary column
named `index` and gave the rows fresh numbers `0, 1, 2`. `set_index('index')` did the reverse
— the column became the row labels again.

`reset_index()` and `set_index()` are the primary tools for moving data between the index
and the columns. Keeping the right things in the index — especially after a groupby — is a
common source of confusion in ch. 6.

> **Picture it:** the index is the spine of a binder with name tabs. `set_index` writes a
> column's values onto the tabs; `reset_index` peels the tabs off and files them as a
> regular column.

## Memory layout: pandas holds NumPy arrays

Underneath the labels, a DataFrame is a few plain NumPy arrays. pandas stacks columns of the
same type together into one array, so similar columns share a single slab of memory.

Internally, pandas groups columns of the same dtype into **blocks** — each block is a single
NumPy 2-D array. This is why a DataFrame with 5 float64 columns costs one allocation, not
five. You can inspect it with `df._data` (private) or `df.dtypes`. (In pandas 2 and 3 the
private attribute is `df._mgr`; for this example `df._mgr.blocks` holds 2 blocks — one
float64 block for `a` and `b`, one int32 block for `c`.)

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    'a': np.ones(3, dtype=np.float64),
    'b': np.zeros(3, dtype=np.float64),
    'c': np.full(3, 2, dtype=np.int32),
})

print("Memory (deep):", df.memory_usage(deep=True).sum(), "bytes")
# float64 block: 3*8*2 = 48; int32 block: 3*4 = 12; index: 24 → ~84 + overhead
```

```output
Memory (deep): 192 bytes
```

Break the 192 bytes down with `df.memory_usage(deep=True)`: `a` and `b` are 3 × 8 = 24
bytes each, `c` is 3 × 4 = 12 bytes, and the remaining 132 bytes are the index's own
bookkeeping. The data itself is only 60 bytes; small frames are mostly overhead.

Understanding the block layout matters in ch. 11 (performance): converting an `object`
column to `category` or int reduces memory by 10–100×, and also un-fragments the blocks.
A **category** column stores each distinct string once and keeps only a small integer code
per row.

## Recap in plain words

- pandas = NumPy arrays + labels (the Index) on rows and columns.
- A Series is one labelled column; a DataFrame is labelled columns sharing one row index.
- Arithmetic aligns on labels, not positions; labels missing on one side become `NaN`.
- `df['a']` gives a Series, `df[['a']]` gives a DataFrame.
- The Index is immutable and hash-backed; `set_index` / `reset_index` move data between
  index and columns.
- Same-dtype columns share one NumPy block; small frames are mostly overhead.

## Try it Yourself

```python
import pandas as pd

# 1) Alignment in action: join two misaligned Series
gdp = pd.Series({'US': 25.5, 'EU': 17.1, 'CN': 17.9})    # 2023 GDP ~trillions
pop = pd.Series({'US': 335, 'CN': 1412, 'IN': 1417})      # ~millions

gdp_per_capita = (gdp * 1e12) / (pop * 1e6)
print("GDP per capita (rough):")
print(gdp_per_capita.dropna().apply(lambda x: f"${x:,.0f}"))

# 2) DataFrame from a dict of lists — verify column dtypes
import numpy as np
df = pd.DataFrame({
    'age':  [25, 32, 28],
    'wage': [55000.0, 72000.0, 61000.0],
    'city': ['Dhaka', 'Dhaka', 'Chittagong'],
})
print("\ndtypes:\n", df.dtypes)
print("memory:", df.memory_usage(deep=True).sum(), "bytes")
```

```output
GDP per capita (rough):
CN    $12,677
US    $76,119
dtype: str

dtypes:
 age       int64
wage    float64
city        str
dtype: object
memory: 224 bytes
```

Alignment did the hard work: only `US` and `CN` appear in both `gdp` and `pop`, so `EU`
(no population) and `IN` (no GDP) came out `NaN` and `dropna()` removed them. Try adding
`'IN': 3.7` to `gdp` and re-run — India appears with no other change to the code.

## Exercise

Create a DataFrame with columns `product`, `units_sold`, `price` (at least 4 rows). Then:

1. Add a `revenue` column (units_sold × price) without a loop.
2. Set `product` as the index.
3. Reset it back and verify the index is a `RangeIndex` again.

> **Hint:** multiplying two columns is one line, the same as multiplying two arrays.
> `type(df.index).__name__` tells you which kind of index you have.

<details>
<summary>Solution</summary>

```python
import pandas as pd

df = pd.DataFrame({
    'product':    ['alpha', 'beta', 'gamma', 'delta'],
    'units_sold': [120, 45, 200, 30],
    'price':      [9.99, 24.99, 4.99, 49.99],
})

# 1) Revenue — vectorized multiplication of two Series (aligned on RangeIndex)
df['revenue'] = df['units_sold'] * df['price']
print(df)

# 2) Set index
df = df.set_index('product')
print("\nindex type:", type(df.index).__name__)

# 3) Reset
df = df.reset_index()
print("after reset:", type(df.index).__name__)
```

The multiplication aligns on the shared RangeIndex — same position, same label — so it
behaves identically to NumPy element-wise multiply here. When the indices differ, pandas
aligns first (ch. 5 and 7 cover this in detail).
</details>
