## The project

You will build, with your own hands, the two workhorses of this course — a boosted-tree
predictor and a set of clustering tools — and prove they work by comparing them against the
professional libraries. If you can write them from the maths alone, you understand them.

You will implement two complete ML systems from scratch: a gradient boosting regressor (with a from-scratch decision tree base) that matches LightGBM within tolerance on a tabular dataset, and a suite of unsupervised algorithms (k-Means, GMM via EM, PCA) applied to a real clustering task with a justified choice of k. The goal is to own every algorithm end-to-end — not just call sklearn.

> **Picture it:** a cookery exam where you must bake the cake from flour, eggs, and sugar, then
> set it next to a bakery's cake for a blind taste test. Buying a cake mix (calling
> `GradientBoostingRegressor`) is not allowed; the bakery cake (LightGBM) is there only as the
> standard to match.

In plain words, there are two halves. The **supervised half**: a regression tree (ch. 10), then
gradient boosting built from many of those trees (ch. 12), scored against LightGBM (ch. 13).
The **unsupervised half**: k-Means, a Gaussian mixture fitted by EM, and PCA (ch. 14–16),
applied to one real dataset where you must defend how many clusters you chose.

## Hard constraints (no vibe coding)

The rules exist so that every line that matters is one you understood well enough to write.
Libraries are allowed for the boring parts — loading data, splitting it, scoring it — and
forbidden for the parts this course taught.

- **No AI assistance** during implementation. Design decisions and debugging are yours.
- **No sklearn estimators** for the core algorithms: no `DecisionTreeRegressor`, no `GradientBoostingRegressor`, no `KMeans`, no `GaussianMixture`, no `PCA` (from sklearn) for the core logic. You may use sklearn for data loading, metrics, and train/test splitting.
- **No XGBoost / LightGBM / CatBoost** for the gradient boosting implementation (you will use LightGBM only as the reference to compare against).
- **No copypaste** of reference implementations. Read the math, implement from the description.
- You may use NumPy, SciPy (for linear algebra helpers), and matplotlib.

> **Watch out:** "SciPy for linear algebra helpers" means things like `scipy.linalg.eigh`
> for eigenvectors. It does not cover `scipy.cluster.vq.kmeans` or similar ready-made
> algorithms — those count as the core logic.

## What it must contain (and the chapter each tests)

Each item below is one component. The short note after each list says what it means in
practice and where people usually go wrong.

- **Decision tree regressor from scratch** (ch. 10): recursive binary splits on MSE impurity; `max_depth` and `min_samples_split` stopping criteria; predict via leaf mean.
- **Gradient boosting from scratch** (ch. 12): fit residuals iteratively; shrinkage (learning rate); subsample rows per tree; early stopping on a validation set; loss = MSE.
- **LightGBM reference** (ch. 13): train on the same split; compare RMSE on the held-out test set. Your implementation must be within 5% of LightGBM's RMSE.

For the supervised part: your tree is ch. 10's stump extended by recursion, with
`min_samples_split` refusing to split nodes that are too small. Your booster is ch. 12's
residual loop plus three additions — a learning rate, a random subset of rows per tree, and a
validation set that decides when to stop. LightGBM must see exactly the same train, validation,
and test rows.

> **Watch out:** the naive "try every unique value as a threshold" search from ch. 10 is
> $O(n^2)$ per feature per node and will be painfully slow on a real dataset. Sort each feature
> once and sweep with running sums, or bin features into a few hundred buckets as LightGBM does
> (ch. 13).

- **k-Means from scratch** (ch. 14): Lloyd's algorithm with random restarts; track inertia per iteration; elbow-method plot to justify k.
- **GMM via EM from scratch** (ch. 14): E-step computes responsibilities $r_{ic} = \pi_c \mathcal{N}(x_i|\mu_c, \Sigma_c) / \sum_k$; M-step updates $\pi$, $\mu$, $\Sigma$; track log-likelihood; BIC to select k.
- **PCA from scratch** (ch. 16): center the data; eigen-decompose the covariance matrix; project; compute explained variance ratio. Do not use `sklearn.decomposition.PCA`.
- **Clustering task** (ch. 14–16): load a real or semi-real dataset; run k-Means, GMM, and PCA (for visualization); compare ARI or silhouette scores; write a short analysis of which algorithm wins and why.

For the unsupervised part: the **responsibility** $r_{ic}$ is the probability that point $i$
belongs to cluster $c$, and the denominator (written $\sum_k$ for short) is the same expression
summed over all clusters so each row of responsibilities adds to 1. The **log-likelihood** is
how probable the whole dataset is under the current mixture; EM must never make it go down.
**BIC** trades that likelihood against the number of parameters, so it can pick $k$ (ch. 14).

> **Watch out:** computing $\mathcal{N}(x_i|\mu_c, \Sigma_c)$ directly underflows to zero in
> more than a handful of dimensions. Work with log-densities and the log-sum-exp trick, and add a
> tiny value to the diagonal of each $\Sigma$ so it stays invertible.

> **Watch out:** a **silhouette score** compares each point's distance to its own cluster with
> its distance to the nearest other cluster (from -1 to 1, higher is better). ARI needs true
> labels; silhouette does not. Use ARI only if your dataset has a ground truth.

## Acceptance criteria

These are the pass marks. Each one is a number or a check you can run, so "done" is not a
matter of opinion.

- **Gradient boosting vs LightGBM**: your test RMSE $\le 1.05 \times$ LightGBM test RMSE on the same split. (ch. 1–13)
- **k-Means**: inertia decreases monotonically; chosen k has a visible elbow; silhouette score > 0.3 on the chosen k. (ch. 14)
- **GMM EM**: log-likelihood increases monotonically per iteration; BIC selects a k consistent with the data; responsibilities sum to 1 per sample. (ch. 14)
- **PCA from scratch**: explained variance ratios sum to 1; first two PCs match sklearn's output within floating-point tolerance (sign may flip). (ch. 16)
- **Gradient boosting convergence**: plot shows training loss decreasing; early stopping triggers within 20 rounds on the validation set.
- **Written analysis** (one paragraph each): (1) what hurt gradient boosting accuracy most — depth, learning rate, or subsampling? (2) which clustering algorithm gave the best ARI, and what does the structure of the data explain about that?

In plain words:

- **Within 5% of LightGBM:** if LightGBM's test RMSE is 40.0, yours must be 42.0 or lower. Give both models a fair, tuned budget (ch. 13's warning about untuned comparisons applies).
- **Monotone inertia and log-likelihood:** record the value after every iteration and assert that each one is no worse than the last. A single increase in inertia, or decrease in log-likelihood, means a bug.
- **Variance ratios sum to 1:** this holds when you keep *all* components; with fewer, they sum to the share you kept.
- **"Sign may flip":** an eigenvector and its negative are equally valid, so compare `abs()` of the components, or flip yours to match sklearn's sign.
- **Early stopping within 20 rounds:** read this as a patience of 20 — training stops once 20 rounds in a row fail to improve the validation loss. It must actually trigger before your round limit; ch. 13 showed what it looks like when it doesn't.

> **Watch out:** never tune anything on the test set. Choose depth, learning rate, and $k$ with
> the validation set or cross-validation, and use the test set once, at the end.
