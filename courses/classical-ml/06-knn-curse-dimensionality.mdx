## The k-NN algorithm

To label something new, look at the most similar things you have already seen and copy
their answer. That is the whole of **k-nearest neighbors (k-NN)**: no training formula, just
a memory of the training set and a way to measure "similar".

k-Nearest Neighbors makes predictions without fitting any parameters. For a query point $x$:

1. Compute distances to all training points (usually Euclidean).
2. Find the $k$ closest training points.
3. **Classification:** return the majority class. **Regression:** return the mean label.

**Euclidean** distance is the ordinary straight-line distance: square the difference in each
feature, add them, take the square root. A **query point** is the new example you want a
prediction for.

> **Picture it:** guessing a stranger's favourite football team by asking the $k$ people who
> live closest to them. With $k=1$ you trust one neighbour, who might be a visitor. With
> $k=50$ you poll half the town and lose what is special about that street.

The dataset is **two moons** — two interlocking crescents of points, a shape no straight
line can separate.

```python
import numpy as np
from sklearn.datasets import make_moons
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import train_test_split

X, y = make_moons(n_samples=400, noise=0.25, random_state=0)
X = StandardScaler().fit_transform(X)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

for k in [1, 5, 20, 50]:
    acc = KNeighborsClassifier(n_neighbors=k).fit(X_tr, y_tr).score(X_te, y_te)
    print(f"k={k:2}: test acc = {acc:.3f}")
```

```output
k= 1: test acc = 0.950
k= 5: test acc = 0.950
k=20: test acc = 0.950
k=50: test acc = 0.938
```

On this 80-point test set, $k = 1$, 5, and 20 all score 0.950, and only $k = 50$ slips to
0.938 — one extra mistake. A test set this small can't separate the first three.

$k=1$ overfits (memorises training noise), $k=50$ is too smooth (high bias). $k=5$ is best here.

The output above does not actually show $k=5$ winning — it ties with 1 and 20. The general
pattern in that sentence is right: small $k$ means high variance (each prediction hangs on
one or two points) and large $k$ means high bias (the boundary is smoothed into a blob), the
same trade-off as ch. 1. To pick $k$ fairly you need more evaluations than one small test
split, which is what cross-validation gives you.

> **Watch out:** k-NN measures distance on raw feature values, so a feature measured in
> thousands drowns out one measured in fractions. Always scale features first, as the
> `StandardScaler` line does.

### Choosing k by cross-validation

Cross-validation scores each $k$ on 5 different held-out slices of the training data and
averages, so a lucky or unlucky split matters much less.

```python
from sklearn.model_selection import cross_val_score

k_range = range(1, 40)
cv_scores = [cross_val_score(KNeighborsClassifier(n_neighbors=k),
                              X_tr, y_tr, cv=5).mean()
             for k in k_range]
best_k = k_range[int(np.argmax(cv_scores))]
print(f"Best k by 5-fold CV: {best_k}, CV acc: {max(cv_scores):.3f}")
```

```output
Best k by 5-fold CV: 10, CV acc: 0.922
```

Across $k$ from 1 to 39, the best 5-fold average is 0.922 at $k = 10$. That is lower than the
0.950 test score above, which is a reminder that a single 80-point test split can flatter a
model by a few points.

## The curse of dimensionality

In 2 or 3 dimensions, "nearby" is a useful idea. In hundreds of dimensions, space is so vast
that every point is far from every other point — and k-NN, which lives on the idea of
"nearby", stops working.

In high dimensions, geometric intuitions from 2D completely break down.

### Volume argument

Consider a unit hypercube in $d$ dimensions. The fraction of volume occupied by a sub-hypercube with side length $2\varepsilon$ centered at a point is $(2\varepsilon)^d$.

A **unit hypercube** is the $d$-dimensional version of a square with sides of length 1. A
small box around a point, reaching $\varepsilon$ in each direction along every axis, has side
$2\varepsilon$.

$$
\text{fraction of data in } \varepsilon\text{-ball} \approx (2\varepsilon)^d
$$

> **In plain words:** if data is spread evenly, the share of points that land inside your
> little box is the box's volume: its side length multiplied by itself once per dimension.
> Multiplying a number below 1 by itself many times makes it vanish fast.

```python
import numpy as np

eps = 0.1  # capture points within 10% of range in each dimension
dims = [1, 2, 5, 10, 20, 50, 100]
fractions = [(2 * eps) ** d for d in dims]

print(f"{'dim':>5} | {'fraction of space':>20}")
print("-" * 30)
for d, f in zip(dims, fractions):
    print(f"{d:>5} | {f:.2e}")
```

```output
  dim |    fraction of space
------------------------------
    1 | 2.00e-01
    2 | 4.00e-02
    5 | 3.20e-04
   10 | 1.02e-07
   20 | 1.05e-14
   50 | 1.13e-35
  100 | 1.27e-70
```

With $\varepsilon = 0.1$, the box spans 20% of each axis. In 1 dimension it catches 20% of the
data. In 10 dimensions it catches $1.02 \times 10^{-7}$ — about one point in ten million. In
100 dimensions the share is $1.27 \times 10^{-70}$.

In 100 dimensions, a ball containing 10% of each axis captures essentially zero data. You would need exponentially many points to cover the space.

(The code's box reaches 10% of the range on *each side* of the point, so 20% in total per
axis; the conclusion is the same either way.)

> **Picture it:** searching for a friend along a 1 km road is easy. Searching a 1 km square
> field is harder. Searching a 1 km cube of air harder again. Each extra dimension multiplies
> the room to search, and your fixed number of data points is spread ever more thinly.

### Distance concentration

In high dimensions, all points become approximately equidistant from a query point.

The code draws 1000 random points around the origin and measures each one's distance from
it. The **coefficient of variation** (CV) is the standard deviation divided by the mean: how
spread out the distances are, as a fraction of their typical size.

```python
import numpy as np

rng = np.random.default_rng(0)
n_samples = 1000
query = np.zeros(1)

for d in [2, 10, 50, 200, 1000]:
    data = rng.standard_normal((n_samples, d))
    q = np.zeros(d)
    dists = np.linalg.norm(data - q, axis=1)
    cv = dists.std() / dists.mean()  # coefficient of variation
    print(f"d={d:4}: min={dists.min():.2f}, max={dists.max():.2f}, "
          f"mean={dists.mean():.2f}, CV={cv:.3f}")
```

```output
d=   2: min=0.03, max=3.93, mean=1.26, CV=0.518
d=  10: min=1.19, max=5.74, mean=3.08, CV=0.224
d=  50: min=4.71, max=9.27, mean=7.03, CV=0.100
d= 200: min=12.00, max=16.82, mean=14.15, CV=0.046
d=1000: min=29.19, max=34.08, mean=31.61, CV=0.023
```

Watch the gap between nearest and farthest. In 2 dimensions the nearest point is at 0.03 and
the farthest at 3.93 — a ratio of more than 100. In 1000 dimensions the nearest is at 29.19 and
the farthest at 34.08, only 17% farther. The CV falls from 0.518 to 0.023.

The coefficient of variation (std/mean) collapses toward zero: all distances are nearly equal. The concept of "nearest neighbor" becomes meaningless — the nearest and furthest points are almost the same distance away.

> **In plain words:** each squared distance is a sum of $d$ independent pieces, one per
> dimension. Sums of many random pieces bunch tightly around their average — the law of
> large numbers — so every point ends up at nearly the same distance.

## k-NN degrades in high dimensions

Here is the curse in action. The code keeps exactly 2 informative features and pads them
with more and more pure-noise features. The signal never changes; only the noise in the
distance grows.

```python
import numpy as np
from sklearn.neighbors import KNeighborsClassifier
from sklearn.datasets import make_classification

rng = np.random.default_rng(0)
results = []

for d in [2, 5, 10, 20, 50, 100]:
    X, y = make_classification(n_samples=500, n_features=d,
                                n_informative=2,  # signal fixed; extra dims are noise
                                n_redundant=0, random_state=0)
    X_tr, X_te = X[:400], X[400:]
    y_tr, y_te = y[:400], y[400:]
    acc = KNeighborsClassifier(n_neighbors=5).fit(X_tr, y_tr).score(X_te, y_te)
    results.append((d, acc))
    print(f"d={d:3}: k-NN acc = {acc:.3f}")
```

```output
d=  2: k-NN acc = 0.920
d=  5: k-NN acc = 0.860
d= 10: k-NN acc = 0.740
d= 20: k-NN acc = 0.740
d= 50: k-NN acc = 0.690
d=100: k-NN acc = 0.680
```

Accuracy falls from 0.920 with 2 features to 0.860 with 5, 0.740 with 10 and 20, and 0.680
with 100 — getting closer to the coin-flip 0.5. The 98 noise dimensions at $d=100$ contribute
most of every distance, so the "nearest" neighbours are mostly chosen by noise.

> **Watch out:** this is why k-NN on wide raw data (hundreds of loosely relevant columns) is
> usually poor. The model has no way to ignore a useless feature: every column counts equally
> in the distance.

## Mitigation strategies

The fixes all try to make distance count only what matters: fewer, better dimensions or
smarter weighting.

- **Dimensionality reduction** before k-NN: PCA, UMAP (ch. 16).
- **Feature selection**: drop uninformative features that add noise to distances.
- **Distance metric learning**: learn a metric that weights dimensions by their importance.
- **Approximate nearest neighbors**: for large n, exact NN search is slow; libraries like FAISS use approximate methods.

**PCA** (principal component analysis) keeps the directions in which the data varies most.
**Approximate nearest neighbors** trade a tiny chance of missing the true nearest point for
search that is orders of magnitude faster.

> **Watch out:** PCA never looks at the labels. It keeps directions of high *variance*, which
> only helps if the signal lives in those directions. The Try-it below shows it failing.

## Recap in plain words

- k-NN predicts by majority vote (or average) of the $k$ closest training points; it stores data instead of learning weights.
- Small $k$ is jumpy (high variance), large $k$ is over-smooth (high bias); pick $k$ by cross-validation, not one small test split.
- Always scale features, because distance treats every unit equally.
- In high dimensions a fixed-size neighbourhood holds almost no data, and all distances become nearly equal.
- Adding pure-noise features steadily drags k-NN toward chance.
- Reducing or selecting dimensions helps — but only if the method keeps the dimensions that carry the signal.

## Try it Yourself

```python
import numpy as np
from sklearn.neighbors import KNeighborsClassifier
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(1)
n, d = 600, 50
# Only first 5 features are informative
X = rng.standard_normal((n, d))
y = (X[:, 0] + X[:, 1] - X[:, 2] > 0).astype(int)

X = StandardScaler().fit_transform(X)
X_tr, X_te = X[:500], X[500:]
y_tr, y_te = y[:500], y[500:]

raw_acc = KNeighborsClassifier(n_neighbors=7).fit(X_tr, y_tr).score(X_te, y_te)

pca = PCA(n_components=5)
X_tr_pca = pca.fit_transform(X_tr)
X_te_pca  = pca.transform(X_te)
pca_acc = KNeighborsClassifier(n_neighbors=7).fit(X_tr_pca, y_tr).score(X_te_pca, y_te)

print(f"k-NN on raw 50D: {raw_acc:.3f}")
print(f"k-NN on PCA 5D:  {pca_acc:.3f}")
```

```output
k-NN on raw 50D: 0.680
k-NN on PCA 5D:  0.600
```

The label depends on only 3 of the 50 columns. On the raw 50 dimensions k-NN scores 0.680.
Squeezing to 5 PCA components makes it *worse*: 0.600. Every column here is independent noise
with the same variance, so PCA has no high-variance direction to find and keeps 5 essentially
random mixtures — mostly noise. (The code comment says "first 5 features"; the label actually
uses features 0, 1, and 2.)

Now try the fix that knows which columns matter: replace the PCA lines with `X_tr[:, :3]` and
`X_te[:, :3]`. Accuracy jumps to about 0.97 — feature selection beats dimensionality reduction
when the signal is not where the variance is.

Generate 800 training and 200 test samples in $d=30$ dimensions where only 3 features matter. Sweep $k\in\{1,3,5,10,20,50\}$ and plot test accuracy vs $k$. Then apply PCA to $d'=3$ first and repeat. How much does PCA help?

```python
import numpy as np
from sklearn.neighbors import KNeighborsClassifier
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(42)
n, d = 1000, 30
X = rng.standard_normal((n, d))
y = (X[:, 0] - X[:, 1] + 0.5 * X[:, 2] > 0).astype(int)
X = StandardScaler().fit_transform(X)
X_tr, X_te, y_tr, y_te = X[:800], X[800:], y[:800], y[800:]

X_tr3 = PCA(n_components=3).fit(X_tr).transform(X_tr)
X_te3 = PCA(n_components=3).fit(X_tr).transform(X_te)

for k in [1, 3, 5, 10, 20, 50]:
    acc_raw = KNeighborsClassifier(k).fit(X_tr, y_tr).score(X_te, y_te)
    acc_pca = KNeighborsClassifier(k).fit(X_tr3, y_tr).score(X_te3, y_te)
    print(f"k={k:2}: raw={acc_raw:.3f}, pca3={acc_pca:.3f}")
```

PCA does not help at all — it destroys the signal. Raw accuracy rises with $k$ from 0.665
($k=1$) to 0.855 ($k=50$), because averaging more neighbours washes out the 27 noise
dimensions. After PCA to 3 components, accuracy sits at about 0.50 for every $k$: chance. The
3 PCA directions are random mixtures dominated by noise. Keeping the 3 true columns
(`X_tr[:, :3]`) instead gives 0.975 to 0.990. The insight: PCA is unsupervised, so it reduces
dimensions in the label's interest only when the label lives along the high-variance
directions.
