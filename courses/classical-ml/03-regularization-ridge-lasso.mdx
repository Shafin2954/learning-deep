## Why regularization

Plain linear regression will use any weights at all, however huge, if they shave a little
off the training error. **Regularization** — charging the model a fee for large weights —
stops it from building wild, fragile fits that fall apart on new data.

Linear regression minimises $\|y - Xw\|_2^2$. When features are correlated or $p$ is close to $n$, the normal equations become ill-conditioned: tiny changes in data cause huge swings in $w$. Regularization adds a penalty to the loss that keeps coefficients small.

Here $p$ is the number of features and $n$ the number of rows. **Ill-conditioned** means the
problem is so wobbly that a nudge in the input causes a shove in the answer — like balancing
a long plank on a pencil tip.

$$
L_{\text{reg}}(w) = \underbrace{\|y - Xw\|_2^2}_{\text{fit}} + \underbrace{\text{penalty}(w)}_{\text{complexity}}
$$

> **In plain words:** the new loss has two parts. The **fit** term is the usual squared
> error. The **complexity** term is a bill that grows as the weights grow. Training now
> balances "fit the data" against "keep the bill low".

> **Picture it:** a tailor told to make a suit that fits, but charged for every extra
> centimetre of fabric. Without the charge, the suit follows every bump of the mannequin,
> including the bumps that won't be on the real customer.

The two canonical penalties produce very different geometries.

## Ridge regression (L2 penalty)

Ridge charges for the *square* of each weight. Big weights are expensive, small weights are
almost free, so every weight shrinks but none disappears.

Add $\lambda\|w\|_2^2$:

$$
L_{\text{Ridge}} = \|y - Xw\|_2^2 + \lambda\|w\|_2^2
$$

> **In plain words:** $\|w\|_2^2$ is the sum of the squared weights (the **L2 norm**,
> squared). $\lambda$ ("lambda") is the price per unit: $\lambda = 0$ is plain linear
> regression; larger $\lambda$ squeezes the weights harder.

Taking the gradient and setting to zero gives a closed-form solution:

$$
w_{\text{Ridge}} = (X^TX + \lambda I)^{-1}X^Ty
$$

> **In plain words:** it is the normal equation from ch. 2 with $\lambda$ added to every
> diagonal entry of $X^TX$. $I$ is the **identity matrix** (1s on the diagonal, 0s
> elsewhere).

Adding $\lambda I$ makes the matrix invertible even when $X^TX$ is singular. Ridge shrinks all coefficients toward 0 proportionally — large coefficients are penalised more — but none ever reach exactly zero.

The data below has 20 features, but only 5 actually drive $y$; the other 15 are pure noise.

```python
import numpy as np
from sklearn.linear_model import Ridge, Lasso, ElasticNet
from sklearn.datasets import make_regression
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
X, y, true_coef = make_regression(n_samples=100, n_features=20,
                                   n_informative=5, noise=10,
                                   coef=True, random_state=0)
sc = StandardScaler()
X = sc.fit_transform(X)

ridge = Ridge(alpha=1.0).fit(X, y)
nonzero = np.sum(np.abs(ridge.coef_) > 1e-10)
print(f"Ridge: {nonzero}/20 nonzero coefs, max |coef| = {np.abs(ridge.coef_).max():.3f}")
```

```output
Ridge: 20/20 nonzero coefs, max |coef| = 55.041
```

All 20 coefficients are nonzero, including the 15 noise features. Ridge turned them down but
never off. The largest coefficient is 55.041, on feature 1 — the real feature with the biggest true weight.

> **Watch out:** penalties compare weights against each other, so the features must be on
> the same scale. A feature in millimetres needs a weight 1000 times smaller than the same
> feature in metres, and would be penalized very differently. That is why the code runs
> `StandardScaler` first.

## Lasso regression (L1 penalty)

Lasso charges for the *absolute value* of each weight. That small change has a big effect:
it pays to set unhelpful weights to exactly zero, so Lasso also picks which features to keep.

Add $\lambda\|w\|_1$:

$$
L_{\text{Lasso}} = \|y - Xw\|_2^2 + \lambda\|w\|_1
$$

> **In plain words:** $\|w\|_1$ is the sum of the absolute weights (the **L1 norm**). Shrinking
> a weight by 0.1 saves the same penalty whether the weight is 100 or 0.1 — the fee per
> unit is flat, so it stays worth pushing small weights all the way to zero. With Ridge the
> fee per unit fades as the weight approaches zero, so it never quite gets there.

There is no closed form because the L1 norm is non-differentiable at zero. The standard solver is **coordinate descent**: cycle through each $w_j$, hold others fixed, and apply the soft-threshold operator $S(z, \lambda) = \text{sign}(z)\max(|z|-\lambda, 0)$.

**Coordinate descent** means optimizing one weight at a time while freezing the rest, then
moving to the next. The **soft-threshold** operator shrinks a number toward zero by
$\lambda$ and snaps it to exactly zero if it was within $\lambda$ of zero already.

Lasso induces **sparsity**: many coefficients go to exactly zero, performing automatic feature selection.

```python
lasso = Lasso(alpha=5.0).fit(X, y)
nonzero_lasso = np.sum(np.abs(lasso.coef_) > 1e-10)
print(f"Lasso: {nonzero_lasso}/20 nonzero coefs")
print(f"Active features: {np.where(np.abs(lasso.coef_) > 1e-10)[0].tolist()}")
```

```output
Lasso: 5/20 nonzero coefs
Active features: [1, 4, 11, 15, 16]
```

With `alpha=5.0`, 15 of the 20 coefficients are exactly zero. The 5 survivors, features
`[1, 4, 11, 15, 16]`, are exactly the 5 informative features that `make_regression` planted.
Lasso found them without being told.

> **Watch out:** sklearn calls the penalty strength `alpha`, not `lambda` (`lambda` is a
> reserved word in Python). It is the same knob, though sklearn's Lasso divides the fit term
> by $2n$, so its `alpha` values are not directly comparable to Ridge's.

### Geometric intuition

The unconstrained loss has elliptical contours. Adding a constraint $\|w\|_q \le t$ forces the solution to lie within the feasible region. For L2 (a ball), contours typically touch the smooth surface away from axes — all components nonzero. For L1 (a diamond in 2D), contours usually touch a **corner** of the diamond, which lies on an axis — forcing one component to zero.

This is why L1 produces sparse solutions geometrically, not just numerically.

> **Picture it:** the error contours are ripples spreading out from the unregularized best
> answer. You are allowed to stand only inside a fence. A round fence (Ridge) is first touched
> by the ripples somewhere along its smooth curve — usually not on an axis. A diamond fence
> (Lasso) sticks its corners out along the axes, so the ripples usually hit a corner first,
> and at a corner one weight is exactly zero.

## Coefficient paths

A **coefficient path** shows what happens to every weight as you slowly raise the penalty.
Reading it left to right tells you which features the model gives up first.

```python
import matplotlib.pyplot as plt
from sklearn.linear_model import lasso_path

alphas, coefs, _ = lasso_path(X, y, alphas=np.logspace(-2, 2, 100))

fig, ax = plt.subplots(figsize=(7, 4))
for i in range(coefs.shape[0]):
    ax.plot(np.log10(alphas), coefs[i], alpha=0.6, linewidth=1)
ax.axhline(0, color='black', linewidth=0.8, linestyle='--')
ax.set_xlabel('log10(alpha)')
ax.set_ylabel('coefficient value')
ax.set_title('Lasso coefficient paths — shrink to zero as alpha increases')
plt.tight_layout()
plt.show()
```

```output
[Figure: Lasso coefficient paths — most features collapse to zero at higher alpha; 5 survive longest]
```

On the right (large alpha) every line sits on the dashed zero line. Moving left, features
switch on one at a time. The 5 informative features switch on first and stay largest; the
noise features only appear at small alpha, close to zero.

## Elastic Net

Elastic Net mixes both bills: part absolute-value fee (to zero out features) and part
squared fee (to stay stable when features move together).

Elastic Net combines both penalties:

$$
L_{\text{EN}} = \|y - Xw\|_2^2 + \alpha_1\|w\|_1 + \alpha_2\|w\|_2^2
$$

> **In plain words:** $\alpha_1$ sets the strength of the Lasso part, $\alpha_2$ the strength
> of the Ridge part. Set either to zero and you get the other method back.

In sklearn, `l1_ratio` controls the mix: `l1_ratio=1` → pure Lasso, `l1_ratio=0` → pure Ridge. Elastic Net is useful when features are grouped and correlated — Lasso tends to pick one from each group arbitrarily, Elastic Net can select the whole group.

```python
en = ElasticNet(alpha=5.0, l1_ratio=0.5).fit(X, y)
nonzero_en = np.sum(np.abs(en.coef_) > 1e-10)
print(f"ElasticNet (l1_ratio=0.5): {nonzero_en}/20 nonzero coefs")
```

```output
ElasticNet (l1_ratio=0.5): 17/20 nonzero coefs
```

At the same `alpha=5.0`, Elastic Net keeps 17 of 20 features, against Lasso's 5. Half of
its penalty is now the Ridge part, which shrinks weights without zeroing them, so far fewer
fall to exactly zero.

## Choosing lambda with cross-validation

You don't guess the penalty strength; you test it. **Cross-validation** splits the data
into folds, trains on some and scores on the held-out one, and repeats for each candidate
strength. The strength with the best held-out score wins.

```python
from sklearn.linear_model import LassoCV, RidgeCV

lasso_cv = LassoCV(cv=5, random_state=0).fit(X, y)
ridge_cv = RidgeCV(alphas=np.logspace(-3, 3, 50), cv=5).fit(X, y)

print(f"LassoCV best alpha: {lasso_cv.alpha_:.4f}")
print(f"RidgeCV best alpha: {ridge_cv.alpha_:.4f}")
```

```output
LassoCV best alpha: 0.4253
RidgeCV best alpha: 0.0010
```

`LassoCV` picks alpha = 0.4253, more than ten times weaker than the 5.0 that recovered the
exact 5 features. Cross-validation optimizes *prediction*, and a few small noise weights
cost it almost nothing, so it does not insist on the sparsest model. `RidgeCV` picks 0.0010,
the smallest value on its grid: with 100 rows and only 20 well-behaved features, there is
nothing to stabilize and Ridge barely needs to act.

> **Watch out:** if the chosen value sits at the edge of your grid (as 0.0010 does here),
> the true best may lie beyond it. Widen the grid and re-run before you trust it.

## Recap in plain words

- Regularization adds a fee for large weights so the fit can't become wild and fragile.
- Ridge (L2) shrinks every weight but never to zero, and always gives an invertible system.
- Lasso (L1) pushes unhelpful weights to exactly zero, so it selects features.
- The diamond shape of the L1 fence, with corners on the axes, is why Lasso produces zeros.
- Elastic Net mixes both and handles groups of correlated features better than Lasso alone.
- Pick the penalty strength by cross-validation, and standardize features first.

## Try it Yourself

```python
import numpy as np
from sklearn.linear_model import Ridge, Lasso
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(42)
n, p = 80, 30
# Correlated features: first 5 are informative, rest are noise
X = rng.standard_normal((n, p))
X[:, 1] = X[:, 0] + rng.normal(0, 0.1, n)  # feature 1 ≈ feature 0
true_w = np.zeros(p)
true_w[:5] = [3, -2, 1.5, -1, 2]
y = X @ true_w + rng.normal(0, 0.5, n)

X = StandardScaler().fit_transform(X)

for name, model in [("Ridge", Ridge(alpha=1.0)), ("Lasso", Lasso(alpha=0.1))]:
    model.fit(X, y)
    nz = np.sum(np.abs(model.coef_) > 0.01)
    err = np.mean((model.predict(X) - y)**2)
    print(f"{name}: {nz} nonzero, MSE={err:.3f}")
```

```output
Ridge: 28 nonzero, MSE=0.166
Lasso: 5 nonzero, MSE=0.295
```

The data has 30 features with 5 informative ones, and feature 1 is almost a copy of
feature 0. Ridge keeps 28 features above 0.01 and has the lower training MSE (0.166). Lasso
keeps only 5 and pays a little in training fit (0.295). Training MSE always favours the less
constrained model; the question is which one generalizes.

Lasso's 5 are not quite the true 5. Printing `np.where(np.abs(model.coef_) > 0.01)[0]` gives
`[0 2 3 4 13]`: it dropped feature 1 (the near-copy of feature 0) and kept noise feature 13
instead. Because the two columns are almost identical, their true weights 3 and -2 act like
a single weight of about 1, and Lasso hands it all to feature 0 — the "picks one from the
group" behaviour described in the Elastic Net section.

Try `Lasso(alpha=0.5)`. The noise feature 13 drops out, leaving `[0 2 3 4]`, and every
surviving weight shrinks further toward zero.

## Exercise

Generate 200 samples with 50 features where only 8 are truly informative. Fit Ridge, Lasso, and ElasticNet. Report how many features each selects (coefficients > 0.01) and which method recovers the true informative features most accurately.

> **Hint:** pass `coef=True` to `make_regression` to get the true coefficients back, then
> compare sets of indices: true positives are in both sets, false positives only in the
> model's set.

<summary>Solution</summary>

```python
import numpy as np
from sklearn.linear_model import Ridge, Lasso, ElasticNet, LassoCV
from sklearn.preprocessing import StandardScaler
from sklearn.datasets import make_regression

X, y, coef = make_regression(n_samples=200, n_features=50, n_informative=8,
                               noise=5, coef=True, random_state=7)
X = StandardScaler().fit_transform(X)
true_nz = set(np.where(np.abs(coef) > 0)[0])

for name, model in [
    ("Ridge", Ridge(alpha=1.0)),
    ("Lasso (CV)", LassoCV(cv=5, random_state=0)),
    ("ElasticNet", ElasticNet(alpha=0.1, l1_ratio=0.5)),
]:
    model.fit(X, y)
    pred_nz = set(np.where(np.abs(model.coef_) > 0.01)[0])
    tp = len(true_nz & pred_nz)
    fp = len(pred_nz - true_nz)
    print(f"{name}: selected={len(pred_nz)}, TP={tp}/8, FP={fp}")
```

Lasso (via LassoCV) typically recovers all 8 informative features with the fewest false positives.

When you run it, all three methods find all 8 true features (TP=8/8). The difference is the
false positives: Ridge keeps 49 features (41 false), ElasticNet 48 (40 false), and LassoCV
19 (11 false). LassoCV is the clear winner, but not perfect — cross-validation tuned it for
prediction, so it leaves 11 tiny noise weights above the 0.01 cut-off. Raise alpha or the
threshold if you want a cleaner selection.
