## Agglomerative clustering builds a tree of merges

Start with every point alone. Join the two closest groups. Repeat until everything is one
group. Write down every join, and you get a family tree of the data that you can cut at any
level to get as many clusters as you like.

k-Means requires you to pick k and assumes spherical clusters. Agglomerative clustering takes a different route: start with every point as its own cluster and repeatedly merge the two closest clusters until one remains. The result is a **dendrogram** — a binary tree where the height of each merge encodes the distance at which two groups joined. You cut the tree at a chosen height to produce k clusters.

> **Picture it:** a family tree read upside down. Siblings join first (very close), then
> cousins, then whole branches of the family, and finally everyone. Cutting the tree halfway
> up separates the big branches.

The linkage function decides what "distance between clusters" means:

- **Single linkage** — distance between the two nearest points across clusters. Produces chaining: one bridge point pulls distant blobs together.
- **Complete linkage** — distance between the two furthest points. Compact clusters, sensitive to outliers.
- **Average linkage** — mean of all pairwise distances. A middle ground.
- **Ward linkage** — merges that minimize within-cluster variance increase. Most commonly used; gives balanced, compact clusters.

Ward's rule in plain words: at each step, join the two groups whose merger makes the total
spread (the k-Means inertia from ch. 14) grow the least.

```python
import numpy as np
from sklearn.datasets import make_blobs
from scipy.cluster.hierarchy import linkage, dendrogram, fcluster
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt

X, y_true = make_blobs(n_samples=80, centers=4, cluster_std=0.8, random_state=42)

Z = linkage(X, method='ward')
print("Linkage matrix shape:", Z.shape)
print("First 5 merges (cluster_a, cluster_b, distance, count):")
print(np.round(Z[:5], 3))
```

```output
Linkage matrix shape: (79, 4)
First 5 merges (cluster_a, cluster_b, distance, count):
[[2.00e+00 5.70e+01 4.60e-02 2.00e+00]
 [3.00e+00 1.80e+01 8.60e-02 2.00e+00]
 [4.00e+01 6.70e+01 1.03e-01 2.00e+00]
 [1.40e+01 4.80e+01 1.21e-01 2.00e+00]
 [1.10e+01 3.00e+01 1.56e-01 2.00e+00]]
```

80 points need 79 merges, hence 79 rows. Each of the first 5 merges joins two single points
(the last column is 2.00e+00, a new cluster of size 2) at tiny distances such as 0.046. Indices
below 80 are original points; a merged cluster gets the next free index, 80, 81, and so on.

Each row of `Z` records: left cluster index, right cluster index, merge distance, size of the new cluster. After $n-1$ merges you have one cluster containing all $n$ points.

### Cutting the dendrogram to get k clusters

Cutting means choosing a height and slicing straight across the tree; every branch that
crosses the cut becomes one cluster.

```python
labels = fcluster(Z, t=4, criterion='maxclust')
print("Cluster labels:", labels[:20])
from sklearn.metrics import adjusted_rand_score
print("ARI vs ground truth:", round(adjusted_rand_score(y_true, labels), 3))
```

```output
Cluster labels: [1 2 3 1 1 4 4 3 1 3 3 2 3 1 3 3 3 4 1 4]
ARI vs ground truth: 1.0
```

The 4-cluster cut matches the true blobs exactly: ARI 1.0. (The label numbers 1 to 4 are
arbitrary names; ARI ignores how the clusters are numbered.)

`criterion='maxclust'` cuts the tree so exactly `t` clusters remain. Alternatively, `criterion='distance'` cuts at a height threshold.

### Reading the dendrogram

The tree's shape tells you how many clusters the data "wants": look for a long stretch of
height where no merges happen.

```python
fig, ax = plt.subplots(figsize=(10, 4))
dendrogram(Z, ax=ax, truncate_mode='lastp', p=20, leaf_rotation=45)
ax.set_title('Ward Linkage Dendrogram (truncated)')
ax.set_xlabel('Sample index / (cluster size)')
ax.set_ylabel('Merge distance')
plt.tight_layout()
plt.savefig('/tmp/dendrogram.png', dpi=80)
print("Saved dendrogram.png")
```

```output
Saved dendrogram.png
```

The code saves the plot to a file instead of showing it, so the output is only a confirmation
line. In the saved figure, the merge heights tell the story: the merges inside the blobs all
happen below a height of about 4.4, and the last three merges happen at 28.78, 62.11, and 74.61.

The long vertical gap before the final four merges is the natural cut point — it signals that those four groups are well-separated. When the dendrogram shows no obvious gap, the data probably doesn't have a clean cluster structure.

To be exact, joining 4 groups into 1 takes the final *three* merges; the gap (from about 4.4
up to 28.78) sits just below them, and a cut anywhere inside it leaves the 4 groups.

## Time and memory complexity

Agglomerative clustering compares every pair of points, so doubling the data roughly
quadruples the work and the memory.

Ward linkage on n points costs $O(n^2 \log n)$ time and $O(n^2)$ memory for the pairwise distance matrix. For n = 10 000, that's 100 M floats (about 800 MB). Agglomerative clustering does not scale to millions of points without approximation.

That is 100 million 8-byte numbers, about 800 MB, for only 10,000 points. At a million
points the matrix would need about 8 TB.

```python
import time
from sklearn.cluster import AgglomerativeClustering

for n in [500, 2000, 5000]:
    Xn, _ = make_blobs(n_samples=n, centers=4, random_state=0)
    t0 = time.perf_counter()
    AgglomerativeClustering(n_clusters=4, linkage='ward').fit(Xn)
    elapsed = time.perf_counter() - t0
    print(f"n={n:5d}  time={elapsed:.3f}s")
```

```output
n=  500  time=0.007s
n= 2000  time=0.172s
n= 5000  time=1.202s
```

Going from 500 to 5000 points (10 times more) multiplies the time by more than 100 — the
quadratic growth in action. The exact seconds vary from machine to machine and run to run;
the ratio is what matters.

> **Watch out:** the time grows gently at first, which tempts people to run it on 200,000
> rows. Memory, not time, usually kills the job first.

## Spectral clustering works where k-Means fails

Spectral clustering cares about who is *connected* to whom, not who is near the centre. It
builds a network linking each point to its close neighbours, then groups points that are
joined by many strong links — even if the group is a long curved shape.

k-Means partitions by Euclidean distance from centroids; it cannot handle two interleaved moons or concentric rings. Spectral clustering maps points into a new space where the clusters become linearly separable, then runs k-Means there.

The key insight: build a **similarity graph** where nodes are data points and edges carry a weight $w_{ij} = \exp(-\|x_i - x_j\|^2 / \sigma^2)$. Two points that are "close" (in graph-connectivity terms) get a high weight, even if they're not close in raw Euclidean distance.

Strictly, the weight itself is high only for points that are close in plain distance. What
makes far-apart points "close in graph terms" is a *chain* of strong links between them —
like two ends of one moon, joined through all the points in between.

> **Picture it:** a city map of footpaths. Two houses at opposite ends of a long, curved
> street are far apart as the crow flies, but they are connected by a continuous chain of
> neighbours. A house on the next street over may be closer in a straight line but has no
> path to them. Spectral clustering groups by footpaths, not by crow-flight distance.

### The graph Laplacian

Given the weight matrix $W$ and degree matrix $D$ (diagonal, $D_{ii} = \sum_j w_{ij}$), the unnormalized graph Laplacian is:

$$
L = D - W
$$

> **In plain words:** $W$ lists the link strength between every pair of points. $D$ is a
> diagonal matrix holding each point's total link strength (its **degree**). The **graph
> Laplacian** $L$ is their difference. A group of points with strong links inside and almost
> none outside makes $L$ have an eigenvector that is nearly constant on that group and zero
> elsewhere, with an eigenvalue near 0.

The normalized version $L_{\mathrm{sym}} = D^{-1/2} L D^{-1/2}$ is more commonly used. The **eigenvectors corresponding to the k smallest eigenvalues** of $L$ form a k-dimensional embedding. Points that are well-connected in the graph cluster together in this eigenspace.

An **eigenvector** of a matrix is a direction the matrix only stretches, never turns; the
stretch factor is its **eigenvalue**. Here each eigenvector assigns one number to every data
point, and points in the same well-connected group get similar numbers.

```python
from sklearn.cluster import KMeans, SpectralClustering
from sklearn.datasets import make_moons
from sklearn.metrics import adjusted_rand_score

X_moons, y_moons = make_moons(n_samples=200, noise=0.08, random_state=42)

km = KMeans(n_clusters=2, random_state=0, n_init=10).fit(X_moons)
sc = SpectralClustering(n_clusters=2, affinity='rbf', gamma=20.0,
                        random_state=0).fit(X_moons)

print("k-Means ARI on moons:", round(adjusted_rand_score(y_moons, km.labels_), 3))
print("Spectral  ARI on moons:", round(adjusted_rand_score(y_moons, sc.labels_), 3))
```

```output
k-Means ARI on moons: 0.236
Spectral  ARI on moons: 0.98
```

k-Means gets ARI 0.236 on the moons; spectral clustering with `gamma=20.0` gets 0.98, almost
a perfect recovery of the two crescents.

k-Means fails because the two moons share the same centroid region. Spectral clustering recovers the true structure because the eigenvector embedding separates connected components.

### Choosing gamma (the RBF bandwidth)

`gamma` decides how far a link reaches. If links reach too far, the two moons are tied
together by many links; if they are short enough, each moon's links stay inside that moon.

`gamma` controls how rapidly similarity drops with distance. Too small: every point looks similar to every other (one blob). Too large: only nearest neighbors are connected (too many components).

(In the weight formula above, `gamma` plays the role of $1/\sigma^2$: large `gamma` means
short-range links.)

```python
for gamma in [0.5, 2.0, 5.0, 20.0]:
    sc = SpectralClustering(n_clusters=2, affinity='rbf', gamma=gamma,
                            random_state=0).fit(X_moons)
    ari = adjusted_rand_score(y_moons, sc.labels_)
    print(f"gamma={gamma:5.1f}  ARI={ari:.3f}")
```

```output
gamma=  0.5  ARI=0.236
gamma=  2.0  ARI=0.345
gamma=  5.0  ARI=0.446
gamma= 20.0  ARI=0.980
```

The sweep shows how much the choice matters. At `gamma=0.5` spectral clustering is no better
than k-Means (0.236). It improves slowly through 2.0 (0.345) and 5.0 (0.446), and only at
20.0 do links become short enough to stop crossing between the moons (0.980).

A useful heuristic: set `gamma = 1 / (2 * median_distance²)` where `median_distance` is computed over a sample of pairwise distances.

> **Watch out:** that heuristic uses the median distance between *any* two points, which
> reflects the size of the whole dataset rather than the gap between clusters. On moon-shaped
> data it picks a `gamma` far too small (the exercise below shows it scoring ARI 0.243). A
> scale based on distances to each point's nearest neighbours works much better.

### Spectral clustering under the hood (manual)

The manual version builds $W$, $D$, and $L_{\mathrm{sym}}$ by hand, takes the eigenvectors of
the two smallest eigenvalues, and runs k-Means on those two numbers per point.

```python
from scipy.spatial.distance import cdist
from scipy.linalg import eigh

X_small, y_small = make_moons(n_samples=60, noise=0.08, random_state=1)
gamma = 20.0
W = np.exp(-gamma * cdist(X_small, X_small, 'sqeuclidean'))
np.fill_diagonal(W, 0)

D = np.diag(W.sum(axis=1))
L = D - W

# Normalized Laplacian
D_inv_sqrt = np.diag(1.0 / np.sqrt(W.sum(axis=1)))
L_sym = D_inv_sqrt @ L @ D_inv_sqrt

vals, vecs = eigh(L_sym)
embedding = vecs[:, :2]   # 2 smallest eigenvectors (eigenvalue-0 is trivial)

labels_manual = KMeans(n_clusters=2, random_state=0, n_init=10).fit_predict(embedding)
print("Manual spectral ARI:", round(adjusted_rand_score(y_small, labels_manual), 3))
```

```output
Manual spectral ARI: 1.0
```

The hand-built version recovers the two moons perfectly (ARI 1.0) on 60 points. Every step
sklearn's `SpectralClustering` does is in these dozen lines.

## Comparing agglomerative and spectral

Both methods are good at shapes k-Means can't handle, and both pay for it with all-pairs
computations.

| Property | Agglomerative (Ward) | Spectral |
|---|---|---|
| Handles non-convex shapes | No | Yes |
| Provides dendrogram | Yes | No |
| Requires k upfront | No (cut later) | Yes |
| Scales to n=100k | No ($O(n^2)$) | No ($O(n^2)$ kernel) |
| Main hyperparameter | linkage | gamma / n_neighbors |

The first row is about Ward specifically. *Single* linkage can follow non-convex shapes,
because it chains through neighbouring points — the very chaining described above as a
weakness for blobs.

For large n, approximate spectral methods (Nyström approximation, sparse k-NN graph) are used.

The **Nyström approximation** builds the similarity matrix from a random sample of points; a
**sparse k-NN graph** keeps only each point's nearest-neighbour links, so most of $W$ is zero.

## Recap in plain words

- Agglomerative clustering merges the closest groups step by step and records the merges in a dendrogram.
- The linkage rule defines "closest": single chains, complete stays compact, average sits between, Ward minimizes added spread.
- A long gap in merge heights suggests a natural number of clusters.
- All-pairs methods cost roughly $n^2$ in memory and time, so they don't scale to millions of rows.
- Spectral clustering groups points by chains of strong links, using eigenvectors of the graph Laplacian.
- Its `gamma` (link reach) decides success or failure; tune it to the nearest-neighbour scale.

## Try it Yourself

```python
from sklearn.datasets import make_circles
from sklearn.cluster import KMeans, SpectralClustering
from sklearn.metrics import adjusted_rand_score
import numpy as np

X, y = make_circles(n_samples=300, factor=0.5, noise=0.05, random_state=42)

km_labels = KMeans(n_clusters=2, random_state=0, n_init=10).fit_predict(X)
sc_labels = SpectralClustering(n_clusters=2, affinity='rbf', gamma=50.0,
                               random_state=0).fit_predict(X)

print("k-Means ARI:", round(adjusted_rand_score(y, km_labels), 3))
print("Spectral ARI:", round(adjusted_rand_score(y, sc_labels), 3))
```

```output
k-Means ARI: -0.003
Spectral ARI: 1.0
```

On two concentric rings, k-Means scores -0.003 — no better than random, because any straight
cut through the centre splits both rings. Spectral clustering with `gamma=50.0` scores 1.0:
each ring is a closed chain of links that never touches the other ring.

Try varying `gamma` on the circles dataset. Also try `affinity='nearest_neighbors'` with different `n_neighbors` values.

For example, `gamma=10.0` drops back to about -0.003 (links reach across the gap between the
rings), while `affinity='nearest_neighbors', n_neighbors=10` scores 1.0 with no `gamma` at all.

You have a dataset with two interleaved spirals (like `make_moons` but three-armed). Describe the steps to cluster it correctly with spectral clustering, choosing gamma from the data. What linkage would you try first with agglomerative, and why?

```python
from sklearn.datasets import make_moons
from sklearn.cluster import SpectralClustering
from sklearn.metrics import adjusted_rand_score
from scipy.spatial.distance import cdist
import numpy as np

X, y = make_moons(n_samples=400, noise=0.06, random_state=7)

# Estimate gamma from the typical squared distance to each point's 10th-nearest neighbour
dists = cdist(X, X, 'sqeuclidean')
np.fill_diagonal(dists, np.inf)
median_sq = np.median(np.sort(dists, axis=1)[:, 9])
gamma_est = 1.0 / (2 * median_sq)
print(f"Estimated gamma: {gamma_est:.3f}")

sc = SpectralClustering(n_clusters=2, affinity='rbf', gamma=gamma_est,
                        random_state=0).fit(X)
print("ARI:", round(adjusted_rand_score(y, sc.labels_), 3))
```

For the gamma estimate: compute pairwise squared distances on a subsample, take the median nonzero value, set $\gamma = 1/(2 \cdot \text{median})$. This puts the "knee" of the RBF curve near the typical inter-point distance, so nearby points have similarity ~0.6 and distant points approach 0.

That all-pairs median version was the original recipe, and it fails here: it gives
$\gamma \approx 0.34$ and an ARI of only 0.243, because the median distance between *any* two
points is about the size of a whole moon. The code above uses the median squared distance to
each point's 10th-nearest neighbour instead, which prints `Estimated gamma: 42.307` and
`ARI: 1.0`. The principle is the same — put the knee of the RBF curve at a typical distance —
but the right typical distance is the neighbour distance.

For agglomerative: **Ward linkage** is the first choice because spirals, while non-convex globally, have locally compact neighborhoods. Ward won't recover the spiral structure (it's not connectivity-aware), but it produces the most internally homogeneous clusters if you know roughly where to cut.

Testing that claim on the same moons gives a different answer: Ward scores ARI 0.383, average
linkage 0.592, and **single linkage 1.0**. Single linkage is the right first try for spirals and
moons, precisely because of its chaining: it links each point to its nearest neighbour, so it
follows each arm from end to end. Its weakness — a single bridge point can merge two clusters —
only bites when the arms nearly touch.
