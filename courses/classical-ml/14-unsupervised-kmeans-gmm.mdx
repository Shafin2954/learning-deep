## Clustering: grouping without labels

**Clustering** is sorting things into groups when nobody has told you what the groups are.
You choose what "similar" means, and the algorithm finds groups of similar points.

Clustering finds structure in unlabelled data. Unlike classification, there is no ground truth during training — you define a notion of similarity and find groups accordingly.

> **Picture it:** tipping a jar of mixed buttons onto a table and sorting them. One person
> sorts by colour, another by size, another by number of holes. All are valid; the "right"
> grouping depends on what you want to do with the buttons.

> **Watch out:** a clustering algorithm always returns clusters, even on data with no real
> groups at all. Whether the groups mean anything is a question you have to answer separately.

In this chapter the toy datasets *do* have true labels, which are used only to grade the
clusterings afterwards with the **adjusted rand score (ARI)** — 1 for a perfect match with the
true groups, about 0 for a random grouping.

## k-Means: Lloyd's algorithm

k-Means places $K$ centre points and gives each data point to its nearest centre. It then
moves each centre to the middle of its points, and repeats until nothing changes.

k-Means partitions $n$ points into $K$ clusters by minimising **inertia** (within-cluster sum of squares):

$$
J = \sum_{k=1}^K \sum_{x_i \in C_k} \|x_i - \mu_k\|^2
$$

> **In plain words:** for every cluster $C_k$, add up the squared distances from each of its
> points $x_i$ to its centre $\mu_k$ (the **centroid**, the mean of the cluster's points).
> Then add over all $K$ clusters. Small $J$ means tight clusters.

The **algorithm (Lloyd's)** has four steps:
1. Initialise $K$ centroids (randomly or with k-Means++).
2. **Assign:** each point to its nearest centroid.
3. **Update:** recompute each centroid as the mean of its assigned points.
4. Repeat until assignments don't change.

**k-Means++** picks the starting centres spread apart: each new centre is chosen with
probability proportional to its squared distance from the centres already chosen.

k-Means always converges (inertia decreases at each step) but may reach a local minimum.

A **local minimum** is a solution that no single assign-or-update step can improve, even
though a better one exists elsewhere — for example, two centres sharing one blob while
another blob has none. `n_init=10` runs 10 different starts and keeps the best.

> **Picture it:** four ice-cream vans on a beach. Each sunbather walks to the nearest van
> (assign). Each van then drives to the middle of its customers (update). Repeat until no
> one changes van.

```python
import numpy as np
from sklearn.datasets import make_blobs
from sklearn.cluster import KMeans
import matplotlib.pyplot as plt

X, y_true = make_blobs(n_samples=300, centers=4, cluster_std=0.8, random_state=0)

km = KMeans(n_clusters=4, init='k-means++', n_init=10, random_state=0)
km.fit(X)
print(f"Inertia: {km.inertia_:.1f}")
print(f"Cluster sizes: {np.bincount(km.labels_).tolist()}")
```

```output
Inertia: 369.5
Cluster sizes: [81, 74, 73, 72]
```

The 300 points come from 4 blobs of 75. k-Means finds 4 clusters of 81, 74, 73, and 72 —
nearly the true sizes — with total inertia 369.5.

### k-Means from scratch

The scratch version is the four steps above in NumPy. The `X[:, None, :] - centers[None, :, :]`
line uses broadcasting to compute every point-to-centre distance at once.

```python
import numpy as np

def kmeans(X, K, n_iters=100, seed=0):
    rng = np.random.default_rng(seed)
    idx = rng.choice(len(X), K, replace=False)
    centers = X[idx].copy()
    for _ in range(n_iters):
        dists   = np.linalg.norm(X[:, None, :] - centers[None, :, :], axis=2)
        labels  = dists.argmin(axis=1)
        new_c   = np.array([X[labels == k].mean(axis=0) if (labels==k).any()
                             else centers[k] for k in range(K)])
        if np.allclose(centers, new_c): break
        centers = new_c
    return labels, centers

from sklearn.datasets import make_blobs
X, _ = make_blobs(n_samples=300, centers=4, cluster_std=0.8, random_state=0)
labels, centers = kmeans(X, K=4)
inertia = sum(np.sum((X[labels==k] - centers[k])**2) for k in range(4))
print(f"Scratch k-Means inertia: {inertia:.1f}")
```

```output
Scratch k-Means inertia: 369.5
```

The scratch version reaches the same inertia, 369.5, as sklearn — it found the same
solution, even from a plain random start.

### Choosing K: the elbow method

Inertia always falls as you add clusters — with one cluster per point it is zero. The
**elbow method** looks for the $K$ after which adding clusters stops buying much.

```python
from sklearn.cluster import KMeans
import numpy as np

from sklearn.datasets import make_blobs
X, _ = make_blobs(n_samples=300, centers=4, cluster_std=0.8, random_state=0)

inertias = []
for k in range(1, 11):
    km = KMeans(n_clusters=k, n_init=10, random_state=0).fit(X)
    inertias.append(km.inertia_)
    print(f"K={k}: inertia={km.inertia_:.1f}")
```

```output
K=1: inertia=2978.6
K=2: inertia=1348.9
K=3: inertia=708.8
K=4: inertia=369.5
K=5: inertia=326.3
K=6: inertia=292.4
K=7: inertia=260.2
K=8: inertia=225.2
K=9: inertia=205.9
K=10: inertia=184.7
```

Each step from $K=1$ to $K=4$ roughly halves inertia: 2978.6, 1348.9, 708.8, 369.5. After that
the drops shrink to about 20 to 45 per step (326.3, 292.4, …). The bend — the elbow — is at
$K = 4$.

The elbow at K=4 confirms the true number of clusters. Beyond K=4, inertia decreases slowly.

> **Watch out:** on real data the elbow is often a smooth curve with no clear bend. Use
> silhouette scores or BIC (below) alongside it, and remember that k-Means assumes round,
> similar-sized clusters.

## Gaussian Mixture Models via EM

A **Gaussian mixture model (GMM)** treats each cluster as a bell-shaped cloud that can be
stretched and tilted. Instead of hard yes/no assignments, each point gets a probability of
belonging to each cloud.

GMM assumes each cluster is a Gaussian $\mathcal{N}(\mu_k, \Sigma_k)$ with mixing weight $\pi_k$. Unlike k-Means, GMM gives **soft assignments** — each point has a probability of belonging to each cluster.

The **mixing weight** $\pi_k$ is the share of all points that cluster $k$ is expected to
hold. The covariance $\Sigma_k$ gives the cloud's shape, as in LDA/QDA (ch. 8).

The **EM algorithm** (expectation–maximization) alternates two steps:
- **E-step:** compute responsibilities $r_{ik} = \pi_k\mathcal{N}(x_i;\mu_k,\Sigma_k) / \sum_j \pi_j\mathcal{N}(x_i;\mu_j,\Sigma_j)$
- **M-step:** update parameters:
  - $\pi_k = \frac{1}{n}\sum_i r_{ik}$
  - $\mu_k = \frac{\sum_i r_{ik}x_i}{\sum_i r_{ik}}$
  - $\Sigma_k = \frac{\sum_i r_{ik}(x_i-\mu_k)(x_i-\mu_k)^T}{\sum_i r_{ik}}$

In plain words: the **responsibility** $r_{ik}$ is the probability that point $i$ came from
cluster $k$ — cluster $k$'s density at the point, as a share of all clusters' densities. The
M-step then recomputes each cluster's weight, mean, and shape as averages *weighted* by those
responsibilities. k-Means is the special case where every responsibility is 0 or 1 and every
cloud is a round ball of the same size.

> **Picture it:** k-Means is a strict school that puts every pupil in exactly one house.
> A GMM is a school that says "this pupil is 88% Gryffindor, 12% Hufflepuff" and uses those
> fractions when working out each house's average.

```python
from sklearn.mixture import GaussianMixture
import numpy as np
from sklearn.datasets import make_blobs

X, y_true = make_blobs(n_samples=300, centers=4, cluster_std=[0.5, 1.0, 0.8, 0.6], random_state=0)

gmm = GaussianMixture(n_components=4, covariance_type='full', random_state=0)
gmm.fit(X)
labels_gmm = gmm.predict(X)
proba = gmm.predict_proba(X)

from sklearn.metrics import adjusted_rand_score
ari = adjusted_rand_score(y_true, labels_gmm)
print(f"GMM ARI: {ari:.3f}")
print(f"Max soft-assignment probability (first 5): {proba.max(axis=1)[:5].round(3)}")
```

```output
GMM ARI: 0.973
Max soft-assignment probability (first 5): [0.884 1.    1.    1.    0.844]
```

The four blobs now have different spreads (0.5 to 1.0), which GMM can model. Its clustering
matches the truth almost perfectly (ARI 0.973). The soft probabilities show the difference
from k-Means: points 2 to 4 belong to their cluster with probability 1.000, but point 1 is only
0.884 sure and point 5 is 0.844 — they sit in overlap regions between clouds.

### BIC/AIC for selecting K in GMM

Because a GMM is a probability model, you can score each $K$ with **BIC** (Bayesian
information criterion): how well the model explains the data, minus a penalty for the number
of parameters. Lower BIC is better. **AIC** is a similar score with a lighter penalty.

```python
from sklearn.mixture import GaussianMixture

bics = [GaussianMixture(k, random_state=0).fit(X).bic(X) for k in range(1, 8)]
best_k = range(1, 8)[np.argmin(bics)]
print(f"BIC-selected K: {best_k}")
for k, b in enumerate(bics, 1):
    print(f"  K={k}: BIC={b:.1f}")
```

```output
BIC-selected K: 4
  K=1: BIC=2534.2
  K=2: BIC=2390.7
  K=3: BIC=2269.5
  K=4: BIC=2209.6
  K=5: BIC=2239.5
  K=6: BIC=2269.6
  K=7: BIC=2291.9
```

BIC falls from 2534.2 at $K = 1$ to its lowest, 2209.6, at $K = 4$, then rises again as extra
components add parameters without explaining enough. BIC selects the true $K$ with no elbow
to eyeball.

## DBSCAN: density-based clustering

**DBSCAN** defines a cluster as a crowded region: points with many close neighbours, linked
together, form a cluster, and isolated points are labelled noise. Clusters can be any shape.

k-Means and GMM require specifying K and assume convex clusters. DBSCAN finds clusters of arbitrary shape based on density:

**Convex** clusters are blob-like: a straight line between any two of their points stays
inside. Two interlocking crescents are not convex. In the bullets below, $\varepsilon$
("epsilon", `eps` in code) is the neighbourhood radius and MinPts (`min_samples`) the crowd
size.

- **Core point:** has at least MinPts neighbours within radius $\varepsilon$.
- **Border point:** within $\varepsilon$ of a core point but has fewer neighbours.
- **Noise point:** not reachable from any core point.

> **Picture it:** people at a festival. Anyone with at least 5 people within arm's reach is
> in a crowd (core). Someone at the edge of a crowd belongs to it (border). Someone standing
> alone in the field is noise. Crowds that touch merge into one.

```python
from sklearn.cluster import DBSCAN
from sklearn.datasets import make_moons
import numpy as np

X_moon, y_moon = make_moons(n_samples=300, noise=0.1, random_state=0)

km_moon = KMeans(n_clusters=2, n_init=10, random_state=0).fit(X_moon)
db_moon = DBSCAN(eps=0.15, min_samples=5).fit(X_moon)

from sklearn.metrics import adjusted_rand_score
print(f"k-Means ARI on moons: {adjusted_rand_score(y_moon, km_moon.labels_):.3f}")
print(f"DBSCAN  ARI on moons: {adjusted_rand_score(y_moon, db_moon.labels_):.3f}")
print(f"DBSCAN noise points: {(db_moon.labels_ == -1).sum()}")
```

```output
k-Means ARI on moons: 0.234
DBSCAN  ARI on moons: 0.904
DBSCAN noise points: 7
```

k-Means scores ARI 0.234 on the moons — it cuts them with a straight line. DBSCAN with
`eps=0.15` scores 0.904 and labels 7 points as noise. It follows each crescent's shape.

k-Means splits the moons along the wrong axis (it can only make convex partitions). DBSCAN follows the density curves.

> **Watch out:** DBSCAN is very sensitive to `eps`. On this exact data, `eps=0.2` links the
> two moons through a few close points and returns one big cluster (ARI 0.000), while
> `eps=0.1` shatters them into 18 fragments. Choose `eps` from a k-distance plot (the sorted
> distance from each point to its $k$-th neighbour), and scale features first.

## HDBSCAN

**HDBSCAN** tries every radius at once and keeps the clusters that survive across a wide range
of radii. You no longer have to guess `eps`; you only say how small a cluster may be.

HDBSCAN (Hierarchical DBSCAN) builds a hierarchy of DBSCAN clusters at all $\varepsilon$ values simultaneously, then extracts the most stable clusters. More robust to the choice of $\varepsilon$.

```python
import hdbscan
import numpy as np
from sklearn.datasets import make_moons
from sklearn.metrics import adjusted_rand_score

X_m, y_m = make_moons(300, noise=0.1, random_state=0)
hdb = hdbscan.HDBSCAN(min_cluster_size=10)
hdb.fit(X_m)
print(f"HDBSCAN ARI: {adjusted_rand_score(y_m, hdb.labels_):.3f}")
print(f"Noise points: {(hdb.labels_ == -1).sum()}")
```

```output
HDBSCAN ARI: 0.890
Noise points: 15
```

With only `min_cluster_size=10` and no `eps` at all, HDBSCAN scores ARI 0.890 and marks 15 of
300 points as noise. That's close to DBSCAN's best result, without the trial-and-error over
`eps`. (sklearn 1.3 and later also ships `sklearn.cluster.HDBSCAN`.)

## Recap in plain words

- Clustering groups unlabelled points by similarity; it always returns groups, meaningful or not.
- k-Means alternates assigning points to the nearest centre and moving centres to their points' mean; it needs $K$ and likes round blobs.
- Use k-Means++ starts and several restarts to avoid bad local minima; pick $K$ with the elbow, silhouette, or BIC.
- GMMs give soft, probabilistic assignments to stretched clouds, fitted by EM, and BIC can choose $K$.
- DBSCAN finds dense regions of any shape and labels outliers as noise, but is touchy about `eps`.
- HDBSCAN removes the `eps` guess by keeping clusters that are stable across all radii.

## Try it Yourself

```python
import numpy as np
from sklearn.cluster import KMeans, DBSCAN
from sklearn.mixture import GaussianMixture
from sklearn.datasets import make_moons, make_blobs
from sklearn.metrics import adjusted_rand_score

# Dataset 1: blobs (k-Means wins)
X1, y1 = make_blobs(300, centers=3, cluster_std=0.6, random_state=0)
# Dataset 2: moons (DBSCAN wins)
X2, y2 = make_moons(300, noise=0.08, random_state=0)

for name, X, y, K in [("Blobs", X1, y1, 3), ("Moons", X2, y2, 2)]:
    km = KMeans(K, n_init=10, random_state=0).fit(X)
    gm = GaussianMixture(K, random_state=0).fit(X)
    db = DBSCAN(eps=0.2, min_samples=5).fit(X)
    print(f"\n{name}:")
    print(f"  k-Means ARI: {adjusted_rand_score(y, km.labels_):.3f}")
    print(f"  GMM     ARI: {adjusted_rand_score(y, gm.predict(X)):.3f}")
    print(f"  DBSCAN  ARI: {adjusted_rand_score(y, db.labels_):.3f}")
```

```output
Blobs:
  k-Means ARI: 1.000
  GMM     ARI: 1.000
  DBSCAN  ARI: 0.142

Moons:
  k-Means ARI: 0.228
  GMM     ARI: 0.470
  DBSCAN  ARI: 0.993
```

No method wins everywhere. On the round blobs, k-Means and GMM are perfect (1.000) while
DBSCAN scores 0.142: with `eps=0.2` on unscaled blobs of spread 0.6, most points don't have 5
neighbours that close, so they become noise. On the moons the ranking flips: DBSCAN 0.993,
GMM 0.470, k-Means 0.228. One `eps` can't suit two datasets with different scales.

Try `eps=0.5` for both datasets. The blobs jump to about 0.93, and the moons collapse into
one cluster (0.000) — the same trade-off, reversed.

## Exercise

Implement k-Means from scratch (random initialisation, not k-Means++). Apply to `make_blobs` with K=4. Run 10 times with different seeds; report min/max/mean inertia. Compare to sklearn's k-Means with k-Means++ init. How much does the initialisation strategy matter?

> **Hint:** reuse the scratch `kmeans` from this chapter, but return the inertia, and loop
> over `seed in range(10)`.

```python
import numpy as np
from sklearn.cluster import KMeans
from sklearn.datasets import make_blobs

X, _ = make_blobs(400, centers=4, cluster_std=1.0, random_state=0)

def kmeans_random_init(X, K, seed):
    rng = np.random.default_rng(seed)
    centers = X[rng.choice(len(X), K, replace=False)].copy()
    for _ in range(200):
        dists   = np.linalg.norm(X[:,None,:] - centers[None,:,:], axis=2)
        labels  = dists.argmin(axis=1)
        new_c   = np.array([X[labels==k].mean(0) if (labels==k).any() else centers[k] for k in range(K)])
        if np.allclose(centers, new_c): break
        centers = new_c
    return sum(np.sum((X[labels==k]-centers[k])**2) for k in range(K))

inertias = [kmeans_random_init(X, 4, s) for s in range(10)]
print(f"Random init: min={min(inertias):.1f}, max={max(inertias):.1f}, mean={np.mean(inertias):.1f}")
sk_inertia = KMeans(4, init='k-means++', n_init=10, random_state=0).fit(X).inertia_
print(f"k-Means++ (sklearn): {sk_inertia:.1f}")
```

The output: random init gives min 702.6, max 1080.6, mean 740.5; sklearn's k-Means++ with 10
restarts gives 702.6. The mean tells the story — $(9 \times 702.6 + 1080.6) / 10 \approx 740.4$ —
so 9 of the 10 random starts found the best solution (702.6 to 702.8) and one got stuck in a local minimum
with 54% more inertia. Initialization matters for individual runs; k-Means++ plus several
restarts makes the bad case very unlikely.
