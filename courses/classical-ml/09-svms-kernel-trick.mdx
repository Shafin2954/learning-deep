## Maximum-margin classification

When many straight lines separate two classes, pick the one that leaves the widest empty
strip between them. A wide strip means a new point has to be far off before it lands on the
wrong side. That is the idea behind the **support vector machine (SVM)**.

Logistic regression picks any separating hyperplane. SVMs find the one with **maximum margin** — the gap between the hyperplane and the nearest training points on either side.

> **Picture it:** building a road between two villages of houses. You want the widest road
> that touches no house. The road's centre line is the decision boundary, its two kerbs are
> the margin, and the few houses that touch the kerbs are the ones that decide where the road
> goes.

Formally, for a linear classifier $f(x) = w^Tx + b$, the **geometric margin** for a correctly classified point is $y_i(w^Tx_i + b)/\|w\|$. The SVM maximises the smallest such margin.

Labels here are $-1$ and $+1$ rather than 0 and 1. That makes $y_i(w^Tx_i + b)$ positive
exactly when point $i$ is on its correct side. Dividing by $\|w\|$ (the length of $w$) turns
the raw score into an actual distance from the boundary.

### Hard-margin SVM (linearly separable data)

$$
\min_{w,b}\; \frac{1}{2}\|w\|^2 \quad \text{s.t.}\; y_i(w^Tx_i + b) \ge 1 \;\forall i
$$

> **In plain words:** make $w$ as short as possible ("min" of its squared length, halved
> for tidy calculus), subject to ("s.t.") one rule for every point $i$ ($\forall i$): its score
> times its label must be at least 1. Short $w$ means wide margin.

The margin is $2/\|w\|$. The constraint $y_i(w^Tx_i+b)\ge1$ requires all points to be on the correct side, at least one margin-width away.

The points that lie exactly on the margin boundary ($y_i(w^Tx_i+b)=1$) are the **support vectors** — the only training points that determine $w$.

Move any other point a little — or delete it — and the boundary doesn't change. Only the
houses touching the kerbs matter.

## Soft-margin SVM (non-separable data)

Real data is messy: some points sit on the wrong side of any line. A soft margin allows
violations, but charges a fine for each one, and $C$ is the size of the fine.

Allow some points to violate the margin using slack variables $\xi_i \ge 0$:

$$
\min_{w,b,\xi}\; \frac{1}{2}\|w\|^2 + C\sum_i\xi_i \quad \text{s.t.}\; y_i(w^Tx_i + b) \ge 1 - \xi_i,\; \xi_i \ge 0
$$

> **In plain words:** $\xi_i$ ("xi") is how far point $i$ pushes into or past the margin —
> 0 if it is safely outside. The loss is "keep the margin wide" plus $C$ times the total
> intrusion. This penalty is the **hinge loss**: zero for points beyond the margin, growing
> linearly as they cross it.

$C$ controls the trade-off: large $C$ → small margin, few violations; small $C$ → large margin, more violations tolerated (more regularisation).

```python
import numpy as np
from sklearn.svm import SVC
from sklearn.datasets import make_classification
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(0)
X, y = make_classification(n_samples=300, n_features=2, n_redundant=0,
                             n_clusters_per_class=1, random_state=3)
y = 2*y - 1  # convert to {-1, +1}
X = StandardScaler().fit_transform(X)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

for C in [0.01, 0.1, 1, 10, 100]:
    svm = SVC(kernel='linear', C=C).fit(X_tr, y_tr)
    n_sv = svm.n_support_.sum()
    acc  = svm.score(X_te, y_te)
    print(f"C={C:5}: acc={acc:.3f}, support vectors={n_sv}")
```

```output
C= 0.01: acc=1.000, support vectors=182
C=  0.1: acc=1.000, support vectors=62
C=    1: acc=1.000, support vectors=25
C=   10: acc=1.000, support vectors=12
C=  100: acc=1.000, support vectors=10
```

This data is cleanly separable, so every value of $C$ classifies all 60 test points correctly.
The difference is in the support vectors: 182 at $C = 0.01$, falling to 10 at $C = 100$. A tiny
fine lets the margin grow so wide that most training points fall inside it — and every point
inside the margin is a support vector.

Fewer support vectors at high C: the model relies on fewer points, more prone to overfitting.

> **Watch out:** on separable data like this, accuracy can't tell different $C$ values apart.
> On noisy data, a large $C$ bends the boundary to avoid every awkward point — choose $C$ by
> cross-validation, as below.

## The kernel trick

Some classes can't be split by any straight line in the original space, but could be if you
added extra, computed features. The kernel trick gets the benefit of those extra features
without ever computing them.

SVMs only need inner products $\langle x_i, x_j\rangle$ in the dual problem. Replace with a **kernel function**:

An **inner product** (dot product) multiplies two vectors entry by entry and adds the results;
it measures how much they point the same way. The **dual problem** is an equivalent rewrite of
the SVM optimization in which the data appear only through these pairwise inner products.

$$
K(x_i, x_j) = \langle\phi(x_i), \phi(x_j)\rangle
$$

> **In plain words:** $\phi$ ("phi") is a recipe for turning each point into a longer list of
> features. $K(x_i, x_j)$ gives the inner product of the two *transformed* points, computed
> directly from the original points. If you can compute $K$, you never need $\phi$.

This implicitly maps inputs to a feature space $\phi$ without ever computing $\phi(x)$ explicitly. If the feature space is infinite-dimensional, this is only tractable via the kernel trick.

> **Picture it:** red and blue marbles mixed on a table, with the reds in the middle. No
> straight line on the table separates them. Lift the middle of the tablecloth: now the reds
> sit higher, and a flat sheet slid in sideways separates them. A kernel is a formula for how
> far apart marbles are *after* lifting, worked out without doing the lifting.

### RBF (Gaussian) kernel

$$
K(x, z) = \exp\!\left(-\gamma\|x - z\|^2\right)
$$

> **In plain words:** similarity between $x$ and $z$ is 1 when they are the same point and
> drops toward 0 as they move apart. $\gamma$ ("gamma") sets how fast it drops: large
> $\gamma$ means only very close points count as similar.

The RBF kernel corresponds to an infinite-dimensional feature space. It measures similarity by Euclidean distance: nearby points get high similarity, distant points get near-zero.

**RBF** stands for **radial basis function**: the similarity depends only on the distance
(radius) between points. Two **concentric circles** — an inner ring of one class inside an
outer ring of the other — are the classic case no line can split.

```python
import numpy as np
from sklearn.svm import SVC
from sklearn.datasets import make_circles
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

# Concentric circles — NOT linearly separable
X, y = make_circles(n_samples=300, noise=0.1, factor=0.4, random_state=0)
X = StandardScaler().fit_transform(X)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

lin_svm = SVC(kernel='linear', C=1.0).fit(X_tr, y_tr)
rbf_svm = SVC(kernel='rbf',    C=1.0, gamma='scale').fit(X_tr, y_tr)

print(f"Linear SVM on circles: {lin_svm.score(X_te, y_te):.3f}")
print(f"RBF SVM on circles:    {rbf_svm.score(X_te, y_te):.3f}")
```

```output
Linear SVM on circles: 0.383
RBF SVM on circles:    1.000
```

The linear SVM scores 0.383 — worse than a coin flip, because no line can do better than
cutting the rings in half. The RBF SVM scores 1.000: all 60 test points correct.

The linear SVM can't separate concentric circles — the boundary must be curved. RBF maps to a space where the circles become linearly separable.

### Effect of gamma

$\gamma$ sets each training point's reach. Small $\gamma$: every point influences a huge area,
so the boundary is very smooth. Large $\gamma$: every point influences only a tiny bubble
around itself.

```python
from sklearn.svm import SVC
from sklearn.model_selection import cross_val_score

for gamma in [0.01, 0.1, 1, 10, 100]:
    cv = cross_val_score(SVC(kernel='rbf', C=1, gamma=gamma),
                          X_tr, y_tr, cv=5).mean()
    print(f"gamma={gamma:4}: CV acc = {cv:.3f}")
```

```output
gamma=0.01: CV acc = 0.529
gamma= 0.1: CV acc = 1.000
gamma=   1: CV acc = 0.996
gamma=  10: CV acc = 0.992
gamma= 100: CV acc = 0.900
```

At $\gamma = 0.01$ the CV accuracy is 0.529, about chance — the boundary is so smooth it is
nearly straight. $\gamma = 0.1$ is perfect (1.000). From there accuracy slides as $\gamma$
grows: 0.996, 0.992, then 0.900 at $\gamma = 100$, where each point's bubble is so small that
the model can only recognize points very near a training point.

Large $\gamma$: only very nearby points have non-zero similarity → model memorises training data → overfits. Small $\gamma$: very smooth decision boundary → may underfit.

## Hyperparameter tuning: C and gamma

$C$ and $\gamma$ interact — a high $\gamma$ can be tamed by a small $C$ and vice versa — so tune
them together. **Grid search** tries every combination from two lists and keeps the best by
cross-validation.

```python
from sklearn.model_selection import GridSearchCV

param_grid = {'C': [0.1, 1, 10, 100], 'gamma': [0.01, 0.1, 1, 10]}
gs = GridSearchCV(SVC(kernel='rbf'), param_grid, cv=5, n_jobs=-1)
gs.fit(X_tr, y_tr)
print(f"Best params: {gs.best_params_}")
print(f"Best CV score: {gs.best_score_:.3f}")
print(f"Test accuracy: {gs.score(X_te, y_te):.3f}")
```

```output
Best params: {'C': 1, 'gamma': 0.1}
Best CV score: 1.000
Test accuracy: 1.000
```

Of the 16 combinations, $C = 1$, $\gamma = 0.1$ wins with a perfect CV score, and it carries
over to a perfect test score.

> **Watch out:** SVMs are distance-based, so unscaled features break them the same way they
> break k-NN (ch. 6). Always standardize first. Also, fitting cost grows somewhere between
> the square and the cube of the number of rows; past roughly 100,000 rows, kernel SVMs
> become impractical.

## Recap in plain words

- An SVM picks the separating line with the widest empty margin around it.
- Only the support vectors — points on or inside the margin — determine the boundary.
- $C$ is the fine for margin violations: small $C$ gives a wide, forgiving margin; large $C$ a narrow, strict one.
- The kernel trick computes similarities in a richer feature space without building that space.
- The RBF kernel's $\gamma$ sets each point's reach: too small underfits, too large overfits.
- Tune $C$ and $\gamma$ together by grid search, and standardize features first.

## Try it Yourself

```python
import numpy as np
from sklearn.svm import SVC
from sklearn.datasets import make_moons
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split, cross_val_score

X, y = make_moons(n_samples=400, noise=0.2, random_state=0)
X = StandardScaler().fit_transform(X)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

for kernel in ['linear', 'poly', 'rbf']:
    cv = cross_val_score(SVC(kernel=kernel, degree=3), X_tr, y_tr, cv=5).mean()
    test_acc = SVC(kernel=kernel, degree=3).fit(X_tr, y_tr).score(X_te, y_te)
    print(f"{kernel:6}: CV={cv:.3f}, test={test_acc:.3f}")
```

```output
linear: CV=0.859, test=0.925
poly  : CV=0.859, test=0.900
rbf   : CV=0.925, test=0.950
```

On the two-moons data, the RBF kernel wins on both CV (0.925) and test (0.950). Linear and
cubic polynomial kernels tie on CV at 0.859. Notice that the linear SVM's test score (0.925)
is far above its CV score — one 80-point test split can flatter a model, which is why you
choose by CV.

Try `SVC(kernel='rbf', C=10)`. The CV accuracy should rise to about 0.959, because the
default $C = 1$ was a little too forgiving for this data.

## Exercise

Generate a 2D XOR problem (four quadrants, alternating labels). Show that a linear SVM and logistic regression both fail (near 50% accuracy). Then show that an RBF SVM achieves >95% accuracy. Explain geometrically why RBF works.

> **Hint:** XOR means "one or the other, not both": label 1 when exactly one coordinate is
> positive. Python's `^` operator on boolean arrays does exactly this.

<details>
<summary>Solution</summary>

```python
import numpy as np
from sklearn.svm import SVC
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
n = 400
X = rng.uniform(-1, 1, (n, 2))
y = ((X[:, 0] > 0) ^ (X[:, 1] > 0)).astype(int)   # XOR

X_tr, X_te = X[:300], X[300:]
y_tr, y_te = y[:300], y[300:]

for name, clf in [
    ("Logistic", LogisticRegression()),
    ("Linear SVM", SVC(kernel='linear')),
    ("RBF SVM", SVC(kernel='rbf', gamma=2)),
]:
    acc = clf.fit(X_tr, y_tr).score(X_te, y_te)
    print(f"{name}: {acc:.3f}")
# RBF SVM works because in the feature space defined by the RBF kernel,
# the four XOR quadrants become linearly separable.
```

On this run logistic regression scores 0.660 and the linear SVM 0.640 — clearly failing, though
a bit above 50%, because a line can still exploit small imbalances in a random sample of 100
test points. The RBF SVM scores 0.960. Geometrically, no single line can put two diagonally
opposite quadrants on one side and the other two on the other side. The RBF SVM doesn't need
a line in the original space: its decision function is a sum of bumps centred on support
vectors, so it can place positive bumps in two quadrants and negative bumps in the other two.
</details>
