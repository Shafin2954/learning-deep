## The exponential family

Linear regression assumes bell-curve noise; logistic regression assumes coin-flip outcomes.
Both are members of one family of distributions that share a single algebraic shape, and
that shared shape is why one recipe can fit all of them.

Linear and logistic regression are special cases of one family. A distribution belongs to the **exponential family** if its density can be written as:

$$
p(y;\theta,\phi) = \exp\!\left[\frac{y\theta - b(\theta)}{a(\phi)} + c(y,\phi)\right]
$$

> **In plain words:**
> - $y$ is the observed value.
> - $\theta$ ("theta") is the dial that sets where the distribution sits.
> - $b(\theta)$ is a fixed helper function that makes the probabilities add up to 1.
> - $a(\phi)$ scales the spread; $\phi$ ("phi") measures how noisy the data is.
> - $c(y, \phi)$ is a leftover term that doesn't involve $\theta$, so it never affects fitting.
>
> The important part is that $y$ and $\theta$ meet only in the simple product $y\theta$.

where $\theta$ is the **natural parameter**, $b(\theta)$ is the log-partition function, and $\phi$ is a dispersion parameter. The key property: $E[Y]=b'(\theta)$, $\text{Var}[Y]=b''(\theta)a(\phi)$.

That key property is the magic trick: once you know $b$, you get the mean by
differentiating it once and the variance by differentiating it twice. The **log-partition
function** is the name for $b$; a **dispersion parameter** is a spread knob.

| Distribution | $b(\theta)$ | $E[Y]$ | $\text{Var}[Y]$ |
|---|---|---|---|
| Normal | $\theta^2/2$ | $\theta=\mu$ | $\sigma^2$ |
| Bernoulli | $\log(1+e^\theta)$ | $\sigma(\theta)$ | $p(1-p)$ |
| Poisson | $e^\theta$ | $e^\theta$ | $e^\theta=\mu$ |
| Gamma | $-\log(-\theta)$ | $-1/\theta$ | $\mu^2/r$ |

Read the variance column. For the Normal it is a constant: noise is the same size
everywhere. For the Poisson it equals the mean: bigger counts are noisier. For the Gamma it
grows like the mean squared ($r$ is the Gamma's shape parameter). Choosing a distribution is
mostly choosing how noise grows with the mean.

> **Picture it:** a set of cake recipes that all start "mix flour, sugar, and eggs, then
> bake". They differ only in one ingredient ($b$). Because the method is shared, one oven
> program (the fitting algorithm) bakes all of them.

## Link functions

A **link function** translates between the model's straight-line score, which can be any
number, and the mean of $y$, which may be restricted to be positive or between 0 and 1.

A GLM specifies a linear predictor $\eta = X\beta$ and a **link function** $g$ connecting $\eta$ to $E[Y]=\mu$:

$$
g(\mu) = \eta = X\beta
$$

> **In plain words:** $\mu$ is the average $y$ you expect for these features. You don't
> model $\mu$ as a straight line directly; you model $g(\mu)$ as a straight line $X\beta$.
> $\beta$ ("beta") is the weight vector — the statistics name for $w$ — and $\eta$ ("eta") is
> the straight-line score. To predict, undo the link: $\mu = g^{-1}(\eta)$.

A **GLM** (generalized linear model) is the combination: a distribution from the family
above, plus a link, plus a linear predictor.

The **canonical link** is $g = (b')^{-1}$; it makes the gradient especially clean.

| Distribution | Canonical link | Inverse link |
|---|---|---|
| Normal | identity $g(\mu)=\mu$ | $\mu=\eta$ |
| Bernoulli | logit $g(\mu)=\log\frac{\mu}{1-\mu}$ | $\mu=\sigma(\eta)$ |
| Poisson | log $g(\mu)=\log\mu$ | $\mu=e^\eta$ |
| Gamma | inverse $g(\mu)=1/\mu$ | $\mu=1/\eta$ |

The second row is ch. 4 in disguise: logistic regression is the Bernoulli GLM, and its
inverse link is the sigmoid. The first row is ch. 2: linear regression is the Normal GLM
with no translation at all.

> **Watch out:** the canonical Gamma link $1/\mu$ can produce negative or infinite means if
> $\eta$ crosses zero. In practice almost everyone fits Gamma models with the log link
> instead, as below.

## Poisson regression

Counts — calls per hour, accidents per month — can't be negative, come in whole numbers,
and get noisier as they get bigger. Poisson regression is the GLM built for exactly that
kind of target.

Count data (events per unit time) violates Normal assumptions: values are non-negative integers and variance scales with mean. Poisson regression uses the log link:

$$
\log E[Y_i] = \beta_0 + \beta_1 x_{i1} + \cdots
$$

> **In plain words:** the *log* of the expected count is a straight line in the features.
> Undoing the log means the expected count is $e^{\text{straight line}}$, which is always
> positive.

The parameter $\beta_j$ says: a one-unit increase in $x_j$ multiplies the expected count by $e^{\beta_j}$.

For example, $\beta_j = 0.1$ means each extra unit raises the expected count by a factor of
$e^{0.1} \approx 1.105$, about 10.5%. Effects multiply rather than add.

The simulation creates 500 hourly counts whose true log-rate rises with temperature, plus a
small daily cycle, then fits both a Poisson model and ordinary linear regression.

```python
import numpy as np
import pandas as pd
from sklearn.linear_model import PoissonRegressor, LinearRegression
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(0)
n = 500
temp  = rng.uniform(10, 35, n)          # temperature in Celsius
hour  = rng.uniform(0, 24, n)
# True log-rate: warm afternoons have more events
log_rate = 0.08 * temp + 0.05 * np.sin(2 * np.pi * hour / 24) - 0.5
counts = rng.poisson(np.exp(log_rate))  # actual counts

X = StandardScaler().fit_transform(np.column_stack([temp, hour]))
y = counts.astype(float)

X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

poi  = PoissonRegressor(alpha=0).fit(X_tr, y_tr)
ols  = LinearRegression().fit(X_tr, y_tr)

poi_pred = poi.predict(X_te)
ols_pred = ols.predict(X_te)

print(f"Poisson MAE: {np.mean(np.abs(poi_pred - y_te)):.3f}")
print(f"Linear  MAE: {np.mean(np.abs(ols_pred - y_te)):.3f}")
print(f"Poisson negative predictions: {(poi_pred < 0).sum()}")
print(f"Linear  negative predictions: {(ols_pred < 0).sum()}")
```

```output
Poisson MAE: 1.686
Linear  MAE: 1.765
Poisson negative predictions: 0
Linear  negative predictions: 2
```

Poisson wins on accuracy (MAE 1.686 against 1.765), but the bigger point is the last two
lines: the linear model predicts a negative count for 2 of the 100 test hours, while the
Poisson model predicts 0 negatives.

Linear regression predicts negative counts — impossible for count data. Poisson regression, by modelling the log of the mean, always predicts non-negative values.

## Deviance: the generalized loss

**Deviance** measures how far your model is from a perfect model that fits every point
exactly. It plays the same role for every GLM that MSE plays for linear regression.

MSE is the natural loss for Normal regression. For GLMs, the generalisation is **deviance**:

$$
D = 2\sum_i \left[\ell(y_i; y_i) - \ell(y_i; \hat{\mu}_i)\right]
$$

> **In plain words:** $\ell(y_i; y_i)$ is the log-likelihood of a **saturated** model —
> one that predicts each $y_i$ exactly. $\ell(y_i; \hat{\mu}_i)$ is the log-likelihood your
> model achieves. Deviance is twice the shortfall, summed over the data. Zero means perfect.

where $\ell$ is the log-likelihood. For Poisson: $D = 2\sum_i [y_i\log(y_i/\hat{\mu}_i) - (y_i - \hat{\mu}_i)]$. This reduces to MSE for Normal.

(For the Normal, deviance is the sum of squared errors divided by $\sigma^2$ — MSE up to a
constant factor.)

The code computes the mean Poisson deviance by hand. When $y_i = 0$ the term
$y_i \log(\cdot)$ is defined to be 0, which the `np.where` handles; linear predictions are
clipped to 0.001 because the log of a negative mean doesn't exist.

```python
def poisson_deviance(y_true, y_pred):
    y_pred = np.maximum(y_pred, 1e-10)
    ratio = np.where(y_true > 0, y_true / y_pred, 1.0)
    return 2 * np.mean(y_true * np.log(ratio) - (y_true - y_pred))

print(f"Poisson deviance: {poisson_deviance(y_te, poi_pred):.4f}")
print(f"Linear  deviance: {poisson_deviance(y_te, np.maximum(ols_pred, 0.001)):.4f}")
```

```output
Poisson deviance: 1.2440
Linear  deviance: 1.5688
```

Lower is better: the Poisson model scores 1.2440 against 1.5688 for linear regression, a
gap of about 21%. Deviance shows the difference more clearly than MAE did, because it
weighs errors the way a count model should.

> **Watch out:** a linear model's predictions had to be clipped to be scored at all. If a
> model can output impossible values, a deviance that "works" only after clipping is
> flattering it.

## Gamma regression

Some targets are positive amounts with a long right tail: most claims are small, a few are
huge. The Gamma GLM handles this shape, with noise that grows with the size of the amount.

When the response is continuous, positive, and right-skewed (insurance claims, revenue, duration), the Gamma distribution with log link is appropriate:

$$
\log E[Y_i] = X_i\beta, \quad \text{Var}[Y_i] = \mu_i^2/\alpha
$$

> **In plain words:** the log of the mean is a straight line, as with Poisson. The
> variance is the mean squared divided by the shape $\alpha$: a claim averaging 10,000 has a
> spread 10 times larger than one averaging 1,000. Note that this $\alpha$ is the Gamma
> shape parameter (the $r$ of the table above), not sklearn's penalty `alpha`.

The log link means predictions are always positive. Fitting uses IRLS (iteratively reweighted least squares), the same algorithm as logistic regression.

**IRLS** solves a weighted linear regression, recomputes the weights from the new
predictions, and repeats until nothing changes. (sklearn's `GammaRegressor` uses the
L-BFGS optimizer by default; both reach the same answer.)

```python
from sklearn.linear_model import GammaRegressor

rng2 = np.random.default_rng(1)
n2 = 400
x1 = rng2.uniform(0, 5, n2)
x2 = rng2.uniform(0, 3, n2)
log_mean = 0.5 * x1 + 0.3 * x2
shape = 2.0
scale = np.exp(log_mean) / shape
y_gamma = rng2.gamma(shape, scale, n2)  # positive, skewed

X2 = np.column_stack([x1, x2])
X2_tr, X2_te, y2_tr, y2_te = train_test_split(X2, y_gamma, test_size=0.2, random_state=0)

gamma_reg = GammaRegressor(alpha=0).fit(X2_tr, y2_tr)
print(f"Gamma regression MAE: {np.mean(np.abs(gamma_reg.predict(X2_te) - y2_te)):.3f}")
print(f"Learned coefs: {gamma_reg.coef_.round(3)}, true: [0.5, 0.3]")
```

```output
Gamma regression MAE: 4.110
Learned coefs: [0.511 0.402], true: [0.5, 0.3]
```

The first coefficient is close to the truth (0.511 against 0.5). The second is off by a
third (0.402 against 0.3). With shape 2, Gamma noise is large — the standard deviation is
about 70% of the mean — and 320 training points are not enough to pin down a weaker effect
on a narrower feature (x2 spans only 0 to 3). The MAE of 4.110 looks big, but it is measured
on a target that reaches values above 30.

## Recap in plain words

- Normal, Bernoulli, Poisson, and Gamma share one exponential-family shape, so one recipe fits them all.
- A GLM is a distribution, a link function, and a linear predictor $X\beta$.
- The link maps the unbounded straight-line score to the allowed range of the mean.
- Poisson regression with a log link is the right tool for counts: it never predicts negatives and its effects multiply.
- Deviance generalizes MSE: twice the gap between your log-likelihood and a perfect model's.
- Gamma regression with a log link fits positive, right-skewed amounts whose noise grows with their size.

## Try it Yourself

```python
import numpy as np
from sklearn.linear_model import PoissonRegressor, LinearRegression
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(7)
n = 600
# Simulate web traffic: count of clicks per hour
weekend = (rng.integers(0, 7, n) >= 5).astype(float)
promo   = rng.binomial(1, 0.3, n).astype(float)
log_lam = 1.5 + 0.8 * weekend + 1.2 * promo
clicks  = rng.poisson(np.exp(log_lam))

X = StandardScaler().fit_transform(np.column_stack([weekend, promo]))
from sklearn.model_selection import train_test_split
X_tr, X_te, y_tr, y_te = train_test_split(X, clicks.astype(float), test_size=0.2, random_state=0)

poi = PoissonRegressor(alpha=0).fit(X_tr, y_tr)
lin = LinearRegression().fit(X_tr, y_tr)

for name, m in [("Poisson", poi), ("Linear", lin)]:
    mae = np.mean(np.abs(m.predict(X_te) - y_te))
    neg = (m.predict(X_te) < 0).sum()
    print(f"{name}: MAE={mae:.2f}, negatives={neg}")
```

```output
Poisson: MAE=2.49, negatives=0
Linear: MAE=3.08, negatives=0
```

The clicks follow a Poisson rate that jumps on weekends and during promotions. Poisson
regression cuts the MAE from 3.08 to 2.49. Neither model predicts negatives here, because
the smallest true rate is $e^{1.5} \approx 4.5$ clicks — far from zero. The Poisson model
still wins because the true effects multiply (weekend *and* promo is far more than the sum)
and a straight line can only add them.

Try lowering the intercept from `1.5` to `-0.5` and print `lin.predict(X_te).min()`. The
smallest linear prediction falls from about 3.18 to about 0.51 — but it stays positive.
With only two yes/no features the line can produce just four different values, each close
to a group average, and an average of counts can't be negative. Negatives need a
continuous feature that lets the line extrapolate, as in the exercise below.

## Exercise

Simulate an insurance claim dataset: claim frequency follows Poisson with rate $e^{0.3\cdot\text{age}/10 + 0.5\cdot\text{risk}}$. Fit Poisson regression and linear regression. Show that (a) Poisson predicts better (lower MAE), and (b) linear regression predicts negative claims on at least some test samples.

> **Hint:** you need some low rates for negatives to appear. Subtract a constant inside the
> exponent so young, low-risk customers have well under one expected claim.

<summary>Solution</summary>

```python
import numpy as np
from sklearn.linear_model import PoissonRegressor, LinearRegression
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(42)
n = 1000
age  = rng.uniform(18, 70, n)
risk = rng.choice([0, 1, 2], n, p=[0.5, 0.3, 0.2]).astype(float)
log_rate = 0.3 * age / 10 + 0.5 * risk - 1.0
claims = rng.poisson(np.exp(log_rate))

X = StandardScaler().fit_transform(np.column_stack([age, risk]))
X_tr, X_te, y_tr, y_te = train_test_split(X, claims.astype(float), test_size=0.25, random_state=0)

poi = PoissonRegressor(alpha=0).fit(X_tr, y_tr)
lin = LinearRegression().fit(X_tr, y_tr)

pp, lp = poi.predict(X_te), lin.predict(X_te)
print(f"Poisson MAE: {np.mean(np.abs(pp - y_te)):.3f}, negatives: {(pp < 0).sum()}")
print(f"Linear  MAE: {np.mean(np.abs(lp - y_te)):.3f}, negatives: {(lp < 0).sum()}")
```

Running this prints a Poisson MAE of 1.178 with 0 negatives and a linear MAE of 1.292 with
6 negative predictions out of 250. The `- 1.0` in the log-rate is what makes (b) happen: it
puts the youngest low-risk customers near $e^{-0.46} \approx 0.63$ expected claims, where
a straight line easily dips below zero.
