## The boosting idea

**Boosting** builds a team of small models one at a time, where each new member studies the
mistakes of the team so far and tries to fix them. Bagging (ch. 11) averages independent
experts; boosting trains a chain of specialists.

Bagging builds trees in parallel from independent bootstrap samples. Boosting builds trees **sequentially**: each tree corrects the errors of the previous ensemble. The model grows stronger with each addition.

> **Picture it:** a student revising for an exam with flashcards. After each round, the
> cards they got wrong go to the front of the pile and get more attention next round. After
> many rounds, the hard cards have had the most practice.

> **Watch out:** bagging fights *variance* by averaging deep trees. Boosting fights *bias* by
> stacking up shallow ones. The flip side is that boosting can overfit if you let it run
> too long, which bagging can't.

## AdaBoost

**AdaBoost** (adaptive boosting) keeps a weight on every training point. After each round,
points the latest model got wrong gain weight, so the next model is pushed to get them right.

AdaBoost trains a sequence of weak learners on **reweighted** training data. Misclassified points get higher weights, forcing the next learner to focus on them.

A **weak learner** is a model only a little better than guessing — typically a **stump**, a
decision tree with a single question (ch. 10).

### Algorithm

Given binary labels $y_i \in \{-1, +1\}$ and initial uniform weights $w_i = 1/n$:

1. Fit a weak learner $h_t$ on the weighted data.
2. Compute its weighted error: $\varepsilon_t = \sum_i w_i \mathbf{1}[h_t(x_i) \ne y_i]$.
3. Compute learner weight: $\alpha_t = \frac{1}{2}\ln\frac{1 - \varepsilon_t}{\varepsilon_t}$.
4. Update sample weights: $w_i \leftarrow w_i \exp(-\alpha_t y_i h_t(x_i))$, then renormalise.
5. Final: $H(x) = \text{sign}\!\left(\sum_t \alpha_t h_t(x)\right)$.

Reading the steps in plain words:

- Step 2: the error $\varepsilon_t$ is the total weight of the points the stump got wrong.
- Step 3: a stump's say in the final vote, $\alpha_t$, is large when its error is small. At
  error 0.5 (a coin flip) $\alpha_t = 0$: no say at all.
- Step 4: $y_i h_t(x_i)$ is $+1$ for a correct point and $-1$ for a wrong one. So correct
  points have their weight multiplied by $e^{-\alpha_t}$ (shrunk) and wrong points by
  $e^{\alpha_t}$ (grown).
- Step 5: the final prediction is a weighted vote of all stumps; `sign` turns the total
  into $+1$ or $-1$.

```python
import numpy as np
from sklearn.tree import DecisionTreeClassifier

def adaboost_fit(X, y, n_estimators=50):
    n = len(y)
    w = np.ones(n) / n
    stumps, alphas = [], []
    for _ in range(n_estimators):
        stump = DecisionTreeClassifier(max_depth=1)
        stump.fit(X, y, sample_weight=w)
        pred = stump.predict(X)
        err  = np.sum(w * (pred != y)) / np.sum(w)
        err  = np.clip(err, 1e-10, 1 - 1e-10)
        alpha = 0.5 * np.log((1 - err) / err)
        w *= np.exp(-alpha * y * pred)
        w /= w.sum()
        stumps.append(stump); alphas.append(alpha)
    return stumps, alphas

def adaboost_predict(stumps, alphas, X):
    vote = sum(a * s.predict(X) for a, s in zip(alphas, stumps))
    return np.sign(vote)

from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=400, n_features=2, n_redundant=0,
                             n_clusters_per_class=1, random_state=0)
y = 2*y - 1   # {-1, +1}
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

stumps, alphas = adaboost_fit(X_tr, y_tr, n_estimators=100)
pred = adaboost_predict(stumps, alphas, X_te)
scratch_acc = np.mean(pred == y_te)
print(f"Scratch AdaBoost: {scratch_acc:.3f}")
```

```output
Scratch AdaBoost: 0.838
```

A hundred stumps reach 0.838 accuracy on the 80 test points. One stump can only draw one
straight horizontal or vertical cut; the weighted vote of 100 of them builds a staircase
boundary.

Now the library version on the same split:

```python
from sklearn.ensemble import AdaBoostClassifier

sk_ada = AdaBoostClassifier(n_estimators=100, random_state=0).fit(X_tr, y_tr)
print(f"Sklearn AdaBoost: {sk_ada.score(X_te, y_te):.3f}")
```

```output
Sklearn AdaBoost: 0.838
```

sklearn's `AdaBoostClassifier` (which also uses stumps by default) scores the same 0.838 —
the from-scratch loop is doing what the library does.

## Exponential loss interpretation

AdaBoost's reweighting rule is not an arbitrary trick: it falls out of minimizing one
particular loss, step by step.

AdaBoost minimises the **exponential loss** $L(y, f) = e^{-yf(x)}$. The weight update is the gradient step that reduces this loss. This connection reveals AdaBoost as a form of gradient descent in function space.

Here $f(x)$ is the ensemble's running score before the `sign`. When a point is right with a
big margin, $yf(x)$ is large and positive, so the loss $e^{-yf(x)}$ is close to 0. When a
point is badly wrong, the loss grows exponentially. Each point's AdaBoost weight is
proportional to its current exponential loss.

**Gradient descent in function space** means: instead of nudging a list of numbers (weights)
downhill, you nudge the whole prediction function downhill by adding a new small model to it.

> **Watch out:** the exponential loss punishes badly-wrong points so hard that a few
> mislabeled points can soak up most of the weight. AdaBoost is fragile on noisy labels.

## Gradient Boosting: the functional gradient view

**Gradient boosting** is the general recipe: work out, for each training point, which
direction its prediction should move to reduce the loss, and fit the next tree to those
directions. For squared error, that direction is the leftover error itself.

Gradient boosting generalises AdaBoost to **any differentiable loss**. The key insight:

> The residuals $y - \hat{y}$ are the **negative gradient** of MSE loss. Fitting the next tree to the residuals is gradient descent in function space.

For MSE loss $L(y, f) = \frac{1}{2}(y - f)^2$: negative gradient $= y - f(x) =$ residuals.
For log-loss (classification): negative gradient $= y - \sigma(f(x))$.

A **residual** is what's left over: the true value minus the current prediction. For
log-loss with labels 0 and 1, the residual is the label minus the predicted probability —
the same "error" you met in logistic regression's gradient (ch. 4).

> **Picture it:** a sculptor roughing out a statue. The first tree chops off the big chunks;
> each later tree removes a little of what is still wrong. No single cut makes the statue,
> but the sum of many small corrections does.

### Algorithm

Given initial prediction $f_0 = \bar{y}$, for $m = 1, \ldots, M$:

1. Compute pseudo-residuals: $r_i = -\frac{\partial L(y_i, f(x_i))}{\partial f(x_i)}$
2. Fit a regression tree $h_m$ to the pseudo-residuals.
3. Update: $f \leftarrow f + \eta \cdot h_m$

**Pseudo-residuals** are the negative gradients for a general loss; they equal the plain
residuals for squared error. The start $f_0 = \bar{y}$ predicts the average for everyone.
$\eta$ ("eta") is the learning rate: how much of each tree's correction you actually apply.

```python
import numpy as np
from sklearn.tree import DecisionTreeRegressor

def gradient_boosting_fit(X, y, n_estimators=100, lr=0.1, max_depth=3):
    f = np.full(len(y), y.mean())
    trees = []
    for _ in range(n_estimators):
        residuals = y - f            # negative gradient of MSE
        tree = DecisionTreeRegressor(max_depth=max_depth, random_state=0)
        tree.fit(X, residuals)
        f += lr * tree.predict(X)
        trees.append(tree)
    return trees, y.mean()

def gradient_boosting_predict(trees, f0, X, lr=0.1):
    pred = np.full(len(X), f0)
    for tree in trees:
        pred += lr * tree.predict(X)
    return pred

from sklearn.datasets import make_regression
from sklearn.model_selection import train_test_split

X, y = make_regression(n_samples=500, n_features=10, noise=20, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

trees, f0 = gradient_boosting_fit(X_tr, y_tr, n_estimators=100)
pred = gradient_boosting_predict(trees, f0, X_te)
rmse = np.sqrt(np.mean((pred - y_te)**2))
print(f"Scratch GB RMSE: {rmse:.2f}")
```

```output
Scratch GB RMSE: 51.55
```

The from-scratch booster — 100 depth-3 trees at learning rate 0.1 — gets a test RMSE of
51.55. **RMSE** (root mean squared error) is in the same units as $y$; for scale, $y$ here
has a standard deviation of about 144, so the model removes most of the spread but not all.

```python
from sklearn.ensemble import GradientBoostingRegressor

sk_gb = GradientBoostingRegressor(n_estimators=100, learning_rate=0.1,
                                    max_depth=3, random_state=0).fit(X_tr, y_tr)
sk_rmse = np.sqrt(np.mean((sk_gb.predict(X_te) - y_te)**2))
print(f"Sklearn GB RMSE: {sk_rmse:.2f}")
```

```output
Sklearn GB RMSE: 51.43
```

sklearn's `GradientBoostingRegressor` with the same settings scores 51.43 — within 0.12 of
the scratch version. The small gap comes from sklearn's split search details, not a different
algorithm.

> **Watch out:** `make_regression` produces a *linear* target, which is the worst case for
> trees: each tree approximates a sloped plane with flat steps. A plain `LinearRegression` on
> this split scores an RMSE of about 21.5, less than half the boosters' 51. Boosting shines on non-linear, interacting, tabular data.

## Shrinkage

**Shrinkage** means applying only a fraction of each tree's correction. Many small careful
steps end up somewhere better than a few big lunges.

The learning rate $\eta \in (0,1)$ scales each tree's contribution. Smaller $\eta$ requires more trees but generalises better — it prevents any single tree from over-correcting.

Roughly, halving $\eta$ calls for doubling the number of trees to reach the same training fit.
The Try-it below shows what happens when the tree count is held fixed instead.

## Stochastic GBM

**Stochastic gradient boosting** fits each new tree on a random fraction of the rows. Each
tree sees a slightly different picture, which adds a helpful dose of randomness — the same
idea as bagging, applied inside boosting.

At each step, subsample a fraction of rows (and/or columns) before fitting the tree. This:
- Reduces overfitting (adds noise, like dropout).
- Speeds up training (smaller dataset per tree).
- Decorrelates trees slightly.

(**Dropout** is the neural-network trick of switching off random units during training;
here, the random part is which rows each tree sees.)

```python
from sklearn.ensemble import GradientBoostingRegressor
import numpy as np

for subsample in [1.0, 0.8, 0.5]:
    gb = GradientBoostingRegressor(n_estimators=200, learning_rate=0.05,
                                    max_depth=3, subsample=subsample,
                                    random_state=0).fit(X_tr, y_tr)
    rmse = np.sqrt(np.mean((gb.predict(X_te) - y_te)**2))
    print(f"subsample={subsample}: RMSE={rmse:.2f}")
```

```output
subsample=1.0: RMSE=51.56
subsample=0.8: RMSE=45.79
subsample=0.5: RMSE=41.53
```

Subsampling helps clearly on this data: RMSE falls from 51.56 with all rows, to 45.79 with
80%, to 41.53 with half the rows per tree — about 19% lower error, while each tree also trains
on half as much data.

## Recap in plain words

- Boosting adds small models one after another, each fixing what the ensemble still gets wrong.
- AdaBoost reweights points: mistakes gain weight, and each stump's vote depends on its accuracy.
- AdaBoost is gradient descent on the exponential loss, which makes it sensitive to label noise.
- Gradient boosting fits each new tree to the negative gradient of any loss — the residuals for squared error.
- A small learning rate (shrinkage) needs more trees but generalizes better.
- Subsampling rows per tree (stochastic boosting) adds helpful randomness and speeds training.

## Try it Yourself

```python
import numpy as np
from sklearn.datasets import make_regression
from sklearn.model_selection import train_test_split
from sklearn.ensemble import GradientBoostingRegressor

X, y = make_regression(n_samples=600, n_features=15, noise=25, random_state=1)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

# Compare learning rate effect
print(f"{'lr':>6} | {'n_trees':>7} | {'RMSE':>7}")
for lr in [0.01, 0.05, 0.1, 0.3, 1.0]:
    gb = GradientBoostingRegressor(n_estimators=200, learning_rate=lr,
                                    max_depth=3, random_state=0).fit(X_tr, y_tr)
    rmse = np.sqrt(np.mean((gb.predict(X_te) - y_te)**2))
    print(f"{lr:>6} | {200:>7} | {rmse:>7.2f}")
```

```output
    lr | n_trees |    RMSE
  0.01 |     200 |  136.77
  0.05 |     200 |   84.42
   0.1 |     200 |   74.97
   0.3 |     200 |   78.85
   1.0 |     200 |  124.18
```

With the tree count fixed at 200, the learning rate has a clear sweet spot. At 0.01, RMSE is
136.77: 200 tiny steps cover only part of the distance. It falls to 74.97 at 0.1, rises to
78.85 at 0.3, and jumps to 124.18 at 1.0, where each tree applies its full correction and the
model overfits the training noise.

Try `n_estimators=2000` with `learning_rate=0.01`. Ten times more trees lets the small rate
catch up: RMSE drops to about 74.7, slightly better than the 0.1 row — the "smaller rate,
more trees" trade from the Shrinkage section.

## Exercise

Using `make_regression` (500 samples, 20 features, noise=15), implement gradient boosting from scratch using max_depth=2 stumps. Compare RMSE at 50, 100, and 200 trees vs `sklearn.GradientBoostingRegressor`. Your RMSE should be within 10%.

> **Hint:** keep a running training prediction `f`, fit each tree to `y_tr - f`, and add
> `0.1 * tree.predict(...)`. For the test prediction, start from `y_tr.mean()` and add up the
> same scaled tree predictions.

```python
import numpy as np
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.datasets import make_regression
from sklearn.model_selection import train_test_split

X, y = make_regression(n_samples=500, n_features=20, noise=15, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)

f = np.full(len(y_tr), y_tr.mean())
trees = []

def rmse(a, b): return np.sqrt(np.mean((a-b)**2))

for m in range(200):
    r = y_tr - f
    t = DecisionTreeRegressor(max_depth=2, random_state=0).fit(X_tr, r)
    f += 0.1 * t.predict(X_tr)
    trees.append(t)
    if (m+1) in [50, 100, 200]:
        pred = y_tr.mean() + 0.1 * sum(t.predict(X_te) for t in trees)
        sk = GradientBoostingRegressor(n_estimators=m+1, learning_rate=0.1, max_depth=2).fit(X_tr, y_tr)
        print(f"m={m+1:3}: scratch={rmse(pred,y_te):.2f}, sklearn={rmse(sk.predict(X_te),y_te):.2f}")
```

Running it prints scratch against sklearn RMSE of 78.19 against 78.19 at 50 trees, 60.23
against 60.23 at 100, and 47.96 against 47.92 at 200 — far inside the 10% target. The
algorithms are the same: sklearn's squared-error gradient boosting fits trees to residuals,
starting from the mean. (Strictly, depth-2 trees are not stumps — a stump has depth 1 — but
the method is unchanged.) Note how RMSE keeps falling with more trees: at learning rate 0.1
and depth 2, 200 trees are not yet enough.
