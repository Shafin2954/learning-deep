## The model and the loss

Linear regression guesses an answer by adding up the inputs, each multiplied by its own
importance number, plus a starting offset. Learning means finding the importance numbers
that make the guesses closest to the truth.

Linear regression models the output as a linear function of the features:

$$
\hat{y} = x^T w + b = \sum_{j=1}^d x_j w_j + b
$$

> **In plain words:**
> - $x$ is one example's list of $d$ **features** (the measured inputs, like size and age of a house).
> - $w$ is the list of **weights** — one importance number per feature.
> - $b$ is the **bias** (intercept) — the prediction when every feature is zero.
> - $\hat{y}$ ("y-hat") is the prediction: multiply each feature by its weight, add them up, add $b$.

> **Picture it:** a shop till. Each item (feature) has a price tag (weight); the till
> multiplies quantity by price for every item and adds a fixed service charge (bias).
> Learning is reverse-engineering the price tags from a stack of old receipts.

Absorb the bias into the weight vector by appending a 1 to each feature vector:
$\tilde{x} = [x_1, \ldots, x_d, 1]^T$, $\tilde{w} = [w_1, \ldots, w_d, b]^T$. Then
$\hat{y} = \tilde{x}^T \tilde{w}$.

That trick means the service charge becomes one more price tag on an item that every
receipt contains exactly once. From here on, $w$ includes $b$ as its last entry.

For a batch of $N$ examples, write $X \in \mathbb{R}^{N \times (d+1)}$ (rows = examples)
and minimize mean squared error:

$$
L(w) = \frac{1}{N} \|Xw - y\|^2 = \frac{1}{N}(Xw - y)^T(Xw - y)
$$

> **In plain words:** $Xw$ is the column of all $N$ predictions at once. Subtract the true
> answers $y$, square every miss, add them up (that's what $\|\cdot\|^2$ means), and divide
> by $N$. The second form writes the same sum as a vector dotted with itself.

## The normal equations — the closed-form solution

The best weights sit at the bottom of a bowl-shaped loss. At the bottom of a bowl the
ground is flat, so you can find the bottom by solving "slope = 0" directly, with no
walking.

Setting $\nabla_w L = 0$ gives the normal equations. The gradient is:

$$
\nabla_w L = \frac{2}{N} X^T(Xw - y) = 0
\implies X^T X w = X^T y
\implies \hat{w} = (X^T X)^{-1} X^T y
$$

> **In plain words:** the **gradient** $\nabla_w L$ is the list of slopes of the loss, one
> per weight. It equals $X^T$ times the misses, scaled by $2/N$. Setting it to zero gives
> the **normal equations** $X^TXw = X^Ty$, and solving them gives the best $\hat{w}$ in one
> shot. This is called a **closed-form** solution: a formula, not a search.

This is exact and requires one matrix inversion. Cost: $O(d^3 + Nd^2)$. For $N \gg d$,
the $O(Nd^2)$ term dominates — fine up to $d \sim 10^4$, expensive beyond.

The code builds 200 examples from known true weights $[2, -1, 0.5]$ and bias 3, adds noise
with standard deviation 0.5, and checks whether the normal equations recover them.

```python
import numpy as np

rng = np.random.default_rng(0)
N, d = 200, 3
X_raw = rng.standard_normal((N, d))
w_true = np.array([2.0, -1.0, 0.5])
b_true = 3.0
y = X_raw @ w_true + b_true + rng.normal(0, 0.5, N)

# Augment with bias column
X = np.c_[X_raw, np.ones(N)]   # shape (N, d+1)

# Normal equations
w_hat = np.linalg.solve(X.T @ X, X.T @ y)   # more stable than inv()
print("True   w:", np.append(w_true, b_true).round(3))
print("Fitted w:", w_hat.round(3))

train_mse = np.mean((X @ w_hat - y) ** 2)
print(f"Train MSE: {train_mse:.4f}")
```

```output
True   w: [ 2.  -1.   0.5  3. ]
Fitted w: [ 1.955 -1.048  0.527  2.982]
Train MSE: 0.2500
```

Every fitted weight lands within 0.05 of its true value: 1.955 for 2, -1.048 for -1,
0.527 for 0.5, and 2.982 for the bias of 3. The small misses come from the noise. The
training MSE of 0.2500 equals the noise variance $0.5^2 = 0.25$, which is the best any model
could do on this data.

Use `np.linalg.solve(A, b)` instead of `np.linalg.inv(A) @ b` — it is numerically more
stable and roughly twice as fast because it uses LU decomposition.

> **Watch out:** computing an explicit inverse and then multiplying amplifies rounding
> errors when $X^TX$ is close to singular. `solve` factors the matrix once (the **LU
> decomposition** — writing it as a lower-triangular times an upper-triangular matrix)
> and back-substitutes, which is both faster and more accurate.

### When the normal equations fail

$X^TX$ is singular (non-invertible) when:
- Features are linearly dependent (one feature is a linear combination of others).
- $N < d$ (more features than samples — underdetermined system).

Example of the first case: a "height in cm" column and a "height in inches" column. Any
weight you move from one to the other (scaled by 2.54) gives identical predictions, so
there is no single best answer and the matrix has no inverse.

The fix: regularization (ch. 3) makes $X^TX + \lambda I$ always invertible.

## Gradient descent — the scalable alternative

Gradient descent finds the bottom of the bowl by walking downhill in small steps instead
of solving for it. Each step looks at the slope under your feet and moves the opposite way.

When $d$ is large or you want to reuse the same algorithm for other models, gradient
descent updates weights iteratively:

$$
w \leftarrow w - \eta \nabla_w L = w - \frac{2\eta}{N} X^T(Xw - y)
$$

> **In plain words:** new weights = old weights minus (step size) times (slope). The slope
> is the same gradient as in the normal equations; here you follow it instead of setting it
> to zero.

$\eta > 0$ is the **learning rate**. Each step is $O(Nd)$ — no matrix inversion.

> **Picture it:** walking down a foggy hill. You can't see the valley, but you can feel
> which way the ground tilts. The learning rate is your stride length: too short and you
> take forever, too long and you leap over the valley onto the opposite slope.

Same data and same true weights as before, now fitted by 200 steps of gradient descent from
all-zero weights.

```python
import numpy as np

rng = np.random.default_rng(0)
N, d = 200, 3
X_raw = rng.standard_normal((N, d))
w_true = np.array([2.0, -1.0, 0.5])
y = X_raw @ w_true + 3.0 + rng.normal(0, 0.5, N)
X = np.c_[X_raw, np.ones(N)]

# Gradient descent
w = np.zeros(d + 1)
lr = 0.1
losses = []
for step in range(200):
    grad = (2 / N) * X.T @ (X @ w - y)
    w -= lr * grad
    losses.append(np.mean((X @ w - y) ** 2))

print(f"GD final w: {w.round(3)}")
print(f"Final MSE:  {losses[-1]:.4f}")
print(f"Loss drop:  {losses[0]:.4f} → {losses[-1]:.4f}")
```

```output
GD final w: [ 1.955 -1.048  0.527  2.982]
Final MSE:  0.2500
Loss drop:  8.8648 → 0.2500
```

The gradient-descent weights `[ 1.955 -1.048  0.527  2.982]` match the normal-equation
weights to all three printed decimals, and the MSE is the same 0.2500. The loss after the
first step was 8.8648, so 200 steps cut it by a factor of about 35.

Both methods converge to the same solution. The learning rate matters: too large and the
loss oscillates or diverges; too small and convergence is slow.

### Choosing the learning rate

The optimal step size for GD on MSE is $\eta = 1 / \lambda_{\max}(X^TX/N)$, where
$\lambda_{\max}$ is the largest eigenvalue of the Gram matrix. In practice, try values
like 0.1, 0.01, 0.001 and watch the loss curve.

The **eigenvalue** here measures how steeply the bowl curves in its steepest direction;
the **Gram matrix** $X^TX/N$ is the table of average feature-times-feature products. For the
data above that largest eigenvalue is about 1.10, so the formula gives $\eta \approx 0.91$.
Because the gradient carries a factor of 2, that is also the edge of stability: a step much
larger makes every update overshoot by more than it corrects. The 0.1 used below is cautious
but steady.

> **Watch out:** features on very different scales (one in metres, one in millimetres) make
> the bowl a long narrow trough. No single learning rate suits both directions, so GD
> zig-zags. Standardize features before running GD.

## The geometric view

Picture all the predictions your model *could* make as a flat sheet floating in space. The
true answers $y$ usually sit slightly off that sheet. The best fit is the point on the sheet
directly beneath $y$ — the spot where a straight drop would land.

The set of all predictions $\{Xw : w \in \mathbb{R}^{d+1}\}$ is the **column space** of $X$.
The normal equations find the $w$ such that $Xw$ is the **orthogonal projection** of $y$ onto
this column space. The residual $y - Xw$ is perpendicular to every column of $X$ — that is
exactly $X^T(Xw - y) = 0$.

> **Picture it:** a lamp straight above a table casts the shadow of a pencil. The shadow is
> the projection; the line from the pencil tip down to its shadow is the **residual** (the
> leftover miss), and it meets the table at a right angle.

```python
import numpy as np

# Verify: residuals are orthogonal to X
rng = np.random.default_rng(0)
X = np.c_[rng.standard_normal((50, 2)), np.ones(50)]
y = X @ np.array([1.0, -0.5, 2.0]) + rng.normal(0, 0.3, 50)
w = np.linalg.solve(X.T @ X, X.T @ y)
residuals = y - X @ w

print("X^T @ residuals (should be ~0):")
print((X.T @ residuals).round(10))
```

```output
X^T @ residuals (should be ~0):
[-0. -0.  0.]
```

All three dot products print as 0 (the minus signs are rounding at the tenth decimal place).
The leftover error has no overlap with any feature column, including the column of ones —
so the residuals also sum to zero. Any leftover pattern a column could explain would already
have been absorbed into the fit.

## Recap in plain words

- Linear regression predicts with a weighted sum of features plus an offset; appending a column of ones folds the offset into the weights.
- The normal equations $X^TXw = X^Ty$ give the exact best weights in one solve.
- Use `np.linalg.solve`, never an explicit inverse.
- The normal equations break when features are redundant or there are fewer rows than features; ridge (ch. 3) repairs that.
- Gradient descent reaches the same answer by repeated downhill steps and scales to huge problems.
- The best fit is a right-angle projection: the residuals are perpendicular to every feature column.

## Try it Yourself

```python
import numpy as np

# Compare GD with different learning rates
rng = np.random.default_rng(5)
N, d = 100, 2
X = np.c_[rng.standard_normal((N, d)), np.ones(N)]
y = X @ np.array([1.5, -0.8, 2.0]) + rng.normal(0, 0.4, N)

for lr in [0.5, 0.1, 0.01]:
    w = np.zeros(d + 1)
    for _ in range(300):
        w -= lr * (2 / N) * (X.T @ (X @ w - y))
    mse = np.mean((X @ w - y) ** 2)
    print(f"lr={lr}: final MSE={mse:.4f}  w={w.round(3)}")
```

```output
lr=0.5: final MSE=0.1446  w=[ 1.498 -0.779  2.005]
lr=0.1: final MSE=0.1446  w=[ 1.498 -0.779  2.005]
lr=0.01: final MSE=0.1447  w=[ 1.487 -0.78   1.998]
```

With 300 steps, learning rates 0.5 and 0.1 both reach the minimum (MSE 0.1446, same
weights). The small rate 0.01 is still short of it: MSE 0.1447 and the first weight is
1.487 instead of 1.498. A stride that is too short leaves you part-way down the hill.

Try `lr=1.0`. The largest eigenvalue of $X^TX/N$ for this data is about 1.08, and with the
factor 2 in the gradient the updates become unstable once $\eta > 1/1.08 \approx 0.93$. At
1.0 the MSE does not shrink — it explodes to an astronomically large number within the 300 steps.

## Exercise

Implement **stochastic gradient descent (SGD)** for linear regression: at each step, pick
one random example $(x_i, y_i)$ and update $w \leftarrow w - \eta \cdot 2(x_i^T w - y_i) x_i$.
Run 500 passes over 100 data points and compare the final MSE with the batch GD above.

> **Hint:** the update uses one row of `X` at a time, so the gradient is a vector of length
> 3, not a matrix product. Draw the row index with `rng.integers(0, N)`.

<summary>Solution</summary>

```python
import numpy as np

rng = np.random.default_rng(5)
N, d = 100, 2
X = np.c_[rng.standard_normal((N, d)), np.ones(N)]
y = X @ np.array([1.5, -0.8, 2.0]) + rng.normal(0, 0.4, N)

w = np.zeros(d + 1)
lr = 0.01
for epoch in range(500):
    idx = rng.integers(0, N)          # one random example
    xi, yi = X[idx], y[idx]
    w -= lr * 2 * (xi @ w - yi) * xi

mse = np.mean((X @ w - y) ** 2)
print(f"SGD final MSE: {mse:.4f}  w: {w.round(3)}")
```

SGD converges to the same neighbourhood as batch GD but with noise; the loss oscillates
around the minimum rather than descending smoothly. Mini-batch GD (batch size 16–256) is
the practical middle ground.

Run as written, this prints an MSE of about 0.153 with weights near `[1.472 -0.854 1.946]` —
close to batch GD's 0.1446, but not on top of it. Note the loop makes 500 single-example
steps, which is only 5 passes over the 100 points; turn `range(500)` into
`range(500 * N)` to do the 500 full passes the problem asks for, and the MSE drops to about
0.146 — closer to 0.1446, but still jittering above it because every step uses a noisy
one-example gradient.
