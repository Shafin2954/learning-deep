## Vectors as points and as directions

A vector is a list of numbers, like `[3, 4]`. You can read it two ways: as a *place*
("3 steps east, 4 steps north of home") or as a *move* ("walk 3 east and 4 north from
wherever you are"). Machine learning uses both readings all the time.

A vector $x \in \mathbb{R}^n$ is just an ordered tuple of real numbers. (Read
$\mathbb{R}^n$ as "lists of $n$ real numbers".) In ML it plays
two roles simultaneously: a **point** in $n$-dimensional space (one data sample, one token
embedding) and a **direction** with a magnitude (a gradient, a weight update). Which role
you emphasize changes how you reason about it.

> **Picture it:** a vector is an arrow on a map. Its tip marks a spot (the point view);
> its length and heading describe a trip (the direction view). Adding two arrows means
> walking one trip, then the other.

```python
import numpy as np

x = np.array([3.0, 4.0], dtype=np.float64)
y = np.array([1.0, 2.0], dtype=np.float64)

print("x       :", x)
print("x + y   :", x + y)       # vector addition — move in direction y from x
print("2 * x   :", 2 * x)       # scalar multiplication — stretch
print("x - y   :", x - y)       # displacement from y to x
```

```output
x       : [3. 4.]
x + y   : [4. 6.]
2 * x   : [6. 8.]
x - y   : [2. 2.]
```

Each operation works number by number. `x + y` is "do trip $x$, then trip $y$": you end
up at `[4, 6]`. `2 * x` keeps the heading but doubles the length. `x - y` is the arrow that
starts at $y$'s tip and ends at $x$'s tip — the **displacement** from $y$ to $x$, which is
what every distance below is built on.

## Norms — measuring size

A **norm** is a rule for "how big is this arrow?". There's more than one sensible answer,
just as "how far is the shop?" depends on whether you fly, drive the streets, or count the
longest single leg.

A **norm** $\|x\|$ is a function that assigns a non-negative scalar to every vector. Three
norms appear constantly in ML:

$$
\|x\|_1 = \sum_i |x_i|, \qquad
\|x\|_2 = \sqrt{\sum_i x_i^2}, \qquad
\|x\|_\infty = \max_i |x_i|
$$

- $\|x\|_1$ (**L1**, "Manhattan"): add up the absolute size of every component.
- $\|x\|_2$ (**L2**, "Euclidean"): square, add, square-root — Pythagoras' straight-line length.
- $\|x\|_\infty$ (**L-infinity**, "max"): the single largest component, ignoring the rest.

> **Picture it:** in a city laid out on a grid, L1 is the taxi distance (you can only drive
> along streets), L2 is the distance a crow flies, and L-infinity is the longest single
> stretch you drive in any one direction.

```python
import numpy as np

x = np.array([3.0, -4.0, 0.0, 1.0], dtype=np.float64)

l1  = np.linalg.norm(x, ord=1)
l2  = np.linalg.norm(x, ord=2)
linf = np.linalg.norm(x, ord=np.inf)

print(f"L1   : {l1}")     # 3+4+0+1
print(f"L2   : {l2}")     # sqrt(9+16+0+1)
print(f"L∞   : {linf}")   # max(3,4,0,1)
```

```output
L1   : 8.0
L2   : 5.0990195135927845
L∞   : 4.0
```

Check each by hand: L1 is $3 + 4 + 0 + 1 = 8$; L2 is $\sqrt{9 + 16 + 0 + 1} = \sqrt{26}
\approx 5.099$; L-infinity is the biggest absolute entry, 4. For the same vector, the order
is always $\|x\|_\infty \le \|x\|_2 \le \|x\|_1$.

### Which norm for what

- **L2** (Euclidean): the default. Minimizing it means "small weights overall"; it penalizes
  large individual weights but not sparsity. Used in Ridge regularization.
- **L1**: sum of absolute values. Minimizing it encourages exact zeros — sparse solutions.
  Used in Lasso regularization. (**Sparse** = most entries exactly zero.)
- **L-infinity** ($\|x\|_\infty$): worst-case magnitude. Used in adversarial robustness
  (bound the maximum perturbation to any single input dimension).

> **In plain words:** **regularization** is adding "and keep the weights small" to a
> model's goal. Measuring "small" with L2 shrinks every weight a little; measuring it with
> L1 tends to switch some weights off completely. Classical ML, ch. 3, shows why.

## The dot product and angle

The **dot product** multiplies two vectors entry by entry and adds up the results. That one
number secretly tells you how much the two arrows point the same way.

The dot product of $x, y \in \mathbb{R}^n$ is:

$$
x \cdot y = x^\top y = \sum_i x_i y_i = \|x\|_2 \|y\|_2 \cos\theta
$$

where $\theta$ is the angle between the vectors. Rearranging:

$$
\cos\theta = \frac{x^\top y}{\|x\|_2 \|y\|_2}
$$

> **In plain words:** the dot product equals (length of $x$) × (length of $y$) × (cosine of
> the angle between them). Divide out both lengths and only the angle part is left. The
> cosine is $1$ when the arrows point the same way, $0$ when they're at right angles, and
> $-1$ when they point in opposite directions.

This is **cosine similarity**. It measures the angle, not the magnitude. Two vectors can
point in exactly the same direction but have very different L2 norms — cosine similarity
sees them as identical (similarity = 1). That's exactly what you want for embeddings:
"dog" and "dogs" should be similar regardless of how the model scaled their representations.
An **embedding** is a vector a model produces to represent a word, sentence, or item, built
so that similar things get arrows pointing in similar directions.

```python
import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# Same direction, different magnitudes
a = np.array([1.0, 2.0, 3.0])
b = 10 * a      # 10× longer, same direction

print("dot(a,b)        :", np.dot(a, b))
print("cos_sim(a, b)   :", cosine_similarity(a, b))   # should be 1.0
print("L2 dist(a, b)   :", np.linalg.norm(a - b))     # 10 × ||a||
```

```output
dot(a,b)        : 140.0
cos_sim(a, b)   : 1.0
L2 dist(a, b)   : 33.67491648096547
```

`b` is `a` stretched 10×, so the cosine similarity is exactly 1.0 — same heading — even
though the arrows' tips are far apart. The distance is $\|a - 10a\| = 9\|a\| = 9\sqrt{14}
\approx 33.67$ (the code comment says 10×, but $b - a$ is $9a$). The dot product $140 =
10 \cdot (1 + 4 + 9)$ grows with length, which is why raw dot products aren't comparable
across vectors of different sizes.

### Cosine vs Euclidean distance

```python
import numpy as np

# Sentence embeddings (unit vectors after normalization)
king   = np.array([0.8, 0.6, 0.0])
queen  = np.array([0.7, 0.7, 0.14])
banana = np.array([0.0, 0.1, 0.995])

def cosine_sim(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

print("cos(king, queen) :", round(cosine_sim(king, queen), 4))
print("cos(king, banana):", round(cosine_sim(king, banana), 4))
print("L2(king, queen)  :", round(np.linalg.norm(king - queen), 4))
print("L2(king, banana) :", round(np.linalg.norm(king - banana), 4))
```

```output
cos(king, queen) : 0.9802
cos(king, banana): 0.06
L2(king, queen)  : 0.199
L2(king, banana) : 1.3711
```

Read the four numbers together. king–queen has a cosine near 1 (almost the same heading)
and a small L2 distance (about 0.2). king–banana has a cosine near 0 (nearly at right
angles) and a large distance (about 1.37).

Both metrics agree that king is close to queen and far from banana, but for
high-dimensional embeddings (dim 768 or 1536) cosine similarity is the standard because all
embeddings tend to have similar magnitudes after normalization, making the angle the
informative part.

> **In plain words:** for unit-length vectors the two measures carry the same information:
> $\|x - y\|_2^2 = 2 - 2\cos\theta$. Ranking by smallest distance and ranking by largest
> cosine give the same order.

## Distances

A **distance** is the norm of the displacement arrow $x - y$: "how big is the trip from one
point to the other?". Each norm gives its own distance.

The L2 norm of the difference vector gives the Euclidean (L2) distance:

$$
d_2(x, y) = \|x - y\|_2
$$

Other useful distances:
- **Manhattan (L1 distance):** $\sum_i |x_i - y_i|$ — robust to outliers.
- **Cosine distance:** $1 - \cos\theta$ — used in retrieval and clustering of embeddings.

L1 is "robust to outliers" because one huge difference counts once, at its size, instead
of being squared into a giant number as L2 does.

```python
import numpy as np

x = np.array([1.0, 0.0, 1.0])
y = np.array([0.0, 1.0, 0.0])

print("L2 distance      :", round(np.linalg.norm(x - y), 4))
print("L1 distance      :", round(np.linalg.norm(x - y, ord=1), 4))
print("cosine distance  :", round(1 - np.dot(x, y) / (np.linalg.norm(x) * np.linalg.norm(y)), 4))
```

```output
L2 distance      : 1.7321
L1 distance      : 3.0
cosine distance  : 1.0
```

The two vectors differ by 1 in each of 3 coordinates, so L1 adds three 1s (3.0) while L2
gives $\sqrt{3} \approx 1.7321$.

Here $x$ and $y$ are orthogonal (dot product = 0), so cosine distance = 1 — maximum dissimilarity.
(**Orthogonal** = at right angles. Strictly, cosine distance can reach 2 for vectors pointing
in exactly opposite directions; for the non-negative features common in text, 1 is the
largest you see.)

## Recap in plain words

- A vector is a list of numbers you can read as a point or as a move.
- Norms measure size: L1 adds absolute values, L2 is straight-line length, L-infinity is
  the biggest component.
- The dot product is lengths × cosine of the angle; divide the lengths out to get cosine
  similarity, which ignores scale.
- A distance is the norm of the difference $x - y$.
- For unit vectors, small L2 distance and large cosine similarity mean the same thing.

## Try it Yourself

```python
import numpy as np

# 1) Normalize a batch of vectors to unit L2 norm (common pre-processing before cosine search)
rng = np.random.default_rng(0)
E = rng.standard_normal((5, 4)).astype(np.float64)   # 5 embeddings, dim 4
norms = np.linalg.norm(E, axis=1, keepdims=True)      # shape (5, 1)
E_unit = E / norms                                     # broadcasting
print("norms after normalization:", np.linalg.norm(E_unit, axis=1).round(8))

# 2) Pairwise cosine similarity matrix — no loop
# For unit vectors: cos(i,j) = E_unit[i] @ E_unit[j] = E_unit @ E_unit.T
C = E_unit @ E_unit.T
print("cosine sim matrix (diagonal = 1):\n", C.round(3))
```

```output
norms after normalization: [1. 1. 1. 1. 1.]
cosine sim matrix (diagonal = 1):
 [[ 1.     0.7   -0.297 -0.615  0.4  ]
 [ 0.7    1.    -0.312 -0.242  0.762]
 [-0.297 -0.312  1.     0.614  0.281]
 [-0.615 -0.242  0.614  1.     0.017]
 [ 0.4    0.762  0.281  0.017  1.   ]]
```

Two ideas in one cell. Dividing each row by its own norm (broadcasting a `(5, 1)` column
against `(5, 4)`) makes every row length 1, as the first line confirms. After that, one
matrix multiply `E_unit @ E_unit.T` computes all 25 pairwise cosines at once: the diagonal
is 1 (each vector against itself) and the matrix is symmetric. Try scaling one row of `E` by
100 before normalizing — the cosine matrix doesn't change.

## Exercise

Given a query embedding $q \in \mathbb{R}^{128}$ and a database of 10 000 unit-normalized
embeddings $E \in \mathbb{R}^{10000 \times 128}$, write a function `top_k(q, E, k)` that
returns the indices of the $k$ most similar embeddings using cosine similarity — in a single
matrix multiply. Verify that for $k=3$ the top result has cosine similarity $\geq 0.9$ when
$q$ is one of the rows in $E$.

> **Hint:** if every row of `E` has length 1, then `E @ q_unit` *is* the cosine similarity
> of `q` with every row. You only need the positions of the largest few scores.

<details>
<summary>Solution</summary>

```python
import numpy as np

def top_k(q, E, k):
    """Return indices of k most similar rows in E (unit-normalized) to query q."""
    q_unit = q / np.linalg.norm(q)
    scores = E @ q_unit          # (N,) — cosine similarity (E already unit-normalized)
    return np.argpartition(scores, -k)[-k:]   # faster than full argsort for large N

rng = np.random.default_rng(42)
E_raw = rng.standard_normal((10_000, 128)).astype(np.float64)
E = E_raw / np.linalg.norm(E_raw, axis=1, keepdims=True)   # unit normalize

q = E[777]   # pick row 777 as the query
idx = top_k(q, E, k=3)
scores = E[idx] @ q
print("top-3 indices:", sorted(idx))
print("top-3 scores :", scores.round(6))
# Row 777 should be in idx with score ≈ 1.0
```

`np.argpartition` is O(N) vs O(N log N) for argsort — use it when you only need the top-k
and don't need them sorted among themselves. The query row itself scores exactly 1.0, so it
always lands in the top 3; the other two are its nearest random neighbours.
</details>
