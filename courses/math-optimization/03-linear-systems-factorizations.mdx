## Gaussian elimination is a factorization in disguise

Almost every model you fit ends in a linear solve. Ordinary and ridge regression solve
$(X^\top X + \lambda I)\mathbf{w} = X^\top\mathbf{y}$, a Gaussian process solves $K\boldsymbol\alpha = \mathbf{y}$ (Bayesian
ML ch. 12), and every Newton step solves $H\boldsymbol\Delta = -\mathbf{g}$ (ch. 12). You learned the method at school:
subtract multiples of one equation from the others until the system is triangular, then read the unknowns off from the
bottom up. The useful idea is to *keep the multipliers*. Stored in a lower-triangular matrix $L$, they reconstruct $A$
from the triangular remainder $U$: $A = LU$. Once you have that, every new right-hand side is cheap.

A tiny example: for $A = \begin{bmatrix}2 & 1\\ 6 & 4\end{bmatrix}$ you subtract 3 times row 1 from row 2, leaving
$U = \begin{bmatrix}2 & 1\\ 0 & 1\end{bmatrix}$. The multiplier 3 goes into $L = \begin{bmatrix}1 & 0\\ 3 & 1\end{bmatrix}$,
and $LU = A$.

### Elimination as multiplication by lower-triangular matrices

This derivation shows why the stored multipliers form $L$, and where the $\tfrac23 n^3$ cost comes from. Step $k$
of elimination on $A \in \mathbb{R}^{n \times n}$ subtracts $\ell_{ik} = u_{ik}/u_{kk}$ times row $k$ from each row
$i > k$ (here $u_{ik}$ is the current entry and $u_{kk}$ the **pivot**). That is left-multiplication by

$$
L_k = I - \boldsymbol\ell_k \mathbf{e}_k^\top, \qquad \boldsymbol\ell_k = (0, \dots, 0, \ell_{k+1,k}, \dots, \ell_{nk})^\top,
$$

where $\mathbf{e}_k$ is the $k$-th unit vector, so $L_{n-1}\cdots L_1 A = U$. Because $\mathbf{e}_k^\top\boldsymbol\ell_k = 0$,
each $L_k$ is inverted by flipping a sign, $L_k^{-1} = I + \boldsymbol\ell_k\mathbf{e}_k^\top$, and the product of the
inverses simply stacks the multipliers in place:

$$
A = \underbrace{L_1^{-1}\cdots L_{n-1}^{-1}}_{L}\,U, \qquad L = I + \sum_{k=1}^{n-1}\boldsymbol\ell_k\mathbf{e}_k^\top .
$$

Step $k$ updates an $(n-k) \times (n-k)$ block with one multiply and one subtract per entry, so

$$
\text{flops} \approx \sum_{k=1}^{n-1} 2(n-k)^2 \approx 2\int_0^n t^2\,dt = \tfrac23 n^3 .
$$

With the row swaps of the next section the result is $PA = LU$ for a permutation matrix $P$. The code below counts every
flop it performs, so you can check the formula rather than trust it.

```python
import numpy as np
from scipy import linalg

def lu_factor_mine(A, pivot=True):
    """PA = LU by Gaussian elimination. Returns perm (A[perm] = L @ U), L, U and the flop count."""
    U = np.array(A, dtype=float); n = len(U)
    L, perm, flops = np.eye(n), np.arange(n), 0
    for k in range(n - 1):
        if pivot:                                          # partial pivoting: biggest |entry| in column k
            p = k + np.argmax(np.abs(U[k:, k]))
            U[[k, p], k:] = U[[p, k], k:]; L[[k, p], :k] = L[[p, k], :k]; perm[[k, p]] = perm[[p, k]]
        r = n - k - 1                                      # rows below the pivot
        m = U[k + 1:, k] / U[k, k];                        flops += r          # multipliers
        U[k + 1:, k + 1:] -= np.outer(m, U[k, k + 1:]);    flops += 2 * r * r  # one mul + one sub each
        U[k + 1:, k] = 0.0; L[k + 1:, k] = m
    return perm, L, U, flops

rng = np.random.default_rng(0)
A4 = rng.standard_normal((4, 4))
perm, L, U, _ = lu_factor_mine(A4)
print("diag(U) =", U.diagonal().round(3), "| max |A[perm] - L U| =", f"{np.abs(A4[perm] - L @ U).max():.1e}", "| max |L_ij| =", f"{np.abs(L).max():.3f}")
P_s, L_s, U_s = linalg.lu(A4)                                 # scipy convention: A = P L U
print("scipy agrees: L", np.allclose(L, L_s), "U", np.allclose(U, U_s), "P", np.allclose(P_s.T @ A4, A4[perm]))
print(f"{'n':>5} {'counted flops':>14} {'2n^3/3':>12} {'ratio':>6}")
for n in (10, 50, 200, 800):
    f = lu_factor_mine(rng.standard_normal((n, n)))[3]
    print(f"{n:>5} {f:>14,} {2 * n ** 3 / 3:>12,.0f} {f / (2 * n ** 3 / 3):>6.3f}")
```

## Why pivoting matters

Elimination divides by the pivot. If the pivot is tiny the multipliers are huge, and adding a huge multiple of one row
to another wipes out the smaller row, the way adding a billion to your bank balance and subtracting it again loses the
cents. The classic case is $\begin{bmatrix}10^{-20} & 1\\ 1 & 1\end{bmatrix}$ with $\mathbf{b} = (1, 2)$, whose solution is
$(1, 1)$ to 20 digits. **Partial pivoting** swaps the row with the largest $|$entry$|$ in the current column into the pivot
position, which guarantees every multiplier satisfies $|\ell_{ik}| \le 1$.

The health measure is the **growth factor** $\rho = \max_{ij}|u_{ij}| / \max_{ij}|a_{ij}|$: how much the entries grew
during elimination. Pivoted LU is backward stable in practice: it returns the exact solution of a problem perturbed by
about $\rho\, n\, \varepsilon_{\text{mach}}\|A\|$, where $\varepsilon_{\text{mach}} \approx 1.1 \times 10^{-16}$ is the
double-precision rounding unit. The block also defines the two triangular solvers, explained in the next section.

```python
def lu_solve_mine(perm, L, U, b):
    return back_sub(U, forward_sub(L, b[perm], unit=True))

def forward_sub(L, b, unit=False):
    y = np.array(b, dtype=float)
    for i in range(len(y)):
        y[i] = (y[i] - L[i, :i] @ y[:i]) / (1.0 if unit else L[i, i])
    return y

def back_sub(U, y):
    x = np.array(y, dtype=float)
    for i in range(len(x) - 1, -1, -1):
        x[i] = (x[i] - U[i, i + 1:] @ x[i + 1:]) / U[i, i]
    return x

def with_cond(m, n, kappa, rng):                        # a matrix with singular values from 1 down to 1/kappa
    U0, _ = np.linalg.qr(rng.standard_normal((m, n))); V0, _ = np.linalg.qr(rng.standard_normal((n, n)))
    return U0 @ np.diag(np.logspace(0, -np.log10(kappa), n)) @ V0.T

eps_A = np.array([[1e-20, 1.0], [1.0, 1.0]]); b2 = np.array([1.0, 2.0])     # true x is about (1, 1)
for piv in (False, True):
    p_, L_, U_, _ = lu_factor_mine(eps_A, pivot=piv)
    print(f"pivot={piv!s:5}: x = {lu_solve_mine(p_, L_, U_, b2)} | U = {U_.ravel()} | max|L| = {np.abs(L_).max():.0e}")

growth = lambda A, U: np.abs(U).max() / np.abs(A).max()
def wilkinson(n):                                              # the textbook worst case for partial pivoting
    W = np.eye(n) - np.tril(np.ones((n, n)), -1); W[:, -1] = 1.0
    return W
print(f"\n{'matrix':22} {'growth no-pivot':>15} {'growth pivot':>13} {'rel err pivot':>14} {'rel err np.solve':>16}")
for name, M in [("Gaussian n=60", rng.standard_normal((60, 60))),
                ("Gaussian n=400", rng.standard_normal((400, 400))),
                ("Wilkinson n=60", wilkinson(60))]:
    x_true = rng.standard_normal(len(M)); b = M @ x_true
    g0 = growth(M, lu_factor_mine(M, pivot=False)[2])
    p_, L_, U_, _ = lu_factor_mine(M)
    err = lambda x: np.linalg.norm(x - x_true) / np.linalg.norm(x_true)
    print(f"{name:22} {g0:>15.1e} {growth(M, U_):>13.1e} {err(lu_solve_mine(p_, L_, U_, b)):>14.1e} "
          f"{err(np.linalg.solve(M, b)):>16.1e}")
```

Without pivoting the $2 \times 2$ system returns $x = (0, 1)$: the first coordinate is completely wrong, because
$1 - 10^{20}$ rounds to $-10^{20}$ and the entry $a_{22} = 1$ is lost. One row swap makes it exact. On random Gaussian
matrices, no pivoting already grows entries by 80 at $n = 60$ and 6700 at $n = 400$; partial pivoting keeps $\rho$ at 4
and 11 and the error at $10^{-15}$ and $10^{-13}$, the same as `np.linalg.solve` (LAPACK's pivoted LU). The Wilkinson
matrix is the honest caveat: $\rho = 2^{59} \approx 5.8 \times 10^{17}$ *with* pivoting, and both your code and LAPACK
lose every digit. Matrices like it essentially never arise in practice (Trefethen and Bau, Lecture 22, call the stability
of pivoted elimination in practice one of the great unexplained facts of numerical analysis); complete pivoting or QR
remove the risk at extra cost.

## Triangular solves cost only n squared

A triangular system can be solved one unknown at a time. In $L\mathbf{y} = \mathbf{b}$ with $L$ lower triangular,
the first equation contains only $y_1$, the second only $y_1, y_2$, and so on: **forward substitution**. $U\mathbf{x} = \mathbf{y}$
is solved from the last unknown upwards: **back substitution**. With $PA = LU$, the system $A\mathbf{x} = \mathbf{b}$ becomes
$L(U\mathbf{x}) = P\mathbf{b}$: forward-solve for $\mathbf{y} = U\mathbf{x}$, then back-solve for $\mathbf{x}$.

### Cost of substitution

This shows that a triangular solve is a factor of $n$ cheaper than the factorization. Row $i$ of forward substitution is

$$
y_i = \frac{b_i - \sum_{j<i} \ell_{ij}\, y_j}{\ell_{ii}},
$$

a dot product of length $i - 1$ ($2(i-1)$ flops) and one division. Summed over rows that is about $n^2$ flops, and back
substitution is the same, so one solve after factoring costs $2n^2$ against $\tfrac23 n^3$ for the factorization.

```python
n = 300
M = rng.standard_normal((n, n)); x_true = rng.standard_normal(n); b = M @ x_true
p_, L_, U_, f_lu = lu_factor_mine(M)
x_mine = lu_solve_mine(p_, L_, U_, b)
lu_s = linalg.lu_factor(M)
print("my solve vs np.linalg.solve:", f"{np.abs(x_mine - np.linalg.solve(M, b)).max():.1e}",
      "| vs scipy lu_solve:", f"{np.abs(x_mine - linalg.lu_solve(lu_s, b)).max():.1e}")
print("forward_sub vs solve_triangular:",
      f"{np.abs(forward_sub(L_, b, unit=True) - linalg.solve_triangular(L_, b, lower=True, unit_diagonal=True)).max():.1e}")
print(f"flops: factor {f_lu:,} | two triangular solves {2 * n * n:,} | ratio {f_lu / (2 * n * n):.0f}x")
```

## Factor once, solve many

The expensive part, the $\tfrac23 n^3$ factorization, does not depend on $\mathbf{b}$. Pay it once and every further
right-hand side costs $2n^2$. This happens constantly: multi-output regression shares one $X^\top X$, a GP predicts
thousands of test points against one kernel matrix, and quasi-Newton or Levenberg-Marquardt codes reuse a factorized
matrix for several steps. scipy exposes it as `lu_factor` / `lu_solve` (and `cho_factor` / `cho_solve` for SPD matrices).

This is also the real case against `np.linalg.inv`. Forming $A^{-1}$ costs $2n^3$, three times an LU; multiplying by it
costs the same $2n^2$ per column as substitution; and $A^{-1}\mathbf{b}$ is not backward stable, so its residual grows with
the condition number $\kappa(A)$, the factor by which $A$ can amplify relative errors (ch. 14). The table counts flops
for $n = 500$; the last lines measure accuracy as the backward error $\|MX - B\| / (\|M\|\,\|X\|)$, which sits at
$\varepsilon_{\text{mach}}$ for any backward-stable method.

```python
n = 500
print(f"{'RHS k':>6} {'k full solves':>15} {'factor once':>13} {'inv then multiply':>18} {'saving':>7}")
for k in (1, 10, 100, 1000):
    each = k * (2 * n ** 3 / 3 + 2 * n ** 2)
    once = 2 * n ** 3 / 3 + k * 2 * n ** 2
    inv = 2 * n ** 3 + k * 2 * n ** 2
    print(f"{k:>6} {each:>15.2e} {once:>13.2e} {inv:>18.2e} {each / once:>6.0f}x")
for label, M in [("Gaussian n=500", rng.standard_normal((n, n))), ("cond(M) = 1e12", with_cond(n, n, 1e12, rng))]:
    B = M @ rng.standard_normal((n, 50))                    # 50 right-hand sides with a well-scaled solution
    lu_s = linalg.lu_factor(M)
    X1 = linalg.lu_solve(lu_s, B); X2 = np.linalg.solve(M, B); X3 = np.linalg.inv(M) @ B
    res = lambda X: np.linalg.norm(M @ X - B) / (np.linalg.norm(M) * np.linalg.norm(X))
    print(f"{label:20} backward error: lu_solve {res(X1):.1e} | np.solve {res(X2):.1e} | inv @ B {res(X3):.1e}")
```

## Cholesky: the factorization for symmetric positive definite matrices

Covariance matrices, kernel matrices, $X^\top X + \lambda I$ and the Hessian at a strict minimum are all **symmetric
positive definite** (SPD): $\mathbf{z}^\top A\mathbf{z} > 0$ for every $\mathbf{z} \neq \mathbf{0}$ (ch. 7). For them
elimination needs no pivoting and becomes symmetric: $A = LL^\top$ with $L$ lower triangular and a positive diagonal. Think
of it as a matrix square root. The scalar case says everything: $a = \ell^2$ has a real solution $\ell > 0$ exactly when
$a > 0$.

### Deriving the Cholesky recurrence

This derivation shows that $L$ follows from $A = LL^\top$ column by column, with one square root per column.
Equating entry $(j, j)$ and entry $(i, j)$ for $i > j$:

$$
\ell_{jj} = \sqrt{a_{jj} - \textstyle\sum_{k<j}\ell_{jk}^2}, \qquad
\ell_{ij} = \frac{a_{ij} - \sum_{k<j}\ell_{ik}\,\ell_{jk}}{\ell_{jj}} .
$$

The number under the square root is the $j$-th pivot. It equals $\det A_{j}/\det A_{j-1}$, the ratio of consecutive leading
principal minors ($A_j$ is the top-left $j \times j$ block), so all pivots are positive if and only if $A$ is positive
definite (Sylvester's criterion). Column $j$ costs about $2j(n - j)$ flops, so

$$
\text{flops} \approx \sum_{j=1}^{n} 2j(n-j) \approx \tfrac13 n^3,
$$

half of LU, because symmetry lets you compute one triangle. The determinant comes for free and never overflows:
$\log|A| = 2\sum_j \log \ell_{jj}$, the term in every Gaussian log-likelihood.

```python
def cholesky_mine(A):
    """A = L L^T for symmetric positive definite A. Raises at the first non-positive pivot."""
    n = len(A); L = np.zeros((n, n)); flops = 0
    for j in range(n):
        d = A[j, j] - L[j, :j] @ L[j, :j];                              flops += 2 * j
        if d <= 0:
            raise np.linalg.LinAlgError(f"not positive definite: pivot {j} is {d:.2e}")
        L[j, j] = np.sqrt(d)
        L[j + 1:, j] = (A[j + 1:, j] - L[j + 1:, :j] @ L[j, :j]) / L[j, j];  flops += (n - j - 1) * (2 * j + 1)
    return L, flops

X = rng.standard_normal((400, 300)); S = X.T @ X / 400                     # a sample covariance, SPD
Lc, fc = cholesky_mine(S)
print(f"max |L - np.linalg.cholesky| = {np.abs(Lc - np.linalg.cholesky(S)).max():.1e} | "
      f"vs scipy = {np.abs(Lc - linalg.cholesky(S, lower=True)).max():.1e}")
print(f"flops: counted {fc:,} | n^3/3 = {300 ** 3 / 3:,.0f} | LU on same matrix {lu_factor_mine(S)[3]:,}")
print(f"log det: 2 sum log diag(L) = {2 * np.log(np.diag(Lc)).sum():.6f} | slogdet = {np.linalg.slogdet(S)[1]:.6f}")
```

### A positive-definiteness test that costs a third of an LU

Because the recurrence stops at the first non-positive pivot, *attempting* a Cholesky factorization is the standard
test for positive definiteness. It is cheaper than eigenvalues (a symmetric eigensolver costs about $\tfrac43 n^3$ flops
for eigenvalues alone, against $\tfrac13 n^3$) and it is what scipy, PyMC and every GP library do internally. Below,
matrices with known eigenvalues straddle zero, then a GP kernel matrix (Bayesian ML ch. 12) that is PD in exact arithmetic
but numerically singular, because neighbouring grid points are nearly identical.

```python
Q, _ = np.linalg.qr(rng.standard_normal((6, 6)))
print(f"{'smallest eigenvalue':>20}  cholesky_mine")
for lam_min in (1e-2, 1e-12, -1e-12, -1e-2):
    A_t = Q @ np.diag([5.0, 3.0, 2.0, 1.0, 0.5, lam_min]) @ Q.T
    A_t = (A_t + A_t.T) / 2
    try: cholesky_mine(A_t); msg = "succeeds"
    except np.linalg.LinAlgError as e: msg = str(e)
    print(f"{lam_min:>20.0e}  {msg}")
xs = np.linspace(0, 10, 200)                                   # GP kernel on a dense grid (Bayesian ML ch. 12)
K = np.exp(-0.5 * (xs[:, None] - xs[None, :]) ** 2 / 1.0 ** 2)
print(f"\nRBF kernel, 200 points: eigvalsh min = {np.linalg.eigvalsh(K).min():.1e}")
def chol_ok(Mx):
    try: np.linalg.cholesky(Mx); return "ok"
    except np.linalg.LinAlgError: return "fails"
print("np.linalg.cholesky(K + jitter I):", ", ".join(f"{j:.0e} {chol_ok(K + j * np.eye(200))}" for j in (0.0, 1e-12, 1e-10, 1e-8, 1e-6)))
```

The verdict flips exactly where the smallest eigenvalue changes sign, even at $\pm 10^{-12}$, and the failing pivot is
the last one, with a value close to the negative eigenvalue. The RBF kernel is the everyday case: its smallest computed
eigenvalue is $-7 \times 10^{-15}$, so the Cholesky fails, and a jitter of $10^{-12}$ on the diagonal fixes it. That is
why GP libraries add $10^{-10}$ to $10^{-6}$ by default, and why a likelihood noise term $\sigma_n^2 I$ removes the
problem entirely.

## QR: orthogonal triangularization

LU reduces $A$ to triangular form with shears, which can blow entries up. QR does it with reflections, which never
change lengths: $A = QR$ with $Q$ having orthonormal columns ($Q^\top Q = I$) and $R$ upper triangular. Gram-Schmidt (ch. 1)
builds $Q$ column by column, subtracting from each column its projections onto the earlier ones. Householder instead
reflects each column onto a coordinate axis. In exact arithmetic the two give the same factors; in floating point they do
not.

### Householder reflections

This shows how one reflection zeroes a whole column below the diagonal. For a vector $\mathbf{x}$, take
$\mathbf{v} = \mathbf{x} + \mathrm{sign}(x_1)\|\mathbf{x}\|\mathbf{e}_1$, normalized to unit length, and

$$
H = I - 2\mathbf{v}\mathbf{v}^\top, \qquad H^\top H = I, \qquad H\mathbf{x} = -\mathrm{sign}(x_1)\|\mathbf{x}\|\,\mathbf{e}_1 .
$$

$H$ is the mirror across the hyperplane orthogonal to $\mathbf{v}$. The sign choice adds two numbers of the same sign in
$v_1$, so there is no cancellation when $\mathbf{x}$ already points along $\mathbf{e}_1$. Applying $H_k$ to the trailing
$(m-k) \times (n-k)$ block of $A \in \mathbb{R}^{m \times n}$ is one matrix-vector product plus one rank-1 update,
$4(m-k)(n-k)$ flops, so

$$
\text{flops} \approx \sum_{k=0}^{n-1} 4(m-k)(n-k) \approx 2mn^2 - \tfrac23 n^3 .
$$

You rarely form $Q = H_1 \cdots H_n$: keeping the vectors $\mathbf{v}_k$ lets you apply $Q^\top$ to a vector in $4mn$ flops.
The computed $Q$ is a product of exactly-orthogonal-up-to-rounding reflections, so it is orthogonal to $O(\varepsilon)$ no
matter what $A$ is. Gram-Schmidt has no such guarantee: when column $\mathbf{a}_j$ is nearly in the span of the earlier
ones, subtracting the projections cancels almost everything and leaves mostly rounding error. Modified Gram-Schmidt
subtracts each projection from all remaining columns immediately, which helps but does not cure it. The loss of
orthogonality $\|Q^\top Q - I\|$ is roughly $\kappa^2\varepsilon$ for classical, $\kappa\varepsilon$ for modified and
$\varepsilon$ for Householder; the table builds matrices with a prescribed $\kappa$ to check.

```python
def householder_qr(A):
    """A = QR. Returns the reflector vectors V, R (n x n), and the flop count."""
    R = np.array(A, dtype=float); m, n = R.shape; V = []; flops = 0
    for k in range(n):
        x = R[k:, k]
        v = x.copy(); v[0] += np.copysign(np.linalg.norm(x), x[0]); v /= np.linalg.norm(v)
        R[k:, k:] -= 2.0 * np.outer(v, v @ R[k:, k:]);  flops += 4 * (m - k) * (n - k)
        V.append(v)
    return V, np.triu(R[:n]), flops

def apply_qt(V, b):                                     # Q^T b without ever forming Q
    y = np.array(b, dtype=float)
    for k, v in enumerate(V):
        y[k:] -= 2.0 * np.outer(v, v @ y[k:]) if y.ndim == 2 else 2.0 * v * (v @ y[k:])
    return y

def form_q(V, m):                                       # thin Q, built by applying reflectors to I
    n = len(V); Qm = np.eye(m)[:, :n]
    for k in range(n - 1, -1, -1):
        v = V[k]; Qm[k:] -= 2.0 * np.outer(v, v @ Qm[k:])
    return Qm

def cgs(A):                                             # classical Gram-Schmidt
    Qm = np.zeros(A.shape)
    for j in range(A.shape[1]):
        v = A[:, j] - Qm[:, :j] @ (Qm[:, :j].T @ A[:, j]); Qm[:, j] = v / np.linalg.norm(v)
    return Qm

def mgs(A):                                             # modified Gram-Schmidt
    Qm = np.array(A, dtype=float)
    for j in range(A.shape[1]):
        Qm[:, j] /= np.linalg.norm(Qm[:, j])
        Qm[:, j + 1:] -= np.outer(Qm[:, j], Qm[:, j] @ Qm[:, j + 1:])
    return Qm

A = rng.standard_normal((100, 20))
V, R, fq = householder_qr(A); Qh = form_q(V, 100)
Q_np, R_np = np.linalg.qr(A)
print(f"max |A - QR| {np.abs(A - Qh @ R).max():.1e} | |R| vs numpy {np.abs(np.abs(R) - np.abs(R_np)).max():.1e} | "
      f"flops {fq:,} vs 2mn^2 - 2n^3/3 = {2 * 100 * 400 - 2 * 8000 / 3:,.0f}")
print(f"\n{'cond(A)':>8} {'CGS':>9} {'MGS':>9} {'Householder':>12} {'np.linalg.qr':>13}   (entries: ||Q^T Q - I||)")
for kappa in (1e2, 1e5, 1e8, 1e11):
    Ak = with_cond(100, 20, kappa, rng)

          f"{loss(np.linalg.qr(Ak)[0]):>13.1e}")
```

## Least squares three ways

When $A$ is tall ($m$ observations, $n < m$ features), $A\mathbf{x} = \mathbf{b}$ usually has no solution, and least
squares picks the $\mathbf{x}$ minimizing $\|A\mathbf{x} - \mathbf{b}\|_2$. That is linear regression. Geometrically,
$A\mathbf{x}$ is the orthogonal projection of $\mathbf{b}$ onto the column space (ch. 2). There are three standard ways
to compute it. They agree on well-conditioned data and differ by many digits on ill-conditioned data, which polynomial,
spline or nearly collinear features produce all the time.

### Normal equations, QR, and SVD

This shows what each method computes and why one of them squares the condition number. The residual must be
orthogonal to every column, $A^\top(\mathbf{b} - A\mathbf{x}) = \mathbf{0}$, which gives the **normal equations**

$$
A^\top A\,\mathbf{x} = A^\top\mathbf{b},
$$

solved by Cholesky in $mn^2 + \tfrac13 n^3$ flops. With a thin QR, $\|A\mathbf{x} - \mathbf{b}\|^2 = \|R\mathbf{x} - Q^\top\mathbf{b}\|^2 + \text{const}$,
so $R\mathbf{x} = Q^\top\mathbf{b}$: one back substitution after $2mn^2 - \tfrac23 n^3$ flops. With the SVD
$A = U\Sigma V^\top$ (ch. 5), $\mathbf{x} = V\Sigma^{-1}U^\top\mathbf{b}$, the most expensive and the most informative.
The condition number is $\kappa(A) = \sigma_{\max}/\sigma_{\min}$, the ratio of the largest to the smallest singular value.
Since $A^\top A = V\Sigma^2 V^\top$,

$$
\boxed{\kappa(A^\top A) = \frac{\sigma_{\max}^2}{\sigma_{\min}^2} = \kappa(A)^2 .}
$$

Forming $A^\top A$ commits you to errors of order $\kappa(A)^2\varepsilon$; QR and SVD work on $A$ itself and achieve
about $\kappa(A)\varepsilon$ when the fit is good. (With a large residual every method picks up a
$\kappa^2\varepsilon\,\|\mathbf{r}\|$ term: Trefethen and Bau, Lecture 18.) Below, $\mathbf{b} = A\mathbf{x}_{\text{true}}$
exactly, so every error is the algorithm's.

```python
def ls_normal(A, b):
    L, _ = cholesky_mine(A.T @ A); return back_sub(L.T, forward_sub(L, A.T @ b))
def ls_qr(A, b):
    V, R, _ = householder_qr(A); return back_sub(R, apply_qt(V, b)[:A.shape[1]])
def ls_svd(A, b):
    U_, s, Vt = np.linalg.svd(A, full_matrices=False); return Vt.T @ ((U_.T @ b) / s)

print(f"{'cond(A)':>8} {'cond(AtA)':>10} {'normal eq':>10} {'QR (mine)':>10} {'SVD':>9} {'lstsq':>9}   (relative error in x)")

    err = lambda x: np.linalg.norm(x - x_true) / np.linalg.norm(x_true)
    try:
        e_ne = f"{err(ls_normal(Ak, bk)):>10.1e}"
    except np.linalg.LinAlgError:

    print(f"{kappa:>8.0e} {np.linalg.cond(Ak.T @ Ak):>10.1e} {e_ne} {err(ls_qr(Ak, bk)):>10.1e} "
          f"{err(ls_svd(Ak, bk)):>9.1e} {err(np.linalg.lstsq(Ak, bk, rcond=None)[0]):>9.1e}")
```

The normal-equations error tracks $\kappa^2\varepsilon$: $8 \times 10^{-12}$ at $\kappa = 10^3$, $6 \times 10^{-3}$ at

digits at $10^9$. The normal equations are not useless: they cost about half of QR when $m \gg n$, can be accumulated one
row batch at a time, and are fine on standardized features with modest $\kappa$, which is why big-data regression still
uses them. They are the first suspect when coefficients look unstable.

## Rank-deficient least squares and the minimum-norm solution

If two features are exactly collinear, you can shift weight between them without changing a single prediction, so
infinitely many coefficient vectors fit equally well. The classic way to get there is the **dummy-variable trap**: an
intercept plus one-hot columns for *every* level of a categorical, so the dummies sum to the intercept column. The
minimizers then form a line (an affine set), and the natural pick is the shortest one, given by the pseudo-inverse
$A^{+}$.

### Why the minimum-norm solution lies in the row space

This shows that the pseudo-inverse picks the unique minimizer with no null-space component. Every minimizer has the form
$\mathbf{x} = \mathbf{x}_{+} + \mathbf{z}$ with $A\mathbf{z} = \mathbf{0}$, since adding $\mathbf{z}$ does not change
$A\mathbf{x}$. If $\mathbf{x}_{+}$ lies in the row space, spanned by the right singular vectors $\mathbf{v}_i$ with
$\sigma_i > 0$, it is orthogonal to every null vector, so $\|\mathbf{x}\|^2 = \|\mathbf{x}_{+}\|^2 + \|\mathbf{z}\|^2$ is
smallest at $\mathbf{z} = \mathbf{0}$. The SVD solution with the zero singular values skipped,

$$
\mathbf{x}_{+} = A^{+}\mathbf{b} = \sum_{\sigma_i > 0} \frac{\mathbf{u}_i^\top\mathbf{b}}{\sigma_i}\,\mathbf{v}_i,
$$

is in the row space by construction. Ridge gives the same answer in the limit:
$(A^\top A + \lambda I)^{-1}A^\top\mathbf{b} \to A^{+}\mathbf{b}$ as $\lambda \to 0^{+}$.

```python
n_obs = 300
g = rng.integers(0, 3, n_obs)                                   # a 3-level categorical feature
Xd = np.c_[np.ones(n_obs), np.eye(3)[g], rng.standard_normal(n_obs)]   # intercept + all 3 dummies + x: the dummy trap
yd = Xd @ np.array([1.0, 0.5, -0.5, 2.0, 3.0]) + 0.1 * rng.standard_normal(n_obs)
print("singular values:", np.linalg.svd(Xd, compute_uv=False).round(3))
print(f"rank {np.linalg.matrix_rank(Xd)} of {Xd.shape[1]} columns | cond(X^T X) = {np.linalg.cond(Xd.T @ Xd):.1e}")
x_mn = np.linalg.pinv(Xd) @ yd
x_ls, *_ = np.linalg.lstsq(Xd, yd, rcond=None)
null = np.array([1.0, -1.0, -1.0, -1.0, 0.0]) / 2              # X @ null = 0: intercept up, every dummy down
print(f"pinv  x = {x_mn.round(3)} | ||x|| = {np.linalg.norm(x_mn):.3f}")
print(f"lstsq x = {x_ls.round(3)} | same as pinv: {np.allclose(x_ls, x_mn)}")
for t in (1.0, 5.0):
    xt = x_mn + t * null
    print(f"pinv + {t:.0f}*null: x = {xt.round(3)} | ||x|| = {np.linalg.norm(xt):.3f} | "
          f"residual change {np.linalg.norm(Xd @ xt - yd) - np.linalg.norm(Xd @ x_mn - yd):+.1e}")
for lam in (1e-1, 1e-4, 1e-8):
    x_r = np.linalg.solve(Xd.T @ Xd + lam * np.eye(5), Xd.T @ yd)
    print(f"ridge lambda={lam:.0e}: max |x_ridge - x_pinv| = {np.abs(x_r - x_mn).max():.1e}")
```

One singular value is exactly 0 and $\kappa(X^\top X) \approx 3 \times 10^{16}$, so the normal equations are hopeless.
`pinv` and `lstsq` return the same minimum-norm vector. Moving along the null direction (intercept up, every dummy down
by the same amount) leaves the residual unchanged to the last bit while the norm grows: the data cannot tell these
vectors apart. What *is* identified is intercept plus level effect: $1.253 + 0.248 = 1.50$, $1.253 - 0.749 = 0.50$ and
$1.253 + 1.754 = 3.01$, against the true 1.5, 0.5 and 3.0, and the slope 3.0. Ridge approaches $A^{+}\mathbf{b}$ in
proportion to $\lambda$ until $\lambda = 10^{-8}$, where solving the nearly singular normal equations adds its own
$10^{-6}$ error. The standard fixes are to drop one dummy, add ridge, or use QR with column pivoting
(`scipy.linalg.qr(A, pivoting=True)`), which moves the redundant column last so its near-zero $r_{nn}$ reveals the rank.

## Iterative refinement: buy back digits cheaply

If a computed solution is slightly off, measure how far off (the residual $\mathbf{r} = \mathbf{b} - A\mathbf{x}$),
solve for the correction with the factorization you already have, and add it. A round costs $2n^2$ flops for the residual
and $2n^2$ for the solve, nothing next to a new factorization. What makes this matter today is mixed precision: factor in
cheap float32 (or float16 on a GPU) and compute only the residual in float64. Each round multiplies the error by roughly
$\kappa(A)\,\varepsilon_{32}$, with $\varepsilon_{32} \approx 6 \times 10^{-8}$, so as long as that is below 1 you converge
to float64 accuracy.

```python
n = 300
M = with_cond(n, n, 1e4, rng); x_true = rng.standard_normal(n); b = M @ x_true
lu32 = linalg.lu_factor(M.astype(np.float32))                  # factor in single precision
x = linalg.lu_solve(lu32, b.astype(np.float32)).astype(np.float64)
errs = []
for it in range(5):
    errs.append(np.linalg.norm(x - x_true) / np.linalg.norm(x_true))
    r = b - M @ x                                              # residual in double precision: 2n^2 flops
    x = x + linalg.lu_solve(lu32, r.astype(np.float32)).astype(np.float64)
print("relative error after steps 0..4:", " ".join(f"{e:.1e}" for e in errs))
print(f"float64 np.linalg.solve: {np.linalg.norm(np.linalg.solve(M, b) - x_true) / np.linalg.norm(x_true):.1e}")
```

```output
relative error after steps 0..4: 1.5e-04 2.0e-08 3.1e-12 2.0e-13 1.9e-13
float64 np.linalg.solve: 3.9e-13
```

The float32 factorization alone gives about 4 digits ($1.5 \times 10^{-4}$, close to $\kappa\,\varepsilon_{32}$). Each
refinement step gains about four more, and after three steps the error ($2 \times 10^{-13}$) matches a full float64
`solve` ($3.9 \times 10^{-13}$), for a few $O(n^2)$ passes. LAPACK's `dsgesv` and mixed-precision GPU solvers do exactly
this.

## When not to factor at all

A dense factorization costs $O(n^3)$ flops and $O(n^2)$ memory no matter what the matrix looks like. Many large ML
matrices are sparse or only available as a product: graph Laplacians, finite-difference grids, $X^\top X$ for a huge
sparse feature matrix, or a neural network's Hessian, which you can multiply by but never store. **Iterative solvers**
need only the map $\mathbf{v} \mapsto A\mathbf{v}$. For SPD systems the conjugate gradient method (derived in ch. 12)
needs on the order of $\sqrt{\kappa}$ iterations, each one matrix-vector product of $2\,\mathrm{nnz}$ flops (nnz is the
number of nonzeros). The test matrix is the 2-D grid Laplacian, the standard SPD sparse benchmark.

```python
from scipy import sparse
from scipy.sparse.linalg import cg
for side in (30, 100):
    N = side * side
    T = sparse.diags([-1.0, 2.0, -1.0], [-1, 0, 1], shape=(side, side))
    Lap = (sparse.kron(sparse.eye(side), T) + sparse.kron(T, sparse.eye(side))).tocsr()   # 2-D grid Laplacian
    bL = np.ones(N); its = []
    xL, info = cg(Lap, bL, rtol=1e-10, maxiter=5000, callback=lambda xk: its.append(1))
    print(f"N={N:>6} nnz={Lap.nnz:>6} | dense LU 2N^3/3 = {2 * N ** 3 / 3:.1e} flops | "
          f"CG {len(its)} iters x 2*nnz = {len(its) * 2 * Lap.nnz:.1e} flops | rel resid {np.linalg.norm(Lap @ xL - bL) / np.linalg.norm(bL):.0e}")
```

```output
N=   900 nnz=  4380 | dense LU 2N^3/3 = 4.9e+08 flops | CG 62 iters x 2*nnz = 5.4e+05 flops | rel resid 4e-11
N= 10000 nnz= 49600 | dense LU 2N^3/3 = 6.7e+11 flops | CG 208 iters x 2*nnz = 2.1e+07 flops | rel resid 7e-11
```

At $N = 10^4$ unknowns a dense LU would cost $6.7 \times 10^{11}$ flops and 800 MB just to store the matrix; CG needs 208
matrix-vector products, $2 \times 10^7$ flops, about 30000 times fewer. Iterations grow from 62 to 208 as the grid side
grows from 30 to 100: the Laplacian's $\kappa$ grows like side$^2$, so $\sqrt\kappa$ grows like the side, 3.3 times. Sparse
direct solvers (`scipy.sparse.linalg.splu`, CHOLMOD) are the middle ground and often win on 2-D problems; CG wins when you
can only multiply by $A$. Rule of thumb: dense with $n \lesssim 10^4$, factor; sparse, huge or matrix-free, iterate
(ch. 12).

```python
    jitter = 0.0
    for _ in range(max_tries):

            L = np.linalg.cholesky(A + jitter * np.eye(len(A)))
            break
        except np.linalg.LinAlgError:
```
