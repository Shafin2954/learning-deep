## Gaussian elimination is a factorization in disguise

Almost every model you fit ends in a linear solve: ridge regression solves $(X^\top X + \lambda I)\mathbf{w} = X^\top\mathbf{y}$,
a Gaussian process solves $K\boldsymbol\alpha = \mathbf{y}$ (Bayesian ML ch. 12), a Newton step solves
$H\boldsymbol\Delta = -\mathbf{g}$ (ch. 12). The school method subtracts multiples of one equation from the others until
the system is triangular. The useful idea is to *keep the multipliers*: stored in a lower-triangular $L$, they rebuild $A$
from the triangular remainder $U$, so $A = LU$, and every later right-hand side is cheap. Tiny example: for
$A = \begin{bmatrix}2 & 1\\ 6 & 4\end{bmatrix}$, subtracting 3 times row 1 from row 2 leaves
$U = \begin{bmatrix}2 & 1\\ 0 & 1\end{bmatrix}$; the 3 goes into $L = \begin{bmatrix}1 & 0\\ 3 & 1\end{bmatrix}$, and $LU = A$.

### Elimination as multiplication by lower-triangular matrices

This derivation shows why the multipliers form $L$ and where the $\tfrac23 n^3$ cost comes from. Step $k$ on
$A \in \mathbb{R}^{n \times n}$ subtracts $\ell_{ik} = u_{ik}/u_{kk}$ times row $k$ from each row $i > k$ ($u_{kk}$ is the
**pivot**). That is left-multiplication by $L_k = I - \boldsymbol\ell_k \mathbf{e}_k^\top$, where
$\boldsymbol\ell_k = (0, \dots, 0, \ell_{k+1,k}, \dots, \ell_{nk})^\top$ and $\mathbf{e}_k$ is the $k$-th unit vector, so
$L_{n-1}\cdots L_1 A = U$. Since $\mathbf{e}_k^\top\boldsymbol\ell_k = 0$, $L_k^{-1} = I + \boldsymbol\ell_k\mathbf{e}_k^\top$,
and the inverses just stack the multipliers in place:

$$
A = \underbrace{L_1^{-1}\cdots L_{n-1}^{-1}}_{L}\,U, \qquad L = I + \sum_{k=1}^{n-1}\boldsymbol\ell_k\mathbf{e}_k^\top,
\qquad \text{flops} \approx \sum_{k=1}^{n-1} 2(n-k)^2 \approx \tfrac23 n^3,
$$

because step $k$ does one multiply and one subtract on each entry of an $(n-k) \times (n-k)$ block. With the row swaps of
the next section the result is $PA = LU$ for a permutation $P$. The code counts every flop, so you can check the formula.

```python
import numpy as np
from scipy import linalg

def lu_factor_mine(A, pivot=True):
    """PA = LU by Gaussian elimination. Returns perm (A[perm] = L @ U), L, U and the flop count."""
    U = np.array(A, dtype=float); n = len(U)
    L, perm, flops = np.eye(n), np.arange(n), 0
    for k in range(n - 1):
        if pivot:                                          # partial pivoting: biggest |entry| in column k
            p = k + np.argmax(np.abs(U[k:, k]))
            U[[k, p], k:] = U[[p, k], k:]; L[[k, p], :k] = L[[p, k], :k]; perm[[k, p]] = perm[[p, k]]
        r = n - k - 1                                      # rows below the pivot
        m = U[k + 1:, k] / U[k, k];                        flops += r          # multipliers
        U[k + 1:, k + 1:] -= np.outer(m, U[k, k + 1:]);    flops += 2 * r * r  # one mul + one sub each
        U[k + 1:, k] = 0.0; L[k + 1:, k] = m
    return perm, L, U, flops

rng = np.random.default_rng(0)
A4 = rng.standard_normal((4, 4))
perm, L, U, _ = lu_factor_mine(A4)
print("diag(U) =", U.diagonal().round(3), "| max |A[perm] - L U| =", f"{np.abs(A4[perm] - L @ U).max():.1e}",
      "| max |L_ij| =", f"{np.abs(L).max():.3f}")
P_s, L_s, U_s = linalg.lu(A4)                                 # scipy convention: A = P L U
print("scipy agrees: L", np.allclose(L, L_s), "U", np.allclose(U, U_s), "P", np.allclose(P_s.T @ A4, A4[perm]))
print(f"{'n':>5} {'counted flops':>14} {'2n^3/3':>12} {'ratio':>6}")
for n in (10, 50, 200, 800):
    f = lu_factor_mine(rng.standard_normal((n, n)))[3]
    print(f"{n:>5} {f:>14,} {2 * n ** 3 / 3:>12,.0f} {f / (2 * n ** 3 / 3):>6.3f}")
```

Your factors match scipy's (which writes $A = PLU$, hence `P_s.T @ A4`), and every $|\ell_{ij}| \le 1$. The ratio creeps

$n = 10$ and nothing by $n = 800$.

## Why pivoting matters

Elimination divides by the pivot. A tiny pivot means huge multipliers, and adding a huge multiple of one row to another
wipes out the smaller row, the way adding a billion to your bank balance and subtracting it again loses the cents. The
classic case is $\begin{bmatrix}10^{-20} & 1\\ 1 & 1\end{bmatrix}$ with $\mathbf{b} = (1, 2)$, solution $(1, 1)$ to 20
digits. **Partial pivoting** swaps the row with the largest $|$entry$|$ in the current column into the pivot position, so
every $|\ell_{ik}| \le 1$. The health measure is the **growth factor** $\rho = \max_{ij}|u_{ij}| / \max_{ij}|a_{ij}|$:
pivoted LU returns the exact solution of a problem perturbed by about $\rho\, n\, \varepsilon_{\text{mach}}\|A\|$, with
$\varepsilon_{\text{mach}} \approx 1.1 \times 10^{-16}$ the double-precision rounding unit. The block also defines the
triangular solvers of the next section.

```python
def forward_sub(L, b, unit=False):
    y = np.array(b, dtype=float)
    for i in range(len(y)):
        y[i] = (y[i] - L[i, :i] @ y[:i]) / (1.0 if unit else L[i, i])
    return y
def back_sub(U, y):
    x = np.array(y, dtype=float)
    for i in range(len(x) - 1, -1, -1):
        x[i] = (x[i] - U[i, i + 1:] @ x[i + 1:]) / U[i, i]
    return x
def lu_solve_mine(perm, L, U, b):
    return back_sub(U, forward_sub(L, b[perm], unit=True))
def with_cond(m, n, kappa, rng):                    # a matrix with singular values from 1 down to 1/kappa
    U0, _ = np.linalg.qr(rng.standard_normal((m, n))); V0, _ = np.linalg.qr(rng.standard_normal((n, n)))
    return U0 @ np.diag(np.logspace(0, -np.log10(kappa), n)) @ V0.T

eps_A = np.array([[1e-20, 1.0], [1.0, 1.0]]); b2 = np.array([1.0, 2.0])     # true x is about (1, 1)
for piv in (False, True):
    p_, L_, U_, _ = lu_factor_mine(eps_A, pivot=piv)
    print(f"pivot={piv!s:5}: x = {lu_solve_mine(p_, L_, U_, b2)} | U = {U_.ravel()} | max|L| = {np.abs(L_).max():.0e}")
growth = lambda A, U: np.abs(U).max() / np.abs(A).max()
def wilkinson(n):                                              # the textbook worst case for partial pivoting
    W = np.eye(n) - np.tril(np.ones((n, n)), -1); W[:, -1] = 1.0
    return W
print(f"\n{'matrix':22} {'growth no-pivot':>15} {'growth pivot':>13} {'rel err pivot':>14} {'rel err np.solve':>16}")
for name, M in [("Gaussian n=60", rng.standard_normal((60, 60))),
                ("Gaussian n=400", rng.standard_normal((400, 400))),
                ("Wilkinson n=60", wilkinson(60))]:
    x_true = rng.standard_normal(len(M)); b = M @ x_true
    g0 = growth(M, lu_factor_mine(M, pivot=False)[2])
    p_, L_, U_, _ = lu_factor_mine(M)
    err = lambda x: np.linalg.norm(x - x_true) / np.linalg.norm(x_true)
    print(f"{name:22} {g0:>15.1e} {growth(M, U_):>13.1e} {err(lu_solve_mine(p_, L_, U_, b)):>14.1e} "
          f"{err(np.linalg.solve(M, b)):>16.1e}")
```

Without pivoting the $2 \times 2$ system returns $x = (0, 1)$: $1 - 10^{20}$ rounds to $-10^{20}$ and $a_{22} = 1$ is lost.
One row swap makes it exact. On Gaussian matrices, no pivoting grows entries by 80 at $n = 60$ and 6700 at $n = 400$;
pivoting keeps $\rho$ at 4 and 11 and the error at $10^{-15}$ and $10^{-13}$, matching `np.linalg.solve` (LAPACK's
pivoted LU). The honest caveat is the Wilkinson matrix: $\rho = 2^{59} \approx 5.8 \times 10^{17}$ *with* pivoting, and
both your code and LAPACK lose every digit. Such matrices essentially never arise in practice, which Trefethen and Bau
(Lecture 22) call one of the great unexplained facts of numerical analysis; complete pivoting or QR remove the risk.

## Triangular solves cost only n squared

A triangular system is solved one unknown at a time. In $L\mathbf{y} = \mathbf{b}$ the first equation contains only $y_1$,
the second only $y_1, y_2$, and so on (**forward substitution**); $U\mathbf{x} = \mathbf{y}$ goes from the last unknown up
(**back substitution**). With $PA = LU$, $A\mathbf{x} = \mathbf{b}$ becomes $L(U\mathbf{x}) = P\mathbf{b}$: forward-solve for
$\mathbf{y} = U\mathbf{x}$, then back-solve for $\mathbf{x}$.

### Cost of substitution

This shows a triangular solve is a factor $n$ cheaper than factoring. Row $i$ of forward substitution,

$$
y_i = \frac{b_i - \sum_{j<i} \ell_{ij}\, y_j}{\ell_{ii}},
$$

is a dot product of length $i - 1$ ($2(i-1)$ flops) and a division: about $n^2$ flops in total, the same for back
substitution, so one solve after factoring costs $2n^2$ against $\tfrac23 n^3$.

```python
n = 300
M = rng.standard_normal((n, n)); x_true = rng.standard_normal(n); b = M @ x_true
p_, L_, U_, f_lu = lu_factor_mine(M)
x_mine = lu_solve_mine(p_, L_, U_, b)
lu_s = linalg.lu_factor(M)
print("my solve vs np.linalg.solve:", f"{np.abs(x_mine - np.linalg.solve(M, b)).max():.1e}",
      "| vs scipy lu_solve:", f"{np.abs(x_mine - linalg.lu_solve(lu_s, b)).max():.1e}")
print("forward_sub vs solve_triangular:",
      f"{np.abs(forward_sub(L_, b, unit=True) - linalg.solve_triangular(L_, b, lower=True, unit_diagonal=True)).max():.1e}")
print(f"flops: factor {f_lu:,} | two triangular solves {2 * n * n:,} | ratio {f_lu / (2 * n * n):.0f}x")
```

```output
my solve vs np.linalg.solve: 5.7e-13 | vs scipy lu_solve: 2.5e-12
forward_sub vs solve_triangular: 1.6e-12
flops: factor 17,954,950 | two triangular solves 180,000 | ratio 100x
```

Agreement to about $10^{-12}$ is rounding, not a bug: this matrix has $\kappa \approx 3000$, and differences of order
$\kappa\varepsilon$ are expected. The two substitutions are 100 times cheaper than the factorization, exactly
$\tfrac23 n^3 / 2n^2 = n/3$.

## Factor once, solve many

The $\tfrac23 n^3$ factorization does not depend on $\mathbf{b}$: pay it once, then each right-hand side costs $2n^2$.
Multi-output regression shares one $X^\top X$, a GP predicts thousands of test points against one kernel matrix, and
quasi-Newton codes reuse a factorized matrix for several steps. scipy exposes this as `lu_factor` / `lu_solve` (and
`cho_factor` / `cho_solve`). It is also the real case against `np.linalg.inv`: forming $A^{-1}$ costs $2n^3$, three LUs'
worth, and $A^{-1}\mathbf{b}$ is not backward stable, so its residual grows with the condition number $\kappa(A)$, the
factor by which $A$ can amplify relative errors (ch. 14). Accuracy below is the backward error
$\|MX - B\| / (\|M\|\,\|X\|)$, which sits at $\varepsilon_{\text{mach}}$ for a backward-stable method.

```python
n = 500
print(f"{'RHS k':>6} {'k full solves':>15} {'factor once':>13} {'inv then multiply':>18} {'saving':>7}")
for k in (1, 10, 100, 1000):
    each = k * (2 * n ** 3 / 3 + 2 * n ** 2)
    once = 2 * n ** 3 / 3 + k * 2 * n ** 2
    inv = 2 * n ** 3 + k * 2 * n ** 2
    print(f"{k:>6} {each:>15.2e} {once:>13.2e} {inv:>18.2e} {each / once:>6.0f}x")
for label, M in [("Gaussian n=500", rng.standard_normal((n, n))), ("cond(M) = 1e12", with_cond(n, n, 1e12, rng))]:
    B = M @ rng.standard_normal((n, 50))                    # 50 right-hand sides with a well-scaled solution
    lu_s = linalg.lu_factor(M)
    X1 = linalg.lu_solve(lu_s, B); X2 = np.linalg.solve(M, B); X3 = np.linalg.inv(M) @ B
    res = lambda X: np.linalg.norm(M @ X - B) / (np.linalg.norm(M) * np.linalg.norm(X))
    print(f"{label:20} backward error: lu_solve {res(X1):.1e} | np.solve {res(X2):.1e} | inv @ B {res(X3):.1e}")
```

### Iterative refinement

A stored factorization also lets you buy back digits. Compute the residual $\mathbf{r} = \mathbf{b} - A\mathbf{x}$, solve
for the correction with the same factors, add it: $4n^2$ flops per round. The modern use is mixed precision: factor in
cheap float32 (float16 on a GPU), compute only the residual in float64. Each round multiplies the error by about
$\kappa(A)\,\varepsilon_{32}$, with $\varepsilon_{32} \approx 6 \times 10^{-8}$, so while that is below 1 you converge to
float64 accuracy.

```python
n = 300
M = with_cond(n, n, 1e4, rng); x_true = rng.standard_normal(n); b = M @ x_true
lu32 = linalg.lu_factor(M.astype(np.float32))                  # factor in single precision
x = linalg.lu_solve(lu32, b.astype(np.float32)).astype(np.float64)
errs = []
for it in range(5):
    errs.append(np.linalg.norm(x - x_true) / np.linalg.norm(x_true))
    r = b - M @ x                                              # residual in double precision: 2n^2 flops
    x = x + linalg.lu_solve(lu32, r.astype(np.float32)).astype(np.float64)
print("relative error after steps 0..4:", " ".join(f"{e:.1e}" for e in errs))
print(f"float64 np.linalg.solve: {np.linalg.norm(np.linalg.solve(M, b) - x_true) / np.linalg.norm(x_true):.1e}")
```

```output
relative error after steps 0..4: 2.0e-04 3.9e-08 6.7e-12 2.4e-13 2.7e-13
float64 np.linalg.solve: 5.0e-13
```

The float32 solve alone gives about 4 digits ($1.5 \times 10^{-4}$, close to $\kappa\,\varepsilon_{32}$); each round adds
about four more, and after three rounds the error matches a full float64 `solve`. LAPACK's `dsgesv` and mixed-precision
GPU solvers do exactly this.

## Cholesky: the factorization for symmetric positive definite matrices

Covariance and kernel matrices, $X^\top X + \lambda I$ and the Hessian at a strict minimum are **symmetric positive
definite** (SPD): $\mathbf{z}^\top A\mathbf{z} > 0$ for every $\mathbf{z} \neq \mathbf{0}$ (ch. 7). For them elimination
needs no pivoting and becomes symmetric, $A = LL^\top$ with $L$ lower triangular and a positive diagonal: a matrix square
root. The scalar case says it all: $a = \ell^2$ has a real solution $\ell > 0$ exactly when $a > 0$.

### Deriving the Cholesky recurrence

This shows $L$ follows from $A = LL^\top$ column by column, one square root per column. Equating entries $(j, j)$ and
$(i, j)$ for $i > j$:

$$
\ell_{jj} = \sqrt{a_{jj} - \textstyle\sum_{k<j}\ell_{jk}^2}, \qquad
\ell_{ij} = \frac{a_{ij} - \sum_{k<j}\ell_{ik}\,\ell_{jk}}{\ell_{jj}}, \qquad
\text{flops} \approx \sum_{j=1}^{n} 2j(n-j) \approx \tfrac13 n^3 .
$$

The number under the root is the $j$-th pivot, equal to $\det A_{j}/\det A_{j-1}$ ($A_j$ is the top-left $j \times j$
block), so all pivots are positive if and only if $A$ is positive definite (Sylvester's criterion). The cost is half of
LU because symmetry lets you compute one triangle, and $\log|A| = 2\sum_j \log \ell_{jj}$, the term in every Gaussian
log-likelihood, comes free and never overflows.

```python
def cholesky_mine(A):
    """A = L L^T for symmetric positive definite A. Raises at the first non-positive pivot."""
    n = len(A); L = np.zeros((n, n)); flops = 0
    for j in range(n):
        d = A[j, j] - L[j, :j] @ L[j, :j];                              flops += 2 * j
        if d <= 0:
            raise np.linalg.LinAlgError(f"not positive definite: pivot {j} is {d:.2e}")
        L[j, j] = np.sqrt(d)
        L[j + 1:, j] = (A[j + 1:, j] - L[j + 1:, :j] @ L[j, :j]) / L[j, j];  flops += (n - j - 1) * (2 * j + 1)
    return L, flops

X = rng.standard_normal((400, 300)); S = X.T @ X / 400                     # a sample covariance, SPD
Lc, fc = cholesky_mine(S)
print(f"max |L - np.linalg.cholesky| = {np.abs(Lc - np.linalg.cholesky(S)).max():.1e} | "
      f"vs scipy = {np.abs(Lc - linalg.cholesky(S, lower=True)).max():.1e}")
print(f"flops: counted {fc:,} | n^3/3 = {300 ** 3 / 3:,.0f} | LU on same matrix {lu_factor_mine(S)[3]:,}")
print(f"log det: 2 sum log diag(L) = {2 * np.log(np.diag(Lc)).sum():.6f} | slogdet = {np.linalg.slogdet(S)[1]:.6f}")
```


### A positive-definiteness test that costs a third of an LU

Because the recurrence stops at the first non-positive pivot, *attempting* a Cholesky is the standard PD test, cheaper
than eigenvalues ($\tfrac43 n^3$ flops for symmetric eigenvalues alone) and what scipy, PyMC and GP libraries do inside.
Below, matrices with known eigenvalues straddle zero, then a GP kernel (Bayesian ML ch. 12) that is PD in exact
arithmetic but numerically singular, because neighbouring grid points are nearly identical.

```python
Q, _ = np.linalg.qr(rng.standard_normal((6, 6)))
print(f"{'smallest eigenvalue':>20}  cholesky_mine")
for lam_min in (1e-2, 1e-12, -1e-12, -1e-2):
    A_t = Q @ np.diag([5.0, 3.0, 2.0, 1.0, 0.5, lam_min]) @ Q.T
    A_t = (A_t + A_t.T) / 2
    try: cholesky_mine(A_t); msg = "succeeds"
    except np.linalg.LinAlgError as e: msg = str(e)
    print(f"{lam_min:>20.0e}  {msg}")
xs = np.linspace(0, 10, 200)                                   # GP kernel on a dense grid (Bayesian ML ch. 12)
K = np.exp(-0.5 * (xs[:, None] - xs[None, :]) ** 2 / 1.0 ** 2)
print(f"\nRBF kernel, 200 points: eigvalsh min = {np.linalg.eigvalsh(K).min():.1e}")
def chol_ok(Mx):
    try: np.linalg.cholesky(Mx); return "ok"
    except np.linalg.LinAlgError: return "fails"
print("np.linalg.cholesky(K + jitter I):", ", ".join(f"{j:.0e} {chol_ok(K + j * np.eye(200))}" for j in (0.0, 1e-12, 1e-10, 1e-8, 1e-6)))
```

```output

               1e-02  succeeds
               1e-12  succeeds
              -1e-12  not positive definite: pivot 5 is -7.91e-09
              -1e-02  not positive definite: pivot 4 is -3.99e-02
```

The verdict flips exactly where the smallest eigenvalue changes sign, even at $\pm 10^{-12}$, and the failing pivot is
close to the negative eigenvalue. The kernel's smallest computed eigenvalue is $-7 \times 10^{-15}$, so Cholesky fails,
and a jitter of $10^{-12}$ fixes it. That is why GP libraries add $10^{-10}$ to $10^{-6}$ to the diagonal by default,
and why a noise term $\sigma_n^2 I$ removes the problem.

## QR: orthogonal triangularization

LU triangularizes with shears, which can blow entries up; QR uses reflections, which never change lengths. $A = QR$ with
orthonormal columns in $Q$ ($Q^\top Q = I$) and $R$ upper triangular. Gram-Schmidt (ch. 1) builds $Q$ by subtracting
from each column its projections onto the earlier ones; Householder reflects each column onto a coordinate axis. Same
factors in exact arithmetic, very different ones in floating point.

### Householder reflections

This shows how one reflection zeroes a column below the diagonal. For $\mathbf{x}$, take
$\mathbf{v} = \mathbf{x} + \mathrm{sign}(x_1)\|\mathbf{x}\|\mathbf{e}_1$ normalized to unit length:

$$
H = I - 2\mathbf{v}\mathbf{v}^\top, \qquad H^\top H = I, \qquad H\mathbf{x} = -\mathrm{sign}(x_1)\|\mathbf{x}\|\,\mathbf{e}_1,
\qquad \text{flops} \approx \sum_{k=0}^{n-1} 4(m-k)(n-k) \approx 2mn^2 - \tfrac23 n^3 .
$$

$H$ mirrors across the hyperplane orthogonal to $\mathbf{v}$; the sign choice avoids cancellation in $v_1$. Applying
$H_k$ to the trailing block of $A \in \mathbb{R}^{m \times n}$ is a matrix-vector product plus a rank-1 update,
$4(m-k)(n-k)$ flops. Keeping the $\mathbf{v}_k$ instead of forming $Q$ lets you apply $Q^\top$ in $4mn$ flops. A product of
reflections is orthogonal to rounding whatever $A$ is. Gram-Schmidt has no such guarantee: when $\mathbf{a}_j$ is nearly in
the span of earlier columns, subtracting projections cancels almost everything. Modified Gram-Schmidt (subtract each
projection from all remaining columns at once) helps but does not cure it: $\|Q^\top Q - I\|$ is roughly
$\kappa^2\varepsilon$ for classical, $\kappa\varepsilon$ for modified, $\varepsilon$ for Householder.

```python
def householder_qr(A):
    """A = QR. Returns the reflector vectors V, R (n x n), and the flop count."""
    R = np.array(A, dtype=float); m, n = R.shape; V = []; flops = 0
    for k in range(n):
        x = R[k:, k]
        v = x.copy(); v[0] += np.copysign(np.linalg.norm(x), x[0]); v /= np.linalg.norm(v)
        R[k:, k:] -= 2.0 * np.outer(v, v @ R[k:, k:]);  flops += 4 * (m - k) * (n - k)
        V.append(v)
    return V, np.triu(R[:n]), flops
def apply_qt(V, b):                                     # Q^T b without ever forming Q
    y = np.array(b, dtype=float)
    for k, v in enumerate(V):
        y[k:] -= 2.0 * v * (v @ y[k:])
    return y
def form_q(V, m):                                       # thin Q, built by applying reflectors to I
    Qm = np.eye(m)[:, :len(V)]
    for k in range(len(V) - 1, -1, -1):
        v = V[k]; Qm[k:] -= 2.0 * np.outer(v, v @ Qm[k:])
    return Qm
def cgs(A):                                             # classical Gram-Schmidt
    Qm = np.zeros(A.shape)
    for j in range(A.shape[1]):
        v = A[:, j] - Qm[:, :j] @ (Qm[:, :j].T @ A[:, j]); Qm[:, j] = v / np.linalg.norm(v)
    return Qm
def mgs(A):                                             # modified Gram-Schmidt
    Qm = np.array(A, dtype=float)
    for j in range(A.shape[1]):
        Qm[:, j] /= np.linalg.norm(Qm[:, j])
        Qm[:, j + 1:] -= np.outer(Qm[:, j], Qm[:, j] @ Qm[:, j + 1:])
    return Qm

A = rng.standard_normal((100, 20))
V, R, fq = householder_qr(A); Qh = form_q(V, 100)
Q_np, R_np = np.linalg.qr(A)
print(f"max |A - QR| {np.abs(A - Qh @ R).max():.1e} | |R| vs numpy {np.abs(np.abs(R) - np.abs(R_np)).max():.1e} | "
      f"flops {fq:,} vs 2mn^2 - 2n^3/3 = {2 * 100 * 400 - 2 * 8000 / 3:,.0f}")
print(f"\n{'cond(A)':>8} {'CGS':>9} {'MGS':>9} {'Householder':>12} {'np.linalg.qr':>13}   (entries: ||Q^T Q - I||)")
for kappa in (1e2, 1e5, 1e8, 1e11):
    Ak = with_cond(100, 20, kappa, rng)
    loss = lambda Qm: np.linalg.norm(Qm.T @ Qm - np.eye(20))
    print(f"{kappa:>8.0e} {loss(cgs(Ak)):>9.1e} {loss(mgs(Ak)):>9.1e} {loss(form_q(householder_qr(Ak)[0], 100)):>12.1e} "
          f"{loss(np.linalg.qr(Ak)[0]):>13.1e}")
```

## Least squares three ways

When $A$ is tall ($m$ observations, $n < m$ features), $A\mathbf{x} = \mathbf{b}$ usually has no solution, and least
squares picks $\mathbf{x}$ minimizing $\|A\mathbf{x} - \mathbf{b}\|_2$: linear regression, with $A\mathbf{x}$ the
projection of $\mathbf{b}$ onto the column space (ch. 2). The three standard algorithms agree on well-conditioned data and
differ by many digits on the ill-conditioned designs that polynomial or nearly collinear features produce.

### Normal equations, QR, and SVD

This shows what each computes and why one squares the condition number. The residual must be orthogonal to every
column, $A^\top(\mathbf{b} - A\mathbf{x}) = \mathbf{0}$: the **normal equations** $A^\top A\,\mathbf{x} = A^\top\mathbf{b}$,
solved by Cholesky in $mn^2 + \tfrac13 n^3$ flops. With a thin QR,
$\|A\mathbf{x} - \mathbf{b}\|^2 = \|R\mathbf{x} - Q^\top\mathbf{b}\|^2 + \text{const}$, so solve $R\mathbf{x} = Q^\top\mathbf{b}$
after $2mn^2 - \tfrac23 n^3$ flops. With the SVD $A = U\Sigma V^\top$ (ch. 5), $\mathbf{x} = V\Sigma^{-1}U^\top\mathbf{b}$,
the most expensive and most informative. With $\kappa(A) = \sigma_{\max}/\sigma_{\min}$, the ratio of largest to smallest
singular value, and $A^\top A = V\Sigma^2 V^\top$,

$$
\boxed{\kappa(A^\top A) = \frac{\sigma_{\max}^2}{\sigma_{\min}^2} = \kappa(A)^2 .}
$$

Forming $A^\top A$ commits you to errors of order $\kappa^2\varepsilon$; QR and SVD work on $A$ and reach about
$\kappa\varepsilon$ when the fit is good (a large residual adds a $\kappa^2\varepsilon\|\mathbf{r}\|$ term to every
method: Trefethen and Bau, Lecture 18). Below, $\mathbf{b} = A\mathbf{x}_{\text{true}}$ exactly, so all error is the
algorithm's.

```python
def ls_normal(A, b):
    L, _ = cholesky_mine(A.T @ A); return back_sub(L.T, forward_sub(L, A.T @ b))
def ls_qr(A, b):
    V, R, _ = householder_qr(A); return back_sub(R, apply_qt(V, b)[:A.shape[1]])
def ls_svd(A, b):
    U_, s, Vt = np.linalg.svd(A, full_matrices=False); return Vt.T @ ((U_.T @ b) / s)

print(f"{'cond(A)':>8} {'cond(AtA)':>10} {'normal eq':>10} {'QR (mine)':>10} {'SVD':>9} {'lstsq':>9}   (relative error in x)")

    err = lambda x: np.linalg.norm(x - x_true) / np.linalg.norm(x_true)
    try: e_ne = f"{err(ls_normal(Ak, bk)):>10.1e}"
    except np.linalg.LinAlgError: e_ne = f"{'fails':>10}"

          f"{err(ls_svd(Ak, bk)):>9.1e} {err(np.linalg.lstsq(Ak, bk, rcond=None)[0]):>9.1e}")
```

when $m \gg n$, accumulable one row batch at a time, fine on standardized features with modest $\kappa$. But they are the
first suspect when coefficients look unstable.

## Rank-deficient least squares and the minimum-norm solution

If two features are exactly collinear you can shift weight between them without changing a single prediction, so
infinitely many coefficient vectors fit equally well. The classic route is the **dummy-variable trap**: an intercept plus
one-hot columns for *every* level of a categorical, so the dummies sum to the intercept column. The minimizers form an
affine set, and the natural pick is the shortest, given by the pseudo-inverse $A^{+}$.

### Why the minimum-norm solution lies in the row space

This shows $A^{+}$ picks the unique minimizer with no null-space component. Every minimizer is
$\mathbf{x} = \mathbf{x}_{+} + \mathbf{z}$ with $A\mathbf{z} = \mathbf{0}$. If $\mathbf{x}_{+}$ lies in the row space
(spanned by the right singular vectors $\mathbf{v}_i$ with $\sigma_i > 0$), it is orthogonal to every null vector, so
$\|\mathbf{x}\|^2 = \|\mathbf{x}_{+}\|^2 + \|\mathbf{z}\|^2$ is smallest at $\mathbf{z} = \mathbf{0}$. The SVD solution with
zero singular values skipped is in the row space by construction, and ridge reaches it as $\lambda \to 0^{+}$:

$$
\mathbf{x}_{+} = A^{+}\mathbf{b} = \sum_{\sigma_i > 0} \frac{\mathbf{u}_i^\top\mathbf{b}}{\sigma_i}\,\mathbf{v}_i
= \lim_{\lambda \to 0^{+}} (A^\top A + \lambda I)^{-1}A^\top\mathbf{b} .
$$

```python
n_obs = 300
g = rng.integers(0, 3, n_obs)                                   # a 3-level categorical feature
Xd = np.c_[np.ones(n_obs), np.eye(3)[g], rng.standard_normal(n_obs)]   # intercept + all 3 dummies + x: the dummy trap
yd = Xd @ np.array([1.0, 0.5, -0.5, 2.0, 3.0]) + 0.1 * rng.standard_normal(n_obs)
print("singular values:", np.linalg.svd(Xd, compute_uv=False).round(3))
print(f"rank {np.linalg.matrix_rank(Xd)} of {Xd.shape[1]} columns | cond(X^T X) = {np.linalg.cond(Xd.T @ Xd):.1e}")

x_ls, *_ = np.linalg.lstsq(Xd, yd, rcond=None)
null = np.array([1.0, -1.0, -1.0, -1.0, 0.0]) / 2              # X @ null = 0: intercept up, every dummy down
print(f"pinv  x = {x_mn.round(3)} | ||x|| = {np.linalg.norm(x_mn):.3f} | lstsq same: {np.allclose(x_ls, x_mn)}")
for t in (1.0, 5.0):
    xt = x_mn + t * null
    print(f"pinv + {t:.0f}*null: x = {xt.round(3)} | ||x|| = {np.linalg.norm(xt):.3f} | "
          f"residual change {np.linalg.norm(Xd @ xt - yd) - np.linalg.norm(Xd @ x_mn - yd):+.1e}")
ridge = lambda lam: np.linalg.solve(Xd.T @ Xd + lam * np.eye(5), Xd.T @ yd)
```

## When not to factor at all

A dense factorization costs $O(n^3)$ flops and $O(n^2)$ memory whatever the matrix looks like. Many large ML matrices are
sparse or exist only as a product: graph Laplacians, $X^\top X$ for a huge sparse feature matrix, a network's Hessian
that you can multiply by but never store. **Iterative solvers** need only $\mathbf{v} \mapsto A\mathbf{v}$. For SPD
systems the conjugate gradient method (ch. 12) needs on the order of $\sqrt{\kappa}$ iterations, each one product of
$2\,\mathrm{nnz}$ flops (nnz = number of nonzeros). The test matrix is the 2-D grid Laplacian.

```python
from scipy import sparse
from scipy.sparse.linalg import cg
for side in (30, 100):
    N = side * side
    T = sparse.diags([-1.0, 2.0, -1.0], [-1, 0, 1], shape=(side, side))
    Lap = (sparse.kron(sparse.eye(side), T) + sparse.kron(T, sparse.eye(side))).tocsr()   # 2-D grid Laplacian
    bL = np.ones(N); its = []
    xL, info = cg(Lap, bL, rtol=1e-10, maxiter=5000, callback=lambda xk: its.append(1))
    print(f"N={N:>6} nnz={Lap.nnz:>6} | dense LU 2N^3/3 = {2 * N ** 3 / 3:.1e} flops | "
          f"CG {len(its)} iters x 2*nnz = {len(its) * 2 * Lap.nnz:.1e} flops | rel resid {np.linalg.norm(Lap @ xL - bL) / np.linalg.norm(bL):.0e}")
```

```output
N=   900 nnz=  4380 | dense LU 2N^3/3 = 4.9e+08 flops | CG 62 iters x 2*nnz = 5.4e+05 flops | rel resid 4e-11
N= 10000 nnz= 49600 | dense LU 2N^3/3 = 6.7e+11 flops | CG 208 iters x 2*nnz = 2.1e+07 flops | rel resid 7e-11
```

At $N = 10^4$ a dense LU would cost $6.7 \times 10^{11}$ flops and 800 MB of storage; CG needs 208 products, $2 \times 10^7$
flops, about 30000 times fewer. Iterations grow from 62 to 208 as the grid side goes from 30 to 100: $\kappa$ grows like
side$^2$, so $\sqrt\kappa$ grows 3.3 times. Sparse direct solvers (`splu`, CHOLMOD) are the middle ground and often win in
2-D; CG wins when you can only multiply by $A$. Rule of thumb: dense with $n \lesssim 10^4$, factor; sparse, huge or
matrix-free, iterate (ch. 12).

Write `chol_solve_logdet(A, B)` that solves $AX = B$ for SPD $A$ and a matrix of right-hand sides $B$ with one Cholesky

```python
def chol_solve_logdet(A, B, jitter0=1e-10, max_tries=8):
    jitter = 0.0
    for _ in range(max_tries):
        try:
            L = np.linalg.cholesky(A + jitter * np.eye(len(A)))
            break
        except np.linalg.LinAlgError:
            jitter = jitter0 if jitter == 0.0 else 10 * jitter
    else:
        raise np.linalg.LinAlgError("still not PD after jitter")
    X = linalg.solve_triangular(L.T, linalg.solve_triangular(L, B, lower=True), lower=False)
    return X, 2 * np.log(np.diag(L)).sum(), jitter

rng = np.random.default_rng(3)

      f"logdet {logdet:.4f} vs slogdet {np.linalg.slogdet(Kj)[1]:.4f}")
```
