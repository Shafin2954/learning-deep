## Multilingual Models

Single models that cover dozens of languages are trained on massive multilingual corpora.
They learn a shared embedding space where semantically similar sentences from different languages
land nearby.

**mBERT** (Multilingual BERT) covers 104 languages; its cross-lingual transfer is surprisingly
strong despite no explicit cross-lingual objective. **XLM-R** (XLM-RoBERTa) was trained with
a larger corpus and no next-sentence-prediction, outperforming mBERT on most benchmarks.
**LaBSE** (Language-Agnostic BERT Sentence Encoder) is fine-tuned specifically for sentence
similarity across 109 languages — the right choice for cross-lingual retrieval.

None of these checkpoints can be downloaded in this course environment, so we reproduce the key idea on a toy scale: a small transformer sentence encoder trained with a **translation-pair contrastive loss** (the LaBSE recipe). The toy language has 16 concepts with an English, a Bengali and a French word each, and sentences are three concepts long. The three languages share no tokens, so any alignment the model finds comes only from the parallel data.

```python
import random, re, unicodedata, numpy as np, torch, torch.nn as nn, torch.nn.functional as F
from collections import Counter
torch.set_num_threads(1)
torch.manual_seed(0)
rng = random.Random(0)

LEX = [("dog", "কুকুর", "chien"), ("cat", "বিড়াল", "chat"), ("water", "জল", "eau"), ("book", "বই", "livre"),
       ("house", "বাড়ি", "maison"), ("sun", "সূর্য", "soleil"), ("river", "নদী", "rivière"), ("school", "স্কুল", "école"),
       ("teacher", "শিক্ষক", "professeur"), ("food", "খাবার", "nourriture"), ("big", "বড়", "grand"),
       ("small", "ছোট", "petit"), ("red", "লাল", "rouge"), ("eats", "খায়", "mange"), ("sees", "দেখে", "voit"),
       ("reads", "পড়ে", "lit")]
LANGS = {"en": 0, "bn": 1, "fr": 2}
render = lambda concepts, lang: " ".join(LEX[c][LANGS[lang]] for c in concepts)
vocab = ["[PAD]", "[CLS]", "[UNK]"] + sorted({w for row in LEX for w in row})
stoi = {w: i for i, w in enumerate(vocab)}

def encode(texts):
    rows = [[1] + [stoi.get(w, 2) for w in t.split()] for t in texts]
    L = max(map(len, rows))
    ids = torch.tensor([r + [0] * (L - len(r)) for r in rows])
    return ids, (ids != 0).long()

class SentenceEncoder(nn.Module):
    def __init__(self, V, d=48):
        super().__init__()
        self.tok, self.pos = nn.Embedding(V, d), nn.Embedding(16, d)
        layer = nn.TransformerEncoderLayer(d, 4, 4 * d, dropout=0.0, batch_first=True, norm_first=True)
        self.enc = nn.TransformerEncoder(layer, 2, enable_nested_tensor=False)
    def forward(self, texts):
        ids, mask = encode(texts)
        h = self.enc(self.tok(ids) + self.pos(torch.arange(ids.shape[1])), src_key_padding_mask=(mask == 0))
        m = mask.unsqueeze(-1).float()
        return F.normalize((h * m).sum(1) / m.sum(1), dim=-1)

model = SentenceEncoder(len(vocab))
opt = torch.optim.Adam(model.parameters(), lr=3e-3)
for step in range(200):
    batch = [tuple(rng.sample(range(16), 3)) for _ in range(32)]
    la, lb = rng.sample(list(LANGS), 2)                          # a random language pair each step
    A, B = model([render(c, la) for c in batch]), model([render(c, lb) for c in batch])
    S, y = A @ B.T / 0.1, torch.arange(len(batch))              # translations are positives, the rest negatives
    loss = (F.cross_entropy(S, y) + F.cross_entropy(S.T, y)) / 2
    opt.zero_grad(); loss.backward(); opt.step()
model.eval()

c = (0, 1, 2)                                                    # "dog cat water"
en, bn, fr = render(c, "en"), render(c, "bn"), render(c, "fr")
other = render((3, 4, 5), "fr")                                  # a different meaning, in French
print(en, "|", bn, "|", fr)
with torch.no_grad():
    embs = model([en, bn, fr, other])
print(f"EN-BN similarity: {embs[0] @ embs[1]:.4f}")
print(f"EN-FR similarity: {embs[0] @ embs[2]:.4f}")
print(f"BN-FR similarity: {embs[1] @ embs[2]:.4f}")
print(f"EN-other (different meaning, French): {embs[0] @ embs[3]:.4f}")
```

```output
dog cat water | কুকুর বিড়াল জল | chien chat eau
EN-BN similarity: 0.9653
EN-FR similarity: 0.9708
BN-FR similarity: 0.9679
EN-other (different meaning, French): -0.3233
```

The same meaning scores near 1 across all three languages, while a different meaning scores far lower: the model maps meaning across scripts. A fair test is cross-lingual retrieval on fresh sentences, where each English sentence must find its own Bengali translation among 100 candidates:

```python
tr = [tuple(rng.sample(range(16), 3)) for _ in range(100)]
with torch.no_grad():
    E_en = model([render(c, "en") for c in tr])
    E_bn = model([render(c, "bn") for c in tr])
    E_fr = model([render(c, "fr") for c in tr])
print("EN -> BN retrieval accuracy:", ((E_en @ E_bn.T).argmax(1) == torch.arange(100)).float().mean().item())
print("EN -> FR retrieval accuracy:", ((E_en @ E_fr.T).argmax(1) == torch.arange(100)).float().mean().item())
```

```output
EN -> BN retrieval accuracy: 0.9900000095367432
EN -> FR retrieval accuracy: 0.9900000095367432
```

With only 16 concepts, many of these triples were also seen in training, so treat this as a sanity check, not a generalisation benchmark.

## The Bengali Script

Bengali (বাংলা) uses the Bengali script, a member of the Brahmic script family.
Key Unicode facts:

- **Block**: U+0980–U+09FF (128 codepoints)
- **Characters**: vowels (স্বরবর্ণ), consonants (ব্যঞ্জনবর্ণ), numerals (০–৯), punctuation
- **Matras**: vowel signs that attach to consonants (e.g., ি, া, ু)
- **Hasanta** (্): suppresses the inherent vowel, used in conjunct consonants

### Conjunct Consonants (যুক্তাক্ষর)

Bengali forms conjuncts by stacking consonants with the hasanta. What looks like one glyph
is actually multiple Unicode codepoints:

```python
word = "ক্ষ"   # ksha — one rendered glyph
print(f"Codepoints: {len(word)}")
print(f"Codepoints: {[hex(ord(c)) for c in word]}")
# ক (U+0995) + ্ (U+09CD, hasanta) + ষ (U+09B7)
```

```output
Codepoints: 3
Codepoints: ['0x995', '0x9cd', '0x9b7']
```

One glyph, three codepoints. This causes issues for tokenisers that treat codepoints as
atomic units.

## How BPE Handles Bengali

GPT-2-style byte-level BPE treats every byte as a potential merge unit. Bengali characters
use 3 bytes each in UTF-8, so a Bengali word costs three times as many bytes as characters, and a tokeniser that never learned Bengali merges can only split it into byte pieces. We cannot load GPT-2, mBERT or XLM-R here, so we train two small character-level BPE tokenizers with byte fallback (as in ch. 2): one on English only, one on a small English + Bengali + Arabic corpus. The corpora are tiny and the Bengali test words appear in the multilingual training text, so the numbers show the *direction* of the effect (coverage), not real-world magnitudes.

```python
def get_vocab(words):
    c = Counter()
    for w in words:
        c[" ".join(list(w)) + " </w>"] += 1
    return dict(c)

def pair_counts(v):
    c = Counter()
    for seq, f in v.items():
        sy = seq.split()
        for a, b in zip(sy, sy[1:]):
            c[(a, b)] += f
    return c

def merge(pair, v):
    pat = re.compile(r"(?<!\S)" + re.escape(" ".join(pair)) + r"(?!\S)")
    return {pat.sub("".join(pair), k): f for k, f in v.items()}

def train_bpe(words, n):
    v, merges = get_vocab(words), []
    for _ in range(n):
        pc = pair_counts(v)
        if not pc:
            break
        best = max(pc, key=lambda p: (pc[p], p))
        merges.append(best); v = merge(best, v)
    return merges

def bpe_encode(word, merges, chars):
    syms = []
    for ch in word:
        syms += [ch] if ch in chars else [f"<0x{b:02X}>" for b in ch.encode("utf-8")]   # byte fallback
    syms.append("</w>")
    for a, b in merges:
        i = 0
        while i < len(syms) - 1:
            if syms[i] == a and syms[i + 1] == b:
                syms[i:i + 2] = [a + b]
            else:
                i += 1
    return syms

en_train = ("the machine learning model was trained on large datasets . the model learns from data and the data is large . "
            "machine translation helps people read the news").split() * 2
bn_train = ("মেশিন লার্নিং মডেলটি বড় ডেটাসেটে প্রশিক্ষিত হয়েছিল । মডেলটি ডেটা থেকে শেখে এবং ডেটা বড় । বাংলাদেশ একটি সুন্দর দেশ । "
            "বাংলাদেশের রাজধানী ঢাকা । প্রযুক্তি ও বিজ্ঞান সভ্যতাকে এগিয়ে নিয়েছে").split() * 2
ar_train = "تم تدريب نموذج التعلم الآلي على مجموعات بيانات كبيرة . يتعلم النموذج من البيانات . اللغة العربية جميلة".split() * 2

tokenizers = {
    "English-only BPE": (train_bpe(en_train, 60), set("".join(en_train))),
    "Multilingual BPE": (train_bpe(en_train + bn_train + ar_train, 200), set("".join(en_train + bn_train + ar_train))),
}
word = "বাংলাদেশ"   # Bangladesh
print(f"{word}: {len(word)} characters, {len(word.encode('utf-8'))} UTF-8 bytes")
for name, (merges, chars) in tokenizers.items():
    tokens = bpe_encode(word, merges, chars)
    print(f"{name:17s}: {len(tokens):2d} tokens  {tokens[:6]}{' ...' if len(tokens) > 6 else ''}")
```

```output
বাংলাদেশ: 8 characters, 24 UTF-8 bytes
English-only BPE : 25 tokens  ['<0xE0>', '<0xA6>', '<0xAC>', '<0xE0>', '<0xA6>', '<0xBE>'] ...
Multilingual BPE :  1 tokens  ['বাংলাদেশ</w>']
```

The multilingual tokenizer has learned Bengali merges, so "বাংলাদেশ" is a single token (1 vs 25); the English-only tokenizer falls back to raw bytes. Real XLM-R or mBERT vocabularies sit between these extremes, while GPT-2's byte-level BPE needs several tokens per Bengali character.

## Fertility: Tokens per Word

Fertility measures how many tokens a model produces per word — a proxy for how well its
vocabulary covers a language:

```python
sentences = {
    "English": "The machine learning model trained on large datasets.",
    "Bengali": "মেশিন লার্নিং মডেলটি বড় ডেটাসেটে প্রশিক্ষিত হয়েছিল।",
    "Bengali (new combination)": "ঢাকা একটি বড় সুন্দর দেশ",
    "Arabic":  "تم تدريب نموذج التعلم الآلي على مجموعات بيانات كبيرة.",
}

def n_tokens(sent, merges, chars):
    return sum(len(bpe_encode(w, merges, chars)) for w in sent.split())

for name, (merges, chars) in tokenizers.items():
    print(name)
    for lang, sent in sentences.items():
        words = sent.split()
        n = n_tokens(sent, merges, chars)
        print(f"  {lang:26s}: {len(words):2d} words  {n:3d} tokens  fertility={n / len(words):.2f}")
```

```output
English-only BPE
  English                   :  8 words   17 tokens  fertility=2.12
  Bengali                   :  7 words  148 tokens  fertility=21.14
  Bengali (new combination) :  5 words   65 tokens  fertility=13.00
  Arabic                    :  9 words   97 tokens  fertility=10.78
Multilingual BPE
  English                   :  8 words   21 tokens  fertility=2.62
  Bengali                   :  7 words    9 tokens  fertility=1.29
  Bengali (new combination) :  5 words    5 tokens  fertility=1.00
  Arabic                    :  9 words   11 tokens  fertility=1.22
```

With the English-only tokenizer, Bengali and Arabic fall back to bytes and pay a fertility of 13-21 (Arabic 10.8) against 2.1 for English. The multilingual tokenizer brings them down to about 1-1.3 tokens per word, because these words (or their pieces) were in its training text; its English fertility rises slightly (2.12 to 2.62) because the merge budget is now shared across three languages. The "new combination" Bengali sentence is cheap (1.0) because each of its words was seen individually. In real models the Bengali penalty is milder (about 3x English for XLM-R) yet still means Bengali inputs use more of the context window and Bengali generation is slower.

## Unicode Normalisation Pitfalls

The same visual text can have multiple Unicode representations. Bengali has real examples: the vowel sign ো (U+09CB) can be written as one codepoint or as the two codepoints ে (U+09C7) + া (U+09BE) that it is made of:

```python
composed   = "কো"                 # ক + ো (U+09CB)
decomposed = "\u0995\u09c7\u09be"   # ক + ে + া
print(f"composed:   len={len(composed)},   codepoints={[hex(ord(c)) for c in composed]}")
print(f"decomposed: len={len(decomposed)}, codepoints={[hex(ord(c)) for c in decomposed]}")
print("equal as strings?        ", composed == decomposed)
nfc = unicodedata.normalize("NFC", decomposed)
print("equal after NFC?         ", composed == nfc)

# The same idea in Latin script: a + combining acute accent
nfd_a_acute = "a\u0301"
nfc_a_acute = unicodedata.normalize("NFC", nfd_a_acute)
print(f"NFD len={len(nfd_a_acute)}, NFC len={len(nfc_a_acute)}")
```

```output
composed:   len=2,   codepoints=['0x995', '0x9cb']
decomposed: len=3, codepoints=['0x995', '0x9c7', '0x9be']
equal as strings?         False
equal after NFC?          True
NFD len=2, NFC len=1
```

Two strings that render identically compare as unequal, so a tokenizer, dictionary lookup or de-duplication step would treat them differently. Always normalise to NFC before tokenising. `unicodedata.normalize("NFC", text)` is a one-line fix that prevents silent mismatches.

### Zero-Width Characters

Zero-width joiners (U+200D) and non-joiners (U+200C) are invisible but change rendering.
They are common in copy-pasted Bengali text and can cause tokeniser mismatches:

```python
clean  = "আমি"
zwj    = "আ\u200dমি"    # zero-width joiner inserted

print(f"Clean:  len={len(clean)}, bytes={clean.encode('utf-8')}")
print(f"ZWJ:    len={len(zwj)},   bytes={zwj.encode('utf-8')}")
print(f"Equal?  {clean == zwj}")
```

```output
Clean:  len=3, bytes=b'\xe0\xa6\x86\xe0\xa6\xae\xe0\xa6\xbf'
ZWJ:    len=4,   bytes=b'\xe0\xa6\x86\xe2\x80\x8d\xe0\xa6\xae\xe0\xa6\xbf'
Equal?  False
```

Strip zero-width characters before tokenising in production: `text.replace("\u200d", "").replace("\u200c", "")`. (Careful: in some scripts, such as Persian, the non-joiner is meaningful; check your language.)

## Tokeniser Robustness Testing

Before deploying a multilingual pipeline, run these checks on your target language:

```python
def tokeniser_robustness_check(merges, chars, word, name=""):
    results = {}
    for label, variant in [("NFC", unicodedata.normalize("NFC", word)),
                           ("NFD", unicodedata.normalize("NFD", word)),
                           ("ZWJ", word + "\u200d")]:
        results[label] = len(bpe_encode(variant, merges, chars))
    consistent = results["NFC"] == results["NFD"]
    print(f"{name}: NFC={results['NFC']} NFD={results['NFD']} ZWJ={results['ZWJ']} consistent={consistent}")

merges, chars = tokenizers["Multilingual BPE"]
tokeniser_robustness_check(merges, chars, "বাংলাদেশ", "no matra-composition  ")
tokeniser_robustness_check(merges, chars, "মোবাইল", "contains ো (U+09CB)")
```

```output
no matra-composition  : NFC=1 NFD=1 ZWJ=5 consistent=True
contains ো (U+09CB): NFC=11 NFD=10 ZWJ=14 consistent=False
```

For words with no decomposable characters NFC and NFD agree; for a word containing ো the counts differ (11 tokens vs 10 here), and a trailing ZWJ changes the count again (3 extra byte tokens for the joiner). This is why a pipeline should strip zero-width characters and normalise to NFC *before* tokenising.

```python
def bengali_fertility(sentence: str, merges, chars) -> float:
    sentence = unicodedata.normalize("NFC", sentence)
    sentence = sentence.replace("\u200d", "").replace("\u200c", "")
    words = sentence.split()
    n = sum(len(bpe_encode(w, merges, chars)) for w in words)
    return n / len(words) if words else 0.0

merges, chars = tokenizers["Multilingual BPE"]
sentences = [
    "আমি বাংলায় কথা বলি।",                         # simple
    "বাংলাদেশের রাজধানী ঢাকা।",                      # medium
    "প্রযুক্তি ও বিজ্ঞানের অগ্রগতি সভ্যতাকে এগিয়ে নিয়েছে।",  # complex
]

scores = [bengali_fertility(s, merges, chars) for s in sentences]
for s, f in zip(sentences, scores):
    print(f"Fertility={f:.2f}: {s}")
print("Highest fertility:", sentences[scores.index(max(scores))])
```

## Under the Trench

Rare and advanced topics you should at least know the name of. You won't need them daily,
but you'll stop being surprised when you meet them.

- **Quantization for inference (GPTQ/AWQ, GGUF)** — run 7B models on consumer GPU; AWQ calibrates which weights are most important to preserve.
- **KV-cache management & paged attention (vLLM)** — PagedAttention treats the KV cache like OS virtual memory; enables 24× higher throughput.
- **Long-context tricks & context compression** — LLMLingua selective compression; StreamingLLM with attention sinks; KV eviction policies.
- **Speculative decoding** — draft with a 3B model, verify in parallel with a 70B model; identical output at 2–3× throughput.
- **Structured generation / constrained decoding** — finite-state machine over token vocabulary; guarantees valid JSON/code/regex output.
- **Tool use & function calling internals** — special tokens signal tool calls; parallel calls; tool result injection into context.
- **Embedding model fine-tuning & hard-negative mining** — mine hard negatives from BM25 top-k to sharpen retrieval models.
- **Guardrails, jailbreak & prompt-injection defense** — NeMo Guardrails, Llama Guard 3, canary tokens, output classifiers.
- **Classic NLP (NER, POS, dependency parsing, coreference)** — spaCy pipelines; still faster and more reliable than LLMs for structured extraction at scale.
