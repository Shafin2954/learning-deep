## The Vocabulary Mismatch Problem

Dense retrieval finds documents semantically similar to the query embedding. But the query "how
do I fix a segfault in C?" and the document "debugging memory access violations in C programs"
are semantically close but share few keywords. BM25 misses; dense retrieval sometimes misses
too if the query phrasing differs from training data.

Query transformation rewrites or expands the query before retrieval to close this gap.

## Query Rewriting

Ask the model to rephrase the user query into a form more likely to match relevant documents:

```python
def rewrite_query(query: str, model_fn) -> str:
    prompt = (
        "Rewrite the following query to be more specific and suitable for document retrieval. "
        "Return only the rewritten query, nothing else.\n\n"
        f"Query: {query}\n"
        "Rewritten:"
    )
    return model_fn(prompt).strip()

# Simulated model_fn response (no LLM is called in this course environment)
original = "why is my model not learning"
rewritten = "neural network training failure: loss not decreasing despite multiple epochs"

print(f"Original : {original}")
print(f"Rewritten: {rewritten}")
```

```output
Original : why is my model not learning
Rewritten: neural network training failure: loss not decreasing despite multiple epochs
```

The rewritten query contains specific vocabulary ("training failure", "loss not decreasing")
that matches troubleshooting documents more precisely.

## Setting up a toy retrieval stack

Pretrained sentence encoders cannot be downloaded here, and no LLM is called. For retrieval we use **LSA** (TF-IDF followed by truncated SVD fitted on a synthetic topical background corpus) as a stand-in dense encoder: low-dimensional vectors that capture word co-occurrence. For the LLM steps (rewriting, hypothetical answers, query variants, decomposition) we use **simulated outputs written by hand**, clearly marked in the code. What the chapter really tests is what happens *after* the LLM: how the transformed query changes retrieval.

```python
import numpy as np, random, re
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.decomposition import TruncatedSVD

rng = random.Random(0)
TOPICS = {
 "optim": ("gradient descent updates model parameters steepest loss learning rate step training momentum velocity "
           "accumulating adam moment estimates per-parameter optimiser optimisers rmsprop sgd converge oscillation "
           "adaptive sparse gradients improve adjusting rules faster").split(),
 "regul": ("dropout zeros activations overfitting regularisation penalty weights batch normalisation mini-batch "
           "augmentation synthetic examples transforms early stopping validation loss weight decay prevent "
           "techniques deep learning").split(),
 "trans": ("attention transformers rnn parallelisable bert masked language modelling pretraining gpt autoregressively "
           "token self-attention queries keys values positional encoding sequence encoder decoder cross-attention "
           "architecture components mechanisms").split(),
 "debug": ("divergence instability diverge training unstable learning rate too large loss nan exploding gradients "
           "clipping warmup resnet epoch causes neural network").split(),
}
FILL = "the a of and is for by in with how what are does to".split()
background = [" ".join(rng.sample(TOPICS[t], 10) + rng.sample(FILL, 4)) for t in TOPICS for _ in range(80)]

def analyzer(text):                          # lowercase words, crude plural stripping
    return [w[:-1] if len(w) > 3 and w.endswith("s") else w for w in re.findall(r"[a-z0-9\-]+", text.lower())]

docs = [
    "Gradient descent updates model parameters in the direction of steepest loss descent.",
    "The learning rate controls how large each update step is during training.",
    "Momentum accelerates gradient descent by accumulating a velocity vector.",
    "Adam uses first and second moment estimates for per-parameter learning rates.",
    "Early stopping monitors validation loss to prevent overfitting.",
]
vec = TfidfVectorizer(analyzer=analyzer, sublinear_tf=True).fit(background + docs)
svd = TruncatedSVD(10, random_state=0).fit(vec.transform(background + docs))

def embed(texts):
    E = svd.transform(vec.transform(texts))
    return E / (np.linalg.norm(E, axis=1, keepdims=True) + 1e-9)

doc_embs = embed(docs)
print("docs embedded:", doc_embs.shape)
```

```output
docs embedded: (5, 10)
```

## HyDE: Hypothetical Document Embedding

HyDE (Gao et al. 2022) generates a hypothetical answer to the query, embeds it, and uses that
embedding for retrieval. The key insight: a hypothetical answer lives in document space, so it
matches real documents better than a short query does.

```python
query = "how do optimisers improve training?"

# Direct query retrieval
direct_scores = (embed([query]) @ doc_embs.T)[0]

# HyDE: generate a hypothetical answer, then embed it  (SIMULATED LLM output)
hypothetical = (
    "Optimisers improve training by adjusting gradient update rules. "
    "Techniques like momentum, Adam, and RMSProp reduce oscillation and adapt learning rates, "
    "converging faster than vanilla gradient descent."
)
hyde_scores = (embed([hypothetical]) @ doc_embs.T)[0]

top2 = lambda sc: [(int(i), round(float(sc[i]), 4)) for i in np.argsort(-sc)[:2]]
print("Direct vs HyDE top-2:")
print("  Direct:", top2(direct_scores))
print("  HyDE  :", top2(hyde_scores))
```

```output
Direct vs HyDE top-2:
  Direct: [(0, 0.8536), (2, 0.748)]
  HyDE  : [(0, 0.9235), (3, 0.7637)]
```

Index 0 is gradient descent, 3 is Adam, 2 is momentum. HyDE keeps the gradient descent document on top with a higher score (0.92 vs 0.85) and brings the Adam document (3) into second place in place of momentum (2), because the hypothetical answer explicitly mentions "Adam" and "learning rates", which the short query did not. With a toy encoder the gain is modest; the mechanism is what matters.

## Multi-Query Retrieval

Generate $N$ variants of the query, retrieve for each, union the results (deduplicated):

```python
def multi_query_retrieve(query, n_variants, embed_fn, doc_embs, docs, top_k=3):
    # Simulated LLM output: query variants
    variants = [
        query,
        "techniques for improving neural network optimisation",
        "gradient-based learning rate adaptation methods",
    ][:n_variants]

    seen, results = set(), []
    for v in variants:
        scores = (embed_fn([v]) @ doc_embs.T)[0]
        for idx in np.argsort(scores)[::-1][:top_k]:
            if idx not in seen:
                seen.add(idx)
                results.append((float(scores[idx]), int(idx), docs[idx]))
    return sorted(results, reverse=True)

results = multi_query_retrieve("how do optimisers work", 3, embed, doc_embs, docs, top_k=2)
print(f"Multi-query union: {len(results)} unique docs retrieved")
for score, idx, doc in results[:4]:
    print(f"  [{score:.4f}] {doc[:60]}")
```

```output
Multi-query union: 4 unique docs retrieved
  [0.7050] Momentum accelerates gradient descent by accumulating a velo
  [0.6921] Gradient descent updates model parameters in the direction o
  [0.4367] Adam uses first and second moment estimates for per-paramete
  [0.2513] The learning rate controls how large each update step is dur
```

Three query variants with `top_k=2` each produce a union of four distinct documents, so the variants did widen coverage compared with a single query's top 2.

## Query Decomposition

For multi-hop questions, decompose into sub-questions and retrieve for each:

```python
complex_query = "What is the difference between Adam and SGD with momentum, and which is better for sparse gradients?"

# Simulated LLM decomposition:
sub_questions = [
    "How does the Adam optimiser work?",
    "How does SGD with momentum work?",
    "Which optimiser handles sparse gradients better?",
]

print("Sub-questions:")
for i, q in enumerate(sub_questions, 1):
    scores = (embed([q]) @ doc_embs.T)[0]
    top_idx = int(np.argmax(scores))
    print(f"  Q{i}: {q}")
    print(f"       -> {docs[top_idx][:60]}")
```

```output
Sub-questions:
  Q1: How does the Adam optimiser work?
       -> Gradient descent updates model parameters in the direction o
  Q2: How does SGD with momentum work?
       -> Momentum accelerates gradient descent by accumulating a velo
  Q3: Which optimiser handles sparse gradients better?
       -> Momentum accelerates gradient descent by accumulating a velo
```

Each sub-question is retrieved independently. The toy encoder is imperfect: Q1 ("How does the Adam optimiser work?") retrieves the gradient descent document instead of the Adam one, because LSA vectors only know topical similarity, not that "Adam" is the key term. Decomposition helps only if the retriever can answer each sub-question; this is where a stronger encoder or hybrid search (ch. 11) pays off.

## Step-Back Prompting

Abstract the question to a more general form, retrieve at that level, then answer the specific:

```python
specific = "Why does my ResNet training diverge with lr=0.1 after epoch 5?"
step_back = "What causes neural network training instability and divergence?"   # simulated LLM output

for name, q in [("specific ", specific), ("step-back", step_back)]:
    sc = (embed([q]) @ doc_embs.T)[0]
    top = int(np.argmax(sc))
    print(f"{name}: top doc [{sc[top]:.3f}] {docs[top]}")
```

```output
specific : top doc [0.447] The learning rate controls how large each update step is during training.
step-back: top doc [0.391] The learning rate controls how large each update step is during training.
```

Both queries reach the learning-rate document, which is the right context for diagnosing divergence. The step-back query has a lower raw score (0.391 vs 0.447) because it is more general; its benefit is robustness: it drops incidental details (ResNet, lr=0.1, epoch 5) that rarely appear in documentation, so it keeps working when the specific query would match nothing.

```python
corpus = [
    "Dropout randomly zeros activations during training to prevent overfitting.",
    "L2 regularisation adds a penalty proportional to the square of weights.",
    "Batch normalisation normalises activations within each mini-batch.",
    "Data augmentation creates synthetic training examples via transforms.",
    "Early stopping halts training when validation loss stops improving.",
]
c_embs = embed(corpus)

query = "prevent overfitting in deep learning"
direct = (embed([query]) @ c_embs.T)[0]

# Try HyDE: write a short hypothetical paragraph and embed it (simulated LLM output)
hypothetical = "To prevent overfitting, common techniques include dropout, weight decay (L2), data augmentation, and early stopping."
hyde = (embed([hypothetical]) @ c_embs.T)[0]

print("Direct  top-3:", [corpus[i][:40] for i in np.argsort(direct)[::-1][:3]])
print("HyDE    top-3:", [corpus[i][:40] for i in np.argsort(hyde)[::-1][:3]])
```

```output
Direct  top-3: ['Dropout randomly zeros activations durin', 'Early stopping halts training when valid', 'Batch normalisation normalises activatio']
HyDE    top-3: ['Dropout randomly zeros activations durin', 'L2 regularisation adds a penalty proport', 'Data augmentation creates synthetic trai']
```

Write a different hypothetical answer (for instance one that mentions only dropout) and watch the ranking follow it: HyDE is only as good as the hypothetical document, which is why a hallucinated answer can mislead retrieval.

## Exercise

Implement a pipeline that (1) rewrites a query using a template prompt, (2) generates three
query variants, (3) retrieves with all four queries (original + rewritten + 2 variants), and
(4) deduplicates and returns the top-5 unique documents by max score across all queries.
(Use simulated rewrite and variants, as above.)

<summary>Solution</summary>

```python
corpus = [
    "Attention mechanisms let models focus on relevant input tokens.",
    "Transformers replaced RNNs due to parallelisability during training.",
    "BERT uses masked language modelling as a pretraining objective.",
    "GPT generates text autoregressively, predicting the next token.",
    "Self-attention computes queries, keys, and values from the same sequence.",
    "Positional encoding injects sequence order information into transformer inputs.",
    "Cross-attention lets the decoder attend to encoder hidden states.",
]
c_embs = embed(corpus)

original = "how does the transformer architecture work"
queries = [
    original,
    "transformer model components and mechanisms",        # rewritten (simulated)
    "self-attention and positional encoding explained",   # variant 1 (simulated)
    "BERT GPT architecture differences",                  # variant 2 (simulated)
]

best_score = np.full(len(corpus), -np.inf)
for q in queries:
    scores = (embed([q]) @ c_embs.T)[0]
    best_score = np.maximum(best_score, scores)

top5 = np.argsort(best_score)[::-1][:5]
print("Top-5 unique docs by max score across all queries:")
for idx in top5:
    print(f"  [{best_score[idx]:.4f}] {corpus[idx]}")
```

```output
Top-5 unique docs by max score across all queries:
  [0.9587] Positional encoding injects sequence order information into transformer inputs.
  [0.9518] BERT uses masked language modelling as a pretraining objective.
  [0.9394] Attention mechanisms let models focus on relevant input tokens.
  [0.9134] GPT generates text autoregressively, predicting the next token.
  [0.9009] Self-attention computes queries, keys, and values from the same sequence.
```

Taking the max over queries means a document is returned if any variant matches it well, which is what lets multi-query retrieval cover several phrasings of the same need.
