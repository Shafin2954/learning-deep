## The overfitting problem in deep nets

A big network can learn the training set by heart, including its noise, the way a student can
memorize last year's answer sheet without understanding the subject. **Overfitting** is that
gap: great on data it has seen, worse on data it has not. **Regularization** is any technique
that makes memorizing harder so the network has to learn the general pattern instead.

A sufficiently large network can memorize any finite training set — it has enough parameters to assign a distinct activation pattern to each example. Regularization techniques constrain the effective capacity to improve generalization to unseen data. The bias-variance tradeoff applies: too much regularization underfits; too little overfits.

**Capacity** is how complicated a function the network can represent; **generalization** is
how well it does on new data. The **bias-variance tradeoff** (Probability & Statistics, ch. 13)
says a model can be too stiff (high bias, **underfitting**) or too jumpy (high variance,
overfitting), and regularization is the dial between them.

The block below does not train anything: it draws two made-up curves with the typical shapes,
so you can recognise the pattern when you see it in real training.

```python
import numpy as np

np.random.seed(42)
# Simulate train/val loss curves: overfit baseline
epochs = np.arange(1, 101)
train_loss_base = 0.5 * np.exp(-0.05 * epochs) + 0.01
val_loss_base   = 0.5 * np.exp(-0.04 * epochs) + 0.01 + 0.3*(1 - np.exp(-0.03*(epochs-30)))*np.maximum(0, epochs-30)/70

print("Epoch | Train  | Val (overfit)")
for e in [10, 30, 50, 70, 100]:
    print(f"  {e:3d} | {train_loss_base[e-1]:.4f} | {val_loss_base[e-1]:.4f}")
```

```output
Epoch | Train  | Val (overfit)
   10 | 0.3133 | 0.3452
   30 | 0.1216 | 0.1606
   50 | 0.0510 | 0.1163
   70 | 0.0251 | 0.1602
  100 | 0.0134 | 0.2824
```

Both curves fall at first: at epoch 30 the training loss is 0.1216 and the validation loss is
0.1606. Then they split. The training loss keeps falling to 0.0134 at epoch 100, while the
validation loss bottoms out near epoch 50 (0.1163) and climbs back to 0.2824. **Validation**
data is held out from training and used only to measure.

Training loss keeps falling while validation loss turns upward around epoch 50 — classic
overfitting. (The overfitting term in the simulation switches on at epoch 30, but it takes
about 20 more epochs to outweigh the still-falling base curve.)

> **Watch out:** never judge a model by its training loss. A training loss near zero with a
> rising validation loss is the signature of memorization, not success.

## Weight decay (L2 regularization)

Big weights let a network make sharp, wiggly decisions that fit noise. **Weight decay** adds a
small charge for weight size to the loss, so the network keeps weights small unless they earn
their keep.

Adding an L2 penalty to the loss shrinks weights toward zero:

$$\mathcal{L}_{\text{reg}} = \mathcal{L} + \frac{\lambda}{2}\|\theta\|^2$$

> **In plain words:** the new loss is the old loss plus $\lambda/2$ times the sum of all squared
> weights. **L2** refers to this sum of squares. $\lambda$ ("lambda") sets the price per unit of
> squared weight; the $1/2$ is there to make the derivative tidy.

The gradient update becomes:

$$\theta \leftarrow \theta - \eta\left(\nabla\mathcal{L} + \lambda\theta\right) = (1 - \eta\lambda)\theta - \eta\nabla\mathcal{L}$$

> **In plain words:** the gradient of $\frac{\lambda}{2}\theta^2$ is $\lambda\theta$. Plugging it
> into the SGD step and regrouping shows that each step first multiplies every weight by a
> number slightly below 1, $(1 - \eta\lambda)$, and then does the ordinary gradient step. That
> constant shrink is why it is called *decay*.

The $(1-\eta\lambda)$ factor multiplies weights on every step, shrinking them. This prevents any single weight from growing large, reducing reliance on any one feature. Typical values: $\lambda \in [10^{-5}, 10^{-2}]$.

**L1 regularization** ($\lambda\|\theta\|_1$) produces sparse solutions — many weights go exactly to zero — because the gradient is a constant $\pm\lambda$ regardless of weight magnitude, pushing small weights all the way to zero.

A **sparse** solution is one where most weights are exactly 0. L2 takes off a *percentage*
each step, so a weight gets closer to 0 but never reaches it. L1 takes off a fixed *amount*
each step, so a small weight runs out. The code implements L1 as a **soft-threshold** step:
shrink by $\eta\lambda$, and if that would cross zero, stop at zero.

> **Picture it:** L2 is a tax of 1% on every bank balance each day — big accounts lose a lot,
> tiny ones lose almost nothing, nobody reaches exactly zero. L1 is a flat fee of 1 cent a day
> — big accounts barely notice, small accounts are emptied and closed.

```python
def apply_l2(params, grads, lr=0.01, lam=1e-3):
    return params - lr*(grads + lam*params)

def apply_l1(params, grads, lr=0.01, lam=1e-3):
    # proximal (soft-threshold) step: shrink by lr*lam, but never past zero
    p = params - lr*grads
    return np.sign(p) * np.maximum(np.abs(p) - lr*lam, 0)

np.random.seed(0)
w = np.array([3.0, 0.01, 1.5, -0.005, 2.0])
g = np.zeros(5)  # zero gradient: see pure regularization effect

w_l2 = w.copy(); w_l1 = w.copy()
for _ in range(100):
    w_l2 = apply_l2(w_l2, g, lam=0.1)
    w_l1 = apply_l1(w_l1, g, lam=0.1)

print(f"Original: {w}")
print(f"L2 (100 steps): {np.round(w_l2, 4)}")
print(f"L1 (100 steps): {np.round(w_l1, 4)}")
```

```output
Original: [ 3.     0.01   1.5   -0.005  2.   ]
L2 (100 steps): [ 2.7144  0.009   1.3572 -0.0045  1.8096]
L1 (100 steps): [2.9 0.  1.4 0.  1.9]
```

With the gradient set to zero you see only the penalty, using $\lambda = 0.1$. L2 multiplied
every weight by the same factor, $(1 - 0.01 \cdot 0.1)^{100} \approx 0.905$: 3.0 became 2.7144,
0.01 became 0.009. L1 subtracted the same amount, $100 \times 0.01 \times 0.1 = 0.1$, from
every weight: 3.0 became 2.9 and 1.5 became 1.4. The two small weights (0.01 and $-0.005$) hit
exactly 0 and stayed there.

L2 shrinks all weights proportionally. L1 zeros out the two near-zero weights while barely touching the large ones.

> **Watch out:** the naive L1 update `params - lr*lam*np.sign(params)` does *not* produce exact
> zeros: a weight near 0 overshoots to the other side, flips sign, and bounces around 0 forever.
> The `np.maximum(..., 0)` clamp is what makes zeros exact.

## Dropout

**Dropout** switches off a random subset of neurons on every training step. Because any neuron
might vanish at any moment, the network cannot lean on one particular neuron and has to spread
what it knows across many.

Dropout randomly sets activations to zero during training with probability $p$ (the "drop rate"). Each forward pass uses a different random mask — the network cannot rely on any particular neuron being present.

A **mask** is an array of 0s and 1s, one per activation: 1 means "keep", 0 means "drop".

**Inverted dropout** (the standard): scale surviving activations by $1/(1-p)$ during training so the expected activation magnitude matches inference (where all neurons are active):

With $p = 0.5$, half the units survive and each is doubled, so the average stays the same as
with no dropout. At inference you then use the network as-is, with no rescaling.

```python
def dropout_forward(x, p=0.5, training=True):
    if not training:
        return x
    mask = (np.random.rand(*x.shape) > p).astype(float)
    return x * mask / (1 - p)  # inverted dropout scaling

np.random.seed(1)
x = np.ones((1000, 8))  # all ones to see the scaling clearly
out_train = dropout_forward(x, p=0.5, training=True)
out_infer = dropout_forward(x, p=0.5, training=False)

print(f"Training output  (some zeros, rest ×2): {out_train[0]}")
print(f"Inference output (no change):           {out_infer[0]}")
print(f"Training mean: {out_train.mean():.4f} (≈1.0 by scaling)")
```

```output
Training output  (some zeros, rest ×2): [0. 2. 0. 0. 0. 0. 0. 0.]
Inference output (no change):           [1. 1. 1. 1. 1. 1. 1. 1.]
Training mean: 1.0065 (≈1.0 by scaling)
```

The first training row shows the mechanism: each entry is either 0 (dropped) or 2 (kept and
doubled by $1/(1 - 0.5)$). This row happens to keep only one of eight units — dropout is
random. Averaged over all 8000 entries, the training mean is 1.0065, about 1.0 as promised.
The inference row is untouched ones.

The inverted scaling ensures `E[output] = E[input]` during training, so inference behavior is identical to the expected training behavior.

`E[...]` is the **expected value**, the long-run average. Individual outputs are noisy; only
the average matches.

### Why dropout works

Dropout trains an exponential ensemble: with $n$ neurons and drop rate 0.5, you sample from $2^n$ sub-networks per batch. At inference, the full network approximates averaging over all these sub-networks. Additionally, dropout prevents co-adaptation — neurons cannot rely on specific other neurons always being present, forcing each to learn useful features independently.

An **ensemble** is a group of models whose predictions are averaged, usually more accurate than
any one member. Each mask defines a different **sub-network** (the neurons that survived), all
sharing the same weights. **Co-adaptation** is when neurons only work as a fragile team, each
fixing the others' mistakes.

> **Picture it:** a football team that trains with random players sent off each drill. Nobody
> can rely on the star striker always being there, so every player learns to pass, defend and
> score. On match day the full team plays — and it is stronger than any reduced squad.

Backward through dropout is the same mask applied to the gradient: a unit that was dropped had
no effect on the loss, so it gets no gradient.

```python
# Dropout backward: gradient only flows through non-dropped units
def dropout_backward(dout, mask, p=0.5):
    return dout * mask / (1 - p)

np.random.seed(2)
x = np.random.randn(4, 8)
mask = (np.random.rand(4, 8) > 0.5).astype(float)
out = x * mask / 0.5

dout = np.random.randn(4, 8)
dx = dropout_backward(dout, mask)
print(f"Gradient only flows through {mask.mean():.0%} of units")
print(f"Dropped units get zero gradient: {(dx[mask==0] == 0).all()}")
```

```output
Gradient only flows through 59% of units
Dropped units get zero gradient: True
```

This random mask kept 59% of the 32 units rather than exactly 50%: with so few units, the share
fluctuates. Every dropped unit got a gradient of exactly 0 (`True`), so the weights feeding
those units are not updated on this step.

### Spatial Dropout and DropConnect

**Spatial Dropout** (for CNNs): drop entire feature maps instead of individual activations. Better for images because spatially correlated features should fail together.

In an image, neighbouring pixels in a feature map carry nearly the same information. Dropping
single pixels barely hurts, because their neighbours fill in; dropping the whole map forces a
real change.

**DropConnect**: drop individual weights (not activations). Rarely used in practice but theoretically more general.

## Early stopping

**Early stopping** is the simplest regularizer: watch the validation loss as training goes, and
stop once it has not improved for a while. You keep the weights from the best moment, before
memorization set in.

Early stopping monitors validation loss during training and halts when it stops improving:

The **patience** is how many epochs without improvement you tolerate before stopping, because
validation loss is noisy and one bad epoch does not mean the trend has turned.

```python
def train_with_early_stopping(patience=10):
    best_val = np.inf
    best_epoch = 0
    wait = 0

    for epoch in range(1, 201):
        # Simulate training/val losses
        train_loss = 0.5 * np.exp(-0.04*epoch) + 0.01
        val_loss   = 0.5 * np.exp(-0.03*epoch) + 0.02 + max(0, (epoch-60)*0.003)

        if val_loss < best_val:
            best_val = val_loss
            best_epoch = epoch
            wait = 0
        else:
            wait += 1
            if wait >= patience:
                print(f"Early stop at epoch {epoch}. Best epoch: {best_epoch}, val_loss={best_val:.4f}")
                return best_epoch
    return 200

stopped_at = train_with_early_stopping(patience=15)
print(f"Would have trained to epoch 200, stopped at {stopped_at}")
```

```output
Early stop at epoch 75. Best epoch: 60, val_loss=0.1026
Would have trained to epoch 200, stopped at 60
```

The simulated validation loss was best at epoch 60 (0.1026). With patience 15, training kept
going through 15 epochs without improvement and halted at epoch 75. The second line is a little
misleading: the function returns `best_epoch`, so "stopped at 60" really means "the weights you
keep are from epoch 60". Training saved 125 epochs of compute.

The key detail: restore the model weights from `best_epoch`, not the weights at the stopping epoch.

> **Watch out:** to restore the best weights you have to *save* them when they happen. In
> PyTorch, keep a copy of `model.state_dict()` (ch. 10) every time validation improves —
> otherwise early stopping leaves you with the weights from epoch 75, which are already worse.

## Recap in plain words

- Overfitting means training loss keeps falling while validation loss rises.
- L2 weight decay shrinks every weight by the same percentage each step.
- L1 subtracts a fixed amount each step and drives small weights to exactly 0.
- Dropout zeroes a random share $p$ of units during training and scales the rest by $1/(1-p)$ to keep the mean.
- Early stopping halts when validation stops improving and keeps the best saved weights.

## Try it Yourself

This block passes 64,000 random values with std about 2 through inverted dropout at $p = 0.3$
and $p = 0.5$ and compares the statistics.

```python
import numpy as np
np.random.seed(42)

def dropout_forward(x, p=0.5, training=True):
    if not training:
        return x
    mask = (np.random.rand(*x.shape) > p).astype(float)
    return x * mask / (1 - p)

# Compare output distributions: no regularization vs dropout
np.random.seed(0)
x = np.random.randn(1000, 64) * 2

# No dropout
out_none = x
# With dropout p=0.3
out_drop = dropout_forward(x, p=0.3, training=True)
# With dropout p=0.5
out_drop5 = dropout_forward(x, p=0.5, training=True)

print(f"No dropout:  mean={out_none.mean():.4f}, std={out_none.std():.4f}")
print(f"Dropout 0.3: mean={out_drop.mean():.4f}, std={out_drop.std():.4f}")
print(f"Dropout 0.5: mean={out_drop5.mean():.4f}, std={out_drop5.std():.4f}")
print(f"Active units: {(out_drop5 != 0).mean():.1%}")
```

```output
No dropout:  mean=-0.0077, std=1.9908
Dropout 0.3: mean=-0.0063, std=2.3835
Dropout 0.5: mean=0.0046, std=2.8320
Active units: 50.5%
```

The means all stay near 0, as inverted scaling promises. The std does *not* stay put: it grows
from 1.99 to 2.38 at $p = 0.3$ and to 2.83 at $p = 0.5$. Zeroing some values and scaling up the
rest keeps the average but adds spread, by a factor of $1/\sqrt{1-p}$: $1/\sqrt{0.7} \approx
1.195$ and $1/\sqrt{0.5} \approx 1.414$, which matches $2.38/1.99$ and $2.83/1.99$. The active
share (50.5%) is close to $1 - p$.

Try changing `p` to 0.8 and predict the std before running: $1.99/\sqrt{0.2} \approx 4.45$.
Inverted scaling preserves the mean, not the spread — that extra noise during training is part
of how dropout regularizes, and it is why BatchNorm statistics computed with dropout active
differ from those at inference.

## Exercise

Implement a simple 2-layer MLP in numpy with both dropout (p=0.3) and L2 regularization (λ=1e-3). Train it on 200 random binary classification samples. Track train and val accuracy every 20 epochs. Show the regularization effect on weight magnitudes.

> **Hint:** apply the same dropout `mask` in the forward pass and to the gradient in the
> backward pass, add `lam * W` to each weight gradient, and evaluate validation accuracy with
> dropout switched off.

<summary>Solution</summary>

```python
import numpy as np
np.random.seed(42)

X_tr = np.random.randn(200, 4); y_tr = (X_tr[:,0] + X_tr[:,1] > 0).astype(float)
X_val = np.random.randn(50, 4); y_val = (X_val[:,0] + X_val[:,1] > 0).astype(float)

def relu(x): return np.maximum(0, x)
def sigmoid(x): return 1/(1+np.exp(-x))

np.random.seed(1)
W1 = np.random.randn(4, 16) * np.sqrt(2/4)
W2 = np.random.randn(16, 1) * np.sqrt(2/16)
b1, b2 = np.zeros(16), np.zeros(1)
lr, lam = 0.05, 1e-3

for epoch in range(1, 201):
    # Forward with dropout
    h = relu(X_tr @ W1 + b1)
    mask = (np.random.rand(*h.shape) > 0.3).astype(float) / 0.7
    h_drop = h * mask
    out = sigmoid(h_drop @ W2 + b2)

    # Loss + L2
    loss = -np.mean(y_tr.reshape(-1,1)*np.log(out+1e-8)+(1-y_tr.reshape(-1,1))*np.log(1-out+1e-8))
    loss += lam/2*(np.sum(W1**2)+np.sum(W2**2))

    # Backward
    dout = (out - y_tr.reshape(-1,1))/len(X_tr)
    dW2 = h_drop.T @ dout + lam*W2; db2 = dout.sum(axis=0)
    dh_drop = dout @ W2.T
    dh = dh_drop * mask
    dh_relu = dh * (h > 0)
    dW1 = X_tr.T @ dh_relu + lam*W1; db1 = dh_relu.sum(axis=0)

    W1 -= lr*dW1; b1 -= lr*db1; W2 -= lr*dW2; b2 -= lr*db2

    if epoch % 50 == 0:
        h_val = relu(X_val @ W1 + b1)
        pred_val = sigmoid(h_val @ W2 + b2) > 0.5
        val_acc = (pred_val.flatten() == y_val).mean()
        print(f"Epoch {epoch}: val_acc={val_acc:.2%}, |W1|={np.abs(W1).mean():.4f}")
```

Dropout + L2 together prevent large weights and reduce co-adaptation. Compare `|W1|` magnitude against training without regularization — regularized weights stay smaller throughout.

The solution logs every 50 epochs: validation accuracy climbs from 90% at epoch 50 to 98% at
epoch 200, with mean $|W_1|$ about 0.52–0.53. Rerunning with `lam = 0` and no dropout gives
mean $|W_1|$ of 0.526 to 0.543 — so the regularized weights are smaller, but only by about 3%
at epoch 200. With $\lambda = 10^{-3}$ and $\eta = 0.05$, each step shrinks the weights by only
$\eta\lambda = 5 \times 10^{-5}$; on this easy, linearly separable task there is little
overfitting for regularization to fix. Raise `lam` to 0.1 to see a large effect.
</details>
