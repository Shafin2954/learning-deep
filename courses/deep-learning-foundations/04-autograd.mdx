## Two modes of automatic differentiation

In ch. 3 you wrote every gradient by hand. **Automatic differentiation (AD)** makes the
computer do it: each basic operation knows its own local slope, and a program chains those
slopes together for you. There are two directions you can chain them in, and the choice
decides how fast it is.

**Forward mode:** alongside every value $x$ you carry a derivative $\dot{x} = \partial x / \partial \theta$ for one input $\theta$. Cost: $O(n)$ forward passes for $n$ inputs. Good when you have few inputs and many outputs.

**Reverse mode (backprop):** one forward pass builds the computation graph; one backward pass accumulates $\bar{x} = \partial L / \partial x$ for every node. Cost: one forward + one backward pass regardless of the number of parameters. Essential for neural networks where $n \gg 1$.

Read the dot and bar notation as follows. $\dot{x}$ ("x-dot") is "how much $x$ moves when the
one chosen input $\theta$ moves". $\bar{x}$ ("x-bar") is "how much the loss moves when $x$
moves" — the `grad` field you will fill in below. A network has millions of parameters and
one scalar loss, so forward mode would need millions of passes. Reverse mode needs two.

> **Picture it:** forward mode is asking "if I change this one ingredient, how does every dish
> on the menu change?" — once per ingredient. Reverse mode is asking "this one dish tasted
> wrong; how much is each ingredient to blame?" — once, for all ingredients together. Training
> has one dish (the loss) and millions of ingredients (the weights).

### Dual numbers (forward mode glimpse)

A **dual number** is an ordinary number with a little "derivative passenger" attached. The
rule $\varepsilon^2 = 0$ makes the passenger obey exactly the rules of calculus when you
multiply.

Represent $x$ as $x + \dot{x}\varepsilon$ where $\varepsilon^2 = 0$. Then:
$$
(a + \dot{a}\varepsilon)(b + \dot{b}\varepsilon) = ab + (a\dot{b} + b\dot{a})\varepsilon
$$

> **In plain words:** multiply out the brackets. The $\dot{a}\dot{b}\varepsilon^2$ term
> vanishes because $\varepsilon^2 = 0$. What is left is the product $ab$ plus
> $(a\dot{b} + b\dot{a})\varepsilon$ — and $a\dot{b} + b\dot{a}$ is exactly the product rule
> from calculus. So the passenger carries the derivative along for free.

The $\varepsilon$ coefficient automatically computes the derivative. You don't need this for backprop, but it shows that AD is just arithmetic in an augmented number system.

## Building a scalar autograd engine

You will now upgrade ch. 2's `Value` class so that it can run backward. Each operation, when
it creates its output, also leaves behind a tiny function that says "here is how to send
gradient back to my inputs". The `backward()` method then calls those functions in the right order.

The core idea: each `Value` node stores its parents (`_prev`) and a `_backward` closure that knows how to push gradient back to those parents.

A **closure** is a function defined inside another function that remembers the local
variables around it — here, `self`, `other`, and `out`. That memory is what lets `_backward`
run long after the forward operation has finished.

```python
import numpy as np

class Value:
    def __init__(self, data, _children=(), _op=''):
        self.data      = float(data)
        self.grad      = 0.0
        self._backward = lambda: None
        self._prev     = set(_children)
        self._op       = _op

    # --- forward operations ---
    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out   = Value(self.data + other.data, (self, other), '+')
        def _backward():
            self.grad  += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out   = Value(self.data * other.data, (self, other), '*')
        def _backward():
            self.grad  += other.data * out.grad
            other.grad += self.data  * out.grad
        out._backward = _backward
        return out

    def __pow__(self, exp):
        out = Value(self.data ** exp, (self,), f'**{exp}')
        def _backward():
            self.grad += exp * (self.data ** (exp - 1)) * out.grad
        out._backward = _backward
        return out

    def exp(self):
        e   = np.exp(self.data)
        out = Value(e, (self,), 'exp')
        def _backward():
            self.grad += e * out.grad
        out._backward = _backward
        return out

    def log(self):
        out = Value(np.log(self.data), (self,), 'log')
        def _backward():
            self.grad += (1.0 / self.data) * out.grad
        out._backward = _backward
        return out

    def relu(self):
        out = Value(max(0, self.data), (self,), 'relu')
        def _backward():
            self.grad += (out.data > 0) * out.grad
        out._backward = _backward
        return out

    # Convenience operators
    def __radd__(self, other): return self + other
    def __rmul__(self, other): return self * other
    def __neg__(self):         return self * -1
    def __sub__(self, other):  return self + (-other)

    # --- backward pass via topological sort ---
    def backward(self):
        topo, visited = [], set()
        def build(v):
            if v not in visited:
                visited.add(v)
                for p in v._prev: build(p)
                topo.append(v)
        build(self)
        self.grad = 1.0
        for v in reversed(topo):
            v._backward()

    def __repr__(self):
        return f"Value({self.data:.4f}, grad={self.grad:.4f})"

print("Value class defined with add/mul/pow/exp/log/relu + backward()")
```

```output
Value class defined with add/mul/pow/exp/log/relu + backward()
```

The one printed line only confirms the class compiled. The interesting parts are in the code:

- `__add__`: addition passes the upstream gradient through unchanged to both inputs (local slope 1).
- `__mul__`: each input gets the *other* input's value times the upstream gradient (product rule).
- `__pow__`, `exp`, `log`, `relu`: each uses its textbook derivative — $n x^{n-1}$, $e^x$, $1/x$, the 0/1 gate.
- `backward()`: sorts the graph so every node comes after its inputs (a **topological sort**), sets
  the loss's own gradient to 1, then calls `_backward` from the loss toward the leaves.

> **Watch out:** every `_backward` uses `+=`, never `=`. When one value feeds two places (for
> example `x` in `x * (x + 1)`), it receives gradient from both paths, and those contributions
> must be added. Writing `=` would keep only the last path and give a wrong gradient with no error.

The topological sort matters because a node may only push its gradient back once it has
received gradient from *every* node that used it. Processing nodes in reverse topological
order guarantees that.

## Verify on $L = (ax^2 + b)^2$

Test the engine on a formula small enough to differentiate by hand. If the engine's gradients
match the hand-derived ones, the plumbing is right.

```python
a, x, b = Value(2.0), Value(3.0), Value(1.0)

inner = a * x**2 + b   # 2*9 + 1 = 19
L     = inner ** 2     # 361

L.backward()

# Analytic: dL/dx = 2*(ax^2+b) * 2ax = 4ax(ax^2+b)
dL_dx_analytic = 4 * 2.0 * 3.0 * (2.0 * 9.0 + 1.0)

print(f"L.data   = {L.data:.1f}   (expected 361)")
print(f"x.grad   = {x.grad:.4f}  (analytic: {dL_dx_analytic:.4f})")
print(f"a.grad   = {a.grad:.4f}")
print(f"b.grad   = {b.grad:.4f}")
```

```output
L.data   = 361.0   (expected 361)
x.grad   = 456.0000  (analytic: 456.0000)
a.grad   = 342.0000
b.grad   = 38.0000
```

The loss is $(2 \cdot 9 + 1)^2 = 19^2 = 361$, as expected. Check every gradient by the chain
rule, with $u = ax^2 + b = 19$:

- $\partial L / \partial x = 2u \cdot 2ax = 2 \cdot 19 \cdot 12 = 456$, matching `x.grad`.
- $\partial L / \partial a = 2u \cdot x^2 = 38 \cdot 9 = 342$, matching `a.grad`.
- $\partial L / \partial b = 2u \cdot 1 = 38$, matching `b.grad`.

All gradients are exact.

## Finite-difference verification

As in ch. 3, you can double-check autograd by nudging the input and measuring the change in
the output. This does not use any of the backward machinery, so it is an independent test.

```python
def f(xval):
    a_n, x_n, b_n = Value(2.0), Value(xval), Value(1.0)
    return (a_n * x_n**2 + b_n)**2

eps = 1e-5
fd_dL_dx = (f(3.0 + eps).data - f(3.0 - eps).data) / (2 * eps)
print(f"Autograd  dL/dx = {x.grad:.6f}")
print(f"Finite-diff     = {fd_dL_dx:.6f}")
print(f"Error           = {abs(x.grad - fd_dL_dx):.2e}")
```

```output
Autograd  dL/dx = 456.000000
Finite-diff     = 456.000000
Error           = 8.32e-09
```

Autograd says 456 and the measured slope also prints 456.000000. The gap is
$8.32 \times 10^{-9}$, which is floating-point rounding in the finite difference, not an error
in autograd. Relative to 456, that is about $2 \times 10^{-11}$.

## Tiny MLP demo

Now put the engine to work: build a $2 \to 4 \to 1$ network out of individual `Value` scalars,
train it on the XOR data from ch. 1 with plain gradient descent, and watch whether the loss
goes down. Nothing here uses NumPy for gradients.

```python
# XOR-like task with the Value autograd
inputs  = [[0.,0.], [0.,1.], [1.,0.], [1.,1.]]
targets = [0.,      1.,      1.,      0.]

rng = np.random.default_rng(7)

def make_param(shape):
    return [[Value(float(v)) for v in row]
            for row in rng.standard_normal(shape) * 0.5]

W1 = make_param((4, 2));  b1 = [Value(0.) for _ in range(4)]
W2 = make_param((1, 4));  b2 = [Value(0.)]

def dot(row, col): return sum(a*b for a, b in zip(row, col))

losses = []
lr = 0.1
for step in range(50):
    total_loss = Value(0.)
    all_params = ([v for row in W1 for v in row] + b1 +
                  [v for row in W2 for v in row] + b2)
    for p in all_params: p.grad = 0.0

    for x_in, y_true in zip(inputs, targets):
        x_vals = [Value(v) for v in x_in]
        h = [dot(W1[i], x_vals) + b1[i] for i in range(4)]
        h = [v.relu() for v in h]
        out = dot(W2[0], h) + b2[0]
        out_sig = Value(1.) * (out * Value(-1.)).exp().__radd__(1)**(-1)
        err = (out_sig - Value(y_true))**2
        total_loss = total_loss + err

    total_loss.backward()
    for p in all_params:
        p.data -= lr * p.grad

    if step % 10 == 0:
        losses.append(round(total_loss.data, 4))

print("Loss at steps 0,10,20,30,40:", losses)
```

```output
Loss at steps 0,10,20,30,40: [1.0009, 0.9988, 0.9963, 0.9937, 0.9903]
```

The loss moves from 1.0009 at step 0 to 0.9903 at step 40. It is going down, which proves the
gradients point the right way, but it is going down slowly: about 1% in 40 steps. Two reasons:
the weights start small (scale 0.5), so the sigmoid output sits near 0.5 where the summed
squared error is about $4 \times 0.25 = 1$; and a learning rate of 0.1 is cautious for this tiny
problem. The loss here is a sum over 4 examples, not a mean.

Loss decreasing — the autograd engine correctly computes gradients and gradient descent is working.

> **Watch out:** every step resets `p.grad = 0.0` before the backward pass. Because
> `_backward` accumulates with `+=`, forgetting the reset adds this step's gradient to all
> previous ones. PyTorch has the same behaviour, which is why its training loops call
> `optimizer.zero_grad()` (ch. 10).

This engine is slow — one Python object per number — but it is the same algorithm PyTorch
runs. PyTorch replaces scalars with tensors and Python closures with fast C++ kernels.

## Recap in plain words

- Reverse-mode AD gets the gradient for every parameter in one backward pass; forward mode needs one pass per input.
- Each operation stores a small closure that sends gradient back to its inputs.
- `backward()` sorts the graph and calls those closures from the loss toward the leaves.
- Gradients accumulate with `+=`, so a value used twice gets both contributions — and you must reset them between steps.
- The engine matched hand-derived gradients (456, 342, 38) and finite differences exactly.

## Try it Yourself

This block uses the engine on a new function, $\log(\mathrm{sigmoid}(x))$, by rewriting it in
operations `Value` already supports: $x - \log(1 + e^x)$.

```python
# Compute d/dx [log(sigmoid(x))] at x=1.5 using Value
# Rewrite with ops Value supports: log(sigmoid(x)) = x - log(1 + e^x)
x = Value(1.5)
L = x - (Value(1.) + x.exp()).log()
L.backward()

sig = 1 / (1 + np.exp(-1.5))
analytic = 1 - sig   # d/dx log(sigmoid(x)) = 1 - sigmoid(x)
print(f"sigmoid(1.5)      = {sig:.6f}")
print(f"log(sigmoid(1.5)) = {L.data:.6f}")
print(f"autograd d/dx     = {x.grad:.6f}")
print(f"analytic d/dx     = {analytic:.6f}")
```

```output
sigmoid(1.5)      = 0.817574
log(sigmoid(1.5)) = -0.201413
autograd d/dx     = 0.182426
analytic d/dx     = 0.182426
```

Autograd's answer (0.182426) matches the analytic formula $1 - \mathrm{sigmoid}(x)$ on every
digit. Notice `x` appears twice in the formula — once alone, once inside `exp` — and the `+=`
accumulation adds the two paths ($1$ and $-\mathrm{sigmoid}(1.5) = -0.817574$) correctly. Try
$x = -3$ or $x = 10$, and try adding a `tanh` method to `Value` (its local slope is $1 - \tanh^2$).
