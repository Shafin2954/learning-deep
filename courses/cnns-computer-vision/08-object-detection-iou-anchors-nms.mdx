## The detection problem

Classification answers "what is in this picture?". **Object detection** answers "what is
where?": it draws a rectangle around every object it finds and names each one.

Classification assigns one label to one image. Detection must find **multiple objects of possibly different classes at unknown locations**. Each prediction is a 5-tuple: $(x_1, y_1, x_2, y_2, \text{class})$ plus a confidence score.

The four numbers are a **bounding box** — the top-left corner $(x_1, y_1)$ and bottom-right
corner $(x_2, y_2)$ in pixels. The **confidence score** is how sure the detector is, from 0 to 1.

Two sub-problems:
1. **Where** — predict bounding box coordinates (regression).
2. **What** — classify each detected region (classification).

> **Picture it:** a "Where's Wally?" page. A classifier says "Wally is on this page". A
> detector circles every Wally, every dog, and every umbrella, and writes how sure it is next
> to each circle.

## Intersection over Union (IoU)

To grade a predicted box you need one number for "how well does it line up with the true box?".
IoU is that number: the shared area divided by the total area covered.

IoU measures how much two boxes overlap:

$$
\text{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|}
$$

> **In plain words:** $|A \cap B|$ is the area where the two boxes overlap (the
> intersection); $|A \cup B|$ is the area covered by either box (the union), counted once.
> Their ratio is 1 when the boxes are identical and 0 when they do not touch.

Range: 0 (no overlap) to 1 (perfect match). IoU $\geq$ 0.5 is typically called a "match"; IoU $\geq$ 0.75 is strict.

The intersection is itself a rectangle: its left edge is the larger of the two left edges, its
right edge the smaller of the two right edges, and the same for top and bottom.

```python
import numpy as np

def iou(box_a: np.ndarray, box_b: np.ndarray) -> float:
    """boxes: [x1, y1, x2, y2]"""
    xi1 = max(box_a[0], box_b[0])
    yi1 = max(box_a[1], box_b[1])
    xi2 = min(box_a[2], box_b[2])
    yi2 = min(box_a[3], box_b[3])

    inter_w = max(0, xi2 - xi1)
    inter_h = max(0, yi2 - yi1)
    inter   = inter_w * inter_h

    area_a  = (box_a[2] - box_a[0]) * (box_a[3] - box_a[1])
    area_b  = (box_b[2] - box_b[0]) * (box_b[3] - box_b[1])
    union   = area_a + area_b - inter
    return inter / (union + 1e-7)

box1 = np.array([0, 0, 10, 10])
box2 = np.array([5, 5, 15, 15])
box3 = np.array([20, 20, 30, 30])

print(f"IoU(box1, box2) = {iou(box1, box2):.3f}")   # partial overlap
print(f"IoU(box1, box1) = {iou(box1, box1):.3f}")   # perfect
print(f"IoU(box1, box3) = {iou(box1, box3):.3f}")   # no overlap
```

```output
IoU(box1, box2) = 0.143
IoU(box1, box1) = 1.000
IoU(box1, box3) = 0.000
```

Look at the first line. Boxes 1 and 2 are each $10 \times 10$ and overlap in a $5 \times 5$ square,
so IoU $= 25 / (100 + 100 - 25) = 25/175 = 0.143$. Even though a quarter of each box overlaps,
the IoU is low — well under the 0.5 "match" bar.

> **Watch out:** IoU punishes small shifts hard on small boxes. Moving a $10 \times 10$ box by
> 5 pixels in both directions drops IoU from 1.0 to 0.143; the same shift on a
> $100 \times 100$ box keeps it at 0.82.

## Anchor boxes

Predicting a box from nothing is hard: the coordinates could be anything. **Anchors** give the
detector a set of starting guesses — rectangles of fixed shapes laid out all over the image —
so it only has to predict small corrections.

Instead of predicting absolute box coordinates (unbounded, hard to regress), detectors place a grid of **anchor boxes** — predefined rectangles at multiple scales and aspect ratios — and predict **offsets** relative to each anchor.

Common anchor setup: at each grid cell, 3 scales $\times$ 3 aspect ratios = 9 anchors.

> **Picture it:** a tray of cookie cutters — small, medium, large, each in tall, square, and
> wide — placed at every grid point of the image. The detector's job is to say which cutter
> fits an object best and how to nudge it.

Each anchor keeps its area near $s^2$: the code sets width $s\sqrt{r}$ and height $s/\sqrt{r}$,
so their product is always $s^2$ while the ratio $r$ = width / height changes.

```python
def generate_anchors(
    feature_hw: tuple, stride: int,
    scales: list = [32, 64, 128],
    ratios: list = [0.5, 1.0, 2.0]
) -> np.ndarray:
    """Returns anchors in [x1, y1, x2, y2] for each (cell, scale, ratio)."""
    H, W = feature_hw
    anchors = []
    for row in range(H):
        for col in range(W):
            cx = (col + 0.5) * stride
            cy = (row + 0.5) * stride
            for s in scales:
                for r in ratios:
                    w = s * np.sqrt(r)
                    h = s / np.sqrt(r)
                    anchors.append([cx - w/2, cy - h/2, cx + w/2, cy + h/2])
    return np.array(anchors)

anchors = generate_anchors((7, 7), stride=32)
print(f"Feature map 7×7 → {len(anchors)} anchors")
print("First anchor (cx=16, cy=16):", anchors[0].round(1))
```

```output
Feature map 7×7 → 441 anchors
First anchor (cx=16, cy=16): [ 4.7 -6.6 27.3 38.6]
```

A $7 \times 7$ grid with 9 anchors per cell gives $49 \times 9 = 441$ anchors. The first one is the
smallest scale (32) with ratio 0.5 — tall and thin, about $22.6 \times 45.3$ — centred at
$(16, 16)$. Its top edge is at $-6.6$, outside the image; anchors at the border often hang over
the edge, and detectors clip or ignore them.

## Box parameterization

The detector does not output corners directly. It outputs four small numbers that say how far
to shift the anchor's centre and how much to stretch its width and height.

Rather than predicting $(x_1, y_1, x_2, y_2)$ directly, detectors predict offsets relative to an anchor $(a_x, a_y, a_w, a_h)$:

$$
t_x = (g_x - a_x) / a_w, \quad t_y = (g_y - a_y) / a_h
$$
$$
t_w = \log(g_w / a_w), \quad t_h = \log(g_h / a_h)
$$

where $(g_x, g_y, g_w, g_h)$ is the ground-truth box centre and size. The log prevents negative width/height predictions.

> **In plain words:**
> - $t_x$, $t_y$: how far the true centre is from the anchor's centre, measured in anchor
>   widths and heights (so the numbers are similar for big and small objects).
> - $t_w$, $t_h$: how much wider or taller the true box is, on a log scale. To decode, you
>   compute $a_w e^{t_w}$, which is positive for any $t_w$.
> - $t_w = 0$ means "same width as the anchor".

```python
def encode_box(gt: np.ndarray, anchor: np.ndarray) -> np.ndarray:
    """gt, anchor: [x1,y1,x2,y2] → encoded [tx,ty,tw,th]"""
    gt_cx, gt_cy = (gt[0]+gt[2])/2, (gt[1]+gt[3])/2
    gt_w,  gt_h  = gt[2]-gt[0], gt[3]-gt[1]
    a_cx,  a_cy  = (anchor[0]+anchor[2])/2, (anchor[1]+anchor[3])/2
    a_w,   a_h   = anchor[2]-anchor[0], anchor[3]-anchor[1]
    return np.array([
        (gt_cx - a_cx) / a_w,
        (gt_cy - a_cy) / a_h,
        np.log(gt_w / a_w),
        np.log(gt_h / a_h),
    ])

gt     = np.array([50., 50., 150., 200.])
anchor = np.array([40., 40., 140., 190.])
enc    = encode_box(gt, anchor)
print("Encoded:", enc.round(3))
```

```output
Encoded: [0.1   0.067 0.    0.   ]
```

The true box and the anchor have the same size ($100 \times 150$), so $t_w = t_h = 0$. The
centre is 10 pixels to the right and 10 down: $10/100 = 0.1$ and $10/150 \approx 0.067$.

Near-zero offsets mean the anchor already closely matches the ground-truth.

## Non-Maximum Suppression (NMS)

Detectors usually fire several boxes on the same object, all slightly shifted. **Non-maximum
suppression** keeps the most confident one and deletes the copies that overlap it too much.

A detector may fire many overlapping boxes for the same object. NMS keeps only the best:

1. Sort boxes by score (descending).
2. Take the highest-score box. Remove all others with IoU $\geq$ threshold against it.
3. Repeat on remaining boxes.

> **Picture it:** five friends point at the same bird and shout. NMS listens to the loudest
> friend, tells everyone pointing at the same spot to be quiet, then moves to the loudest
> friend pointing somewhere else.

```python
def nms(boxes: np.ndarray, scores: np.ndarray, iou_threshold: float = 0.5) -> list:
    """
    boxes: (N, 4) [x1,y1,x2,y2]
    scores: (N,)
    returns indices of kept boxes
    """
    order   = scores.argsort()[::-1]
    keep    = []
    while len(order) > 0:
        i = order[0]
        keep.append(i)
        ious = np.array([iou(boxes[i], boxes[j]) for j in order[1:]])
        order = order[1:][ious < iou_threshold]
    return keep

boxes  = np.array([
    [10, 10, 80, 80],
    [15, 12, 85, 82],   # overlaps box 0 heavily
    [12, 11, 83, 83],   # overlaps box 0 heavily
    [200, 200, 280, 280],  # separate box
])
scores = np.array([0.95, 0.88, 0.76, 0.91])
kept   = nms(boxes, scores, iou_threshold=0.5)
print("Kept box indices:", kept)
print("Kept boxes:\n", boxes[kept])
```

```output
Kept box indices: [np.int64(0), np.int64(3)]
Kept boxes:
 [[ 10  10  80  80]
 [200 200 280 280]]
```

Box 0 has the top score (0.95) and is kept. Boxes 1 and 2 overlap it with IoU above 0.5 and are
removed. Box 3 (score 0.91) does not touch box 0 at all, so it survives as a second detection.
(`np.int64(0)` is how NumPy 2 prints an integer index.)

Boxes 1 and 2 were suppressed because they heavily overlapped box 0 (the highest-score box).

> **Watch out:** run NMS separately for each class. Otherwise a confident "person" box can
> delete the "bicycle" box underneath it, because the two overlap heavily.

## Soft-NMS

Hard NMS has a weakness: two people standing close together produce overlapping boxes, and
one of them gets deleted. Soft-NMS turns those scores down instead of deleting them.

Hard NMS discards boxes above the IoU threshold. Soft-NMS decays scores instead:

$$
s_i = s_i \cdot e^{-\text{IoU}(M, b_i)^2 / \sigma}
$$

then remove only boxes with score below a minimum. This helps when two objects genuinely overlap.

> **In plain words:** $M$ is the box that was kept; $b_i$ is another box with score $s_i$. The
> more $b_i$ overlaps $M$, the closer $e^{-\text{IoU}^2/\sigma}$ gets to a small number, and
> the more its score shrinks. A box with IoU 0 keeps its score exactly. $\sigma$ sets how
> harsh the decay is.

## Mean Average Precision (mAP)

To score a detector over a whole dataset you need to reward finding every object (**recall**:
the share of true objects found) and punish false alarms (**precision**: the share of predicted
boxes that are right). Average precision sums up that trade-off in one number.

For each class:
1. Rank predictions by confidence.
2. Mark each prediction as TP (IoU $\geq$ 0.5 with a GT box) or FP.
3. Compute a precision–recall curve.
4. Interpolate: $\text{AP} = \sum_{r} \text{precision}(r) \cdot \Delta r$ over 11 or 101 points.

(TP = **true positive**, a correct detection; FP = **false positive**, a false alarm; GT =
ground truth, the labelled boxes.)

> **In plain words:** AP is the area under the precision–recall curve. Walk recall from 0 to 1
> in small steps $\Delta r$; at each step take the best precision you can get at that recall
> or higher; add them up.

mAP@0.5 = average AP across all classes at IoU threshold 0.5. COCO mAP averages over IoU 0.5:0.05:0.95.

That last notation means 10 thresholds, 0.50, 0.55, …, 0.95, so COCO mAP rewards boxes that are
tight, not only roughly right.

```python
def compute_ap(precisions: np.ndarray, recalls: np.ndarray) -> float:
    """11-point interpolated AP."""
    ap = 0.0
    for thr in np.linspace(0, 1, 11):
        p = precisions[recalls >= thr]
        ap += (p.max() if len(p) > 0 else 0.0)
    return ap / 11

# Synthetic PR curve
recalls    = np.array([0.0, 0.1, 0.3, 0.5, 0.7, 0.9, 1.0])
precisions = np.array([1.0, 0.9, 0.8, 0.7, 0.5, 0.3, 0.2])
print(f"AP = {compute_ap(precisions, recalls):.3f}")
```

```output
AP = 0.582
```

At each of the 11 recall levels $0, 0.1, \dots, 1.0$ the code takes the best precision at that
recall or higher: 1.0, 0.9, 0.8, 0.8, 0.7, 0.7, 0.5, 0.5, 0.3, 0.3, 0.2. Their sum is 6.4, and
$6.4 / 11 \approx 0.582$.

## Recap in plain words

- A detector outputs boxes, class labels, and confidence scores, many per image.
- IoU = overlap area / combined area; 0.5 is the usual "this counts as a hit" bar.
- Anchors are fixed starting boxes at every grid cell; the network predicts small offsets from them.
- Offsets are centre shifts in anchor units and log size ratios, so decoded sizes stay positive.
- NMS keeps the highest-scoring box and removes overlapping duplicates; Soft-NMS only lowers their scores.
- AP summarises the precision–recall curve per class; mAP averages AP over classes (and, for COCO, over IoU thresholds).

```python
import numpy as np

# Generate random boxes and test NMS
np.random.seed(0)

boxes[:, 3] = boxes[:, 1] + np.random.randint(20, 80, 20)

print(f"After  NMS: {len(kept)} boxes kept")
```

```output
Before NMS: 20 boxes
After  NMS: 19 boxes kept
```

Only one box out of 20 is removed. Random boxes of 20 to 80 pixels scattered over a
$200 \times 200$ area rarely overlap by IoU 0.5 or more, so NMS has little to do. Real detector
outputs are the opposite: dozens of near-identical boxes per object.

## Exercise

Implement `batch_iou(boxes_a, boxes_b)` that computes the IoU of every pair in an $(N, 4)$ array with every box in an $(M, 4)$ array, returning an $(N, M)$ matrix — all in NumPy without explicit loops. This is the vectorized IoU needed inside fast NMS and anchor assignment.

> **Hint:** add a new axis to each array, `boxes_a[:, None, :]` and `boxes_b[None, :, :]`,
> so that `np.maximum` and `np.minimum` broadcast to $(N, M)$ automatically.

<summary>Solution</summary>

```python
import numpy as np

def batch_iou(boxes_a: np.ndarray, boxes_b: np.ndarray) -> np.ndarray:
    """
    boxes_a: (N, 4)  boxes_b: (M, 4)  returns (N, M)
    """
    # Expand dims for broadcasting: (N,1,4) vs (1,M,4)
    a = boxes_a[:, None, :]  # (N, 1, 4)
    b = boxes_b[None, :, :]  # (1, M, 4)

    xi1 = np.maximum(a[..., 0], b[..., 0])
    yi1 = np.maximum(a[..., 1], b[..., 1])
    xi2 = np.minimum(a[..., 2], b[..., 2])
    yi2 = np.minimum(a[..., 3], b[..., 3])

    inter = np.maximum(0, xi2 - xi1) * np.maximum(0, yi2 - yi1)
    area_a = (boxes_a[:, 2] - boxes_a[:, 0]) * (boxes_a[:, 3] - boxes_a[:, 1])
    area_b = (boxes_b[:, 2] - boxes_b[:, 0]) * (boxes_b[:, 3] - boxes_b[:, 1])
    union  = area_a[:, None] + area_b[None, :] - inter
    return inter / (union + 1e-7)

A = np.array([[0,0,10,10],[5,5,15,15]], dtype=float)
B = np.array([[0,0,10,10],[20,20,30,30]], dtype=float)
print(batch_iou(A, B))
```

The key is broadcasting `(N,1,4)` against `(1,M,4)` — all pairwise operations vectorize without loops, giving $O(NM)$ time with minimal Python overhead.

The printed matrix is `[[1, 0], [0.143, 0]]`: box A0 matches B0 exactly, A1 overlaps B0 the
same way as in the first example on this page, and B1 touches neither. With 441 anchors and
a few ground-truth boxes, this one call replaces thousands of Python-level `iou` calls.
</details>
