## BatchNorm in convolutional networks

**BatchNorm** (batch normalization) rescales a layer's outputs so that each channel has mean 0
and spread 1 across the current batch. Keeping every channel on the same scale makes deep
networks train faster and more stably.

In a fully-connected BatchNorm, you normalize over the batch dimension $N$. In a conv net, feature maps have shape $(N, C, H, W)$. BatchNorm normalizes over $(N, H, W)$ **separately for each channel** $c$:

$$
\hat{x}_{n,c,h,w} = \frac{x_{n,c,h,w} - \mu_c}{\sqrt{\sigma_c^2 + \epsilon}}
$$

where $\mu_c$ and $\sigma_c^2$ are computed over all elements $(n, h, w)$ for channel $c$. Two learned parameters $\gamma_c$ and $\beta_c$ then rescale and shift.

> **In plain words:**
> - $x_{n,c,h,w}$ is one number: image $n$, channel $c$, row $h$, column $w$.
> - $\mu_c$ is the average of channel $c$ over every image and every pixel in the batch.
> - $\sigma_c^2$ is that channel's variance; $\epsilon$ is a tiny constant (default $10^{-5}$)
>   that stops division by zero.
> - After this step each channel has mean 0 and variance 1; then $\gamma_c$ and $\beta_c$ let
>   the network pick a new scale and centre if it wants one.

> **Picture it:** grading on a curve, one subject at a time. Every channel is a subject; BN
> rescales that subject's scores across the whole class (the batch and all pixels) so the
> average is 0 and the spread is 1. Maths scores are never mixed with art scores.

```python
import torch
import torch.nn as nn

bn = nn.BatchNorm2d(64)
x  = torch.randn(8, 64, 28, 28)     # N=8, C=64, H=W=28
y  = bn(x)

print("Input:  ", x.shape)
print("Output: ", y.shape)
print("γ shape:", bn.weight.shape)   # one per channel
print("β shape:", bn.bias.shape)
print("Running mean shape:", bn.running_mean.shape)
```

```output
Input:   torch.Size([8, 64, 28, 28])
Output:  torch.Size([8, 64, 28, 28])
γ shape: torch.Size([64])
β shape: torch.Size([64])
Running mean shape: torch.Size([64])
```

The shape is unchanged, and $\gamma$, $\beta$, and the running mean each have 64 entries: one per
channel, not one per pixel. With $N = 8$ and $28 \times 28$ maps, each channel's mean is taken
over $8 \times 784 = 6{,}272$ numbers.

BatchNorm keeps a running mean/variance for inference (no batch statistics available then).

> **Watch out:** forgetting `model.eval()` at test time makes BN use the statistics of the
> test batch instead of the running averages. Predictions then change with batch size —
> with a batch of 1, they can be badly wrong.

### BN before or after activation?

There are two common orders for the trio conv, BN, ReLU, and both work. The choice mostly matters
for very deep networks.

The original ResNet paper places BN between conv and activation: `conv → BN → ReLU`. The pre-activation (v2) variant does `BN → ReLU → conv`. Empirically, v2 gives better gradient flow in very deep nets, but for typical networks of 50 layers or fewer the difference is small. Most standard architectures use the original ordering.

```python
# Original ordering
original = nn.Sequential(
    nn.Conv2d(64, 64, 3, padding=1, bias=False),
    nn.BatchNorm2d(64),
    nn.ReLU(),
)

# Pre-activation ordering
pre_act = nn.Sequential(
    nn.BatchNorm2d(64),
    nn.ReLU(),
    nn.Conv2d(64, 64, 3, padding=1, bias=False),
)

x = torch.randn(2, 64, 14, 14)
print("Original:", original(x).shape)
print("Pre-act: ", pre_act(x).shape)
```

```output
Original: torch.Size([2, 64, 14, 14])
Pre-act:  torch.Size([2, 64, 14, 14])
```

Both orderings give the same shape, `[2, 64, 14, 14]`; the difference is only in *what* is
normalised. The original normalises the conv's output; pre-activation normalises the conv's
input.

## Depthwise separable convolution

A normal conv does two jobs at once: it looks at a spatial neighbourhood and it mixes channels.
Doing those two jobs in separate, cheap steps saves most of the weights.

A standard $3 \times 3$ conv on $C_{in}$ channels to $C_{out}$ channels uses $C_{in} \times C_{out} \times 9$ parameters. You can factor this into two steps:

1. **Depthwise conv** — apply one $3 \times 3$ filter per input channel independently (groups = $C_{in}$).
2. **Pointwise conv** — $1 \times 1$ conv to mix channels.

Parameter cost: $C_{in} \times 9 + C_{in} \times C_{out}$ vs $C_{in} \times C_{out} \times 9$.

> **Picture it:** a kitchen. A standard conv is one chef who, for every dish, chops every
> ingredient *and* mixes them. Depthwise-separable is an assembly line: one prep cook per
> ingredient chops (depthwise), then a mixer combines the bowls (pointwise).

The `groups=in_c` argument is what makes a conv depthwise: it splits the channels into
`in_c` groups of one, so each filter only sees its own channel.

```python
C_in, C_out = 128, 256

class DepthwiseSepConv(nn.Module):
    def __init__(self, in_c, out_c):
        super().__init__()
        self.dw = nn.Conv2d(in_c, in_c, 3, padding=1, groups=in_c, bias=False)
        self.pw = nn.Conv2d(in_c, out_c, 1, bias=False)
    def forward(self, x):
        return self.pw(self.dw(x))

standard = nn.Conv2d(C_in, C_out, 3, padding=1, bias=False)
dws      = DepthwiseSepConv(C_in, C_out)

std_params = sum(p.numel() for p in standard.parameters())
dws_params = sum(p.numel() for p in dws.parameters())

x = torch.randn(2, C_in, 28, 28)
print(f"Standard  params: {std_params:,}  output: {standard(x).shape}")
print(f"DWS       params: {dws_params:,}  output: {dws(x).shape}")
print(f"Reduction: {std_params / dws_params:.1f}×")
```

```output
Standard  params: 294,912  output: torch.Size([2, 256, 28, 28])
DWS       params: 33,920  output: torch.Size([2, 256, 28, 28])
Reduction: 8.7×
```

The standard conv has $128 \times 256 \times 9 = 294{,}912$ weights; the DWS version has
$128 \times 9 + 128 \times 256 = 1{,}152 + 32{,}768 = 33{,}920$. Same output shape, about 8.7 times
fewer parameters — and almost all of the remaining weights are in the $1 \times 1$ step.

MobileNetV1 replaces all standard convs with DWS, cutting parameters by about 8 to 9 times with modest accuracy loss.

## Inverted residual block (MobileNetV2)

MobileNetV2 flips the ResNet bottleneck around: it keeps the information on a *thin* path
between blocks, widens it only inside the block for the depthwise step, and squeezes it back.

MobileNetV2 adds a twist: **expand → depthwise → project** with a skip connection on the narrow (bottleneck) features. This is the opposite of ResNet bottleneck (which compresses then expands).

$$
x \xrightarrow{\text{1×1 expand}} \xrightarrow{\text{3×3 DW}} \xrightarrow{\text{1×1 project}} + x
$$

The expansion ratio $t$ (typically 6) increases channels before the depthwise step, giving the DW conv more channels to mix, then projects back down.

> **In plain words:** read the arrow left to right. A $1 \times 1$ conv widens $x$ from $C$ to
> $tC$ channels, a $3 \times 3$ depthwise conv filters each wide channel, a $1 \times 1$ conv
> projects back to $C$, and the result is added to the original $x$.

```python
class InvertedResidual(nn.Module):
    def __init__(self, in_c: int, out_c: int, t: int = 6, stride: int = 1):
        super().__init__()
        mid = in_c * t
        layers = [
            nn.Conv2d(in_c, mid, 1, bias=False), nn.BatchNorm2d(mid), nn.ReLU6(),
            nn.Conv2d(mid, mid, 3, stride=stride, padding=1, groups=mid, bias=False),
            nn.BatchNorm2d(mid), nn.ReLU6(),
            nn.Conv2d(mid, out_c, 1, bias=False), nn.BatchNorm2d(out_c),
        ]
        self.conv = nn.Sequential(*layers)
        self.skip = (stride == 1 and in_c == out_c)

    def forward(self, x):
        out = self.conv(x)
        return out + x if self.skip else out

blk = InvertedResidual(32, 32, t=6)
x   = torch.randn(2, 32, 28, 28)
print("Output:", blk(x).shape)
print("Params:", sum(p.numel() for p in blk.parameters()))
```

```output
Output: torch.Size([2, 32, 28, 28])
Params: 14848
```

With 32 channels and $t = 6$, the middle is 192 channels wide. The count works out as
$32 \cdot 192 + 9 \cdot 192 + 192 \cdot 32 = 14{,}016$ conv weights plus 832 BatchNorm weights,
14,848 in total. **ReLU6** is ReLU capped at 6; it behaves well in low-precision arithmetic on
phones.

> **Watch out:** the projection layer has no ReLU after it, on purpose. A ReLU on a thin
> 32-channel output would zero out negative values and destroy information that the skip
> path cannot recover.

## Squeeze-and-Excite (SE) block

An SE block lets a layer turn its own channels up or down, like a mixing desk. It looks at
the whole image to decide which channels are useful right now, then scales them.

SE blocks add **channel attention**: after a conv, pool the spatial dimensions to a vector, run two FC layers to predict channel weights (sigmoid gate), and re-scale the feature map channel-wise.

$$
s = \sigma(W_2 \cdot \text{ReLU}(W_1 \cdot \text{GAP}(F))) \quad;\quad \tilde{F}_c = s_c \cdot F_c
$$

> **In plain words:**
> - $F$ is the feature map; $\text{GAP}(F)$ averages each channel to one number (ch. 3).
> - $W_1$ squeezes those $C$ numbers down to $C/16$; $W_2$ expands back to $C$.
> - $\sigma$ (sigmoid) turns each result into a gate $s_c$ between 0 and 1.
> - $\tilde{F}_c = s_c \cdot F_c$ multiplies every pixel of channel $c$ by its gate.

```python
class SEBlock(nn.Module):
    def __init__(self, channels: int, reduction: int = 16):
        super().__init__()
        self.pool = nn.AdaptiveAvgPool2d(1)
        self.fc   = nn.Sequential(
            nn.Linear(channels, channels // reduction, bias=False), nn.ReLU(),
            nn.Linear(channels // reduction, channels, bias=False), nn.Sigmoid(),
        )

    def forward(self, x):
        b, c, _, _ = x.shape
        s = self.pool(x).view(b, c)        # (B, C)
        s = self.fc(s).view(b, c, 1, 1)    # (B, C, 1, 1)
        return x * s                        # channel-wise rescale

se  = SEBlock(256)
x   = torch.randn(2, 256, 14, 14)
out = se(x)
print("SE output:", out.shape)
print("SE params:", sum(p.numel() for p in se.parameters()))
```

```output
SE output: torch.Size([2, 256, 14, 14])
SE params: 8192
```

The SE block is cheap: two linear layers, $256 \times 16 + 16 \times 256 = 8{,}192$ weights, and
the output shape is unchanged. It never changes *where* things are, only how loud each channel is.

SENet won ImageNet 2017. Adding SE blocks to ResNet-50 costs ~2.5M extra parameters but lifts top-1 accuracy by ~1–2%. (**Top-1 accuracy** = how often the model's single best guess is right.)

## DropBlock

Ordinary dropout on a feature map is too easy to cheat: neighbouring pixels carry nearly the
same information, so the network fills in a missing pixel from its neighbours. DropBlock hides
whole squares instead.

Dropout applied to conv features drops individual pixels — spatially adjacent units share the same activation and information "leaks" around dropped units. **DropBlock** drops contiguous $k \times k$ regions of the feature map, forcing the network to use global information.

> **Picture it:** studying a jigsaw with a few single pieces missing is easy — you guess
> them from their neighbours. Remove whole $3 \times 3$ chunks, and you must understand the
> full picture to know what was there.

The code picks random "seed" pixels, grows each into a $3 \times 3$ square with max pooling,
and rescales the survivors so the average activation stays about the same.

```python
class DropBlock2d(nn.Module):
    def __init__(self, block_size: int = 7, p: float = 0.1):
        super().__init__()
        self.block_size = block_size
        self.p = p

    def forward(self, x):
        if not self.training or self.p == 0:
            return x
        b, c, h, w = x.shape
        seed_prob = self.p / (self.block_size ** 2)
        mask = (torch.rand(b, 1, h, w, device=x.device) > seed_prob).float()
        mask = 1 - nn.functional.max_pool2d(
            1 - mask, self.block_size, stride=1,
            padding=self.block_size // 2)
        mask = mask.expand_as(x)
        return x * mask / (mask.mean() + 1e-6)

torch.manual_seed(0)
drop = DropBlock2d(block_size=3, p=0.1)
drop.train()
x   = torch.ones(2, 64, 8, 8)
out = drop(x)
print("Fraction dropped:", (out == 0).float().mean().item())
```

```output
Fraction dropped: 0.140625
```

With this seed, about 14% of the values are zero. The seed probability is
$p / k^2 = 0.1 / 9 \approx 0.011$, so an $8 \times 8$ map gets fewer than one seed on average,
and each seed blanks up to 9 cells. On such a tiny map the dropped fraction swings a lot from
draw to draw (another seed gives under 5%); on large maps it settles near $p$.

> **Watch out:** the `if not self.training` line matters. DropBlock, like dropout, must be
> off at evaluation time, or your validation scores will be randomly damaged.

## Recap in plain words

- BatchNorm in a CNN normalises each channel over the batch and all pixels, with one $\gamma$ and $\beta$ per channel.
- In eval mode BN uses running averages, so `model.eval()` is not optional.
- Depthwise-separable convs split spatial filtering and channel mixing, saving 8–9 times the weights.
- Inverted residuals widen inside the block and keep a thin skip path; the last projection has no ReLU.
- SE blocks scale whole channels with gates learned from a global average.
- DropBlock drops square regions instead of single pixels so the network cannot cheat from neighbours.

## Try it Yourself

This counts parameters for three building blocks at 64 channels. It reuses `DepthwiseSepConv`
and `SEBlock` from earlier on this page (the notebook session remembers them).

```python
import torch
import torch.nn as nn

# Compare parameter counts across block types
class StandardBlock(nn.Module):
    def __init__(self, c):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(c, c, 3, padding=1, bias=False),
            nn.BatchNorm2d(c), nn.ReLU(),
            nn.Conv2d(c, c, 3, padding=1, bias=False),
            nn.BatchNorm2d(c), nn.ReLU(),
        )
    def forward(self, x): return self.net(x)

C = 64
std_blk = StandardBlock(C)
dws_blk = DepthwiseSepConv(C, C)
se_blk  = SEBlock(C)

print(f"Standard block:      {sum(p.numel() for p in std_blk.parameters()):,} params")
print(f"DWS block:           {sum(p.numel() for p in dws_blk.parameters()):,} params")
print(f"SE block (overhead): {sum(p.numel() for p in se_blk.parameters()):,} params")
```

```output
Standard block:      73,984 params
DWS block:           4,672 params
SE block (overhead): 512 params
```

The standard two-conv block costs 73,984 parameters; one DWS conv costs 4,672 ($64 \times 9 + 64 \times 64$);
an SE block adds only 512 ($2 \times 64 \times 4$). SE is nearly free, which is why so many modern
networks sprinkle it everywhere.

Try wrapping a `DepthwiseSepConv` in a skip connection (add input to output) and verify the output shape. Then add an `SEBlock` on top of that. Stack 5 such blocks and count total params.

```python
class MobileBlock(nn.Module):
    def __init__(self, channels: int, t: int = 4):
        super().__init__()
        mid = channels * t
        self.expand  = nn.Sequential(nn.Conv2d(channels, mid, 1, bias=False),
                                     nn.BatchNorm2d(mid), nn.ReLU6())
        self.dw      = nn.Sequential(nn.Conv2d(mid, mid, 3, padding=1,
                                               groups=mid, bias=False),
                                     nn.BatchNorm2d(mid), nn.ReLU6())
        self.se      = SEBlock(mid)
        self.project = nn.Sequential(nn.Conv2d(mid, channels, 1, bias=False),
                                     nn.BatchNorm2d(channels))

    def forward(self, x):
        out = self.expand(x)
        out = self.se(self.dw(out))
        out = self.project(out)
        return out + x

mb = MobileBlock(64)
x  = torch.randn(2, 64, 28, 28)
print("Output:", mb(x).shape)
print("MobileBlock params:", sum(p.numel() for p in mb.parameters()))
```

Running it prints a `[2, 64, 28, 28]` output and 44,416 parameters, versus 73,984 for
`ResidualBlock(64)` — about 1.7 times fewer, while adding a skip connection and channel
attention. The cost breakdown: the two $1 \times 1$ convs dominate ($2 \times 64 \times 256 = 32{,}768$),
the depthwise conv is tiny ($9 \times 256 = 2{,}304$), and the SE block on 256 channels adds
8,192. The saving looks modest here because the expansion makes the $1 \times 1$ convs wide; the
real win is compute, since the expensive $3 \times 3$ step is depthwise.
