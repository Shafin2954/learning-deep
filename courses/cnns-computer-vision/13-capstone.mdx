## The project

In plain words: you build a small computer-vision system from the ground up — first the
convolution itself, then a trained image classifier, then a model that finds or outlines
objects — and you measure each part honestly.

You will build a complete vision pipeline: implement convolution forward and backward passes
manually, train a custom CNN on an image classification task, and then construct either an
anchor-based detector head or a U-Net segmenter — evaluating with mAP or mIoU. The point is
not to beat Torchvision's pretrained models; it is to prove you can build and debug the
building blocks that make modern computer vision work.

> **Picture it:** building a bicycle from tubes and bearings instead of buying one. It will be
> slower than a shop bike, but when something squeaks you will know exactly which part it is.

## Hard constraints (no vibe coding)

The rules exist so that every number you report comes from code you understand. "No vibe
coding" means no copying a working pipeline and tweaking it until the score looks right.

- You MAY NOT import any pretrained vision backbone for the core task. Define your own
  architecture and train from scratch (or from random init).
- You MAY NOT use a library's built-in IoU, NMS, or mAP implementation — implement these
  yourself in NumPy.
- You MAY NOT use a detection or segmentation framework (Detectron2, MMDetection, etc.) for
  the core pipeline. Torchvision's `ops` module is off-limits for the core; it is allowed
  only for validation.
- You MAY use Torchvision `DataLoader`, `transforms`, and dataset classes.
- You MAY use PyTorch's `nn.Conv2d` for the training pipeline after you have implemented at
  least one conv forward + backward by hand.

> **Watch out:** "allowed only for validation" means `torchvision.ops.nms` and
> `ops.box_iou` may appear in your *tests*, comparing against your own functions — never inside
> the pipeline that produces your reported scores.

## What it must contain (and the chapter each tests)

Each item below is one piece of the pipeline, with the chapter where you learned it. Build them
in this order; each one is a test of the previous ones.

- **Manual convolution** (ch. 1–2): implement 2D convolution forward pass in NumPy; verify it
  matches `scipy.signal.correlate2d`. Implement the backward pass (gradient w.r.t. input and
  weight); verify with numerical gradients. A **numerical gradient** nudges one input by a tiny
  amount and measures how much the loss changes — slow, but a trustworthy reference. Note that
  `correlate2d` (not `convolve2d`) matches deep learning's convention (ch. 1).
- **Custom CNN** (ch. 3–5): build a CNN in PyTorch with at least three conv-pool stages and a
  BatchNorm layer; train on CIFAR-10 or a similarly sized dataset to $\geq$ 80% test accuracy.
  CIFAR-10 has 60,000 colour images of $32 \times 32$ pixels in 10 classes.
- **Data augmentation pipeline** (ch. 7): apply at least three augmentation types during
  training (random crop, horizontal flip, color jitter); show that augmentation improves
  validation accuracy over the unaugmented baseline. Run both versions with the same seed,
  epochs, and model, so augmentation is the only difference.
- **IoU and NMS** (ch. 8): implement both in NumPy; test on at least five synthetic bounding
  box sets and verify outputs against Torchvision `ops.nms`.
- **Detection head or segmenter** (ch. 9–10): either (a) attach an anchor-based detection head
  to your CNN backbone and train it on a small object detection dataset (Pascal VOC subset or
  a toy dataset), reporting mAP@0.5; or (b) implement a U-Net with skip connections in
  PyTorch and train it on a binary segmentation task, reporting mIoU. Option (b) is the gentler
  path; option (a) exercises anchors, box encoding, and NMS together.
- **ViT comparison** (ch. 11): train or fine-tune a small ViT on the same classification
  dataset and compare accuracy, training time, and data efficiency vs your CNN.
  **Data efficiency** means accuracy as a function of how much training data you use — try,
  for example, 10%, 50%, and 100% of the training set.
- **Mixed precision** (DL Foundations, ch. 13): use `torch.cuda.amp.autocast` +
  `GradScaler` in your training loop; report the wall-clock speedup vs FP32. **Mixed
  precision** runs most maths in 16-bit floats for speed while keeping a 32-bit master copy of
  the weights. In current PyTorch the same API is spelled `torch.amp.autocast("cuda")` and
  `torch.amp.GradScaler("cuda")`.

> **Watch out:** CIFAR-10 images are $32 \times 32$. A ResNet-style stem with a stride-2
> $7 \times 7$ conv plus max pooling (ch. 2) shrinks them to $8 \times 8$ before the first block
> and costs you accuracy. Use a $3 \times 3$, stride-1 stem, as in the ch. 4 `SmallResNet`.

## Acceptance criteria

These are pass/fail checks with numbers, so "it looks like it works" is not an option.

- Manual convolution matches `scipy.signal.correlate2d` to floating-point tolerance on at
  least three kernel sizes ($3 \times 3$, $5 \times 5$, $7 \times 7$) and at least two input sizes.
- Gradient check passes: max absolute error between analytic and numerical gradient < 1e-5.
  (Do the check in float64; in float32, rounding alone can exceed 1e-5.)
- CNN reaches $\geq$ 80% test accuracy on CIFAR-10 (or equivalent dataset) within 30 epochs.
- IoU implementation matches Torchvision on 10 random box pairs to four decimal places.
- NMS implementation produces identical output order to Torchvision `ops.nms` (same threshold).
- Detection head reports mAP@0.5 $\geq$ 0.40 on the chosen dataset, or U-Net reports mIoU $\geq$ 0.70.
- A clear comparison table: CNN vs ViT — accuracy, parameters, epochs to convergence.
- Training loop uses mixed precision; timing logs show $\geq$ 1.3 times speedup on GPU.

> **Watch out:** report test metrics on data the model never saw during training or tuning.
> Picking the best epoch by test accuracy turns the test set into a validation set; hold out a
> separate validation split for that.

  gradient flow. (ch. 4)
- [ ] I can implement BatchNorm in my training loop and explain the difference between train
  and eval mode. (ch. 5)
- [ ] I can write a data augmentation pipeline with at least three transforms and measure its
  effect on validation accuracy. (ch. 7)
- [ ] I can implement IoU from scratch and explain the difference between IoU and GIoU.
  (ch. 8; **GIoU**, generalised IoU, subtracts a penalty for the empty space in the smallest box
  enclosing both, so it still gives a useful signal when boxes do not overlap.)
- [ ] I can implement greedy NMS from scratch and explain what the IOU threshold controls. (ch. 8)
- [ ] I can compute mAP@0.5 by hand (precision-recall curve → AP per class → mean). (ch. 8)
- [ ] I can implement a U-Net encoder-decoder with skip connections and report mIoU on a
  segmentation task. (ch. 10)
- [ ] I can train with `autocast` + `GradScaler` and explain what the scaler does and why.
  (DL Foundations, ch. 13)
- [ ] I can compare CNN and ViT training dynamics and explain when ViT needs more data. (ch. 11)
