## What an LLM actually computes

A large language model looks mysterious, but each step it takes is a short chain of ordinary
arithmetic: multiply, add, turn scores into chances, and measure how wrong the chances were.
This chapter shows you those few pieces in plain code.

You know linear algebra and probability. This chapter connects them to what a neural network —
and an LLM — literally computes, so nothing later feels like magic. Three objects do almost all
the work: the **linear layer**, the **softmax**, and the **cross-entropy loss**. An LLM is
mostly these, repeated.

Here is what each one means in everyday words:

- A **linear layer** is a grid of numbers that mixes the inputs into new outputs ("take 30% of
  this, minus 10% of that, …").
- A **softmax** turns a list of scores into a list of probabilities that add up to 1.
- A **cross-entropy loss** is one number that says how surprised the model was by the right
  answer. Low surprise means a good model.

> **Picture it:** a talent-show jury. The linear layer is each judge scoring each act. The
> softmax converts the raw scores into "chance this act wins". The cross-entropy loss is how
> embarrassed the jury is when the real winner is announced: very embarrassed if they gave that
> act a 1% chance, not at all if they gave it 99%.

## The linear layer is a matrix multiply

A linear layer takes a list of numbers in and gives a (possibly longer or shorter) list of
numbers out. Each output is a weighted sum of all the inputs, plus a constant.

A linear (dense / fully-connected) layer maps an input vector $x$ of size $d_{\text{in}}$ to an
output of size $d_{\text{out}}$:

$$
y = xW + b, \qquad W \in \mathbb{R}^{d_{\text{in}} \times d_{\text{out}}},\quad b \in \mathbb{R}^{d_{\text{out}}}
$$

> **In plain words:**
> - $x$ is the input row of numbers (length $d_{\text{in}}$).
> - $W$ is the **weight matrix** — the grid of mixing amounts, with one row per input and one
>   column per output.
> - $b$ is the **bias** — one extra constant added to each output.
> - $y$ is the output row (length $d_{\text{out}}$). Output number $j$ is "input times column
>   $j$ of $W$, plus $b_j$".

For a whole batch $X$ of shape $(N, d_{\text{in}})$ it's $Y = XW + b$, shape $(N, d_{\text{out}})$.
That's it. When you hear "7 billion parameters," the overwhelming majority are entries of the $W$
matrices in linear layers. **Attention itself is built from linear layers and matmuls** (you build
it in F10), so being fluent with `X @ W` *is* being fluent with the core of an LLM. Get comfortable
reading shapes — shape bugs are most deep-learning bugs.

A **batch** is a stack of $N$ inputs processed together, one per row. A **parameter** is any
number the model learns during training; here that means every entry of $W$ and $b$. With
$d_{\text{in}} = 4$ and $d_{\text{out}} = 5$, the layer has $4 \times 5 + 5 = 25$ parameters.

> **Watch out:** the shape rule for `X @ W` is "inner sizes must match, outer sizes survive":
> $(N, d_{\text{in}}) \times (d_{\text{in}}, d_{\text{out}}) \to (N, d_{\text{out}})$. When a
> matmul crashes, write the two shapes side by side and check the middle pair first.

## Softmax turns scores into probabilities

A model's raw scores can be any size and any sign, so they are not probabilities yet. Softmax
makes every score positive (by raising $e$ to it) and then divides by the total so they sum to 1.

The final linear layer outputs raw scores called **logits**, one per class (for an LLM, one per
vocabulary token). Softmax maps a logit vector $z$ to a probability distribution:

$$
\mathrm{softmax}(z)_i = \frac{e^{z_i}}{\sum_j e^{z_j}}
$$

> **In plain words:** take $e$ to the power of each score, then divide each result by the sum
> of all of them. A score of 2 becomes $e^2 \approx 7.4$, a score of 0 becomes $e^0 = 1$, and
> the probabilities are each piece's share of the total. The **vocabulary** is the full list of
> tokens (word pieces) the model can output, often 30,000 to 150,000 of them.

The outputs are positive and sum to 1. Two properties to carry forever: it is **shift-invariant**
(adding a constant to every logit changes nothing) and **monotonic** (bigger logit → bigger
probability).

Shift-invariance follows from one line of algebra: adding $c$ to every logit multiplies every
$e^{z_i}$ by the same $e^{c}$, and that common factor cancels between top and bottom. Only the
*gaps* between logits matter, never their absolute level.

> **Picture it:** softmax is a tug-of-war where each team's pull is exponential in its score.
> If every team gets 5 points stronger, the rope still ends up in the same place.

### Numerical stability: the log-sum-exp trick

Computers store numbers with a size limit. $e^{1000}$ is far beyond that limit, so a naive
softmax breaks on large scores. The fix uses shift-invariance to keep every exponent small.

$e^{z}$ overflows for moderately large $z$. Because softmax is shift-invariant, subtract the max
logit first: $z \leftarrow z - \max(z)$. Now the largest exponent is $e^{0}=1$ — no overflow,
identical result. The same idea defines **log-sum-exp**, which appears whenever you compute
log-probabilities (constantly, in LLMs):

$$
\mathrm{LSE}(z) = \max(z) + \log \sum_j e^{\,z_j - \max(z)}
$$

> **In plain words:** "the log of the sum of exponentials" is computed as the biggest score plus
> a small correction. Every exponent inside is now $e^{\text{something} \le 0}$, which is at most
> 1, so nothing overflows. A 64-bit float overflows past about $e^{709}$, so logits of 1000 are
> already fatal without this trick.

**Overflow** means a number grows too large to store and becomes `inf`; then `inf / inf` gives
`nan` ("not a number"), which poisons every calculation that touches it.

## Cross-entropy is negative log-likelihood

To grade a prediction, look only at the probability the model gave to the correct answer, and
take minus its logarithm. Confident and right costs nothing; confident and wrong costs a lot.

For a true class $y$, the cross-entropy loss is

$$
L = -\log p_y, \qquad p = \mathrm{softmax}(z)
$$

> **In plain words:** $p_y$ is the probability the model put on the right answer. $-\log$ of 1
> is 0; $-\log$ of 0.5 is about 0.69; $-\log$ of 0.01 is about 4.6. Each halving of the right
> answer's probability adds the same fixed penalty, about 0.69.

If the model puts probability 1 on the right token, loss is 0; as $p_y \to 0$, loss $\to \infty$.
Averaged over a sequence of next-token predictions, this *is* the loss an LLM trains on. (F3
derives why minimizing it equals maximum likelihood; F13 connects it to perplexity.)

The **log-likelihood** is the log of the probability the model assigns to what really happened;
"negative" flips its sign so that smaller is better, which is the direction optimizers expect.

> **Watch out:** never let $p_y$ be exactly 0. Then $-\log 0 = \infty$ and training produces
> `inf` or `nan`. The stable fix is to compute log-probabilities directly (this chapter's
> Exercise) rather than taking the log of a probability that has already rounded to 0.

## The gradient you'll memorize

Training needs to know, for each logit, "should this score go up or down, and by how much?"
For softmax followed by cross-entropy the answer is strikingly simple: the model's probabilities
minus the right answer.

The gradient of cross-entropy with respect to the logits is

$$
\boxed{\;\frac{\partial L}{\partial z} = \mathrm{softmax}(z) - \mathrm{onehot}(y)\;}
$$

> **In plain words:** $\mathrm{onehot}(y)$ is a list of zeros with a single 1 at the correct
> class. Subtract it from the predicted probabilities. The right class gets "probability minus
> 1" (a negative number, so gradient descent pushes its logit up). Every wrong class gets its
> own probability (positive, so its logit is pushed down, harder the more it was over-trusted).

"Predicted distribution minus the truth." This clean expression is why softmax and cross-entropy
are always paired — the messy $\exp$/$\log$ derivatives cancel. (Derived in full in F2.) Every
backward pass through an LLM's output layer starts here.

A **gradient** is the list of slopes: how much the loss would change if you nudged each number
a tiny bit. The **backward pass** is the step that computes these slopes for every parameter.

### The whole forward pass in code

The **forward pass** is running the input through the model to get a prediction and a loss.
The block below does exactly that for 3 examples and 5 classes, then computes the gradient.

A classifier's forward pass — and an LLM's per-token step — is `linear → softmax → cross-entropy`:

```python
import numpy as np

def softmax(z):                         # stable: shift by row max
    z = z - z.max(axis=-1, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=-1, keepdims=True)

def cross_entropy(logits, y):           # mean negative log-likelihood
    p = softmax(logits)
    return -np.log(p[np.arange(len(y)), y]).mean()

np.random.seed(0)
X = np.random.randn(3, 4)               # batch of 3, d_in = 4
W = np.random.randn(4, 5); b = np.zeros(5)   # -> d_out = 5 (5 classes)
logits = X @ W + b
probs  = softmax(logits)
y = np.array([0, 2, 4])

print("logits row 0 :", logits[0].round(2))
print("probs  row 0 :", probs[0].round(3), "sum =", probs[0].sum())
print("loss         :", round(cross_entropy(logits, y), 4))

grad = probs.copy(); grad[np.arange(3), y] -= 1; grad /= 3   # softmax - onehot
print("dL/dlogits[0]:", grad[0].round(3))
```

```output
logits row 0 : [ 1.69  3.05  5.96 -1.51  3.79]
probs  row 0 : [0.012 0.046 0.845 0.    0.097] sum = 1.0
loss         : 2.4397
dL/dlogits[0]: [-0.329  0.015  0.282  0.     0.032]
```

The whole classifier head, in six lines.

Read the output line by line:

- **Row 0's logits** range from $-1.51$ to $5.96$. They are raw and unbounded.
- **Row 0's probabilities** put 0.845 on class 2, the largest logit, and the row sums to 1.0.
  Class 3, with logit $-1.51$, rounds to 0.
- **The loss is 2.4397**, averaged over three rows. Row 0's correct class is 0, which got only
  0.012. Its share alone is $-\log 0.012 \approx 4.4$, which drags the average up.
- **The gradient row** is $(p - \mathrm{onehot})/3$. Class 0 gets $(0.012 - 1)/3 = -0.329$,
  negative, so its logit should rise. Class 2 gets $0.845 / 3 = 0.282$, the biggest positive
  push down, because it is the most over-trusted wrong answer. The division by 3 comes from
  averaging the loss over the batch.

## Recap in plain words

- A linear layer is `X @ W + b`: every output is a weighted sum of the inputs plus a constant.
- Softmax turns any scores into positive probabilities that sum to 1; only the gaps between
  scores matter.
- Subtract the maximum score before exponentiating, or large scores overflow into `nan`.
- Cross-entropy is minus the log of the probability given to the right answer.
- The gradient of softmax plus cross-entropy with respect to the logits is "probabilities minus
  the one-hot truth".
- An LLM's output step is this exact pipeline, with one class per vocabulary token.

## Try it Yourself

This experiment checks three softmax facts at once: the naive version breaks on big numbers,
shifting all scores changes nothing, and dividing by a **temperature** $T$ sharpens or flattens
the probabilities.

```python
import numpy as np
def softmax(z):
    z = z - z.max(axis=-1, keepdims=True); e = np.exp(z); return e / e.sum(axis=-1, keepdims=True)

# 1) Why max-subtraction matters: huge logits overflow naively.
z = np.array([1000.0, 1001.0, 1002.0])
naive = np.exp(z) / np.exp(z).sum()
print("naive  :", naive)                  # nan (overflow)
print("stable :", softmax(z).round(4))    # correct

# 2) Shift-invariance: add 50 to every logit -> identical probabilities.
print("shifted:", softmax(z + 50).round(4))

# 3) Temperature: divide logits by T. T<1 sharpens, T>1 flattens.
#    This is exactly the `temperature` knob in LLM generation (Bengali ch. 11).
for T in [0.5, 1.0, 2.0]:
    print(f"T={T}:", softmax(z / T).round(3))
```

```output
naive  : [nan nan nan]
stable : [0.09   0.2447 0.6652]
shifted: [0.09   0.2447 0.6652]
T=0.5: [0.016 0.117 0.867]
T=1.0: [0.09  0.245 0.665]
T=2.0: [0.186 0.307 0.506]
```

The temperature line is not a toy — it's the same parameter you set when sampling from a Bengali
LLM at inference.

Check each claim in the output. The **naive** line is `[nan nan nan]`: $e^{1000}$ overflowed to
`inf`, and `inf / inf` is `nan`. The **stable** and **shifted** lines are identical,
`[0.09 0.2447 0.6652]`, which proves shift-invariance. In the temperature rows, the top
probability goes 0.867 at $T = 0.5$, then 0.665 at $T = 1$, then 0.506 at $T = 2$: lower
temperature makes the model more decisive, higher makes it more even-handed.

Try a variation: set `T = 0.01` and `T = 100`. Very low $T$ should put nearly all the
probability on the largest logit, and very high $T$ should approach $1/3$ for each.

## Exercise

Implement `log_softmax(z)` using the log-sum-exp trick (do **not** call `log(softmax(z))` — that's
unstable), then write `nll(logits, y)` with it and verify it matches `cross_entropy` above.

> **Hint:** $\log \mathrm{softmax}(z)_i = z_i - \mathrm{LSE}(z)$. Compute $\mathrm{LSE}$ with
> the max-subtraction formula above, keeping `keepdims=True` so the shapes broadcast.

<details>
<summary>Solution</summary>

```python
import numpy as np
def log_softmax(z):
    m = z.max(axis=-1, keepdims=True)
    return z - m - np.log(np.exp(z - m).sum(axis=-1, keepdims=True))

def nll(logits, y):
    return -log_softmax(logits)[np.arange(len(y)), y].mean()

np.random.seed(0)
logits = np.random.randn(3, 5); y = np.array([0, 2, 4])
print(nll(logits, y))   # equals cross_entropy(logits, y)
```

`log_softmax` never forms the tiny probability before logging, so it stays accurate even when one
logit dominates — the normal case for a confident LLM.

The script prints about 1.7849, the same value `cross_entropy` gives for these logits. The
difference only shows up at extremes: for logits $(-1000, 0)$, `np.log(softmax(z))` returns
`-inf` for the first class because its probability underflows to 0, while `log_softmax` returns
the correct $-1000$.
</details>
