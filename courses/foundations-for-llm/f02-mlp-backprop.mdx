## What backpropagation computes

Training a network means asking, for every single weight, "if I nudge you a little, does the
error go up or down, and by how much?" **Backpropagation** is the bookkeeping method that
answers that question for millions of weights at once, by walking backwards from the error.

To train a network we use gradient descent: nudge every weight $w$ a little against its
gradient $\dfrac{\partial L}{\partial w}$, where $L$ is the loss. So the entire job of
backpropagation is to compute $\dfrac{\partial L}{\partial w}$ for **every** weight, efficiently.

**Gradient descent** is the training rule "move each weight a small step in the direction that
lowers the loss". The **gradient** of the loss with respect to a weight is that weight's slope:
how much the loss changes per unit change in the weight.

"Efficiently" is the whole point. A network is a chain of operations; the chain rule says the
gradient w.r.t. an early quantity is the product of the local gradients along the path from the
loss back to it. Computing those products **backwards**, reusing each intermediate result, is
backpropagation — and it's why one backward pass costs about the same as one forward pass.

The **chain rule** says that when A affects B and B affects C, the effect of A on C is "effect
of A on B" times "effect of B on C".

> **Picture it:** a row of gears. Turn the first gear once and the last gear turns by the
> product of all the gear ratios in between. Backprop reads the ratios from the last gear
> toward the first, so each partial product is computed once and reused by every gear behind
> it, instead of being recomputed for each weight.

We'll build it on a 2-layer MLP, deriving each piece from scratch.

An **MLP** (multi-layer perceptron) is a stack of linear layers with a simple bend between them.
"2-layer" here means two weight matrices: input to hidden, and hidden to output.

## The network we differentiate

The network does four things in order: mix the inputs, zero out the negative values, mix again
into class scores, and turn the scores into probabilities.

One hidden layer with a ReLU, then a softmax classifier:

$$
z_1 = X W_1 + b_1, \qquad h = \mathrm{ReLU}(z_1), \qquad z_2 = h W_2 + b_2, \qquad p = \mathrm{softmax}(z_2)
$$

> **In plain words:**
> - $z_1$ is the first mix of the inputs $X$ (weights $W_1$, bias $b_1$).
> - $h$ is the **hidden layer**: $\mathrm{ReLU}$ keeps positive numbers and replaces negatives
>   with 0. That bend is what lets the network learn curved patterns.
> - $z_2$ is the second mix, producing one **logit** (raw score) per class.
> - $p$ is the softmax of the logits: one probability per class (F1).

and the loss is the cross-entropy between $p$ and the one-hot labels $Y$, averaged over the
$N$ samples in the batch.

A **one-hot label** is a row of zeros with a single 1 marking the true class, so class 1 out of
2 becomes `[0, 1]`.

### Forward pass in code

The block builds a tiny network (3 inputs, 5 hidden units, 2 classes) and pushes 4 random
samples through it.

```python
import numpy as np
np.random.seed(0)

def relu(z): return np.maximum(0, z)
def softmax(z):
    z = z - z.max(axis=1, keepdims=True)        # subtract max for numerical stability
    e = np.exp(z); return e / e.sum(axis=1, keepdims=True)

X  = np.random.randn(4, 3)                       # 4 samples, 3 features
W1 = np.random.randn(3, 5) * 0.5; b1 = np.zeros(5)
W2 = np.random.randn(5, 2) * 0.5; b2 = np.zeros(2)

z1 = X @ W1 + b1
h  = relu(z1)
z2 = h @ W2 + b2                                 # logits
p  = softmax(z2)                                 # probabilities
print("logits z2[0]:", z2[0].round(3))
print("probs  p[0] :", p[0].round(3), " sum:", round(p[0].sum(), 3))
```

```output
logits z2[0]: [0.268 1.121]
probs  p[0] : [0.299 0.701]  sum: 1.0
```

The probabilities are positive and sum to 1. Now we differentiate this, starting at the loss.

For sample 0, the logits are 0.268 and 1.121. The gap of 0.853 turns into probabilities 0.299
and 0.701: the bigger score wins, but not overwhelmingly, because the random weights were
scaled down by 0.5.

## Deriving the softmax–cross-entropy gradient

The single most-used result in deep learning is that the slope of "softmax then cross-entropy"
is "predicted probabilities minus the truth". Here you derive it, so you know why it is true.

This is the gradient everything else hangs on, so we derive it fully rather than quote it.

### Softmax

Softmax raises $e$ to each score and divides by the total.

For logits $z = (z_1, \dots, z_K)$:

$$
p_i = \frac{e^{z_i}}{\sum_{k} e^{z_k}}
$$

> **In plain words:** probability $i$ is "$e$ to score $i$" as a share of the sum over all $K$
> classes.

Its derivative (quotient rule, splitting the two cases) is the **softmax Jacobian**:

$$
\frac{\partial p_i}{\partial z_j} =
\begin{cases}
p_i (1 - p_i) & i = j \\[2pt]
- p_i\, p_j & i \neq j
\end{cases}
\;=\; p_i\,(\delta_{ij} - p_j)
$$

where $\delta_{ij} = 1$ if $i = j$ and $0$ otherwise.

> **In plain words:** a **Jacobian** is a table of slopes, one for every (output, input) pair.
> Raising your own score $z_i$ raises your own probability, by $p_i(1 - p_i)$. Raising someone
> else's score $z_j$ lowers yours, by $p_i p_j$, because the probabilities must still sum to 1.
> The $\delta_{ij}$ symbol (the **Kronecker delta**) is a switch that packs both cases into one
> formula.

### Cross-entropy

Cross-entropy picks out the log-probability of the true class and flips its sign.

With one-hot labels $y$ (so $y_c = 1$ for the true class $c$, else $0$):

$$
L = -\sum_i y_i \log p_i = -\log p_c
$$

> **In plain words:** the sum looks over all classes, but every $y_i$ is 0 except the true
> class $c$, so only $-\log p_c$ survives.

### Putting them together

Now chain the two: the loss depends on each probability, and each probability depends on each
logit.

Apply the chain rule through every $p_i$:

$$
\frac{\partial L}{\partial z_j}
= -\sum_i \frac{y_i}{p_i}\,\frac{\partial p_i}{\partial z_j}
= -\sum_i \frac{y_i}{p_i}\, p_i(\delta_{ij} - p_j)
= -\sum_i y_i(\delta_{ij} - p_j)
$$

> **In plain words:** the first step is the chain rule ("slope of loss with respect to $p_i$"
> times "slope of $p_i$ with respect to $z_j$", summed over $i$). The middle step plugs in the
> Jacobian. The $p_i$ on top cancels the $p_i$ underneath, which is where all the mess vanishes.

Split the sum and use $\sum_i y_i = 1$ (one-hot):

$$
\frac{\partial L}{\partial z_j}
= -y_j + p_j \sum_i y_i
= p_j - y_j
$$

> **In plain words:** $-\sum_i y_i \delta_{ij}$ picks out $-y_j$, and $\sum_i y_i p_j$ is $p_j$
> times the total of the labels, which is 1.

So the gradient of the logits is just

$$
\boxed{\,dz = p - y = \mathrm{softmax}(z) - \mathrm{onehot}(y)\,}
$$

A messy Jacobian and a log collapse into a subtraction. Let's confirm it numerically.

> **In plain words:** the slope for each logit is "how much probability you gave this class"
> minus "how much it deserved" (1 for the true class, 0 for the rest).

A **numerical gradient** is the slope measured by experiment: nudge one number up by a tiny
$\varepsilon$, nudge it down, and divide the change in loss by $2\varepsilon$. It is slow but
hard to get wrong, which makes it the perfect referee for a hand-derived formula.

```python
y_idx = np.array([0, 1, 1, 0])
Y = np.eye(2)[y_idx]                              # one-hot labels

def ce_loss(P, Y):                               # mean cross-entropy
    return -np.mean(np.sum(Y * np.log(P + 1e-12), axis=1))

dz2_analytic = (p - Y) / len(X)                  # our derived result (averaged over N)

# numerical gradient: nudge each logit by +/- eps and measure the loss change
eps = 1e-6; dz2_num = np.zeros_like(z2)
for i in range(z2.shape[0]):
    for j in range(z2.shape[1]):
        zp = z2.copy(); zp[i, j] += eps
        zm = z2.copy(); zm[i, j] -= eps
        dz2_num[i, j] = (ce_loss(softmax(zp), Y) - ce_loss(softmax(zm), Y)) / (2 * eps)

print("max |analytic (p - y)/N  -  numerical|:", np.abs(dz2_analytic - dz2_num).max())
```

```output
max |analytic (p - y)/N  -  numerical|: 3.4308889063083825e-11
```

Agreement to $10^{-11}$ — the derivation is correct.

The printed gap, about $3.4 \times 10^{-11}$, is the size of floating-point rounding noise for a
step of $10^{-6}$. A wrong formula would disagree at the first or second decimal place.

> **Watch out:** the analytic gradient is divided by `len(X)` because `ce_loss` takes the
> *mean* over the batch. Forget the $1/N$ and every gradient is $N$ times too large, which the
> numerical check would flag immediately.

## Backprop is the chain rule, organized

Going backwards, each layer does the same small job: take the slope that arrived from above,
use it to compute the slopes for its own weights, and hand a slope down to the layer below.

With $dz_2 = \frac{1}{N}(p - Y)$ in hand, we push it back through each operation. Every layer,
going backward, does three things: receive the gradient w.r.t. its output, produce the gradient
w.r.t. its weights, and pass the gradient w.r.t. its input to the layer before it.

> **Picture it:** a relay race run in reverse. Each runner (layer) receives the baton (the
> incoming gradient), writes down their own split (the weight gradient), and passes the baton
> back to the runner before them.

### The backward equations

Read these top to bottom: they follow the forward pass in reverse order.

$$
\begin{aligned}
dz_2 &= \tfrac{1}{N}(p - Y) & &\text{(softmax+CE result above)}\\
dW_2 &= h^{\top} dz_2 & &\text{(how the loss depends on } W_2)\\
db_2 &= \textstyle\sum_n dz_2 & &\text{(sum over the batch)}\\
dh   &= dz_2\, W_2^{\top} & &\text{(push gradient into the hidden layer)}\\
dz_1 &= dh \odot \mathbb{1}[z_1 > 0] & &\text{(ReLU's gradient gate)}\\
dW_1 &= X^{\top} dz_1, \quad db_1 = \textstyle\sum_n dz_1 &
\end{aligned}
$$

> **In plain words:** $d\square$ means "gradient of the loss with respect to $\square$".
> $\top$ is a **transpose** (flip rows and columns). $\odot$ is element-by-element
> multiplication. $\mathbb{1}[z_1 > 0]$ is 1 where the hidden value was positive and 0 where
> ReLU zeroed it. Each bias gradient sums over the batch because the same bias was added to
> every sample.

Each line is the chain rule for one operation. A matmul $A B$ sends gradient to $A$ as
$(\text{grad})B^{\top}$ and to $B$ as $A^{\top}(\text{grad})$. ReLU multiplies the incoming
gradient by 1 where its input was positive and 0 elsewhere. That's the entire vocabulary.

The ReLU rule has a plain reason: where ReLU output 0, wiggling its input a little still gives
0, so no gradient can flow through. That zeroing is the **gate**.

```python
N = len(X)
dz2 = (p - Y) / N
dW2 = h.T @ dz2
db2 = dz2.sum(0)
dh  = dz2 @ W2.T
dz1 = dh * (z1 > 0)                              # ReLU gate
dW1 = X.T @ dz1
db1 = dz1.sum(0)
print("dW1", dW1.shape, "db1", db1.shape, "dW2", dW2.shape, "db2", db2.shape)
```

```output
dW1 (3, 5) db1 (5,) dW2 (5, 2) db2 (2,)
```

Each gradient has the same shape as its parameter — the sanity check you do every time.

Compare the output to the setup: `W1` was $(3, 5)$ and `dW1` is $(3, 5)$; `W2` was $(5, 2)$
and `dW2` is $(5, 2)$; the biases are $(5,)$ and $(2,)$. Each gradient has one entry per weight,
because each weight needs its own slope.

A deep network, or a 32-layer transformer, is just this local rule repeated. Frameworks
(`autograd`) automate it, but the rule is exactly what you derived.

**Autograd** (automatic differentiation) is software that records your forward operations and
replays these exact backward rules for you. PyTorch's `loss.backward()` is autograd.

## Gradient checking — your correctness seatbelt

Before you trust a hand-written gradient, measure a few slopes by experiment and compare.

Analytic gradients are easy to get subtly wrong. The check: perturb one weight by a tiny
$\varepsilon$ and approximate the gradient numerically,

$$
\frac{\partial L}{\partial w} \approx \frac{L(w + \varepsilon) - L(w - \varepsilon)}{2\varepsilon}
$$

then compare to your analytic value. They should match to many decimals.

> **In plain words:** the slope is roughly "loss a little to the right minus loss a little to
> the left, divided by the distance between them". Using both sides (a **central
> difference**) is far more accurate than one side alone.

```python
def forward_loss(W1, b1, W2, b2):
    h = relu(X @ W1 + b1); P = softmax(h @ W2 + b2); return ce_loss(P, Y)

def numerical_grad(param, idx):
    orig = param[idx]
    param[idx] = orig + eps; Lp = forward_loss(W1, b1, W2, b2)
    param[idx] = orig - eps; Lm = forward_loss(W1, b1, W2, b2)
    param[idx] = orig
    return (Lp - Lm) / (2 * eps)

diffs = [abs(numerical_grad(W1, idx) - dW1[idx]) for idx in [(0, 0), (1, 2), (2, 4)]]
print("max gradient-check diff on W1 entries:", max(diffs))
```

```output
max gradient-check diff on W1 entries: 2.012559563446814e-11
```

A difference around $10^{-11}$ means the analytic gradient is right. If you ever see $10^{-2}$,
you have a bug — usually a missing transpose, a wrong axis on a sum, or a dropped ReLU gate.

The output shows $2.0 \times 10^{-11}$ as the worst of the three checked entries of `W1`. That
is rounding noise, so the full backward pass, all the way to the first layer, is correct.

> **Watch out:** gradient checking is for debugging, not training. It needs two full forward
> passes *per weight*, so checking a million-weight model would cost two million forward
> passes. Check a handful of entries on a tiny batch, then turn it off.

## Training it

Now repeat "forward, backward, step" thousands of times and watch the network learn. The
target is a pattern that no straight line can separate.

Put forward + backward in a loop and step the weights. We use an XOR-style target, which a
linear model **cannot** solve — it forces the hidden layer to earn its keep.

**XOR** here means: the label is 1 when the two inputs have the same sign (both positive or both
negative) and 0 otherwise. The two classes sit in opposite corners of a checkerboard, so any
single straight line gets about half of them wrong. An **epoch** is one pass over the training
data; here, one gradient step on all 200 points.

```python
np.random.seed(1)
Xt = np.random.randn(200, 2)
yt = ((Xt[:, 0] * Xt[:, 1]) > 0).astype(int)     # XOR pattern: needs a hidden layer
Yt = np.eye(2)[yt]

W1 = np.random.randn(2, 16) * 0.5; b1 = np.zeros(16)
W2 = np.random.randn(16, 2) * 0.5; b2 = np.zeros(2)
lr = 0.5

def accuracy():
    h = relu(Xt @ W1 + b1); P = softmax(h @ W2 + b2); return (P.argmax(1) == yt).mean()

for ep in range(2001):
    z1 = Xt @ W1 + b1; h = relu(z1); P = softmax(h @ W2 + b2)
    N = len(Xt); dz2 = (P - Yt) / N              # the gradient we derived
    dW2 = h.T @ dz2; db2 = dz2.sum(0)
    dh = dz2 @ W2.T; dz1 = dh * (z1 > 0)
    dW1 = Xt.T @ dz1; db1 = dz1.sum(0)
    W1 -= lr*dW1; b1 -= lr*db1; W2 -= lr*dW2; b2 -= lr*db2   # gradient descent step
    if ep in (0, 500, 1000, 2000):
        print(f"epoch {ep:4d}: loss {ce_loss(P, Yt):.3f}  acc {accuracy():.3f}")
```

```output
epoch    0: loss 0.817  acc 0.705
epoch  500: loss 0.042  acc 1.000
epoch 1000: loss 0.026  acc 1.000
epoch 2000: loss 0.015  acc 1.000
```

The loss falls from 0.817 to 0.042 by epoch 500 and to 0.015 by epoch 2000, and accuracy
reaches 1.000: the gradient you derived by hand, looped, learns XOR. Everything larger — a
transformer, an LLM — is this same loop at scale.

Read the epoch-0 row carefully. The loss, 0.817, is computed *before* the first update, from
the random starting weights. The accuracy, 0.705, is measured by `accuracy()` *after* that
first update. The untrained network scores 0.46 on these 200 points (chance is 0.5 for two
balanced classes), so one step at learning rate 0.5 already moves it to 70.5%.

> **Watch out:** when you log metrics inside a training loop, be clear whether each number is
> from before or after the step. Mixing the two, as this row does, makes early progress look
> faster or slower than it is.

## Recap in plain words

- Backpropagation computes every weight's slope in one backward sweep, reusing work via the
  chain rule.
- Softmax followed by cross-entropy has the slope "probabilities minus one-hot truth", averaged
  over the batch.
- Each layer, backwards, turns the incoming slope into its weight slopes and passes a slope on
  to the layer below.
- A matmul passes gradient back through a transpose; ReLU passes it only where its input was
  positive.
- Every gradient has the same shape as the parameter it belongs to.
- Gradient checking compares your formula with a measured slope; agreement near $10^{-11}$
  means correct.

## Try it Yourself

This block plants a classic bug, forgetting the ReLU gate, and lets the gradient check catch it.

```python
import numpy as np
# Break the ReLU gate on purpose and watch gradient checking catch it.
np.random.seed(0)
def relu(z): return np.maximum(0, z)
def softmax(z):
    z = z - z.max(1, keepdims=True); e = np.exp(z); return e / e.sum(1, keepdims=True)
def ce_loss(P, Y): return -np.mean(np.sum(Y*np.log(P+1e-12), 1))

X = np.random.randn(4, 3); Y = np.eye(2)[np.array([0,1,1,0])]
W1 = np.random.randn(3,5)*0.5; b1=np.zeros(5); W2=np.random.randn(5,2)*0.5; b2=np.zeros(2)
z1 = X@W1+b1; h = relu(z1); p = softmax(h@W2+b2)
N=len(X); dz2=(p-Y)/N; dh=dz2@W2.T

dz1_correct = dh * (z1 > 0)          # correct ReLU gate
dz1_buggy   = dh                     # BUG: forgot the gate
dW1_correct = X.T @ dz1_correct
dW1_buggy   = X.T @ dz1_buggy

eps=1e-6
def num(idx):
    o=W1[idx]; W1[idx]=o+eps; Lp=ce_loss(softmax(relu(X@W1+b1)@W2+b2),Y)
    W1[idx]=o-eps; Lm=ce_loss(softmax(relu(X@W1+b1)@W2+b2),Y); W1[idx]=o
    return (Lp-Lm)/(2*eps)
idx=(1,2)
print("correct gate diff:", abs(num(idx)-dW1_correct[idx]))   # ~1e-11  -> passes
print("buggy   gate diff:", abs(num(idx)-dW1_buggy[idx]))     # large   -> caught!
```

```output
correct gate diff: 1.215036404822456e-11
buggy   gate diff: 0.0854299768582195
```

The correct version disagrees with the numerical slope by about $1.2 \times 10^{-11}$, which is
rounding noise. The buggy version is off by about 0.085, roughly ten billion times worse. That
huge gap is exactly what a gradient check is designed to expose: without the gate, slope flows
through hidden units that ReLU had switched off.

Try a variation: change `idx=(1,2)` to other entries such as `(0,0)` or `(2,4)`. If you happen
to pick a hidden unit that was positive for every sample, the buggy gradient will match, because
the gate was all ones there anyway. That is why you check several entries, not one.

## Exercise

Extend this MLP to **two** hidden layers ($X \to h_1 \to h_2 \to \text{logits}$). Derive and
implement the backward pass for the extra layer (it's the same matmul + ReLU-gate pattern),
gradient-check every weight matrix to $\approx 10^{-10}$, and train it on the XOR data. The point:
once you can add a layer and pass the gradient check, depth holds no mystery.

> **Hint:** write the forward pass first and keep every intermediate ($z_1, h_1, z_2, h_2$).
> The backward pass then repeats the same three moves per layer, from the top down: weight
> gradient via a transpose, pass the gradient down through $W^{\top}$, apply the ReLU gate.

<summary>Solution</summary>

Forward: $z_1 = XW_1+b_1,\ h_1=\mathrm{ReLU}(z_1),\ z_2=h_1W_2+b_2,\ h_2=\mathrm{ReLU}(z_2),\
z_3=h_2W_3+b_3,\ p=\mathrm{softmax}(z_3)$. Backward, top down: $dz_3=\frac1N(p-Y)$;
$dW_3=h_2^\top dz_3$; $dh_2=dz_3W_3^\top$; $dz_2=dh_2\odot\mathbb{1}[z_2>0]$; $dW_2=h_1^\top dz_2$;
$dh_1=dz_2W_2^\top$; $dz_1=dh_1\odot\mathbb{1}[z_1>0]$; $dW_1=X^\top dz_1$. Same three moves per
layer.

```python
import numpy as np
def relu(z): return np.maximum(0, z)
def softmax(z):
    z = z - z.max(1, keepdims=True); e = np.exp(z); return e / e.sum(1, keepdims=True)
def ce_loss(P, Y): return -np.mean(np.sum(Y * np.log(P + 1e-12), 1))

np.random.seed(1)
Xt = np.random.randn(200, 2)
yt = ((Xt[:, 0] * Xt[:, 1]) > 0).astype(int); Yt = np.eye(2)[yt]
params = {"W1": np.random.randn(2, 16) * 0.5, "b1": np.zeros(16),
          "W2": np.random.randn(16, 16) * 0.5, "b2": np.zeros(16),
          "W3": np.random.randn(16, 2) * 0.5, "b3": np.zeros(2)}

def forward(P_, X):
    z1 = X @ P_["W1"] + P_["b1"]; h1 = relu(z1)
    z2 = h1 @ P_["W2"] + P_["b2"]; h2 = relu(z2)
    p = softmax(h2 @ P_["W3"] + P_["b3"])
    return z1, h1, z2, h2, p

def backward(P_, X, Y):
    z1, h1, z2, h2, p = forward(P_, X)
    dz3 = (p - Y) / len(X)
    g = {"W3": h2.T @ dz3, "b3": dz3.sum(0)}
    dz2 = (dz3 @ P_["W3"].T) * (z2 > 0)
    g["W2"], g["b2"] = h1.T @ dz2, dz2.sum(0)
    dz1 = (dz2 @ P_["W2"].T) * (z1 > 0)
    g["W1"], g["b1"] = X.T @ dz1, dz1.sum(0)
    return g

# gradient-check every entry of every weight matrix on a small batch
Xs, Ys = Xt[:8], Yt[:8]; g = backward(params, Xs, Ys); eps = 1e-6
for name in ["W1", "W2", "W3"]:
    W = params[name]; worst = 0.0
    for idx in np.ndindex(W.shape):
        o = W[idx]
        W[idx] = o + eps; Lp = ce_loss(forward(params, Xs)[-1], Ys)
        W[idx] = o - eps; Lm = ce_loss(forward(params, Xs)[-1], Ys); W[idx] = o
        worst = max(worst, abs((Lp - Lm) / (2 * eps) - g[name][idx]))
    print(name, "max grad-check diff:", f"{worst:.1e}")

for ep in range(2001):
    g = backward(params, Xt, Yt)
    for k in params: params[k] -= 0.5 * g[k]
p = forward(params, Xt)[-1]
print(f"final loss {ce_loss(p, Yt):.3f}  acc {(p.argmax(1) == yt).mean():.3f}")
```

Running it prints a worst-case gradient-check gap of about $2 \times 10^{-10}$ for each of
`W1`, `W2` and `W3`, then a final loss of 0.003 at accuracy 1.000. The new layer needed no new
idea: its backward code is a copy of the old hidden layer's, with the names shifted by one. That
is the whole secret of depth.
