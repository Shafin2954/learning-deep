## Similar users like similar things

If people who bought A also tend to buy B, and you bought A, you will probably like B. That is
the whole idea, and it needs nothing but counting.

The oldest working recommender is also the most explainable: score an item by how much it
resembles the items this user already interacted with. No training loop, no gradients — just a
similarity matrix and a sparse product.

**Collaborative filtering** means learning from the behaviour of many users together, rather than
from descriptions of the items. A **neighbourhood** method is the simplest kind: an item's
**neighbours** are the items most often consumed by the same people.

> **Picture it:** a librarian who has never read a single book but has watched who borrows what for
> years. "People who borrowed this one usually borrowed those three" is a useful suggestion, and the
> librarian can always tell you *why*.

The setup is the same synthetic world as ch. 2: 2,500 users, 900 items in 6 genres, a 60-day
temporal holdout. `X` is the training interaction matrix in CSR form (ch. 1).

```python
import numpy as np
import pandas as pd
from scipy import sparse

rng = np.random.default_rng(0)
n_users, n_items = 2_500, 900
user_taste = rng.normal(0, 1, (n_users, 4))
genre = rng.integers(0, 6, n_items)
item_style = rng.normal(0, 1.4, (6, 4))[genre] + rng.normal(0, 0.35, (n_items, 4))
activity = rng.lognormal(-0.4, 1.0, n_users)
exposure = rng.lognormal(-1.0, 1.7, n_items) * np.where(genre == 0, 4.0, 1.0)

months = []
for month in range(12):
    user_taste = user_taste + rng.normal(0, 0.25, (n_users, 4))
    logit = (user_taste @ item_style.T / 2 - 4.0
             + np.log(activity)[:, None] + np.log(exposure)[None, :])
    r, c = np.nonzero(rng.random((n_users, n_items)) < 1 / (1 + np.exp(-logit)) / 12)
    months.append(pd.DataFrame({"user": r, "item": c,
                                "ts": month * 30 + rng.integers(0, 30, len(r))}))
events = pd.concat(months).sort_values("ts").reset_index(drop=True)

cut = events["ts"].max() - 60
train, test = events[events["ts"] <= cut], events[events["ts"] > cut]
X = sparse.csr_matrix((np.ones(len(train)), (train["user"], train["item"])),
                      shape=(n_users, n_items))
X.data[:] = 1.0
seen = {u: set(g) for u, g in train.groupby("user")["item"]}
truth = {u: set(g) for u, g in test.groupby("user")["item"]}
users = [u for u in truth if truth[u] and u in seen][:1_200]
pop = np.asarray(X.sum(axis=0)).ravel()
print(f"train matrix {X.shape}, {X.nnz:,} interactions | evaluating {len(users):,} users")
```

```output
train matrix (2500, 900), 90,508 interactions | evaluating 1,200 users
```

The training matrix holds 90,508 distinct user-item pairs, and every metric in this chapter is
averaged over the same 1,200 evaluation users. Next, a compact recall/NDCG scorer (the same
definitions as ch. 2) and the popularity baseline to beat.

```python
def recall_ndcg(score_fn, k=10):
    rec_scores, ndcgs = [], []
    for u in users:
        s = np.asarray(score_fn(u), dtype=float).copy()
        known = list(seen.get(u, ()))
        if known:
            s[known] = -np.inf
        top = np.argpartition(-s, k)[:k]
        top = top[np.argsort(-s[top])]
        rel = truth[u]
        hits = [i in rel for i in top]
        rec_scores.append(sum(hits) / min(k, len(rel)))
        dcg = sum(1 / np.log2(j + 2) for j, h in enumerate(hits) if h)
        idcg = sum(1 / np.log2(j + 2) for j in range(min(k, len(rel))))
        ndcgs.append(dcg / idcg)
    return float(np.mean(rec_scores)), float(np.mean(ndcgs))

r, n = recall_ndcg(lambda u: pop)
print(f"popularity baseline: recall@10 {r:.4f} | ndcg@10 {n:.4f}")
```

```output
popularity baseline: recall@10 0.0927 | ndcg@10 0.0819
```

Popularity scores recall@10 of 0.0927 and NDCG@10 of 0.0819. Every model below is judged
against those two numbers.

## Item-item similarity

Two items are similar if the same users touched both. Cosine similarity turns that into a number
between 0 and 1.

Cosine similarity between item columns, computed on the sparse matrix:

$$
\mathrm{sim}(i, j) = \frac{\mathbf{x}_i \cdot \mathbf{x}_j}{\|\mathbf{x}_i\| \, \|\mathbf{x}_j\|}
$$

> **In plain words:** $\mathbf{x}_i$ is item $i$'s column, a list with a 1 for every user who
> touched it. The top is the number of users who touched *both* items; the bottom divides by the
> square roots of each item's own user count. With 0/1 data, two items each touched by 100 users,
> 20 of them shared, have similarity $20 / (10 \times 10) = 0.2$.

and a user's score for item $j$ is the sum of similarities to the items they already have:

$$
\hat{s}(u, j) = \sum_{i \in I_u} \mathrm{sim}(i, j)
$$

> **In plain words:** $I_u$ is the set of items user $u$ already has. To score a candidate $j$, add
> up how similar $j$ is to each of them. A candidate that resembles many of the user's items gets a
> big total.

> **Picture it:** every item in your history casts a vote for each candidate, and its vote weighs as
> much as the two items are alike. The candidates with the most weighted votes win.

The block also tries **truncation**: keep only each item's top-$k$ most similar neighbours and set
the rest to zero.

```python
def item_cosine(X):
    norms = np.sqrt(np.asarray(X.multiply(X).sum(axis=0)).ravel())
    norms[norms == 0] = 1.0
    Xn = X.multiply(sparse.csr_matrix(1.0 / norms))
    S = (Xn.T @ Xn).toarray()
    np.fill_diagonal(S, 0.0)                       # an item is not its own neighbour
    return S

S_cos = item_cosine(X)
user_rows = X.tolil().rows

def knn_scores(S, k_neighbours=None):
    M = S
    if k_neighbours is not None:
        M = np.zeros_like(S)
        idx = np.argpartition(-S, k_neighbours, axis=1)[:, :k_neighbours]
        rows = np.repeat(np.arange(S.shape[0]), k_neighbours)
        M[rows, idx.ravel()] = S[rows, idx.ravel()]
    def score(u):
        items = user_rows[u]
        return M[items].sum(axis=0) if items else np.zeros(S.shape[1])
    return score

r, n = recall_ndcg(knn_scores(S_cos))
print(f"item-item cosine, all neighbours: recall@10 {r:.4f} | ndcg@10 {n:.4f}")
print(f"{'k neighbours':>13} {'recall@10':>11} {'ndcg@10':>9}")
for kn in (5, 20, 50, 200):
    r, n = recall_ndcg(knn_scores(S_cos, kn))
    print(f"{kn:>13} {r:>11.4f} {n:>9.4f}")
```

```output
item-item cosine, all neighbours: recall@10 0.1197 | ndcg@10 0.1037
 k neighbours   recall@10   ndcg@10
            5      0.1131    0.0988
           20      0.1140    0.0987
           50      0.1090    0.0959
          200      0.1135    0.0994
```

Here truncation *costs* accuracy: using all 899 neighbours scores 0.1037 NDCG, and every
truncation lands between 0.0959 and 0.0994. That is what a small catalogue looks like — with 900
items the far neighbours are weak but not misleading, and throwing them away discards signal.

Item-item with all neighbours already beats popularity clearly: 0.1197 against 0.0927 recall@10.

The picture inverts on a real catalogue. With a million items, the tail of the similarity row is
mostly noise from items that co-occur once or twice, the full matrix does not fit in memory, and
truncation becomes both necessary and helpful. Treat $k$ as a parameter you tune per dataset, not
as a rule, and know that its main job is compute.

> **Watch out:** a full item-item matrix has (number of items)$^2$ cells. At 900 items that is
> 810,000 floats; at a million items it is $10^{12}$, about 8 TB. Production systems store only the
> top neighbours per item for that reason.

## Popularity leaks into similarity

A blockbuster sits in almost everyone's history, so it ends up "similar" to almost everything.
Two pairs that look equally similar can rest on 2 shared users or on 200, and only the second
deserves trust.

Raw co-occurrence counts make popular items look similar to *everything*, because they co-occur
with everything. Two standard fixes: shrink by the co-occurrence count, and down-weight popular
items before computing similarity.

A **co-occurrence count** $c_{ij}$ is the number of users who touched both items. **Shrinkage**
pulls a similarity towards zero when it rests on little evidence:

$$
\mathrm{sim}_{\text{shrunk}}(i,j) = \frac{c_{ij}}{c_{ij} + \lambda}\,\mathrm{sim}(i,j)
$$

> **In plain words:** multiply the similarity by $c_{ij} / (c_{ij} + \lambda)$. With $\lambda = 5$,
> a pair backed by 5 shared users keeps half its similarity, and a pair backed by 95 keeps 95%.
> $\lambda$ is the number of shared users at which you trust a similarity halfway.

> **Picture it:** two restaurant reviews of 5 stars, one from a single reviewer and one averaged
> over 200. Shrinkage is your instinct to discount the first.

```python
C = (X.T @ X).toarray()                            # co-occurrence counts
np.fill_diagonal(C, 0.0)

def shrink(S, C, lam):
    return S * (C / (C + lam))

print(f"{'lambda':>8} {'recall@10':>11} {'ndcg@10':>9}")
for lam in (0, 1, 5, 25, 100):
    r, n = recall_ndcg(knn_scores(shrink(S_cos, C, lam) if lam else S_cos, 50))
    print(f"{lam:>8} {r:>11.4f} {n:>9.4f}")

top_pop = int(np.argmax(pop))
niche = int(np.argsort(pop)[len(pop) // 10])
for label, item in (("most popular", top_pop), ("niche", niche)):
```

## TF-IDF and BM25 weighting

Liking something everybody likes says little about you; liking something obscure says a lot. So
weight each interaction by how rare the item is, before measuring similarity.

The same idea applied before the similarity: weight each interaction by how informative it is.
A user's interaction with an obscure item says more about their taste than an interaction with the
most popular item in the catalogue.

Both schemes come from text search. **IDF** (inverse document frequency) multiplies each item's
column by roughly $\log(N / \text{df})$, where df is how many users touched the item and $N$ is the number
of users: rare items get big weights. **BM25** adds a second correction: it shrinks the weight of
interactions from users with very long histories, using `k1` to cap how much repeats count and `b`
to set how strongly to normalise by history length.

```python
def idf_weight(X):
    df = np.asarray((X > 0).sum(axis=0)).ravel()
    idf = np.log((X.shape[0] + 1) / (df + 1))
    return X.multiply(sparse.csr_matrix(idf)).tocsr()

def bm25_weight(X, k1=1.2, b=0.75):
    df = np.asarray((X > 0).sum(axis=0)).ravel()
    idf = np.log((X.shape[0] - df + 0.5) / (df + 0.5) + 1)
    length = np.asarray(X.sum(axis=1)).ravel()
    avg = length.mean()
    Xc = X.tocoo()
    denom = Xc.data + k1 * (1 - b + b * length[Xc.row] / avg)
    data = Xc.data * (k1 + 1) / denom * idf[Xc.col]
    return sparse.csr_matrix((data, (Xc.row, Xc.col)), shape=X.shape)

variants = {"raw counts": X, "TF-IDF": idf_weight(X), "BM25": bm25_weight(X)}
print(f"{'weighting':>12} {'recall@10':>11} {'ndcg@10':>9}")
for name, Xw in variants.items():
    S = item_cosine(Xw)
    r, n = recall_ndcg(knn_scores(shrink(S, C, 5), 50))
    print(f"{name:>12} {r:>11.4f} {n:>9.4f}")
```

```output
   weighting   recall@10   ndcg@10
  raw counts      0.1117    0.0976
      TF-IDF      0.1117    0.0976
        BM25      0.1186    0.1026
```

TF-IDF changes **nothing** — 0.0976, identical to raw counts to four decimals — and that is not a
bug. IDF multiplies each item's column by a constant, and cosine similarity divides each column by
its norm, so the constant cancels exactly. Column-wise reweighting is invisible to cosine.

BM25 does help (+0.0050 NDCG) because it does something IDF cannot: its `b` term normalises by
**row** length, damping users with hundreds of interactions so they stop dominating every
similarity they participate in. When you reach for a weighting scheme, check whether it survives
your similarity function's normalisation before you attribute a gain to it.

> **Watch out:** "we added IDF weighting and nothing changed" usually means the similarity already
> normalises columns. It is a sign to think about the maths, not to tune the IDF formula.

## User-user, and when to prefer it

Flip the question around: find the people most like this user, and recommend what they liked.

The transpose of the same algorithm: find users like this one, recommend what they liked.

$$
\hat{s}(u, j) = \sum_{v \in N(u)} \mathrm{sim}(u, v)\, x_{vj}
$$

> **In plain words:** $N(u)$ is the set of the user's nearest neighbours (here, the 50 most
> similar users by cosine). Each neighbour $v$ adds $\mathrm{sim}(u, v)$ to every item they touched
> ($x_{vj}$ is 1 if $v$ touched $j$). Items liked by many close neighbours score highest.

> **Picture it:** item-item asks "what is like the things you own?"; user-user asks "what do people
> like you own?". Same table, read across rows instead of down columns.

```python
def user_cosine(X):
    norms = np.sqrt(np.asarray(X.multiply(X).sum(axis=1)).ravel())
    norms[norms == 0] = 1.0
    Xn = sparse.diags(1.0 / norms) @ X
    return Xn, norms

Xn, _ = user_cosine(X)

def user_user_scores(k_neighbours=50):
    def score(u):
        sims = np.asarray((Xn @ Xn[u].T).todense()).ravel()
        sims[u] = 0.0
        nb = np.argpartition(-sims, k_neighbours)[:k_neighbours]
        return np.asarray(X[nb].T @ sims[nb]).ravel()
    return score

r_uu, n_uu = recall_ndcg(user_user_scores(50))
r_ii, n_ii = recall_ndcg(knn_scores(shrink(item_cosine(bm25_weight(X)), C, 5), 50))
print(f"user-user (k=50): recall@10 {r_uu:.4f} | ndcg@10 {n_uu:.4f}")
print(f"item-item (BM25): recall@10 {r_ii:.4f} | ndcg@10 {n_ii:.4f}")
print(f"\nsimilarity matrix sizes: item-item {n_items ** 2:,} cells | "
      f"user-user {n_users ** 2:,} cells")
```

```output
user-user (k=50): recall@10 0.1212 | ndcg@10 0.1049
item-item (BM25): recall@10 0.1186 | ndcg@10 0.1026

similarity matrix sizes: item-item 810,000 cells | user-user 6,250,000 cells
```

On this data they are within 0.0023 NDCG of each other — 0.1049 for user-user against 0.1026 for
item-item — so the choice is decided by shape and by churn, not by accuracy. **Item-item wins when
there are fewer items than users** (the similarity matrix is smaller and can be precomputed), and when
item catalogues change slowly while user histories change constantly — a user's recommendations
update the moment they click, with no retraining, because their score is just a fresh sum over the
same item matrix.

The last line makes the size argument concrete: 810,000 item-item cells against 6,250,000
user-user cells, almost eight times as many, because there are 2,500 users and only 900 items.

## Recap in plain words

- Neighbourhood CF scores a candidate by adding up its similarity to everything the user already has.
- Cosine similarity on the interaction matrix needs no training, only counting and a sparse product.
- Popular items look similar to everything; shrinkage and BM25 weighting counter that.
- IDF does nothing under cosine, because cosine divides out any per-item constant.
- User-user and item-item score about the same here; item-item is cheaper when items are fewer than users.
- Truncating to the top neighbours is mainly a compute saving; tune it per dataset.

## Try it Yourself

Every score is a sum of per-item contributions, so you can print the top contributors as the
"because of" explanation. The block does that for two users.

```python
def explain(u, k=5, k_neighbours=50):
    S = shrink(item_cosine(bm25_weight(X)), C, 5)
    score = knn_scores(S, k_neighbours)
    s = score(u).copy()
    s[list(seen[u])] = -np.inf
    top = np.argsort(-s)[:k]
    print(f"user {u} has {len(seen[u])} training items, genres "
          f"{sorted({int(genre[i]) for i in seen[u]})}")
    for item in top:
        contrib = [(float(S[j, item]), int(j)) for j in seen[u]]
        contrib.sort(reverse=True)
        why = ", ".join(f"item {j} ({c:.3f})" for c, j in contrib[:3])
        print(f"  recommend {int(item):>3} (genre {int(genre[item])}, score {s[item]:.3f}) "
              f"because of {why}")

explain(users[0])
print()
explain(users[1])
```

```python
def build_itemknn(X, weighting="bm25", lam=5.0, k_neighbours=50):
    Xw = {"raw": X, "idf": idf_weight(X), "bm25": bm25_weight(X)}[weighting]
    S = item_cosine(Xw)
    if lam:
        S = S * (C / (C + lam))
    if k_neighbours:
        M = np.zeros_like(S)
        idx = np.argpartition(-S, k_neighbours, axis=1)[:, :k_neighbours]
        rows = np.repeat(np.arange(S.shape[0]), k_neighbours)
        M[rows, idx.ravel()] = S[rows, idx.ravel()]
        S = M
    return S

def full_metrics(score_fn, k=10):
    shown, recs, ndcgs, pops = set(), [], [], []
    for u in users:
        s = np.asarray(score_fn(u), dtype=float).copy()
        s[list(seen[u])] = -np.inf
        top = np.argpartition(-s, k)[:k]
        top = top[np.argsort(-s[top])]
        shown.update(int(i) for i in top)
        rel = truth[u]
        hits = [i in rel for i in top]
        recs.append(sum(hits) / min(k, len(rel)))
        dcg = sum(1 / np.log2(j + 2) for j, h in enumerate(hits) if h)
        ndcgs.append(dcg / sum(1 / np.log2(j + 2) for j in range(min(k, len(rel)))))
        pops.append(float(np.mean(pop[top])))
    return {"recall@10": round(float(np.mean(recs)), 4),
            "ndcg@10": round(float(np.mean(ndcgs)), 4),
            "coverage": round(len(shown) / n_items, 4),
            "mean pop of recs": round(float(np.mean(pops)), 1)}

rows = []
for weighting in ("raw", "idf", "bm25"):
    for lam in (0.0, 5.0):
        for kn in (20, 100):
            S = build_itemknn(X, weighting, lam, kn)
            m = full_metrics(knn_scores(S, None))
            rows.append({"weighting": weighting, "shrink": lam, "k": kn, **m})
table = pd.DataFrame(rows).sort_values("ndcg@10", ascending=False)
print(table.to_string(index=False))

best = table.iloc[0]
S_best = build_itemknn(X, best["weighting"], best["shrink"], int(best["k"]))
base = full_metrics(lambda u: pop)
print(f"\npopularity baseline: {base}")
print(f"best item-kNN     : {full_metrics(knn_scores(S_best, None))}")

# how much of the gain is just popularity? score the recommendations' popularity rank
best_score = knn_scores(S_best, None)
corr = []
for u in users[:300]:
    s = best_score(u)
    corr.append(float(np.corrcoef(s, pop)[0, 1]))
print(f"\nmean correlation between the model's scores and raw popularity: "
      f"{np.mean(corr):.4f}")
```

Read the table by column, not by row. **Weighting** dominates: every BM25 row sits above every
non-BM25 row, and raw and IDF match each other row for row (up to one floating-point tie in the
fourth decimal) for the reason above. **Neighbourhood size** is next, with 20 beating 100
everywhere. **Shrinkage** is the smallest effect, and its sign depends on the weighting: under
BM25, `shrink=0` wins at both neighbourhood sizes (0.1069 against 0.1055 at $k = 20$), while for
raw and IDF weighting `shrink=5` wins at both (0.0997 against 0.0987 at $k = 20$). BM25 already
damps the heavy users whose co-occurrences shrinkage is meant to discount, so the two corrections
overlap. On a sparser catalogue shrinkage matters more, which is exactly why it is in the grid
rather than in the defaults.

Notice the tension in the last two columns. The best configuration recommends *less* popular items
than the baseline (533 against 648 mean popularity) while covering five times as much of the
catalogue (0.151 against 0.030). Both of those are improvements the accuracy column alone would
not have shown you.

The last number is the one to keep in your head, and it is uncomfortable: **0.71**. Even the best
configuration's scores correlate strongly with raw popularity, so a meaningful share of its
advantage is popularity that the similarity matrix has re-derived. It still beats the popularity
baseline by 0.025 NDCG and covers five times the catalogue, so it is doing real work — but a
product that already promotes popular items elsewhere on the page will see less of that gain than
the offline number promises. It
is the cheapest available check for "is this actually personalised", and it costs one line.

Two properties of this family worth remembering when you meet the matrix-factorisation models in
the next chapter. Item-kNN has **no training step** — every number in it is a count — so it
updates incrementally as interactions arrive and never goes stale between retrains. And it has a
hard floor: an item with no co-occurrences has no neighbours and can never be recommended, which
is the cold-start failure chapter 9 exists to fix and which no amount of tuning here will touch.
