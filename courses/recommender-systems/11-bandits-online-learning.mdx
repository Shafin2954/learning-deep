## The log only shows what the old policy chose

Every model in chapters 3–10 was trained on interactions that a previous recommender caused. An
item the old system never showed has no clicks, so it looks bad, so the new model never shows it
either. Offline metrics cannot see the problem, because the held-out data was produced by the same
loop (ch. 1, ch. 2). Simulate it: 200 items, a hidden CTR for each, and an inherited log in which
the previous system only ever exposed 40 of them.

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
n_items = 200
true_ctr = rng.beta(1.5, 40, n_items)
old_favourites = rng.choice(n_items, 40, replace=False)    # the old system only ever showed these
best10 = np.argsort(-true_ctr)[:10]

def run_loop(policy, days=30, users=2_000, k=5, eps=0.0, seed=0):
    r = np.random.default_rng(seed)
    imps = np.zeros(n_items)
    imps[old_favourites] = r.integers(20, 400, 40)
    clicks = r.binomial(imps.astype(int), true_ctr).astype(float)
    rows = []
    for day in range(1, days + 1):
        score = clicks if policy == "popularity" else (clicks + 1) / (imps + 30)
        shown = np.tile(np.argsort(-score)[:k], (users, 1))      # same top-k for everyone
        explore = r.random(shown.shape) < eps
        shown[explore] = r.integers(0, n_items, explore.sum())   # random slots, if any
        c = r.random(shown.shape) < true_ctr[shown]
        np.add.at(imps, shown.ravel(), 1)
        np.add.at(clicks, shown.ravel(), c.ravel())
        if day in (1, 3, 10, 30):
            top5 = np.argsort(-((clicks + 1) / (imps + 30)))[:5]
            rows.append({"policy": policy + (f" + {eps:.0%} random" if eps else ""), "day": day,
                         "true CTR shown": true_ctr[shown].mean(),
                         "items shown": len(np.unique(shown)),
                         "best-10 ever shown": int((imps[best10] > 0).sum()),
                         "best-10 in top-5": len(set(top5) & set(best10))})
    return rows

print(f"catalogue mean CTR {true_ctr.mean():.4f} | oracle top-5 CTR {np.sort(true_ctr)[-5:].mean():.4f}")
print(f"of the 10 truly best items, the old system showed {len(set(best10) & set(old_favourites))}")
rows = run_loop("popularity") + run_loop("greedy CTR") + run_loop("greedy CTR", eps=0.05)
print(pd.DataFrame(rows).to_string(index=False, float_format="%.4f"))
```

None of the 10 truly best items is in the inherited log, and neither deterministic policy ever
finds one. Popularity freezes on five items at 0.0669; ranking by smoothed CTR is no better
(0.0699), because an unseen item scores the prior $1/30$, below every proven item. Both collapse the
40 exposed items to 5, and 10,000 impressions a day carry no information about the other 195.

Replacing 5% of slots with random items costs a little on day 3 (0.0633), then lifts CTR to 0.0982,
40% above the greedy ranker, once four of the best ten reach the top five. That 5% is paid every
day, forever. The rest of this chapter is about paying less for the same information, and about
measuring a policy from logs without deploying it.

## A quick recap of the non-contextual bandit

The basics are in (Reinforcement Learning, ch. 2): $\varepsilon$-greedy, UCB1 with bonus
$\sqrt{2\ln t / N_a}$, and Thompson sampling from a Beta posterior. What changes in a recommender is
the regime. There are hundreds of arms, rewards are clicks with means of a few percent, and every
impression spent exploring is a real user shown something worse. Run the three algorithms on the
200 items above, one slot per request.

```python
def bernoulli_bandit(algo, p, T=50_000, seed=0, eps=0.05):
    r = np.random.default_rng(seed)
    K = len(p)
    n, s, regret = np.zeros(K), np.zeros(K), np.zeros(T)
    for t in range(T):
        if algo == "eps-greedy":
            a = r.integers(K) if r.random() < eps else np.argmax((s + 1) / (n + 2))
        elif algo == "UCB1":
            a = t if t < K else np.argmax(s / n + np.sqrt(2 * np.log(t) / n))
        else:                                                    # Thompson, Beta(1, 1) prior
            a = np.argmax(r.beta(s + 1, n - s + 1))
        n[a] += 1
        s[a] += r.random() < p[a]
        regret[t] = p.max() - p[a]
    return np.cumsum(regret)

checks = [1_000, 5_000, 20_000, 50_000]
table = {algo: bernoulli_bandit(algo, true_ctr)[np.array(checks) - 1]
         for algo in ("eps-greedy", "UCB1", "Thompson")}
print("cumulative regret (expected clicks lost vs always showing the best item)")
print(pd.DataFrame(table, index=[f"T={c:,}" for c in checks]).round(1).to_string())
```

```output

T=20,000       292.6  1752.6    1278.8
T=50,000       445.4  4255.7    1958.3
```

Two results go against the textbook ordering. UCB1 is worst by far (4,256 clicks lost): its
Hoeffding bonus assumes rewards spread over $[0, 1]$, but a 4% click has standard deviation
$\sqrt{0.04 \cdot 0.96} \approx 0.2$, so it keeps re-checking items it already knows are bad.
KL-UCB and UCB-V use the variance and fix this; Thompson sampling is calibrated to Bernoulli
rewards by construction. And $\varepsilon$-greedy wins only because $(s+1)/(n+2)$ scores an
untried item at 0.5, which is the optimistic initialisation of RL ch. 2. Its fixed 5% still costs
linear regret (153 clicks between 20k and 50k).

The structural lesson: each algorithm learns every item separately, so exploration cost scales
with the catalogue, and one non-personalised arm is the best it can converge to.

## Contextual bandits: let the features share the exploration

A **contextual bandit** observes a context $x_t$ (user features, time, device), picks an arm
$a_t$, and sees only that arm's reward. Its regret is measured against the best arm *for that
context*, not the best arm overall. The environment below has 30 items with item features, users
with 5 features, and a logistic click model whose interaction term $x^\top B f_a$ makes different
users prefer different items. LinUCB will model it linearly, so the model is deliberately a little
misspecified, as real models are.

```python
rng = np.random.default_rng(1)
K, d_u, d_i = 30, 6, 5
item_feat = np.c_[np.ones(K), rng.normal(0, 1, (K, d_i - 1))]      # [1, 4 item attributes]
B = rng.normal(0, 0.45, (d_u, d_i))
B[0] = [-3.6, 0.2, -0.1, 0.15, 0.1]                                  # weak item main effects
theta_true = item_feat @ B.T                                          # (K, d_u): one theta per arm

def draw_users(n, r):
    return np.c_[np.ones(n), r.normal(0, 1, (n, d_u - 1))]          # [1, 5 user features]

def click_prob(X):
    return 1 / (1 + np.exp(-(X @ theta_true.T)))                      # (n, K), logistic truth

Xpop = draw_users(100_000, rng)
P = click_prob(Xpop)
print(f"CTR of a random item     {P.mean():.4f}")
print(f"best single item for all {P.mean(0).max():.4f}")
print(f"best item per user       {P.max(1).mean():.4f}   <- the prize for personalising")
```

```output
CTR of a random item     0.0515
best single item for all 0.1046
best item per user       0.2385   <- the prize for personalising
```

Personalising is worth more than doubling the CTR: 0.2385 against 0.1046. The non-contextual
algorithms above can at best converge to the 0.1046 row.

### Deriving the LinUCB bonus

Disjoint LinUCB (Li et al., 2010) fits one ridge regression per arm. After the arm has been
played on contexts $X_a$ with rewards $y_a$:

$$
A_a = \lambda I + X_a^\top X_a, \qquad b_a = X_a^\top y_a, \qquad \hat\theta_a = A_a^{-1} b_a
$$

Assume $y = X_a\theta_a + \varepsilon$ with independent noise of variance $\sigma^2$. Substitute and
separate the error:

$$
\hat\theta_a - \theta_a = A_a^{-1}X_a^\top\varepsilon - \lambda A_a^{-1}\theta_a
$$

The second term is the ridge bias. The first has covariance
$\sigma^2 A_a^{-1}X_a^\top X_a A_a^{-1} \preceq \sigma^2 A_a^{-1}$, because
$X_a^\top X_a = A_a - \lambda I \preceq A_a$. The prediction error for a new context therefore
satisfies

$$
\operatorname{sd}\bigl(x^\top\hat\theta_a - x^\top\theta_a\bigr) \le \sigma\sqrt{x^\top A_a^{-1}x} = \sigma\,\lVert x\rVert_{A_a^{-1}}
$$

The geometric reading is that $\theta_a$ lies, with high probability, in the ellipsoid
$\{\theta : (\theta-\hat\theta_a)^\top A_a(\theta-\hat\theta_a) \le \beta\}$. By Cauchy–Schwarz in the
$A_a$ inner product, the largest value of $x^\top\theta$ over that ellipsoid is
$x^\top\hat\theta_a + \sqrt{\beta}\,\lVert x\rVert_{A_a^{-1}}$. That is the LinUCB score:

$$
a_t = \arg\max_a \Bigl[\, x_t^\top\hat\theta_a + \alpha\sqrt{x_t^\top A_a^{-1}x_t} \,\Bigr]
$$

The bonus is large in directions of feature space the arm has not been tried in, not merely for
arms tried rarely, so a user who resembles earlier clickers stops costing exploration. The bound
ignores the ridge bias $\lambda A_a^{-1}\theta_a$; the theoretical radius of Abbasi-Yadkori et al.
(2011), $\sqrt{\beta_t} = \sigma\sqrt{d\log((1 + t/\lambda)/\delta)} + \sqrt{\lambda}\lVert\theta\rVert$,
adds a term for it and is too conservative to use in practice, so $\alpha$ is tuned instead.

Updates use Sherman–Morrison, so a click costs $O(d^2)$ instead of a $d \times d$ inversion:

$$
(A + xx^\top)^{-1} = A^{-1} - \frac{A^{-1}xx^\top A^{-1}}{1 + x^\top A^{-1}x}
$$

### Linear Thompson sampling

With a Gaussian prior $\theta_a \sim \mathcal{N}(0, \tfrac{v^2}{\lambda}I)$ and Gaussian noise of
variance $v^2$, the posterior is exactly $\mathcal{N}(\hat\theta_a, v^2A_a^{-1})$, the same quantities
LinUCB keeps. Linear Thompson sampling (Agrawal and Goyal, 2013) draws $\tilde\theta_a$ from the
posterior and plays $\arg\max_a x_t^\top\tilde\theta_a$. Each arm's score depends only on the scalar
$x_t^\top\tilde\theta_a \sim \mathcal{N}\bigl(x_t^\top\hat\theta_a,\; v^2 x_t^\top A_a^{-1}x_t\bigr)$,
so you can sample that scalar directly: $K$ normal draws per request instead of $K$ Cholesky
factorisations. The two algorithms then differ only in replacing the constant $\alpha$ with
$v\,z_a$, where $z_a \sim \mathcal{N}(0,1)$.

```python
def run_contextual(algo, T=20_000, alpha=1.0, v=0.5, lam=1.0, seed=0):
    r = np.random.default_rng(seed)
    X = draw_users(T, r)
    Pt, U = click_prob(X), r.random(T)
    A_inv = np.tile(np.eye(d_u) / lam, (K, 1, 1))
    b = np.zeros((K, d_u))
    n, s, regret, reward = np.zeros(K), np.zeros(K), np.zeros(T), np.zeros(T)
    for t in range(T):
        x = X[t]
        if algo == "random":
            a = r.integers(K)
        elif algo == "Thompson (no context)":
            a = np.argmax(r.beta(s + 1, n - s + 1))
        else:
            mean = np.einsum("kij,kj->ki", A_inv, b) @ x
            width = np.sqrt(np.einsum("i,kij,j->k", x, A_inv, x))
            if algo == "LinUCB":
                a = np.argmax(mean + alpha * width)
            else:                                   # LinTS: x.theta_a ~ N(mean_a, v^2 width_a^2)
                a = np.argmax(mean + v * width * r.standard_normal(K))
        y = float(U[t] < Pt[t, a])
        n[a] += 1
        s[a] += y
        Ax = A_inv[a] @ x                           # Sherman-Morrison: O(d^2), no inversion
        A_inv[a] -= np.outer(Ax, Ax) / (1 + x @ Ax)
        b[a] += y * x
        regret[t], reward[t] = Pt[t].max() - Pt[t, a], y
    return np.cumsum(regret), np.einsum("kij,kj->ki", A_inv, b), reward

checks = [1_000, 5_000, 10_000, 20_000]
res = {}
for algo, kw in (("random", {}), ("Thompson (no context)", {}), ("LinUCB", {"alpha": 0.0}),
                 ("LinUCB", {"alpha": 0.5}), ("LinUCB", {"alpha": 1.0}),
                 ("LinTS", {"v": 0.1}), ("LinTS", {"v": 0.25})):
    name = algo + "".join(f" {k}={val}" for k, val in kw.items())
    R, _, rew = run_contextual(algo, **kw)
    res[name] = [R[c - 1] for c in checks] + [rew[-5_000:].mean()]
print(pd.DataFrame(res, index=[f"regret@{c:,}" for c in checks] + ["CTR last 5k"]).T
      .to_string(float_format=lambda v: f"{v:.4f}" if v < 1 else f"{v:.1f}"))
```

The ranking is clear. Both linear bandits reach a CTR of about 0.22 out of a possible 0.2385, more

and its CTR of 0.0818 is below the best single item. It locks onto whichever arms happened to pay

LinTS trails LinUCB (755 against 649 at its best $v$) and is more sensitive to its scale, which
matches practice: Thompson sampling usually needs its posterior shrunk well below the "correct"
variance. This is one seed; gaps of ~100 between tuned variants are noise, gaps of thousands are not.

## Off-policy evaluation: scoring a policy you never ran

Each experiment above was run online. In production you have logs from the current policy
$\mu$ and a candidate $\pi$, and you want $V(\pi) = \mathbb{E}_x\bigl[\bar r(x, \pi(x))\bigr]$, its
expected CTR, before you expose real users to it. The candidate here is the greedy policy implied by
what LinUCB learned, and the simulator gives its true value.

```python
_, theta_lin, _ = run_contextual("LinUCB", alpha=0.5)

def target_policy(X):                               # deterministic: greedy on what LinUCB learned
    return np.argmax(X @ theta_lin.T, axis=1)

V_true = P[np.arange(len(Xpop)), target_policy(Xpop)].mean()
print(f"true CTR of the target policy (100k simulated users): {V_true:.4f}")
```

```output
true CTR of the target policy (100k simulated users): 0.2211
```

### The replay method

Li et al. (2011) evaluated news bandits on Yahoo! front-page logs served **uniformly at random**.
Then $P(a_{\log} = \pi(x)) = 1/K$ for every $x$, so the events where the logged arm agrees with
the policy are an unbiased sample of $(x, \pi(x), r)$: discard the rest and average. A *learning*
policy is replayed the same way, updating only on matched events; the retained stream has the
distribution of an online run of that length.

```python
r = np.random.default_rng(5)
n_log = 60_000
Xl = draw_users(n_log, r)
Al = r.integers(0, K, n_log)                                   # uniformly random logging
Rl = (r.random(n_log) < click_prob(Xl)[np.arange(n_log), Al]).astype(float)
match = target_policy(Xl) == Al
print(f"fixed policy: {match.sum():,} of {n_log:,} events match | replay CTR "
      f"{Rl[match].mean():.4f} +/- {Rl[match].std() / np.sqrt(match.sum()):.4f} (truth {V_true:.4f})")
```

```output
fixed policy: 2,045 of 60,000 events match | replay CTR 0.2166 +/- 0.0091 (truth 0.2211)
```

2,045 events survive, close to $60{,}000/30$, and the estimate is within one standard error of the
truth. The price: a fraction $(K-1)/K$ of the data is discarded, and you need uniformly random
logging, which you rarely have. The estimators below accept any logging policy whose propensities
were recorded.

### Inverse propensity scoring is unbiased

Log the propensity $\mu(a_i \mid x_i)$ with every impression. The IPS estimator reweights each
logged reward by how much more (or less) often $\pi$ would have taken that action:

$$
\hat V_{\text{IPS}} = \frac{1}{n}\sum_{i=1}^n \frac{\pi(a_i \mid x_i)}{\mu(a_i \mid x_i)}\, r_i
$$

It is unbiased. Condition on $x$, take the expectation over $a \sim \mu(\cdot \mid x)$ and the
reward:

$$
\mathbb{E}\!\left[\frac{\pi(a \mid x)}{\mu(a \mid x)}\, r \,\middle|\, x\right]
= \sum_a \mu(a \mid x)\,\frac{\pi(a \mid x)}{\mu(a \mid x)}\,\bar r(x, a)
= \sum_a \pi(a \mid x)\,\bar r(x, a)
$$

Averaging over $x$ gives $V(\pi)$. The single condition is **support**: wherever
$\pi(a \mid x) > 0$, $\mu(a \mid x)$ must be positive, so the logging policy has to explore. A
deterministic production ranker cannot be evaluated off-policy at all. Replay is the special case
$\mu = 1/K$.

The price is variance. For a deterministic $\pi$ the second moment is
$\mathbb{E}_x\bigl[\bar r^{(2)}(x, \pi(x)) / \mu(\pi(x) \mid x)\bigr]$, which grows with the
*inverse* propensity of the action $\pi$ wants. One logged event with $\mu = 10^{-3}$ that happens
to be a click contributes 1,000 times its fair share. The **effective sample size**
$\bigl(\sum_i w_i\bigr)^2 / \sum_i w_i^2$ tells you how many unweighted samples your estimate is
actually worth.

### Self-normalised and doubly robust estimators

**Self-normalised IPS** divides by the realised total weight instead of $n$:
$\hat V_{\text{SNIPS}} = \sum_i w_i r_i / \sum_i w_i$. Since $\mathbb{E}[w] = 1$, the denominator
estimates $n$. It is biased by $O(1/n)$, it is invariant to adding a constant to all rewards, and it
usually has much lower variance.

The **direct method** fits a reward model $\hat q(x, a)$ and averages $\hat q(x, \pi(x))$. It has
low variance and is biased by whatever the model gets wrong, including extrapolation to actions the
logger rarely took. **Doubly robust** (Dudík et al., 2011) uses the model and corrects its residual
with IPS:

$$
\hat V_{\text{DR}} = \frac{1}{n}\sum_{i=1}^n \Bigl[\hat q\bigl(x_i, \pi(x_i)\bigr) + w_i\bigl(r_i - \hat q(x_i, a_i)\bigr)\Bigr]
$$

If the propensities are right, the correction term has expectation
$\mathbb{E}_x\bigl[\bar r(x, \pi(x)) - \hat q(x, \pi(x))\bigr]$ (by the IPS argument), which cancels
the model's bias exactly. If instead the model is right, $\mathbb{E}[r - \hat q(x, a) \mid x, a] = 0$
for any weights. Either one being correct is enough. Now compare all four as the logging
policy gets more peaked (larger $\beta$, so less exploration):

```python
theta_rough = theta_true + np.random.default_rng(7).normal(0, 0.4, theta_true.shape)

def logging_probs(X, beta):                         # softmax of an imperfect ranker's logits
    z = beta * (X @ theta_rough.T)
    e = np.exp(z - z.max(1, keepdims=True))
    return e / e.sum(1, keepdims=True)

def simulate_log(n, beta, r):
    X = draw_users(n, r)
    mu = logging_probs(X, beta)
    A = (mu.cumsum(1) > r.random((n, 1))).argmax(1)
    R = (r.random(n) < click_prob(X)[np.arange(n), A]).astype(float)
    return X, A, mu[np.arange(n), A], R

def ope(X, A, p, R, lam=1.0):
    pi_a = target_policy(X)
    w = (pi_a == A) / p                                         # importance weights
    th = np.zeros((K, d_u))                                     # direct method: ridge per arm
    for a in range(K):
        m = A == a
        th[a] = np.linalg.solve(X[m].T @ X[m] + lam * np.eye(d_u), X[m].T @ R[m])
    q_pi, q_log = (X * th[pi_a]).sum(1), (X * th[A]).sum(1)
    return {"DM": q_pi.mean(), "IPS": (w * R).mean(), "SNIPS": (w * R).sum() / w.sum(),
            "DR": (q_pi + w * (R - q_log)).mean(), "ESS": w.sum() ** 2 / (w ** 2).sum(),
            "max w": w.max()}

rows = []
for beta in (0.0, 1.0, 2.0, 4.0):
    r = np.random.default_rng(11)
    out = pd.DataFrame([ope(*simulate_log(3_000, beta, r)) for _ in range(200)])
    row = {"beta": beta, "ESS": f"{out['ESS'].mean():.0f}", "max w": f"{out['max w'].max():.0f}"}
    for e in ("DM", "IPS", "SNIPS", "DR"):
        row[e + " bias / sd"] = f"{out[e].mean() - V_true:+.4f} / {out[e].std():.4f}"
    rows.append(row)
print(f"200 logs of 3,000 events each; target value {V_true:.4f}")
print(pd.DataFrame(rows).to_string(index=False))
```

Read down the IPS column. As logging gets greedier the largest weight goes from 30 to 10,095 and
the standard deviation from 0.028 to 0.157: at $\beta = 4$ one 3,000-event log can miss by more than
the value itself. IPS stays unbiased (every bias is under 0.01), which is no comfort when you have one
log. SNIPS roughly halves the spread at $\beta \ge 2$.

The direct method is the mirror image: the largest bias in the table under uniform logging
($-0.047$, a linear model of a logistic truth underestimates exactly the high-CTR pairs the target
picks) but a standard deviation never above 0.017, so at $\beta = 4$ the *biased* DM has the lowest
error. DR beats IPS everywhere and is best for $\beta \le 2$; at $\beta = 4$ it inherits the
weights through $w_i(r_i - \hat q)$ and loses to SNIPS (0.100 against 0.079), which is why SWITCH,
clipped DR and MRDR exist. Practical rules: always log propensities, and keep enough randomisation in
production that the policies you will want to evaluate have support.

## Slates and position bias

A real recommender shows a ranked **slate**, so a click depends on the position as well as the item.
Under the position-based model

$$
P(\text{click} \mid i, k) = \underbrace{P(\text{examined} \mid k)}_{\theta_k}\cdot \underbrace{P(\text{relevant} \mid i)}_{\rho_i}
$$

so naive CTR estimates $\theta_k\rho_i$, and an item the old ranker kept at slot 6 looks a quarter
as good as it is; train on it and the next ranker keeps it there. If the $\theta_k$ are known
(estimated from small randomised swaps of adjacent results, Joachims et al., 2017), weighting each
click by $1/\theta_k$ is IPS again with position as the action, and $\sum \text{clicks}_i / \sum_k \theta_{k}$
over the item's impressions is unbiased for $\rho_i$, with the familiar variance cost at low slots.
Full slate OPE is harder, because the action space is every ordered list: the **pseudo-inverse
estimator** (Swaminathan et al., 2017) assumes the slate reward is additive over positions, and
**cascading bandits** model a user scanning top-down and stopping at the first click. Both reduce a
combinatorial action space to per-position quantities.

## Running a bandit in production

**Exploration budget.** Exploration is spent on real users; cap it as a traffic percentage (the 5%
above) or as a regret guardrail against the current policy (conservative bandits), and report it.
**Delayed and batched feedback.** Conversions arrive days later and models refresh hourly; within one
refresh a deterministic UCB serves the same arm to everyone, while Thompson keeps randomising.
**Non-stationarity.** Items age and tastes drift. **Discounting** multiplies counts by $\gamma$ each
step (memory $1/(1-\gamma)$); a **sliding window** keeps only the last $W$ events.

```python
from collections import deque

def bandit_run(algo, p_before, p_after=None, T=40_000, gamma=1.0, window=None, batch=1, seed=0):
    r = np.random.default_rng(seed)
    K_ = len(p_before)
    n, s = np.zeros(K_), np.zeros(K_)
    seen_n, seen_s = n.copy(), s.copy()                 # what the policy sees (stale if batched)
    hist, reg = deque(), np.zeros(T)
    for t in range(T):
        p = p_before if p_after is None or t < T // 2 else p_after
        if algo == "UCB1":
            a = (int(np.argmin(seen_n)) if seen_n.min() == 0 else
                 np.argmax(seen_s / seen_n + np.sqrt(2 * np.log(t + 1) / seen_n)))
        else:
            a = np.argmax(r.beta(seen_s + 1, seen_n - seen_s + 1))
        y = r.random() < p[a]
        n *= gamma                                      # discounting: forget old evidence
        s *= gamma
        n[a] += 1
        s[a] += y
        if window:                                      # sliding window: drop evidence older than W
            hist.append((a, y))
            if len(hist) > window:
                a_old, y_old = hist.popleft()
                n[a_old] -= 1
                s[a_old] -= y_old
        if (t + 1) % batch == 0:                        # delayed feedback: refresh every `batch`
            seen_n, seen_s = n.copy(), s.copy()
        reg[t] = p.max() - p[a]
    return reg

p0 = np.random.default_rng(42).uniform(0.02, 0.08, 10)
p0[0] = 0.10
p1 = p0.copy()
p1[0], p1[1] = 0.03, 0.12                               # at T/2 the winner fades, a new one rises
rows = []
for name, kw in (("Thompson", {}), ("Thompson, discount 0.999", {"gamma": 0.999}),
                 ("Thompson, window 2,000", {"window": 2_000})):
    regs = np.array([bandit_run("TS", p0, p1, seed=sd, **kw) for sd in range(3)])
    rows.append({"policy": name, "regret first half": regs[:, :20_000].sum(1).mean(),
                 "regret second half": regs[:, 20_000:].sum(1).mean()})
print("non-stationary: CTRs swap at t = 20,000 (mean of 3 seeds)")
print(pd.DataFrame(rows).round(1).to_string(index=False))
```

```output
non-stationary: CTRs swap at t = 20,000 (mean of 3 seeds)
                  policy  regret first half  regret second half
                Thompson              150.0               815.5
Thompson, discount 0.999              549.5               683.2
  Thompson, window 2,000              427.0               527.3
```

After the swap, stationary Thompson loses 815 clicks: its posterior on the old winner holds
thousands of observations and gives way slowly. Both forgetting schemes recover faster, the window
best (527). Forgetting costs 3–4x stationary Thompson's 150 in the first half, because at a 5–10% CTR
a memory of 1,000–2,000 impressions holds only 50–200 clicks. Set the memory from how fast your
items actually change, not from a default.

## Try it Yourself

```python
import numpy as np

rng = np.random.default_rng(0)
n_seg, K = 20, 10                                       # user segments x items
ctr = rng.beta(2, 30, (n_seg, K))
target = np.argmax(ctr + rng.normal(0, 0.02, ctr.shape), axis=1)   # a decent but imperfect policy
V = ctr[np.arange(n_seg), target].mean()

noise = rng.normal(0, 0.5, ctr.shape)                   # the logging ranker's own errors

def logging_probs(beta):                                # softmax over the ranker's log-CTR
    z = beta * (np.log(ctr) + noise)
    e = np.exp(z - z.max(1, keepdims=True))
    return e / e.sum(1, keepdims=True)

mu = logging_probs(beta=4.0)                            # try 0.0 (uniform) up to 6.0 (peaked)

def estimates(n, r, clips=(np.inf, 200, 50, 10)):
    seg = r.integers(0, n_seg, n)
    a = (mu[seg].cumsum(1) > r.random((n, 1))).argmax(1)
    y = (r.random(n) < ctr[seg, a]).astype(float)
    w = (a == target[seg]) / mu[seg, a]
    out = {f"IPS clip {c:g}": (np.minimum(w, c) * y).mean() for c in clips}
    out["SNIPS"] = (w * y).sum() / w.sum()
    return out

r = np.random.default_rng(1)
runs = pd.DataFrame([estimates(5_000, r) for _ in range(300)])
summary = pd.DataFrame({"bias": runs.mean() - V, "sd": runs.std()})
summary["rmse"] = np.sqrt(summary["bias"] ** 2 + summary["sd"] ** 2)
print(f"true value {V:.4f} | smallest logging propensity on the target's action "
      f"{mu[np.arange(n_seg), target].min():.4f}")
print(summary.round(4).to_string())
```

```output
true value 0.1389 | smallest logging propensity on the target's action 0.0008
                bias      sd    rmse
IPS clip inf  0.0030  0.0402  0.0403
IPS clip 200 -0.0020  0.0132  0.0134
IPS clip 50  -0.0027  0.0118  0.0122
IPS clip 10  -0.0087  0.0093  0.0127
SNIPS         0.0023  0.0318  0.0318
```

With $\beta = 4$ the logging policy almost never takes the action the target wants for one
segment (smallest propensity 0.0008). Unclipped IPS is nearly unbiased but has a standard deviation
of 0.040 on a value of 0.139. Clipping weights at 50 cuts the RMSE to 0.012 at a cost of a 0.003
bias. Clipping at 10 cuts the variance further, but the bias (−0.0087) now dominates and the RMSE
rises again. SNIPS helps only a little (0.032), because the problem is a handful of huge weights, not their
total. Set `beta=0.0` to see every estimator agree, then raise it to 6.0. Also try making the target
policy disagree more with the logger: the support condition is what breaks first.

## Exercise

Disjoint LinUCB learns a separate $\theta_a$ per item, so a newly launched item starts with no
knowledge and a large bonus. Implement a **shared** LinUCB whose context is the feature cross
$z(x, a) = \operatorname{vec}(x f_a^\top)$, one ridge model for all items, so a new item inherits
what was learned about its attributes. Run both on the 30-item catalogue from this chapter and
launch 10 new items (drawn from the same feature model) at $t = 5{,}000$. Compare regret before the
launch, in the first 1,000 rounds after it, and over the remainder. Also count how many impressions
each model spends on the new items.

```python
rng = np.random.default_rng(9)
K_new = 10
feat_all = np.r_[item_feat, np.c_[np.ones(K_new), rng.normal(0, 1, (K_new, d_i - 1))]]
theta_all = feat_all @ B.T                                  # same B: new items obey the same rule
K_all = K + K_new

def cross(x, F):                                            # z(x, a) = vec(x f_a^T), dim d_u * d_i
    return (x[None, :, None] * F[:, None, :]).reshape(len(F), -1)

def run_catalogue(algo, T=15_000, t_new=5_000, alpha=0.5, lam=1.0, seed=0):
    r = np.random.default_rng(seed)
    X = draw_users(T, r)
    Pt = 1 / (1 + np.exp(-(X @ theta_all.T)))
    U = r.random(T)
    dz = d_u * d_i
    Ad = np.tile(np.eye(d_u) / lam, (K_all, 1, 1))
    bd = np.zeros((K_all, d_u))
    As, bs = np.eye(dz) / lam, np.zeros(dz)
    regret, new_pulls = np.zeros(T), 0
    for t in range(T):
        live = K_all if t >= t_new else K
        x = X[t]
        if algo == "disjoint":
            mean = np.einsum("kij,kj->ki", Ad[:live], bd[:live]) @ x
            width = np.sqrt(np.einsum("i,kij,j->k", x, Ad[:live], x))
        else:
            Z = cross(x, feat_all[:live])
            mean = Z @ (As @ bs)
            width = np.sqrt(np.einsum("ki,ij,kj->k", Z, As, Z))
        a = int(np.argmax(mean + alpha * width))
        y = float(U[t] < Pt[t, a])
        if algo == "disjoint":
            Ax = Ad[a] @ x
            Ad[a] -= np.outer(Ax, Ax) / (1 + x @ Ax)
            bd[a] += y * x
        else:
            z = cross(x, feat_all[a:a + 1])[0]
            Az = As @ z
            As -= np.outer(Az, Az) / (1 + z @ Az)
            bs += y * z
        regret[t] = Pt[t, :live].max() - Pt[t, a]
        new_pulls += (a >= K) and t >= t_new
    return regret, new_pulls

rows = []
for algo in ("disjoint", "shared"):
    reg, new_pulls = run_catalogue(algo)
    rows.append({"model": algo, "regret before launch": reg[:5_000].sum(),
                 "regret 1k after launch": reg[5_000:6_000].sum(),
                 "regret 10k after launch": reg[5_000:].sum(),
                 "pulls of new items": new_pulls})
print(pd.DataFrame(rows).round(1).to_string(index=False))
```

```output
   model  regret before launch  regret 1k after launch  regret 10k after launch  pulls of new items
disjoint                 112.8                    73.5                    198.8                3671
  shared                  77.6                     9.9                     60.8                2797
```

The shared model is better at every stage. After the launch it loses 9.9 clicks in the first 1,000
rounds against 73.5 for the disjoint model, and 60.8 against 198.8 over the following 10,000. It
also spends fewer impressions on the new items (2,797 against 3,671), because it does not need to
explore them blindly: each new item's score comes from its features via the shared
$d_u \times d_i = 30$-parameter model, and the bonus is already small in directions the model has
seen. The disjoint model must learn each new item's 6 parameters from scratch. The shared model is also better *before* the launch (77.6 against 112.8), since 30 parameters
in total learn faster than $30 \times 6 = 180$.

This is the hybrid LinUCB of Li et al. (2010), which combines shared feature-cross terms with
per-arm residuals, and it is the bandit version of the cold-start argument of ch. 9. The shared
model is only as good as the features, though. When an item's appeal is not in $f_a$, a per-arm
residual is what catches it, and that is why the production version keeps both.

## Under the Trench

Rare and advanced topics you should at least know the name of. You won't need them daily,
but you'll stop being surprised when you meet them.

- **Wide & Deep / DeepFM / DLRM** — industrial CTR architectures that combine memorising feature crosses with deep embeddings of sparse ids; DLRM is the reference design for embedding-table-bound ranking at scale.
- **Graph-based recsys (LightGCN)** — treat the user-item matrix as a bipartite graph and smooth embeddings over neighbours with simplified, nonlinearity-free graph convolutions.
- **Diversity, novelty, serendipity, fairness** — objectives beyond accuracy, usually enforced at re-ranking with MMR or DPP; fairness covers exposure to item providers as well as treatment of users.
- **Exposure bias & debiasing** — logged interactions reflect what was shown; inverse-propensity training, randomised buckets and causal embeddings correct the training signal, not only the evaluation.
- **Approximate nearest neighbours (FAISS/HNSW)** — product quantisation, IVF and navigable small-world graphs serve two-tower retrieval over billions of vectors in milliseconds.
- **Multi-task & multi-objective ranking** — predict click, dwell, like and purchase jointly (shared-bottom, MMoE, PLE) and combine them with a tuned value formula or a Pareto method.
- **Reranking & calibration in ranking** — a final stage that applies business rules, diversity and freshness, and calibrates scores so a predicted 3% means 3%.
- **Counterfactual learning-to-rank** — train (not only evaluate) rankers with position-propensity-weighted losses so the model learns relevance rather than the old ranking.
- **Slate and combinatorial bandits** — choose whole lists with interacting items (cascading, slate Q-learning, SlateQ) instead of one arm per request.
- **Off-policy learning (POEM, BanditNet)** — optimise a policy directly on logged bandit feedback using a variance-regularised or self-normalised IPS objective.
- **Generative retrieval / semantic IDs** — give each item a short discrete token code (e.g. RQ-VAE) and train a sequence model to decode the next item's code instead of searching an index.
- **LLM-based recommenders** — use language models as feature encoders, zero-shot rankers or conversational recommenders; strong for cold start, expensive and hard to ground in a catalogue.
- **Reinforcement learning for long-term value** — optimise retention or lifetime engagement rather than the next click, with off-policy corrections such as top-K REINFORCE (Chen et al., 2019).
