## Linear Dynamical Systems

A state space model keeps a small running memory, the **state**, and updates it every time a
new input arrives. The output is read off that memory. Nothing grows as the sequence gets
longer, which is exactly what attention could not offer (ch. 1).

State space models (SSMs) come from control theory. A continuous-time linear system:

**Control theory** is the engineering field that models things like thermostats and cruise
control. **Continuous-time** means time flows smoothly rather than in steps.

$$
h'(t) = A h(t) + B x(t)
$$
$$
y(t) = C h(t) + D x(t)
$$

> **In plain words:** the first line says how fast the memory $h$ changes: it drifts on its
> own (the $A h$ part, usually a slow fade) and gets pushed by the input (the $B x$ part).
> The second line says the output is a weighted read of the memory ($C h$) plus a direct
> shortcut from the input ($D x$). $h'(t)$ means "rate of change of $h$ at time $t$".

where $x(t) \in \mathbb{R}$ is the input signal, $h(t) \in \mathbb{R}^N$ is a hidden state, and $y(t) \in \mathbb{R}$ is the output. $A \in \mathbb{R}^{N \times N}$, $B \in \mathbb{R}^{N \times 1}$, $C \in \mathbb{R}^{1 \times N}$, $D \in \mathbb{R}$.

So one input number goes in, $N$ numbers of memory are kept, and one output number comes
out. A real model runs one such SSM per channel of the hidden vector.

> **Picture it:** a bathtub with a slow leak. Water pouring in is the input $x$, the water
> level is the state $h$, the leak is $A$ (it drains the tub towards empty), and a gauge
> reading the level is $C$. The tub "remembers" recent pouring, and forgets old pouring at
> the leak's rate.

For sequence modeling, you discretize this system at time steps $\Delta$ (the **step size**, a learned parameter):

To **discretize** means to convert smooth time into steps, because text arrives one token
at a time.

$$
\bar{A} = \exp(\Delta A), \quad \bar{B} = (\Delta A)^{-1}(\exp(\Delta A) - I) \cdot \Delta B
$$

> **In plain words:** $\bar{A}$ is how much of the old memory survives one step. For a
> single fading mode $A = -a$, it is $e^{-a \Delta}$, a number between 0 and 1. $\bar{B}$ is
> how strongly one step of input is written in; the odd-looking factor in front is the exact
> amount of input that piles up over a step of length $\Delta$ while the memory is also fading.

This is the **Zero-Order Hold (ZOH)** discretization. The resulting discrete system:

"Zero-order hold" means you assume the input stays constant during each step, like holding
a dial still for $\Delta$ seconds.

$$
h_t = \bar{A} h_{t-1} + \bar{B} x_t, \quad y_t = C h_t + D x_t
$$

> **In plain words:** new memory = (fade factor) times old memory + (write strength) times the
> new input. Output = a read of the memory plus the direct shortcut. This is the whole
> model you will compute with.

This looks like an RNN — but the key difference is that $A$, $B$, $C$, $D$ are **fixed matrices**, not input-dependent. That enables a different way to compute.

An **RNN** (recurrent neural network) also updates a hidden state each step, but squashes it
through a nonlinearity like $\tanh$. The SSM has no nonlinearity inside the update, and that
is what makes the trick in the next section possible.

```python
import numpy as np

def discretize_zoh(A, B, delta):
    """Zero-Order Hold discretization of continuous SSM (A, B)."""
    N = A.shape[0]
    # A_bar = exp(delta * A)
    # For diagonal A, this is just exp(delta * diag(A))
    A_bar = np.diag(np.exp(delta * np.diag(A)))
    # B_bar = (delta*A)^{-1} * (A_bar - I) * delta * B
    dA_inv = np.diag(1.0 / (delta * np.diag(A)))
    B_bar = dA_inv @ (A_bar - np.eye(N)) @ (delta * B)
    return A_bar, B_bar

N = 4  # state dim
# Simple diagonal A (negative for stability)
A = np.diag([-0.5, -1.0, -2.0, -4.0])
B = np.ones((N, 1))
delta = 0.1

A_bar, B_bar = discretize_zoh(A, B, delta)
print("A_bar (diagonal):", np.diag(A_bar).round(4))
print("B_bar:", B_bar.flatten().round(4))
```

```output
A_bar (diagonal): [0.9512 0.9048 0.8187 0.6703]
B_bar: [0.0975 0.0952 0.0906 0.0824]
```

Read the first line from left to right: the four fade factors are 0.9512, 0.9048, 0.8187 and
0.6703. They match $e^{-0.05}, e^{-0.1}, e^{-0.2}, e^{-0.4}$: the mode with $A = -4$ forgets a
third of its memory every step, while the one with $A = -0.5$ keeps 95%. The second line shows
the matching write strengths, each a bit below $\Delta = 0.1$.

> **Watch out:** the entries of $A$ must be negative (more precisely, have negative real
> part). A positive entry gives a fade factor above 1, and the memory grows without limit.

## Two Modes: Convolution and Recurrence

Because the update is linear, you can compute the same output in two very different ways:
one step at a time, or all at once as a filter slid over the whole input.

The SSM has two equivalent computations.

### Recurrence view (efficient for inference)

A **recurrence** computes each step from the previous one.

Step by step: $h_t = \bar{A} h_{t-1} + \bar{B} x_t$, $y_t = C h_t$. Each step is $O(N)$, total $O(TN)$. Perfect for autoregressive generation — no growing KV cache.

**Autoregressive** generation produces one token, feeds it back in, and produces the next. The
model only carries its $N$ memory numbers forward from step to step.

### Convolution view (efficient for training)

During training the whole sequence is known in advance, so you would like to process it all
at once on a GPU. Writing the recurrence out by hand shows how.

Unroll the recurrence:

$$
y_t = C \bar{A}^t \bar{B} x_0 + C \bar{A}^{t-1} \bar{B} x_1 + \ldots + C \bar{B} x_t = \sum_{k=0}^{t} \bar{K}_k \, x_{t-k}
$$

> **In plain words:** the output at time $t$ is a weighted sum of every past input. The
> input from $k$ steps ago gets weight $\bar{K}_k$, which is "write it in ($\bar{B}$), let it
> fade $k$ times ($\bar{A}^k$), read it out ($C$)". The weights depend only on *how long
> ago*, never on the input itself.

where $\bar{K}_k = C \bar{A}^k \bar{B}$ is the **SSM kernel** — a fixed convolutional filter of length $T$.

$$
y = \bar{K} * x
$$

> **In plain words:** the output is the input slid against the filter $\bar{K}$; the $*$
> means **convolution**, a running weighted sum with the same weights at every position.

This is a 1D convolution! And convolution can be computed in $O(T \log T)$ via FFT.

The **FFT** (fast Fourier transform) is a classic algorithm that turns a long convolution into
cheap element-wise multiplication, in $O(T \log T)$ time and fully parallel.

> **Picture it:** an echo. Clap once, and you hear the clap again, fainter and fainter. The
> kernel $\bar{K}$ is the shape of that echo. The room's response to a whole song is every
> note's echo added together, which you can compute note by note (recurrence) or all at once
> from the echo shape (convolution).

```python
def ssm_recurrent(x, A_bar, B_bar, C, D=0.0):
    """Run SSM as a recurrence."""
    T = len(x)
    N = A_bar.shape[0]
    h = np.zeros(N)
    ys = []
    for t in range(T):
        h = A_bar @ h + B_bar.flatten() * x[t]
        ys.append(C @ h + D * x[t])
    return np.array(ys)

def ssm_convolutional(x, A_bar, B_bar, C, D=0.0):
    """Run SSM as convolution — build the kernel then convolve."""
    T = len(x)
    N = A_bar.shape[0]
    # Build kernel K of length T
    K = np.zeros(T)
    A_pow = np.eye(N)
    for k in range(T):
        K[k] = C @ A_pow @ B_bar.flatten()
        A_pow = A_pow @ A_bar
    # 1D convolution (causal)
    y_conv = np.convolve(x, K, mode='full')[:T]
    return y_conv + D * x

# Test equivalence
N, T = 4, 32
rng = np.random.default_rng(42)
A = np.diag(rng.uniform(-1, -0.1, N))
B = rng.standard_normal((N, 1))
C = rng.standard_normal(N)
x = rng.standard_normal(T)

A_bar, B_bar = discretize_zoh(A, B, delta=0.1)

y_rec  = ssm_recurrent(x, A_bar, B_bar, C)
y_conv = ssm_convolutional(x, A_bar, B_bar, C)

print(f"Max difference between recurrent and conv: {np.abs(y_rec - y_conv).max():.2e}")
print(f"Output shape: {y_rec.shape}")
```

```output
Max difference between recurrent and conv: 1.11e-16
Output shape: (32,)
```

The first line is the proof: the largest gap between the two methods' outputs is
$1.11 \times 10^{-16}$, which is the rounding limit of 64-bit floats. Same model, same
answer, two schedules.

They're numerically identical — up to floating point. This dual-mode property is the key to S4's efficiency.

## The HiPPO Matrix: Why A Matters

The fade matrix $A$ decides *what* the memory keeps. A random $A$ forgets the past in a
useless way; a well-designed $A$ keeps a compact summary of the whole history.

Not any $A$ works well. The **HiPPO** (High-Order Polynomial Projection Operators) paper shows that you want $A$ to efficiently memorize the history $x(0), \ldots, x(t)$ by projecting it onto a polynomial basis.

**Projecting onto a polynomial basis** means describing the whole input history as a sum of
smooth curves (polynomials). The $N$ state numbers are the amounts of each curve, so $N$
numbers summarize the entire past signal.

> **Picture it:** describing a mountain range's skyline with a few numbers: "mostly flat,
> rising a bit, with a dip in the middle". More numbers give finer detail. HiPPO's $A$
> keeps those numbers up to date as new skyline keeps arriving.

The HiPPO-LegS matrix (Legendre polynomials, measure-preserving):

$$
A_{nk} = -\begin{cases}
(2n+1)^{1/2}(2k+1)^{1/2} & \text{if } n > k \\
n+1 & \text{if } n = k \\
0 & \text{if } n < k
\end{cases}
$$

> **In plain words:** row $n$, column $k$ of $A$ is negative and nonzero only on and below
> the diagonal: $-(n+1)$ on the diagonal, $-\sqrt{2n+1}\sqrt{2k+1}$ below it, and $0$ above.
> **Legendre polynomials** are a particular family of smooth curves; "LegS" means the history
> is weighted evenly over the whole past.

This creates a structured lower-triangular matrix whose eigenvalues are all negative real — stable and efficient at capturing both local and long-range history.

An **eigenvalue** of $A$ is a rate at which one mode of the memory grows or shrinks; all
negative means every mode fades, so nothing blows up.

```python
def make_hippo_legs(N):
    """HiPPO-LegS matrix for polynomial projection."""
    A = np.zeros((N, N))
    for n in range(N):
        for k in range(N):
            if n > k:
                A[n, k] = -np.sqrt(2*n+1) * np.sqrt(2*k+1)
            elif n == k:
                A[n, k] = -(n + 1)
    return A

N = 8
A_hippo = make_hippo_legs(N)
eigenvalues = np.linalg.eigvals(A_hippo)
print("HiPPO eigenvalues (all negative = stable):")
print(np.sort(eigenvalues.real).round(2))
```

```output
HiPPO eigenvalues (all negative = stable):
[-8. -7. -6. -5. -4. -3. -2. -1.]
```

The eigenvalues are exactly $-8, -7, \dots, -1$. That is no accident: for a lower-triangular
matrix the eigenvalues are the diagonal entries, here $-(n+1)$ for $n = 0, \dots, 7$. All
negative, so the system is stable.

## S4: Structured State Spaces

HiPPO gives a good $A$, but a dense $N \times N$ matrix is slow to raise to powers. S4's
contribution is making that fast enough to train deep networks.

The S4 paper (Gu et al., 2021) makes SSMs practical for deep learning by:

1. **Diagonal plus Low Rank (DPLR)**: $A = \Lambda - PQ^*$ where $\Lambda$ is diagonal. This lets you compute the SSM kernel in $O(N + L\log L)$ via the Cauchy kernel.
2. **S4D**: simplify to purely diagonal $A$ — near identical performance, much easier.
3. **Initialization from HiPPO**: start $A$ from the HiPPO matrix, then learn $\Delta$, $B$, $C$.

**DPLR** writes $A$ as a diagonal matrix minus a thin correction; $PQ^*$ is that correction,
built from a few columns. A **Cauchy kernel** is a known fast formula for sums of the form
$\sum_n c_n / (z - \lambda_n)$, which is what the kernel becomes in this form. A **diagonal**
$A$ means every memory slot fades on its own, with no mixing between slots, so $\bar{A}^k$ is
a plain element-wise power.

In practice you parameterize the diagonal of $A$ with $\text{Re}(A) < 0$ for stability.

The code stores $\log$ of the decay rate and sets the real part to $-\exp(\cdot)$, which is
negative no matter what value training pushes the parameter to. The imaginary part makes each
mode oscillate as it fades, like a ringing bell. Using complex numbers in conjugate pairs
is why the kernel has the factor 2 and takes the real part.

```python
# S4D: diagonal A with complex eigenvalues
# Parameterize as A_diag = -exp(log_A_real) + i * A_imag
def s4d_kernel(log_A_real, A_imag, B, C, delta, L):
    """Compute S4D convolution kernel."""
    # Complex diagonal: A = -exp(log_A_real) + i*A_imag
    A_diag = -np.exp(log_A_real) + 1j * A_imag  # (N,)
    # Discretize
    A_bar = np.exp(delta * A_diag)              # (N,)
    B_bar = (A_bar - 1) / A_diag * B            # (N,)
    # Build kernel: K[t] = 2 * Re(C * A_bar^t * B_bar)
    t = np.arange(L)
    # A_bar^t for each element: (L, N)
    A_pow = A_bar[None, :] ** t[:, None]
    K = 2 * np.real(A_pow @ (C * B_bar))       # (L,)
    return K

N, L = 16, 64
rng = np.random.default_rng(0)
log_A_real = np.log(rng.uniform(0.1, 1.0, N))
A_imag = rng.uniform(-np.pi, np.pi, N)
B = rng.standard_normal(N) + 1j * rng.standard_normal(N)
C = rng.standard_normal(N) + 1j * rng.standard_normal(N)

K = s4d_kernel(log_A_real, A_imag, B, C, delta=0.01, L=L)
print(f"S4D kernel shape: {K.shape}")
print(f"Kernel (first 8): {K[:8].round(3)}")
print(f"Kernel norm: {np.linalg.norm(K):.3f}")
```

```output
S4D kernel shape: (64,)
Kernel (first 8): [0.046 0.045 0.045 0.044 0.044 0.043 0.043 0.042]
Kernel norm: 0.203
```

The kernel has 64 taps, one per lag. The first eight values fall smoothly from 0.046 to 0.042
because $\Delta = 0.01$ is a tiny step: in 8 steps the memory has barely faded or rotated. A
larger $\Delta$ would make the kernel decay and wiggle much faster. The kernel norm is
0.203.

> **Watch out:** $\Delta$ is a learned *time scale*, and it matters as much as $A$. A small
> $\Delta$ means "each token is a short moment, remember far back"; a large $\Delta$ means
> "each token is a long time, focus on recent ones".

## Recap in plain words

- An SSM keeps $N$ memory numbers, fades them by $\bar{A}$ each step, writes the input in with $\bar{B}$, and reads out with $C$.
- Discretizing with step $\Delta$ turns the smooth-time model into a step-by-step update; the fade factors here ran from 0.67 to 0.95.
- Because the update is linear and fixed, the same model is both a recurrence (cheap per step at inference) and a convolution (parallel at training); they agreed to $10^{-16}$.
- The HiPPO matrix chooses $A$ so the state summarizes the whole history with polynomials; its eigenvalues here were $-1$ to $-8$, all stable.
- S4 and S4D make the kernel fast to compute, with S4D using a plain diagonal $A$.

## Try it Yourself

The experiment counts rough operation numbers for the three ways to process a length-$T$
sequence: SSM recurrence, SSM convolution via FFT, and attention.

```python
import numpy as np

def compare_recurrence_complexity(T_values, N=64):
    """Show why dual-mode is the right design."""
    print(f"{'T':>8} | {'Recurrence ops':>16} | {'Conv via FFT':>14} | {'Attn O(T²)':>12}")
    print("-" * 60)
    for T in T_values:
        rec = T * N            # T steps * N state dim
        conv = T * np.log2(T)  # FFT convolution
        attn = T * T
        print(f"{T:>8} | {rec:>16,.0f} | {conv:>14,.0f} | {attn:>12,.0f}")

compare_recurrence_complexity([256, 1024, 4096, 16384, 65536])
```

```output
       T |   Recurrence ops |   Conv via FFT |   Attn O(T²)
------------------------------------------------------------
     256 |           16,384 |          2,048 |       65,536
    1024 |           65,536 |         10,240 |    1,048,576
    4096 |          262,144 |         49,152 |   16,777,216
   16384 |        1,048,576 |        229,376 |  268,435,456
   65536 |        4,194,304 |      1,048,576 | 4,294,967,296
```

Look at the last row, $T = 65{,}536$: the recurrence needs about 4.2 million operations, the
FFT about 1.0 million, and attention about 4.3 billion, roughly 1,000 times more. Each time
$T$ grows 4 times, the recurrence column grows 4 times, but attention grows 16 times.

Try `N=256`: the recurrence gets 4 times more expensive, but it still scales linearly, so
it stays far below attention at long $T$.

```python
# The SSM state is always size N — a compressed summary of all past inputs.
# No matter how many tokens you've seen, the state stays the same shape.
# This contrasts with the KV cache in transformers, which grows as O(T * d_head * layers).

def ssm_inference_state_bytes(N, layers, dtype_bytes=4):
    """Fixed memory for SSM during generation."""
    return N * layers * dtype_bytes

def transformer_kv_cache_bytes(T, heads, d_head, layers, dtype_bytes=2):
    """Growing memory for transformer KV cache."""
    return 2 * T * heads * d_head * layers * dtype_bytes

N, layers = 16, 12
print("SSM inference state (fixed):")
print(f"  {ssm_inference_state_bytes(N, layers):,} bytes = {ssm_inference_state_bytes(N, layers)/1024:.1f} KB")

print("\nTransformer KV cache (grows with T):")
for T in [512, 2048, 8192]:
    kb = transformer_kv_cache_bytes(T, heads=12, d_head=64, layers=12) / 1024
    print(f"  T={T:5d}: {kb:8.1f} KB")
```

```output
SSM inference state (fixed):
  768 bytes = 0.8 KB

Transformer KV cache (grows with T):
  T=  512:  18432.0 KB
  T= 2048:  73728.0 KB
  T= 8192: 294912.0 KB
```

The SSM's state is 768 bytes no matter how long the sequence — versus megabytes for a transformer at long context. This is the core advantage for streaming generation.

The update overwrites $h$ in place, so its shape never mentions $t$; old inputs survive only
as a faded blend inside those $N$ numbers. The transformer instead keeps a key and value for
every past token: 18 MB at 512 tokens growing to 288 MB at 8,192. Each generation step also
has to *read* all of that cache, whereas the SSM reads only its fixed state.

> **Watch out:** this toy counts one $N$-sized state per layer. A real SSM layer keeps $N$
> numbers for *every channel* of the hidden vector, so multiply by the model width (768 for
> this size of model). The state is bigger, but still fixed, whatever the length.
