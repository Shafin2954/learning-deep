## Why evaluation is hard

Grading a classifier is easy because every question has one right answer. Grading a generator
is like grading a painting class: there is no answer key, and "good" has several meanings at once.

For a classifier you check accuracy. For a generative model there is no single right answer —
you want samples that are (a) high quality (realistic), (b) diverse (not all the same image),
and (c) faithful to the conditioning signal (if text → image). These goals can conflict, and
no single number captures all of them.

> **Picture it:** judging a bakery. One judge tastes single cakes (quality). Another checks the
> whole shop window has variety (diversity). A third checks the cake matches the customer's order
> (fidelity). A bakery making one perfect chocolate cake wins the first judge and fails the
> second.

The metrics below each measure a different aspect. You need more than one.

## Fréchet Inception Distance (FID)

FID turns every image into a list of features with a pre-trained image network, then measures
how far apart the "cloud" of real features and the "cloud" of generated features are.

FID is the most widely used metric for image generation. It:

1. Passes a large set of real images and a large set of generated images through
   InceptionV3 (up to the last pooling layer, producing 2048-d features).
2. Fits a multivariate Gaussian to each set: $(\mu_r, \Sigma_r)$ and $(\mu_g, \Sigma_g)$.
3. Computes the Fréchet distance between the two Gaussians:

**InceptionV3** is an ImageNet classifier; its internal features describe image content (edges,
textures, object parts). A **multivariate Gaussian** is a bell-shaped cloud in many dimensions,
described by its centre $\mu$ and its **covariance** $\Sigma$ (the cloud's spread and tilt).

$$
\text{FID} = \|\mu_r - \mu_g\|^2 + \text{Tr}\!\left(\Sigma_r + \Sigma_g - 2(\Sigma_r \Sigma_g)^{1/2}\right)
$$

- $\|\mu_r - \mu_g\|^2$ — how far apart the two cloud centres are (squared distance).
- $\text{Tr}(\cdot)$ — the **trace**, the sum of a matrix's diagonal entries.
- $\Sigma_r + \Sigma_g - 2(\Sigma_r \Sigma_g)^{1/2}$ — how different the two clouds' shapes are;
  it is zero when the covariances match.

> **In plain words:** FID = (distance between the average real image and the average fake image,
> in feature space) + (mismatch in how the two sets vary). Both parts are zero only if the two
> clouds coincide.

Lower FID = closer to the real distribution. A perfect model would have FID = 0. A random
noise generator has FID in the hundreds.

### Practical FID with torchmetrics

`torchmetrics` wraps the whole recipe. The demo uses the early 64-dimensional Inception
features (`feature=64`) so it runs in seconds on a CPU and stays stable with only 128 images;
published FIDs use `feature=2048` and 10,000+ images. `normalize=True` means images are floats in
$[0, 1]$. With `reset_real_features=False`, `fid.reset()` clears only the generated features,
so the real images are encoded once and reused.

```python
from torchmetrics.image.fid import FrechetInceptionDistance
import torch

# feature=64: early 64-d Inception features (fast on CPU, stable with ~100 images).
# Papers use feature=2048 with 10k+ images.
fid = FrechetInceptionDistance(feature=64, normalize=True, reset_real_features=False)

# Simulate batches of real and generated images (B, C, H, W) in [0, 1]
torch.manual_seed(0)
real_imgs = torch.rand(128, 3, 299, 299)  # needs 299x299 for InceptionV3
fake_imgs = torch.rand(128, 3, 299, 299) * 0.5  # dimmer → different distribution

fid.update(real_imgs, real=True)
fid.update(fake_imgs, real=False)
score = fid.compute()
print(f"FID (random noise vs dimmer noise): {score:.2f}")

# A model that generates images identical to the real set
fid.reset()                          # drops fake features, keeps the real ones
fid.update(real_imgs, real=False)    # same images
score2 = fid.compute()
print(f"FID (real vs real):                 {score2:.2f}")
```

```output
FID (random noise vs dimmer noise): 47.19
FID (real vs real):                 -0.00
```

The dimmer noise is far from the real noise: FID 47.19. Feeding the real images back in as the
"generated" set gives 0.00 — two identical clouds. The minus sign in $-0.00$ is floating-point
round-off in the matrix square root, a tiny negative number printed to two decimals; FID itself
can't be negative.

> **Watch out:** FID values are only comparable when computed the same way — same feature layer,
> same number of images, same image resizing, same reference set. A 64-feature FID of 47 and a
> 2048-feature FID of 47 mean different things.

### FID limitations

- Requires a large sample (at least 10 000 images for stable estimates). With 1 000 samples
  FID is noisy and not comparable across papers.
- InceptionV3 was trained on ImageNet — FID on medical images or Bengali text renders is
  not meaningful.
- FID rewards mode coverage but doesn't catch mode dropping directly.

FID is also **biased** with few samples: the estimate is systematically too high, and the bias
depends on the model, so two models compared at 1,000 samples can even swap order at 50,000.

## Inception Score (IS)

IS asks the Inception classifier two questions about generated images only: is each image
clearly one thing, and do the images together cover many different things?

IS is an older metric that measures two things from the generator alone (no real images):

$$
\text{IS} = \exp\!\left(\mathbb{E}_x\!\left[\text{KL}\!\left(p(y|x) \,\|\, p(y)\right)\right]\right)
$$

- $p(y|x)$: InceptionV3's class distribution for a generated image $x$ (should be sharp = high confidence).
- $p(y) = \int p(y|x) p_g(x) dx$: marginal across all generated images (should be uniform = diversity).

> **In plain words:** for each image, measure how different its class prediction is from the
> average prediction over all images (the KL divergence). If every image is confidently one class
> and the classes vary across images, that difference is large. Average it over images and
> exponentiate. The score ranges from 1 (useless) to the number of classes, 1000 (perfect).

High IS means images are individually recognizable as a specific class AND the generator
covers many classes.

```python
from torchmetrics.image.inception import InceptionScore
import torch

is_metric = InceptionScore(normalize=True)
torch.manual_seed(42)

# Low-quality: all images look like noise → low confidence, no recognizable class
noise_imgs = torch.rand(50, 3, 299, 299)
is_metric.update(noise_imgs)
mean, std = is_metric.compute()
print(f"IS (random noise):   {mean:.2f} ± {std:.2f}")

# Higher-quality simulation: structured images would score much higher
# (we can't fake this without a real trained generator)
```

```output
IS (random noise):   1.05 ± 0.02
```

Random noise scores 1.05 with a spread of 0.02 across the 10 splits torchmetrics uses by default
— almost exactly the minimum of 1. Inception has no confident class for static, so each image's
prediction looks like the average prediction, and the KL term is near 0.

IS near 1.0 = random noise. A good GAN on ImageNet typically scores 100–300.
IS is widely criticized because it ignores real images entirely and can be gamed by a
model that memorizes the training set.

> **Watch out:** IS only makes sense for ImageNet-like content. A perfect generator of faces
> scores poorly, because Inception doesn't spread faces over many ImageNet classes.

## Kernel Inception Distance (KID)

KID compares the same two feature clouds as FID, but without assuming they are bell-shaped, and
its estimate doesn't drift with sample size.

KID is a statistically unbiased alternative to FID. It estimates the squared Maximum Mean
Discrepancy between the Inception feature distributions:

**Maximum Mean Discrepancy (MMD)** compares two sets of points through a **kernel** — a
similarity function between two points (KID uses a cubic polynomial). **Unbiased** means that,
on average over repeated draws, the estimate equals the true value even with small samples.

$$
\text{KID} = \text{MMD}^2\!\left(f_{\text{real}}, f_{\text{gen}}\right)
$$

> **In plain words:** $\text{MMD}^2$ = (average similarity within the real set) + (average similarity
> within the generated set) minus twice (average similarity between the sets). It is zero when the
> two sets come from the same distribution.

FID assumes Gaussian distributions; KID does not. KID can be computed reliably with as
few as 1 000 samples, making it better for small-scale experiments.

KID is computed on random subsets (here of 50 images) and reported as a mean and a standard
deviation across subsets.

```python
from torchmetrics.image.kid import KernelInceptionDistance
import torch

kid = KernelInceptionDistance(feature=64, subset_size=50, normalize=True)
torch.manual_seed(0)
real = torch.rand(100, 3, 299, 299)
fake = torch.rand(100, 3, 299, 299) * 0.8

kid.update(real, real=True)
kid.update(fake, real=False)
mean_kid, std_kid = kid.compute()
print(f"KID: {mean_kid:.4f} ± {std_kid:.4f}")
```

```output
KID: 164.7160 ± 0.9106
```

KID is 164.7160 with a subset-to-subset spread of only 0.9106, so the difference between plain
noise and noise dimmed to 0.8 is detected very reliably. The size of the number comes from the
feature layer: the early 64-d features are large raw activations, and the polynomial kernel
cubes them.

KID = 0 would mean the distributions match exactly. Values < 0.01 are considered good
for high-quality generators on standard benchmarks.

That rule of thumb applies to the standard 2048-d features only; on other layers, compare
KIDs only with each other.

## Negative Log-Likelihood (NLL)

For models that can compute a probability, the most direct test is: how probable does the model
find real images it has never seen?

For likelihood-based models (VAEs, normalizing flows, diffusion models) you can compute
the log probability the model assigns to held-out real images. Lower NLL = better model.

$$
\text{NLL} = -\frac{1}{N}\sum_{i=1}^N \log p_\theta(x_i)
$$

> **In plain words:** average, over $N$ held-out images, the negative log-probability the model
> gives each one. A model that finds real images likely scores low.

For VAEs you have the ELBO as a lower bound on NLL. For diffusion models you integrate
the denoising score over all noise levels. GANs have no tractable NLL.

(Strictly, the ELBO is a lower bound on the log-likelihood, so its negative is an *upper* bound
on NLL.) For images, NLL is usually reported in **bits per dimension**: NLL divided by the
number of pixel values and by $\log 2$, so models of different image sizes are comparable.

> **Watch out:** NLL and sample quality can disagree badly. A model can achieve good NLL while
> producing poor samples, and vice versa. Good likelihood is about covering everything; good
> samples are about what you see.

## Precision and recall for generative models

FID mixes quality and diversity into one number. Precision and recall pull them apart again:
"are my fakes realistic?" and "did I cover all the kinds of real data?".

Kynkäänniemi et al. (2019) define precision and recall by comparing the manifolds of
real and generated feature distributions:

A **manifold** here is the region of feature space the data occupies, estimated by drawing a
small ball around each point that reaches its $k$-th nearest neighbour.

- **Precision**: fraction of generated samples that fall within the real manifold (quality / no hallucination).
- **Recall**: fraction of real samples that are covered by the generated manifold (diversity / no mode dropping).

> **Picture it:** a dartboard where real images are the target shapes. Precision asks "of your
> darts, how many landed on a shape?". Recall asks "of the shapes, how many got hit?".

A model can have high precision but low recall (cherry-picked, repetitive) or high recall
but low precision (random-looking but diverse). You want both.

## CLIP Score (text-image alignment)

For text-to-image models you also need to know whether the picture matches the prompt. CLIP
Score asks a model trained on image–caption pairs how well the two match.

For conditional text-to-image models, FID doesn't measure whether the image matches the
prompt. CLIP Score measures the cosine similarity between the CLIP embedding of the generated
image and the CLIP embedding of the text prompt:

**CLIP** maps images and text into the same vector space so that matching pairs point the same
way. **Cosine similarity** is the cosine of the angle between two vectors: 1 for the same
direction, 0 for unrelated.

$$
\text{CLIP Score} = w \cdot \max(0, \text{cos}(E_{\text{image}}, E_{\text{text}}))
$$

> **In plain words:** embed the image and the prompt, take the cosine of the angle between them,
> clip negative values to 0, and multiply by a constant $w$ (usually 100) to make the numbers
> readable.

Higher is better. Unrelated image–caption pairs still get a small positive cosine (around 0.1 to
0.15), not 0; a good text-to-image model scores about 0.25–0.35 in raw cosine terms (25–35 with
$w = 100$).

## Choosing the right metric

Pick the metric that matches the question you are asking, and report more than one.

| Goal | Metric |
|------|--------|
| Overall image quality + diversity | FID (large sample) |
| Small-scale experiments | KID |
| Individual image quality | IS |
| Memorization check | Precision & recall |
| Text-image alignment | CLIP Score |
| Likelihood comparison | NLL / ELBO |
| Human judgment | Human evaluation study |

> **Watch out:** none of these catches memorization on its own: a model that copies its training
> set scores excellent FID, precision and recall. To check memorization, also search the training
> set for each sample's nearest neighbour.

## Recap in plain words

- A generator must be judged on quality, diversity and fidelity; no single number covers all
  three.
- FID compares the mean and spread of real versus generated Inception features; lower is better
  and 0 means identical.
- IS uses only generated images and only makes sense for ImageNet-like content.
- KID is an unbiased, small-sample-friendly cousin of FID; its scale depends on the feature layer.
- NLL scores likelihood models directly; precision/recall split quality from coverage; CLIP Score
  checks prompt matching.

## Try it Yourself

This compares two fake "generators" against the same 64 real noise images: one that adds a
little noise to each real image, and one that outputs nearly the same grey image every time.

```python
from torchmetrics.image.fid import FrechetInceptionDistance
import torch

# Compare two generators: one with low variance (mode collapse) vs high variance (diverse)
torch.manual_seed(0)
n = 64
real = torch.rand(n, 3, 299, 299)
fid = FrechetInceptionDistance(feature=64, normalize=True, reset_real_features=False)
fid.update(real, real=True)          # real features computed once, reused below

# Generator 1: mean-shifted but diverse
gen1 = real + torch.randn_like(real) * 0.05

# Generator 2: collapsed — all images near the mean
gen2 = torch.full_like(real, 0.5) + torch.randn_like(real) * 0.01

for name, gen in [("diverse", gen1), ("collapsed", gen2)]:
    fid.reset()                      # clear the previous generator's features
    fid.update(gen.clamp(0, 1), real=False)
    print(f"FID ({name:>9}): {fid.compute():.2f}")
```

```output
FID (  diverse): 0.01
FID (collapsed): 389.86
```

The near-copies score FID 0.01 — almost identical feature clouds. The collapsed generator scores
389.86: its cloud has the wrong centre and almost no spread. That is the mode-collapse signature
from ch. 5, now in a metric. Raise the collapsed generator's noise from `0.01` to `0.3` and
watch its FID fall as its spread grows; switch to `feature=2048` (slower) and compare the sizes
of the numbers.

## Exercise

You train a VAE and obtain ELBO values. You train a GAN on the same dataset and measure
FID. The VAE has an NLL of about 2.1 bits/dim and the GAN has FID = 15.

Which model generates better-looking images? Which has better probability estimates?

> **Hint:** ask which metric each model can even produce. Can you compute an NLL for a GAN? Does
> FID tell you anything about probabilities? A question that compares unlike metrics is partly a
> trick question.

<details>
<summary>Solution</summary>

The GAN likely generates sharper, more realistic images — FID = 15 is excellent and
indicates the generated distribution closely matches real images. However, GANs have no
tractable likelihood: you cannot compute NLL for a GAN.

The VAE gives you a tractable NLL (as an ELBO lower bound) and is useful when you need
calibrated probabilities (anomaly detection, compression). Its samples are typically blurrier
because the MSE reconstruction loss averages over modes.

The key insight: FID measures perceptual quality and diversity; NLL measures probabilistic
calibration. A model can be excellent on one and poor on the other. For downstream tasks
(image generation for humans), FID matters more. For tasks requiring uncertainty (OOD
detection, lossless compression), NLL matters more.

To compare them fairly on images, compute FID for the VAE too (it can generate samples). For
probabilities, the GAN simply has no entry — that, not a number, is the answer.

</details>

## Under the Trench

Rare and advanced topics you should at least know the name of. You won't need them daily,
but you'll stop being surprised when you meet them.

- **Score-based models & SDEs** — the continuous-time view unifying all diffusion variants; Langevin dynamics as sampling. In plain words: noising becomes a smooth random flow (a stochastic differential equation), and sampling walks uphill on $\log p$ with a little noise.
- **Energy-based models & contrastive divergence** — unnormalized densities learned via MCMC; trained by MCMC-driven negative phase. The model gives every input an "energy" (low = likely) without dividing by the total, and training pushes energy down on data and up on samples the model itself produces.
- **VQ-VAE-2 & discrete latents** — hierarchical discrete tokenization; the backbone of image generation via autoregressive models. It stacks two codebook grids, a coarse one for layout and a fine one for detail (ch. 10).
- **Consistency & flow-matching models** — few-step generation (1–4 NFE); flow matching uses a simpler straight-path ODE objective. NFE (network function evaluations) counts model calls per sample; diffusion needs 50–1000.
- **Restricted Boltzmann machines** — historical two-layer undirected model trained with contrastive divergence; inspired deep learning. Stacks of them pre-trained the first deep networks around 2006.
- **Conditional GANs / pix2pix / CycleGAN** — paired image translation (pix2pix) and unpaired domain transfer (CycleGAN). CycleGAN learns horse-to-zebra without paired photos by requiring that translating there and back returns the original.
