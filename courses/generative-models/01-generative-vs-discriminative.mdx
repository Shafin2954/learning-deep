## Discriminative vs Generative Models

Some models answer questions about data ("is this a cat?"). Others learn what the data itself
looks like, well enough to make new examples. That second kind is what this course is about.

A discriminative model learns $p(y|x)$ — given an input, predict a label. A logistic classifier, a gradient-boosted tree, a fine-tuned BERT all fall here. They draw a boundary between classes.

Here $p(y|x)$ is a **conditional probability** — "how likely is label $y$, given that I see
input $x$". A **discriminative model** only cares about this: where the line between "cat"
and "dog" runs. It never learns what a cat looks like in detail, only which side of the line
a picture falls on.

A generative model learns something harder: $p(x)$, the distribution of the data itself. Given that distribution you can do three things a discriminative model cannot: generate new samples that look real, compute how likely a given input is, and fill in missing parts of an input.

A **generative model** learns $p(x)$, the **data distribution** — a rule that says, for every
possible input, how common inputs like it are. For images, $p(x)$ is high for photos of real
scenes and almost zero for TV static.

> **Picture it:** a discriminative model is a border guard who only checks which country a
> traveller belongs to. A generative model is a novelist who knows each country so well they
> can invent a convincing new citizen, tell you how typical any given traveller is, and finish
> a half-written passport.

Some models learn the joint $p(x, y)$ and derive $p(y|x) = p(x,y)/p(x)$. Naive Bayes works this way. But modern deep generative models target $p(x)$ directly.

The **joint distribution** $p(x, y)$ says how common each (input, label) pair is. If you know
it, dividing by $p(x)$ gives back the classifier — so the generative view contains the
discriminative one. The reverse is not true.

## Likelihood-Based vs Implicit Models

Generative models split into two camps: those that can tell you a number for "how likely is
this input?", and those that can only produce samples without ever writing that number down.

The core divide in deep generative models is whether you ever explicitly compute $p(x)$.

**Likelihood-based models** — VAEs, normalizing flows, diffusion models — define or bound $p(x)$ and train by maximizing it. You can assign a likelihood score to any new input, which is useful for anomaly detection and compression.

A **likelihood** is the probability (or density) the model assigns to one specific input.
"Maximizing it" means: tune the model so the real training examples get the highest possible
scores. "Bound" means some models (VAEs) can only compute a guaranteed lower limit on
$p(x)$, and push that limit up instead.

**Implicit models** — GANs — never write down $p(x)$. Instead, a generator network maps noise to data space, and a discriminator separates real from fake. Training is adversarial, not maximum-likelihood.

An **implicit model** is like a vending machine: press the button (feed in random noise) and
out comes a sample, but there is no readout of how likely that sample was. **Adversarial**
means two networks compete: one forges, one detects forgeries (ch. 4).

> **Picture it:** a likelihood model is a weather forecaster who says "70% chance of rain
> tomorrow". An implicit model is a simulator that can play out a thousand possible tomorrows
> but never states a percentage.

The code below builds a concrete $p(x)$ you can look at: a **mixture of Gaussians**, two bell
curves added together, centred at $-2$ and $+2$.

```python
import numpy as np
import matplotlib.pyplot as plt

# Illustrate: real data is a mixture of Gaussians
rng = np.random.default_rng(0)
real = np.concatenate([rng.normal(-2, 0.5, 300),
                        rng.normal(2, 0.5, 300)])

# A generative model learns this shape
x = np.linspace(-5, 5, 500)
# Two-component mixture density (true distribution)
density = (0.5 * np.exp(-0.5*((x+2)/0.5)**2) / (0.5*np.sqrt(2*np.pi)) +
           0.5 * np.exp(-0.5*((x-2)/0.5)**2) / (0.5*np.sqrt(2*np.pi)))

print(f"Real samples: {real.shape}")
print(f"Sample mean: {real.mean():.3f}, std: {real.std():.3f}")
print(f"Peak density at x=-2: {density[np.argmin(np.abs(x+2))]:.4f}")
print(f"Peak density at x=+2: {density[np.argmin(np.abs(x-2))]:.4f}")
```

```output
Real samples: (600,)
Sample mean: -0.011, std: 2.068
Peak density at x=-2: 0.3989
Peak density at x=+2: 0.3989
```

Look at the second line: the samples' mean is $-0.011$, almost exactly 0, but the standard
deviation is 2.068. Both numbers describe a single blob centred at 0 — yet there is almost no
data at 0. The two peak lines (0.3989 at $x=-2$ and at $x=+2$) show where the data really
lives. That is why a generative model must learn the full *shape* of $p(x)$, not only a mean
and a spread.

> **Watch out:** 0.3989 is a *density*, not a probability. Each half-component has height
> $0.5 \cdot \frac{1}{0.5\sqrt{2\pi}} \approx 0.399$. A density can exceed 1 when the curve is
> narrow; only its area must equal 1.

## The Generative Modeling Goal

The goal in one sentence: from a pile of examples, learn a recipe that produces new examples
from the same pile's "style".

You have a dataset $\mathcal{D} = \{x^{(1)}, \ldots, x^{(N)}\}$ drawn i.i.d. from an unknown distribution $p_\text{data}(x)$. Your model defines a parameterized family $p_\theta(x)$. Training pushes $p_\theta$ toward $p_\text{data}$ — either by minimizing KL divergence (MLE), matching score functions, or adversarial game.

- **i.i.d.** — "independent and identically distributed": every example is drawn from the
  same source and none influences another.
- $p_\text{data}(x)$ — the true, unknown distribution nature used. You only see samples.
- $p_\theta(x)$ — your model's distribution; $\theta$ is the bag of adjustable numbers
  (weights) that shape it. A **parameterized family** is the set of all distributions you get
  by turning those knobs.
- **KL divergence** — a measure of how different two distributions are (zero when they
  match). Minimizing it is the same as **maximum likelihood estimation (MLE)**.
- **Score functions** — the slope of $\log p(x)$; diffusion models match these (ch. 7–8).

Once trained, you sample $x_\text{new} \sim p_\theta(x)$. If the model learned well, new samples are indistinguishable from training data.

The symbol $\sim$ reads "is drawn from". **Sampling** means asking the model for one random
new example, the way rolling a die samples from the numbers 1–6.

## Latent Variable Models

Most generators work in two steps: first pick a short random "recipe card" $z$, then expand
that card into a full data point $x$. The card is called the latent variable.

Most deep generative models introduce a latent variable $z$ — a compressed, structured code. The generative story is:

$$
z \sim p(z), \quad x \sim p_\theta(x|z)
$$

> **In plain words:** first draw a code $z$ from a simple distribution $p(z)$ (usually a
> standard bell curve). Then let a network turn that code into data, with
> $p_\theta(x|z)$ describing which $x$ comes out of which $z$.

A **latent variable** is a hidden quantity you never observe directly — "latent" means
hidden. For faces, one direction of $z$ might end up controlling smile, another hair colour.
Nobody labels these; the model discovers them.

> **Picture it:** $z$ is the DNA, $x$ is the organism. A few thousand letters of DNA expand
> into a whole creature. Different DNA, different creature; similar DNA, similar creatures.

The marginal $p_\theta(x) = \int p_\theta(x|z) p(z)\, dz$ is what you want to maximize, but the integral is intractable for high-dimensional $x$. Different models handle this differently:

The **marginal** $p_\theta(x)$ adds up the chance of $x$ over *every* code that could have made
it. **Intractable** means you cannot compute it in reasonable time: with a 100-dimensional
$z$ you would need to sum over a 100-dimensional space. Every model family below is a
different workaround:

- **VAE**: bound the integral with a variational lower bound (ELBO).
- **Flow**: make the mapping invertible so the integral becomes a change of variables.
- **Diffusion**: define a forward process that destroys $x$ into noise, learn to reverse it.
- **GAN**: skip the integral entirely, train a generator adversarially.

The next block shows the two-step story with a hand-written **decoder** — the function that
turns a code $z$ into data $x$. It is not trained; it only shows how a simple round cloud of
codes becomes a curved, twisted cloud of data.

```python
# Visualize the latent-variable picture
import numpy as np
rng = np.random.default_rng(42)

# Sample from a simple latent space (2D standard normal)
z = rng.normal(0, 1, (500, 2))

# A toy "decoder": nonlinear map from z to x (not trained)
def toy_decode(z):
    x1 = z[:, 0] * np.cos(z[:, 1]) - z[:, 1] * np.sin(z[:, 0])
    x2 = z[:, 0] * np.sin(z[:, 1]) + z[:, 1] * np.cos(z[:, 0])
    return np.stack([x1, x2], axis=1)

x = toy_decode(z)
print(f"Latent z: shape={z.shape}, mean={z.mean(axis=0).round(2)}")
print(f"Generated x: shape={x.shape}, mean={x.mean(axis=0).round(2)}")
print(f"x range: [{x.min():.2f}, {x.max():.2f}]")
```

```output
Latent z: shape=(500, 2), mean=[-0.02 -0.04]
Generated x: shape=(500, 2), mean=[-0.1   0.11]
x range: [-4.60, 3.85]
```

The first line shows the codes are what you asked for: 500 two-dimensional points with mean
close to 0 (the means are $-0.02$ and $-0.04$). After the decoder, the mean barely moved
($-0.1$, $0.11$), but the range stretched to $[-4.60, 3.85]$ — the non-linear map bent and
spread the cloud. A trained decoder does the same thing, except it bends the cloud into the
shape of real data.

## Applications

Knowing $p(x)$ — or being able to sample from it — turns out to power a surprising list of
products.

Generative models are the engine behind:

- **Image synthesis** — Stable Diffusion, Midjourney (latent diffusion).
- **Data augmentation** — generate more training examples for rare classes.
- **Anomaly detection** — an input with low $p_\theta(x)$ is anomalous.
- **Learned compression** — encode $x$ as $z$, store $z$, reconstruct with decoder.
- **Imputation** — condition on observed dimensions, sample missing ones.
- **Drug discovery** — generate molecules with desired properties.

**Anomaly detection** means spotting the odd one out (a fraudulent transaction, a broken
part). **Imputation** means filling in missing values. **Conditioning** on observed dimensions
means fixing the parts you know and sampling only the parts you don't.

> **Watch out:** anomaly detection with $p_\theta(x)$ is less reliable than it sounds. Deep
> likelihood models are known to give *higher* likelihood to some out-of-distribution inputs
> (for example, simple, smooth images) than to their own training data. Treat a low score as a
> hint, not proof.

The rest of this course builds each model family from scratch, starting with autoencoders (ch. 2), VAEs (ch. 3), GANs (ch. 4–5), flows (ch. 6), and diffusion (ch. 7–9).

After that come autoregressive models (ch. 10), which generate one piece at a time like a
language model, and evaluation metrics (ch. 11).

## Recap in plain words

- A discriminative model learns $p(y|x)$: it only draws the boundary between classes.
- A generative model learns $p(x)$: it can create, score, and complete inputs.
- Likelihood-based models (VAE, flow, diffusion) can score any input; implicit models (GAN)
  only produce samples.
- Most generators draw a simple random code $z$ and decode it into data $x$.
- The exact likelihood $p_\theta(x)$ is an intractable integral over $z$; each model family is a
  different trick around it.

## Try it Yourself

The experiment below is the smallest possible generative model: three bell curves with
hand-set centres, widths, and weights. "Sampling" is two steps — pick a bell curve by its
weight, then draw a number from it — exactly the latent-variable story with $z$ = "which bell".

```python
import numpy as np

rng = np.random.default_rng(7)

# Simple 1D generative model: Gaussian mixture
# "Training" = fit means and weights from data
data = np.concatenate([rng.normal(-3, 0.8, 200),
                        rng.normal(1, 0.5, 200),
                        rng.normal(4, 0.6, 100)])

# Fit a 3-component model (manually for illustration)
means = np.array([-3.0, 1.0, 4.0])
stds  = np.array([0.8, 0.5, 0.6])
weights = np.array([0.4, 0.4, 0.2])

# Sample from the model
component = rng.choice(3, size=50, p=weights)
samples = rng.normal(means[component], stds[component])
print("Generated samples (first 10):", samples[:10].round(2))
print(f"Generated mean: {samples.mean():.2f}, std: {samples.std():.2f}")
print(f"Data mean:      {data.mean():.2f}, std: {data.std():.2f}")
```

```output
Generated samples (first 10): [ 1.12 -2.89  0.93  3.74  1.28 -4.33  1.23 -2.81  1.14 -2.69]
Generated mean: -0.62, std: 2.53
Data mean:      -0.08, std: 2.75
```

The first line shows the samples land near the three centres ($-3$, 1, and 4). The statistics
are close but not equal: generated mean $-0.62$ vs data mean $-0.08$. With only 50 samples, the
luck of which bell gets picked moves the mean a lot. Change `size=50` to `size=5000` and the
generated mean and std should settle near the data's. Then try wrong weights such as
`[0.2, 0.2, 0.6]` and watch the mean drift toward 4.

## Exercise

You observe 1000 data points drawn from a Gaussian mixture. Without sklearn, write code to estimate the mixture means and weights using the sample mean and a histogram. Then draw 100 new samples from your estimated model and verify the sample statistics are close to the original.

> **Hint:** a histogram shows two humps with an empty valley between them. Pick a split point
> in the valley, then treat each side as one bell curve: its mean, std, and share of the points
> are your component parameters.

<summary>Solution</summary>

```python
import numpy as np

rng = np.random.default_rng(0)
data = np.concatenate([rng.normal(-2, 1.0, 500), rng.normal(3, 0.8, 500)])

# Rough two-component fit: split at 0
left = data[data < 0.5]
right = data[data >= 0.5]
w_left = len(left) / len(data)
w_right = len(right) / len(data)

mu_left, s_left   = left.mean(), left.std()
mu_right, s_right = right.mean(), right.std()

print(f"Left component:  mu={mu_left:.2f}, sigma={s_left:.2f}, weight={w_left:.2f}")
print(f"Right component: mu={mu_right:.2f}, sigma={s_right:.2f}, weight={w_right:.2f}")

# Sample 100 points
comp = rng.choice([0,1], size=100, p=[w_left, w_right])
samples = np.where(comp==0,
                   rng.normal(mu_left, s_left, 100),
                   rng.normal(mu_right, s_right, 100))
print(f"\nOriginal: mean={data.mean():.2f}, std={data.std():.2f}")
print(f"Samples:  mean={samples.mean():.2f}, std={samples.std():.2f}")
```

Splitting the data at $x = 0.5$ (the valley between the humps at $-2$ and 3) gives a good
approximation of the two components: running it recovers $\mu = -2.04, \sigma = 0.99$ and
$\mu = 2.93, \sigma = 0.77$, each with weight 0.50, very close to the true $(-2, 1)$ and
$(3, 0.8)$. The 100 samples have mean 0.15 and std 2.52 against the data's 0.46 and 2.64 —
close, with the gap coming from drawing only 100 points. The key insight is that fitting $p(x)$ lets you generate new points — the core promise of generative modeling.
