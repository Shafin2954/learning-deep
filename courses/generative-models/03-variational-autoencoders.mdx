## The Probabilistic View

A plain autoencoder maps each input to one exact point. A variational autoencoder maps each
input to a small fuzzy cloud of points instead, and that fuzziness is what fills in the gaps
from ch. 2.

A VAE frames the autoencoder problem probabilistically. The encoder is no longer a deterministic function; it outputs the parameters of a distribution over $z$:

$$
q_\phi(z|x) = \mathcal{N}(\mu_\phi(x),\, \text{diag}(\sigma^2_\phi(x)))
$$

> **In plain words:** for an input $x$, the encoder outputs two vectors: a centre $\mu$ and a
> spread $\sigma$ for every code dimension. The code is then "somewhere in a bell curve around
> $\mu$, about $\sigma$ wide". $\text{diag}$ means each dimension gets its own independent spread,
> with no correlations between dimensions.

A **deterministic** function always gives the same output for the same input. The VAE
encoder $q_\phi(z|x)$ is not: it describes a *range* of plausible codes.

> **Picture it:** instead of sticking a pin in the map for each training image, you drop a
> blob of paint. Blobs from neighbouring images overlap and cover the farmland between
> neighbourhoods, so the decoder learns what lives there too.

The decoder defines a conditional likelihood $p_\theta(x|z)$. The true posterior $p(z|x)$ is intractable (requires integrating out all possible $z$), so you approximate it with $q_\phi(z|x)$ — variational inference.

The **posterior** $p(z|x)$ is the exact answer to "which codes could have produced this $x$?"
under the model. Computing it needs the intractable marginal from ch. 1. **Variational
inference** replaces it with a simple stand-in distribution $q_\phi$ and tunes $\phi$ until the
stand-in is as close as possible.

## The ELBO

You can't compute the true score $\log p_\theta(x)$, but you can compute a number that is always
below it. Pushing that floor up pushes the real score up with it.

Maximizing $\log p_\theta(x)$ directly is intractable. Instead, maximize the **Evidence Lower BOund (ELBO)**:

$$
\mathcal{L}(\phi, \theta; x) = \underbrace{\mathbb{E}_{q_\phi(z|x)}[\log p_\theta(x|z)]}_{\text{reconstruction}} - \underbrace{\text{KL}(q_\phi(z|x) \| p(z))}_{\text{regularization}}
$$

- **Reconstruction term**: how well the decoder recovers $x$ from a sampled $z$.
- **KL term**: forces the approximate posterior $q_\phi(z|x)$ toward the standard Gaussian prior $p(z)=\mathcal{N}(0,I)$.

> **In plain words:** ELBO = (how well can you rebuild $x$ from a code drawn from its cloud?)
> minus (how far is that cloud from a plain standard bell curve?). The first part wants
> sharp, informative codes. The second part wants every cloud to look like the same
> featureless bell. Training balances the two.

"Evidence" is another name for $\log p_\theta(x)$. The **prior** $p(z)$ is what you assume codes
look like before seeing any data — here a standard normal $\mathcal{N}(0, I)$. Because every
cloud is pulled toward that one bell, at generation time you can draw $z$ from $\mathcal{N}(0, I)$
and land somewhere the decoder knows.

> **Picture it:** a sculptor with a strict budget. The reconstruction term pays for detail;
> the KL term is the tax on deviating from a plain block. A high tax gives smooth, generic
> sculptures; a low tax gives detailed ones that might not fit together.

With a Gaussian $q_\phi$ and standard Gaussian prior, the KL has a closed form:

$$
\text{KL}(q_\phi(z|x) \| p(z)) = -\frac{1}{2}\sum_{j=1}^{d_z}(1 + \log\sigma_j^2 - \mu_j^2 - \sigma_j^2)
$$

> **In plain words:** for each code dimension $j$ (there are $d_z$ of them), the cost is zero
> exactly when $\mu_j = 0$ and $\sigma_j = 1$. Moving the centre away from 0 adds $\mu_j^2$;
> making the spread too narrow or too wide makes $\sigma_j^2 - \log\sigma_j^2 - 1$ positive.

A **closed form** is a formula you can evaluate directly, with no sampling or integration. The
code below works with $\log\sigma^2$ (called `log_var`) rather than $\sigma$, because a network
output can be any real number, while $\sigma$ must be positive.

```python
import torch

def kl_divergence_gaussian(mu, log_var):
    """Closed-form KL(N(mu, sigma^2) || N(0, 1)) per dimension, summed."""
    return -0.5 * torch.sum(1 + log_var - mu.pow(2) - log_var.exp(), dim=1)

mu      = torch.tensor([[0.5, -0.3, 1.2]])
log_var = torch.tensor([[-0.4, 0.1, -0.8]])

kl = kl_divergence_gaussian(mu, log_var)
print(f"mu:      {mu.numpy().round(2)}")
print(f"log_var: {log_var.numpy().round(2)}")
print(f"KL:      {kl.item():.4f}")
# At mu=0, log_var=0: KL should be 0
print(f"KL at (0,0): {kl_divergence_gaussian(torch.zeros(1,3), torch.zeros(1,3)).item():.4f}")
```

```output
mu:      [[ 0.5 -0.3  1.2]]
log_var: [[-0.4  0.1 -0.8]]
KL:      1.0524
KL at (0,0): -0.0000
```

The total KL is 1.0524. Splitting it by hand, the three dimensions contribute about 0.160,
0.048, and 0.845 — the third dimension, with $\mu = 1.2$ far from 0, pays most of the bill. The
last line checks the formula's anchor: at $\mu = 0, \log\sigma^2 = 0$ the KL is 0 (the
"$-0.0000$" is a floating-point zero with a sign bit, not a negative number).

## The Reparameterization Trick

Gradients can't flow through a dice roll. The trick: roll the dice *first*, with no learnable
parts, then move and stretch the result with learnable numbers. Moving and stretching can be
differentiated.

To backpropagate through a sample $z \sim q_\phi(z|x)$, you can't differentiate through the sampling operation. The reparameterization trick rewrites sampling as a deterministic function:

$$
z = \mu_\phi(x) + \sigma_\phi(x) \odot \epsilon, \quad \epsilon \sim \mathcal{N}(0, I)
$$

> **In plain words:** draw plain noise $\epsilon$ from a standard bell curve, multiply it by the
> spread $\sigma$, and add the centre $\mu$. The symbol $\odot$ means element-by-element
> multiplication.

The randomness is in $\epsilon$ (not a function of $\phi$), so gradients flow through $\mu$ and $\sigma$ normally.

> **Picture it:** a dart thrower with a fixed shaky hand ($\epsilon$). You can't train the shake,
> but you can move where they stand ($\mu$) and how far back they stand ($\sigma$). Both of those
> are smooth knobs you can tune by gradient.

The encoder below computes `(0.5 * log_var).exp()`, which is $\sqrt{\sigma^2} = \sigma$.

```python
import torch
import torch.nn as nn
torch.manual_seed(0)

class VAEEncoder(nn.Module):
    def __init__(self, input_dim=784, hidden=256, latent_dim=16):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(input_dim, hidden), nn.ReLU())
        self.mu_head      = nn.Linear(hidden, latent_dim)
        self.log_var_head = nn.Linear(hidden, latent_dim)

    def forward(self, x):
        h = self.net(x)
        mu, log_var = self.mu_head(h), self.log_var_head(h)
        # Reparameterize
        eps = torch.randn_like(mu)
        z   = mu + (0.5 * log_var).exp() * eps
        return z, mu, log_var

enc = VAEEncoder(784, 256, 16)
x   = torch.rand(4, 784)
z, mu, log_var = enc(x)
print(f"z shape:       {z.shape}")
print(f"mu range:      [{mu.min():.3f}, {mu.max():.3f}]")
print(f"sigma range:   [{(0.5*log_var).exp().min():.3f}, {(0.5*log_var).exp().max():.3f}]")
print(f"z has grad_fn: {z.grad_fn is not None}")   # gradients flow
```

```output
z shape:       torch.Size([4, 16])
mu range:      [-0.273, 0.300]
sigma range:   [0.877, 1.183]
z has grad_fn: True
```

The untrained encoder outputs centres between $-0.273$ and $0.300$ and spreads between 0.877 and
1.183 — close to the prior already, since random weights give small outputs and
$e^{0} = 1$. The key line is the last: `z has grad_fn: True` means PyTorch recorded how $z$ was
computed from $\mu$ and $\sigma$, so a loss on $z$ can send gradients back into the encoder.

> **Watch out:** if you write `z = torch.normal(mu, sigma)` instead, the result still carries a
> `grad_fn`, but the gradients it sends back to `mu` and `sigma` are all zeros, so the encoder
> silently never learns. Always sample $\epsilon$ separately and combine (or use
> `torch.distributions.Normal(mu, sigma).rsample()`, which does exactly that).

## Full VAE

Put the probabilistic encoder, the reparameterized sample, and a decoder together, and the
loss is the negative ELBO.

The reconstruction term uses **binary cross-entropy (BCE)** — the right log-likelihood when
each pixel is treated as a probability between 0 and 1. `reduction='sum'` adds the error over
all 784 pixels, so it lives on the same scale as the KL (which is also summed), and the total
is divided by the batch size.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
torch.manual_seed(0)

class VAE(nn.Module):
    def __init__(self, input_dim=784, hidden=256, latent_dim=16):
        super().__init__()
        self.enc_net      = nn.Sequential(nn.Linear(input_dim, hidden), nn.ReLU())
        self.mu_head      = nn.Linear(hidden, latent_dim)
        self.log_var_head = nn.Linear(hidden, latent_dim)
        self.decoder      = nn.Sequential(
            nn.Linear(latent_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, input_dim), nn.Sigmoid()
        )

    def encode(self, x):
        h = self.enc_net(x)
        return self.mu_head(h), self.log_var_head(h)

    def reparameterize(self, mu, log_var):
        return mu + (0.5 * log_var).exp() * torch.randn_like(mu)

    def forward(self, x):
        mu, log_var = self.encode(x)
        z = self.reparameterize(mu, log_var)
        recon = self.decoder(z)
        return recon, mu, log_var

def vae_loss(recon, x, mu, log_var, beta=1.0):
    bce = F.binary_cross_entropy(recon, x, reduction='sum')
    kl  = -0.5 * torch.sum(1 + log_var - mu.pow(2) - log_var.exp())
    return (bce + beta * kl) / x.size(0)

vae = VAE(784, 256, 16)
x   = torch.rand(32, 784)
recon, mu, log_var = vae(x)
loss = vae_loss(recon, x, mu, log_var)
print(f"ELBO loss: {loss.item():.2f}")
print(f"Recon shape: {recon.shape}, mu shape: {mu.shape}")
```

```output
ELBO loss: 549.95
Recon shape: torch.Size([32, 784]), mu shape: torch.Size([32, 16])
```

The printed "ELBO loss" of 549.95 is the *negative* ELBO per example: smaller is better. It is
large because it sums over 784 pixels. The shapes confirm the plumbing: 32 reconstructions of 784
pixels and 32 code centres of 16 numbers.

> **Watch out:** the ELBO is something you *maximize*; the loss you *minimize* is its negative.
> Papers and code often call both "the ELBO". Check the sign before comparing numbers.

## Training a VAE

Training is the usual loop on the negative ELBO. Here it runs on 4000 random-noise vectors.

```python
import torch
import torch.nn.functional as F
from torch.utils.data import DataLoader, TensorDataset

torch.manual_seed(0)
X = torch.rand(4000, 784)
loader = DataLoader(TensorDataset(X), batch_size=128, shuffle=True)

vae = VAE(784, 256, 16)
opt = torch.optim.Adam(vae.parameters(), lr=1e-3)

for epoch in range(1, 6):
    epoch_loss = 0
    for (x,) in loader:
        recon, mu, log_var = vae(x)
        loss = vae_loss(recon, x, mu, log_var)
        opt.zero_grad(); loss.backward(); opt.step()
        epoch_loss += loss.item() * len(x)
    print(f"Epoch {epoch}  ELBO={epoch_loss/len(X):.1f}")
```

```output
Epoch 1  ELBO=545.9
Epoch 2  ELBO=544.6
Epoch 3  ELBO=544.3
Epoch 4  ELBO=544.2
Epoch 5  ELBO=544.1
```

The loss barely moves: 545.9 to 544.1. As in ch. 2, random noise has no structure to learn. You
can compute the floor exactly: a decoder that outputs 0.5 for every pixel pays a BCE of
$\log 2 \approx 0.693$ per pixel, and $784 \times 0.693 \approx 543.4$. The VAE sits about 0.7
above that floor, which is the small KL it still pays. On real images the loss would fall far
below the "predict 0.5" floor.

## Posterior Collapse and β-VAE

Sometimes the VAE's tax on informative codes wins, and the encoder gives up on some code
dimensions entirely — they carry no information about the input.

**Posterior collapse**: some latent dimensions learn $q_\phi(z_j|x) \approx p(z_j) = \mathcal{N}(0,1)$ — the encoder ignores them. The decoder then ignores those dimensions too. You end up with fewer effective latent dimensions than you asked for.

> **Picture it:** a group project where one teammate's slides are blank. The presenter learns
> to skip them. Nobody is graded on those slides, so they stay blank.

**β-VAE**: multiply the KL term by $\beta > 1$ to push for more disentangled representations. Higher $\beta$ trades reconstruction quality for disentanglement — each $z_j$ controls one factor of variation.

A representation is **disentangled** when each code dimension controls one understandable
factor — one for rotation, one for size, one for colour — instead of all being mixed. The
`beta` argument of `vae_loss` above is exactly this multiplier.

The check below applies the collapse rule (centre near 0 and spread near 1) to four example
dimensions:

```python
import torch
from torch.distributions import Normal

# Check if a latent dimension has collapsed
# A collapsed dim: encoder mean ≈ 0, encoder sigma ≈ 1
mu_vals      = torch.tensor([0.02, 0.85, -0.01, 0.63])   # means for 4 dims
sigma_vals   = torch.tensor([1.01, 0.30,  0.99, 0.55])   # sigmas

for i, (m, s) in enumerate(zip(mu_vals, sigma_vals)):
    collapsed = abs(m) < 0.1 and abs(s - 1.0) < 0.1
    print(f"Dim {i}: mu={m:.2f}, sigma={s:.2f}  {'(COLLAPSED)' if collapsed else '(active)'}")
```

```output
Dim 0: mu=0.02, sigma=1.01  (COLLAPSED)
Dim 1: mu=0.85, sigma=0.30  (active)
Dim 2: mu=-0.01, sigma=0.99  (COLLAPSED)
Dim 3: mu=0.63, sigma=0.55  (active)
```

Dimensions 0 and 2 have $\mu$ within 0.02 of zero and $\sigma$ within 0.01 of one, so they are
flagged as collapsed: they look identical to the prior and carry no information. Dimensions 1
and 3 have shifted centres (0.85, 0.63) and narrow spreads (0.30, 0.55), meaning the encoder is
pinning down a specific value per input.

> **Watch out:** in real use, measure collapse over a whole dataset — per-dimension *average*
> KL, or the variance of $\mu_j$ across inputs. One input's $\mu$ near zero is not enough; a
> dimension is collapsed only if it is near the prior for *every* input.

## Recap in plain words

- A VAE encoder outputs a bell curve (centre and spread) for each input, not a single point.
- The ELBO = reconstruction quality minus the KL cost of differing from a standard bell curve;
  it is a guaranteed lower bound on $\log p_\theta(x)$.
- The KL between two Gaussians has a closed form, zero at $\mu = 0, \sigma = 1$.
- The reparameterization trick ($z = \mu + \sigma \odot \epsilon$) lets gradients pass through
  sampling.
- Posterior collapse is when code dimensions copy the prior and carry nothing; $\beta$ scales the
  KL to trade detail for disentanglement.

## Try it Yourself

This is a tiny VAE (8 inputs, 2-number code) trained for 200 full-batch steps, then used as a
generator: draw $z$ from the prior and decode.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

# Train a tiny VAE and sample from the prior
class TinyVAE(nn.Module):
    def __init__(self):
        super().__init__()
        self.enc = nn.Linear(8, 4)
        self.mu  = nn.Linear(4, 2)
        self.lv  = nn.Linear(4, 2)
        self.dec = nn.Sequential(nn.Linear(2, 4), nn.ReLU(), nn.Linear(4, 8), nn.Sigmoid())
    def forward(self, x):
        h = F.relu(self.enc(x))
        mu, lv = self.mu(h), self.lv(h)
        z = mu + (0.5*lv).exp() * torch.randn_like(mu)
        return self.dec(z), mu, lv

torch.manual_seed(5)
X = torch.rand(500, 8)
model = TinyVAE()
opt = torch.optim.Adam(model.parameters(), lr=1e-3)

for _ in range(200):
    recon, mu, lv = model(X)
    kl   = -0.5 * torch.sum(1 + lv - mu**2 - lv.exp()) / len(X)
    bce  = F.mse_loss(recon, X)
    (bce + kl).backward(); opt.step(); opt.zero_grad()

# Sample from prior
with torch.no_grad():
    z_prior = torch.randn(5, 2)
    samples = model.dec(z_prior)
    print("Samples from prior (5 × 8):")
    print(samples.numpy().round(2))
```

```output
Samples from prior (5 × 8):
[[0.49 0.57 0.44 0.56 0.51 0.49 0.49 0.51]
 [0.48 0.55 0.49 0.53 0.5  0.49 0.46 0.51]
 [0.5  0.57 0.42 0.55 0.52 0.49 0.5  0.51]
 [0.49 0.56 0.47 0.51 0.52 0.49 0.48 0.51]
 [0.49 0.56 0.49 0.49 0.52 0.49 0.46 0.51]]
```

Every generated value sits between 0.42 and 0.57 — the samples are all close to 0.5, the average
of uniform data. That is the honest outcome on structureless data: there is nothing to encode,
so the KL term wins and the decoder outputs the mean. Note the code uses `F.mse_loss` (a mean
over 8 values) against a KL summed over 2 dimensions, so the KL is weighted much more heavily
than in the BCE version. Try multiplying the MSE by 8 (sum instead of mean), or replace `X` with
structured data such as `torch.rand(500, 1).repeat(1, 8)`, and watch the sample rows become
different from each other.

## Exercise

Implement the KL annealing trick: start training with $\beta=0$ (pure reconstruction) and linearly increase $\beta$ to 1 over the first 10 epochs. Train a VAE on the synthetic data below and compare the fraction of collapsed latent dimensions at epoch 1 vs epoch 20 with and without annealing.

> **Hint:** compute `beta = min(1.0, epoch / 10)` at the start of each epoch and multiply the
> KL by it. Run the loop twice — once with that schedule, once with `beta = 1.0` throughout —
> and count dimensions whose average $|\mu|$ stays below 0.1.

<summary>Solution</summary>

```python
import torch
import torch.nn.functional as F

torch.manual_seed(0)
X = torch.rand(1000, 64)
vae = VAE(64, 128, 8)
opt = torch.optim.Adam(vae.parameters(), lr=1e-3)

def count_collapsed(mu, threshold=0.1):
    """Count dims where mean is near-zero across the batch (proxy for collapse)."""
    return (mu.abs().mean(0) < threshold).sum().item()

for epoch in range(1, 21):
    beta = min(1.0, epoch / 10)    # anneal from 0 to 1 over 10 epochs
    for i in range(0, len(X), 128):
        x = X[i:i+128]
        recon, mu, lv = vae(x)
        kl  = -0.5 * torch.sum(1 + lv - mu.pow(2) - lv.exp()) / len(x)
        rec = F.mse_loss(recon, x)
        (rec + beta * kl).backward(); opt.step(); opt.zero_grad()
    if epoch in (1, 10, 20):
        with torch.no_grad():
            _, mu, _ = vae(X)
            print(f"Epoch {epoch:2d}  beta={beta:.1f}  collapsed_dims={count_collapsed(mu)}/8")
```

KL annealing lets the reconstruction loss establish useful representations before the KL term collapses unused dimensions. Without annealing, many dimensions collapse immediately in early training.

Run on this data, though, the annealed model reports `collapsed_dims=8/8` at epochs 1, 10 and 20.
That is the right answer for uniform noise: there is no shared structure to encode, so
whatever the schedule, the KL eventually wins on every dimension. (Note also that the schedule
starts at $\beta = 0.1$, not 0, because epoch 1 gives $1/10$.) To see annealing help, use data
with real structure — for example, 8-dimensional vectors generated from 2 hidden factors — and
compare the two runs: the annealed one typically keeps more dimensions active.
