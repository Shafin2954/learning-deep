## Every metric is a summary of one table

A yes/no model can be right in two ways and wrong in two ways. Count all four, put them in a
2-by-2 table, and every classification metric you will ever meet is a ratio of numbers in
that table.

That table is the **confusion matrix** — a grid that counts, for every row of data, what the
model said versus what was true. Its four cells have names:

- **True positive (TP)** — the model said "yes" and the answer was yes (a correct catch).
- **False positive (FP)** — the model said "yes" but the answer was no (a false alarm).
- **False negative (FN)** — the model said "no" but the answer was yes (a miss).
- **True negative (TN)** — the model said "no" and the answer was no (a correct pass).

The confusion matrix holds everything; each metric is a different ratio taken from it. Learn to
read the table and you never have to memorize a formula again.

> **Picture it:** a metal detector at an airport. TP: it beeps and the bag has a knife. FP: it
> beeps at a belt buckle. FN: a knife walks through in silence. TN: a clean bag walks through
> in silence. Every "how good is this detector?" number is a way of comparing those four piles.

The demo below builds a synthetic problem with 20,000 rows where only 3% are positives — the
**prevalence**, meaning the share of rows whose true answer is "yes". The model's score is
higher on average for positives (0.70) than negatives (0.25), but with noise, so it makes mistakes.
A **threshold** turns the score into a decision: score at or above 0.5 means "yes".

```python
import numpy as np
rng = np.random.default_rng(0)

n, prevalence = 20_000, 0.03                      # 3% positives: a realistic imbalance
y = (rng.random(n) < prevalence).astype(int)
score = np.clip(rng.normal(0.25 + 0.45 * y, 0.18), 0, 1)     # a decent but imperfect model

def confusion(y, pred):
    tp = int(((pred == 1) & (y == 1)).sum()); fp = int(((pred == 1) & (y == 0)).sum())
    fn = int(((pred == 0) & (y == 1)).sum()); tn = int(((pred == 0) & (y == 0)).sum())
    return tp, fp, fn, tn

pred = (score >= 0.5).astype(int)
tp, fp, fn, tn = confusion(y, pred)
print(f"{'':12}{'pred 1':>9}{'pred 0':>9}")
print(f"{'actual 1':12}{tp:>9,}{fn:>9,}")
print(f"{'actual 0':12}{fp:>9,}{tn:>9,}")
print(f"\nprevalence {y.mean():.3f} | predicted positive rate {pred.mean():.3f}")
```

```output
               pred 1   pred 0
actual 1          500       89
actual 0        1,626   17,785

prevalence 0.029 | predicted positive rate 0.106
```

Read the table row by row. Of the 589 real positives (500 + 89), the model caught 500 and
missed 89. Of the 19,411 real negatives, it falsely flagged 1,626. The sample prevalence came
out at 0.029 (close to the 3% we asked for), yet the model flags 10.6% of all rows — more than
three times as many as are really positive.

Now the three headline ratios. Each one asks a different question of the same table:

$$
\text{precision} = \frac{TP}{TP + FP}, \quad
\text{recall} = \frac{TP}{TP + FN}, \quad
F_1 = \frac{2 \cdot P \cdot R}{P + R}
$$

> **In plain words:** **precision** — of everything I flagged, what fraction was real
> ($TP$ over all predicted yeses). **Recall** — of everything real, what fraction did I flag
> ($TP$ over all actual yeses). **$F_1$** — the **harmonic mean** of the two, an average that
> is dragged down hard by whichever of $P$ (precision) and $R$ (recall) is smaller, so you
> cannot score well by maxing one and ignoring the other.

Two more ratios appear below. **Accuracy** is the share of all rows the model got right,
$(TP+TN)$ over everything. **Specificity** is recall for the negative class: of all real
negatives, what fraction did the model correctly leave alone.

```python
def metrics(y, pred):
    tp, fp, fn, tn = confusion(y, pred)
    prec = tp / (tp + fp) if tp + fp else 0.0
    rec = tp / (tp + fn) if tp + fn else 0.0
    f1 = 2 * prec * rec / (prec + rec) if prec + rec else 0.0
    return {"accuracy": (tp + tn) / len(y), "precision": prec, "recall": rec, "f1": f1,
            "specificity": tn / (tn + fp) if tn + fp else 0.0}

for name, value in metrics(y, pred).items():
    print(f"{name:12} {value:.4f}")
print(f"\n{'always predict 0':16} accuracy {metrics(y, np.zeros(n, int))['accuracy']:.4f} "
      f"<- beats nothing, and is useless")
```

```output
accuracy     0.9143
precision    0.2352
recall       0.8489
f1           0.3683
specificity  0.9162

always predict 0 accuracy 0.9706 <- beats nothing, and is useless
```

Look at the numbers side by side. Recall is high (0.849: most positives are caught), but
precision is low (0.235: fewer than 1 in 4 flags is real). Accuracy reads a healthy 0.9143. And
the last line is the punchline: a "model" that answers "no" to everything scores 0.9706 accuracy
— *higher* than the real model — while catching zero positives.

That last line is why **accuracy is the wrong default metric on imbalanced data**: a model that
predicts "no" every time scores 97% and catches nothing. Accuracy only means something when the
classes are balanced *and* both error types cost the same.

> **Watch out:** **imbalanced data** — where one class is much rarer than the other — is the
> normal case in fraud, medicine, churn, and ads. Any time you see a high accuracy on such a
> problem, compare it against the "always predict the common class" baseline first.

## Precision and recall answer different questions

Precision worries about false alarms; recall worries about misses. You can usually buy more
of one by paying with the other, and the price tag is the threshold.

- **Precision**: of the cases I flagged, how many were real? — the cost of a false alarm.
- **Recall**: of the real cases, how many did I catch? — the cost of a miss.

> **Picture it:** a fishing net. A net with big holes (high threshold) only lands the big fish
> you are sure about — high precision, but many fish slip through (low recall). A net with tiny
> holes (low threshold) catches every fish — high recall — along with boots, weeds, and
> plastic bags (low precision).

The loop below keeps the same scores and moves only the threshold:

```python
for thresh in (0.3, 0.5, 0.7, 0.9):
    m = metrics(y, (score >= thresh).astype(int))
    flagged = int((score >= thresh).sum())
    print(f"threshold {thresh:.1f} -> flagged {flagged:>6,} | precision {m['precision']:.3f} "
          f"| recall {m['recall']:.3f} | F1 {m['f1']:.3f}")
```

```output
threshold 0.3 -> flagged  8,179 | precision 0.071 | recall 0.988 | F1 0.133
threshold 0.5 -> flagged  2,126 | precision 0.235 | recall 0.849 | F1 0.368
threshold 0.7 -> flagged    432 | precision 0.644 | recall 0.472 | F1 0.545
threshold 0.9 -> flagged     76 | precision 0.895 | recall 0.115 | F1 0.205
```

Follow one column at a time. As the threshold climbs from 0.3 to 0.9, the number flagged
drops from 8,179 to 76, precision rises from 0.071 to 0.895, and recall falls from 0.988 to
0.115. $F_1$ peaks in the middle (0.545 at 0.7) because that is where neither side has
collapsed.

One model, four operating points, wildly different behaviour. **A classifier is not a single
model but a family of decisions indexed by a threshold**, which is why threshold-free metrics
(ROC AUC, PR AUC) and threshold selection (ch. 3) are separate topics.

> **Watch out:** "the model has 0.85 recall" is meaningless without the threshold. Always
> report the threshold alongside precision, recall, and $F_1$.

## ROC and PR curves

Instead of picking one threshold, you can try every threshold and draw a line through all
the results. The area under that line becomes a single score that does not depend on any
threshold choice.

The ROC curve plots recall (true positive rate) against the false positive rate; the PR curve
plots precision against recall. Both sweep every threshold, and they behave very differently
under class imbalance.

The terms, in plain words:

- **True positive rate (TPR)** — another name for recall: the share of real positives caught.
- **False positive rate (FPR)** — the share of real negatives wrongly flagged, $FP/(FP+TN)$.
- **ROC curve** (receiver operating characteristic) — TPR on the vertical axis, FPR on the
  horizontal, one point per threshold.
- **PR curve** — precision on the vertical axis, recall on the horizontal.
- **AUC** (area under the curve) — the area beneath either curve; 1.0 is perfect.

The code sorts rows from highest score to lowest, then counts TPs and FPs cumulatively: each
step down the list is "lower the threshold to include one more row". `np.trapezoid` adds up the
area under the resulting points.

```python
def curve_points(y, score, kind="roc"):
    order = np.argsort(-score)
    ys = y[order]
    tp = np.cumsum(ys); fp = np.cumsum(1 - ys)
    P, N = ys.sum(), len(ys) - ys.sum()
    if kind == "roc":
        return fp / N, tp / P
    return tp / P, tp / np.maximum(tp + fp, 1)      # recall, precision

def auc(x, y_):
    return float(np.trapezoid(y_, x))

fpr, tpr = curve_points(y, score, "roc")
rec, prec = curve_points(y, score, "pr")
print(f"ROC AUC {auc(fpr, tpr):.4f}")
print(f"PR  AUC {auc(rec, prec):.4f}   (baseline = prevalence = {y.mean():.4f})")
print(f"\nROC baseline is always 0.5, whatever the prevalence — that is the trap")
```

```output
ROC AUC 0.9579
PR  AUC 0.5949   (baseline = prevalence = 0.0295)

ROC baseline is always 0.5, whatever the prevalence — that is the trap
```

ROC AUC is 0.9579 — it sounds excellent. PR AUC is 0.5949, which sounds mediocre. Both are
correct, because they measure against different floors. A random-guessing model has ROC AUC
0.5 always, but PR AUC equal to the prevalence (0.0295 here). Against a floor of 0.03, a PR AUC
of 0.59 is a 20-fold improvement.

> **Picture it:** ROC AUC has a useful meaning of its own. It equals the chance that a randomly
> picked positive gets a higher score than a randomly picked negative. Here, 96 times out of
> 100 the real positive outranks the negative.

Next, the same kind of model is tested at four prevalences, from balanced (50%) down to one
positive in a thousand (0.1%). The model's ability to separate the classes stays the same;
only the class ratio changes.

```python
def compare_imbalance(prev, seed=1):
    r = np.random.default_rng(seed)
    m = 40_000
    yy = (r.random(m) < prev).astype(int)
    ss = np.clip(r.normal(0.25 + 0.45 * yy, 0.18), 0, 1)
    f, t = curve_points(yy, ss, "roc")
    rc, pr = curve_points(yy, ss, "pr")
    print(f"prevalence {prev:6.3%} -> ROC AUC {auc(f, t):.4f} | PR AUC {auc(rc, pr):.4f} "
          f"| PR baseline {prev:.4f}")

for p in (0.5, 0.1, 0.01, 0.001):
    compare_imbalance(p)
```

```output
prevalence 50.000% -> ROC AUC 0.9615 | PR AUC 0.9622 | PR baseline 0.5000
prevalence 10.000% -> ROC AUC 0.9599 | PR AUC 0.8068 | PR baseline 0.1000
prevalence 1.000% -> ROC AUC 0.9637 | PR AUC 0.4802 | PR baseline 0.0100
prevalence 0.100% -> ROC AUC 0.9778 | PR AUC 0.2734 | PR baseline 0.0010
```

Read the two AUC columns. ROC AUC stays around 0.96 at every prevalence (it even ticks up to
0.9778 at 0.1%, but that row rests on only about 40 positives, so it is noisy). PR AUC slides
from 0.9622 to 0.8068 to 0.4802 to 0.2734.

The same *separation* gives essentially the same ROC AUC at every prevalence, while PR AUC
collapses as positives get rarer. That is not a defect of PR — it is the honest signal.
**On rare-positive problems, report PR AUC (or precision at a fixed recall) and treat a high ROC
AUC with suspicion**, because the enormous negative class makes the false positive rate look
small no matter how many false alarms you actually produce.

The next demo makes that last sentence concrete: same threshold (0.55), same FPR, two
prevalences.

```python
thresh = 0.55
for prev in (0.5, 0.01):
    r = np.random.default_rng(2)
    m = 40_000
    yy = (r.random(m) < prev).astype(int)
    ss = np.clip(r.normal(0.25 + 0.45 * yy, 0.18), 0, 1)
    pp = (ss >= thresh).astype(int)
    tp_, fp_, fn_, tn_ = confusion(yy, pp)
    mm = metrics(yy, pp)
    print(f"prevalence {prev:5.1%}: FPR {fp_/(fp_+tn_):.4f} (looks tiny) but "
          f"precision {mm['precision']:.3f} — {fp_:,} false alarms for {tp_:,} true ones")
```

```output
prevalence 50.0%: FPR 0.0461 (looks tiny) but precision 0.945 — 921 false alarms for 15,897 true ones
prevalence  1.0%: FPR 0.0462 (looks tiny) but precision 0.144 — 1,830 false alarms for 309 true ones
```

Both rows have an FPR of about 0.046 — under 5% of negatives are flagged. At 50% prevalence that
means 921 false alarms next to 15,897 true ones, so precision is 0.945. At 1% prevalence there
are 99 times as many negatives as positives, so the same 4.6% becomes 1,830 false alarms next to
only 309 true ones, and precision falls to 0.144. FPR divides by the huge negative count, which
hides the damage; precision does not.

> **Watch out:** "our FPR is only 5%" is the classic way rare-event models get oversold. Ask
> how many false alarms that is *per true catch*.

## Averaging in the multi-class case

With more than two classes, you compute precision, recall, and $F_1$ for each class separately
(that class versus everything else), and then you have to choose how to average the per-class
numbers into one score. The choice changes the answer.

The three averages:

- **Macro average** — the plain mean over classes; every class counts once, whatever its size.
- **Weighted average** — the mean weighted by **support** (the number of true rows in each class).
- **Micro average** — pool all TPs, FPs, and FNs across classes first, then compute the ratio once.

> **Picture it:** a school with three big classes of 30 students and one small class of 5. The
> macro average asks "how is each class doing?" and gives the small class one vote in four.
> The weighted average asks "how is the average student doing?" and gives the small class 5
> votes in 95.

The demo builds 4 classes and then throws away 85% of class 3, making it rare.

```python
K = 4
yk = rng.integers(0, K, 6_000)
logits = rng.normal(0, 1, (6_000, K))
logits[np.arange(6_000), yk] += 1.6                 # the true class gets a boost
pred_k = logits.argmax(1)

keep = np.ones(6_000, bool)
keep[(yk == 3) & (rng.random(6_000) < 0.85)] = False    # make class 3 rare
yk, pred_k = yk[keep], pred_k[keep]

def per_class(y, pred, k):
    tp = int(((pred == k) & (y == k)).sum())
    fp = int(((pred == k) & (y != k)).sum())
    fn = int(((pred != k) & (y == k)).sum())
    p = tp / (tp + fp) if tp + fp else 0.0
    r = tp / (tp + fn) if tp + fn else 0.0
    return p, r, (2 * p * r / (p + r) if p + r else 0.0), tp + fn

rows = [per_class(yk, pred_k, k) for k in range(K)]
for k, (p, r, f1, support) in enumerate(rows):
    print(f"class {k}: precision {p:.3f} recall {r:.3f} F1 {f1:.3f} support {support:>5}")

macro = np.mean([f1 for _, _, f1, _ in rows])
weighted = np.average([f1 for _, _, f1, _ in rows], weights=[s for *_, s in rows])
micro = (pred_k == yk).mean()
print(f"\nmacro F1    {macro:.4f}  (every class counts equally — small classes dominate)")
print(f"weighted F1 {weighted:.4f}  (weights by support — big classes dominate)")
print(f"micro F1    {micro:.4f}  (= accuracy in single-label multi-class)")
```

```output
class 0: precision 0.777 recall 0.759 F1 0.768 support  1475
class 1: precision 0.800 recall 0.715 F1 0.755 support  1493
class 2: precision 0.803 recall 0.734 F1 0.767 support  1532
class 3: precision 0.322 recall 0.753 F1 0.451 support   243

macro F1    0.6850  (every class counts equally — small classes dominate)
weighted F1 0.7471  (weights by support — big classes dominate)
micro F1    0.7365  (= accuracy in single-label multi-class)
```

Classes 0–2 each have about 1,500 rows and $F_1$ near 0.76. Class 3 has only 243 rows, and its
precision is 0.322: many rows from the big classes get mislabelled as class 3, which swamps the
few real ones. Its $F_1$ of 0.451 pulls the macro $F_1$ down to 0.6850. The weighted $F_1$
(0.7471) barely notices it, because 243 rows is about 5% of the weight. Micro $F_1$ is 0.7365,
exactly the accuracy.

Pick the average that matches the decision. **Macro** if every class matters equally (a rare
disease must not be drowned out); **weighted** if you care about overall case volume; **micro**
only when you genuinely mean accuracy.

> **Watch out:** libraries often default to one average silently. A "weighted $F_1$ of 0.75"
> can hide a rare class performing at 0.45. Print the per-class table, not only the average.

## Confidence intervals: is the difference real?

Your test set is one sample of the world. A different sample would give a slightly different
score, so every metric deserves an error bar before you trust a small difference.

A **confidence interval** is a range of plausible values for the metric. The **bootstrap** gets
one without any formulas: resample the test rows *with replacement* (so some rows appear twice
and some not at all), recompute the metric, repeat a few hundred times, and take the middle 95%
of the results.

> **Picture it:** you have one bag of 20,000 marbles. You cannot get more bags, so you make
> pretend bags by drawing 20,000 marbles from yours, putting each back after drawing it. How
> much the score jumps from pretend bag to pretend bag tells you how much it would jump from
> real bag to real bag.

```python
def bootstrap_ci(y, score, metric_fn, n_boot=400, alpha=0.05, seed=0):
    r = np.random.default_rng(seed)
    stats = []
    idx = np.arange(len(y))
    for _ in range(n_boot):
        b = r.choice(idx, size=len(idx), replace=True)
        if y[b].sum() == 0:
            continue
        stats.append(metric_fn(y[b], score[b]))
    lo, hi = np.percentile(stats, [100 * alpha / 2, 100 * (1 - alpha / 2)])
    return float(np.mean(stats)), float(lo), float(hi)

def roc_auc(y_, s_):
    f, t = curve_points(y_, s_, "roc")
    return auc(f, t)

mean, lo, hi = bootstrap_ci(y, score, roc_auc)
print(f"ROC AUC {mean:.4f}  95% CI [{lo:.4f}, {hi:.4f}]  (width {hi-lo:.4f})")

small = slice(0, 1_000)
mean_s, lo_s, hi_s = bootstrap_ci(y[small], score[small], roc_auc)
print(f"on 1,000 rows: {mean_s:.4f}  95% CI [{lo_s:.4f}, {hi_s:.4f}]  (width {hi_s-lo_s:.4f})")
print("\nan 0.004 'improvement' inside a 0.013-wide interval is noise (ch. 12)")
```

```output
ROC AUC 0.9581  95% CI [0.9513, 0.9643]  (width 0.0130)
on 1,000 rows: 0.9801  95% CI [0.9689, 0.9898]  (width 0.0209)

an 0.004 'improvement' inside a 0.013-wide interval is noise (ch. 12)
```

On all 20,000 rows the 95% interval is [0.9513, 0.9643], width 0.0130. On the first 1,000 rows
alone the width grows to 0.0209 — fewer rows, wider uncertainty. Notice also that the small
subset's point estimate (0.9801) is 0.02 higher than the full set's: a lucky slice, which is
exactly the kind of wobble the interval warns about.

> **Watch out:** if model B beats model A by 0.004 AUC and the interval is 0.013 wide, you have
> not shown that B is better. Ch. 12 covers paired comparisons that do this properly.

## Recap in plain words

- The confusion matrix (TP, FP, FN, TN) holds everything; every metric is a ratio of its cells.
- Accuracy is misleading on imbalanced data: "always no" can beat a real model.
- Precision counts false alarms, recall counts misses, and the threshold trades one for the other.
- ROC AUC has a floor of 0.5 at every prevalence; PR AUC's floor is the prevalence, so PR AUC
  tells the truth about rare positives.
- For multi-class problems, macro, weighted, and micro averages answer different questions.
- Every metric needs a bootstrap confidence interval before you trust a small difference.

def report(y, score, threshold=0.5, name="model"):
    pred = (score >= threshold).astype(int)
    m = metrics(y, pred)
    f, t = curve_points(y, score, "roc")
    rc, pr = curve_points(y, score, "pr")
    tp, fp, fn, tn = confusion(y, pred)
    print(f"{name} @ {threshold:.2f}: P {m['precision']:.3f} R {m['recall']:.3f} "
          f"F1 {m['f1']:.3f} | ROC {auc(f, t):.3f} PR {auc(rc, pr):.3f} | "
          f"TP {tp:,} FP {fp:,} FN {fn:,}")

weak = np.clip(rng.normal(0.25 + 0.20 * y, 0.18), 0, 1)      # less separation
strong = np.clip(rng.normal(0.25 + 0.75 * y, 0.18), 0, 1)    # more separation
for nm, s in [("weak  ", weak), ("medium", score), ("strong", strong)]:
    report(y, s, 0.5, nm)
print()
for th in (0.4, 0.5, 0.6):
    report(y, score, th, "medium")

The `report` helper prints everything from this chapter in one line. The first three rows

## Exercise

You are evaluating a fraud model on 200,000 transactions with a 0.4% fraud rate. Compute ROC
AUC, PR AUC, and precision at recall levels of 0.5, 0.7, and 0.9, with bootstrap confidence
intervals. Then answer with numbers: at each recall level, how many false alarms does the
review team receive per true fraud caught, and which operating point would you recommend if a
small review team can process 50 cases a day? (Treat the 200,000 rows as one month of traffic.)

> **Hint:** read the precision–recall curve at the first point where recall reaches each
> target. If precision is $p$, the false alarms per true catch are $(1-p)/p$. The number of
> rows above that threshold, divided by 30, is the daily queue.

```python
r = np.random.default_rng(7)
N = 200_000
yf = (r.random(N) < 0.004).astype(int)
sf = np.clip(r.normal(0.20 + 0.50 * yf, 0.15), 0, 1)

rec_curve, prec_curve = curve_points(yf, sf, "pr")
order = np.argsort(-sf)
sorted_scores = sf[order]

def precision_at_recall(target):
    idx = int(np.searchsorted(rec_curve, target))
    idx = min(idx, len(rec_curve) - 1)
    return float(prec_curve[idx]), float(rec_curve[idx]), float(sorted_scores[idx]), idx + 1

print(f"prevalence {yf.mean():.4%} | positives {yf.sum():,}")
f, t = curve_points(yf, sf, "roc")
print(f"ROC AUC {auc(f, t):.4f} | PR AUC {auc(rec_curve, prec_curve):.4f} "
      f"(baseline {yf.mean():.4f})\n")

CAPACITY = 50                                     # cases one small review team clears per day
print(f"{'recall':>8}{'precision':>11}{'threshold':>11}{'flagged/day':>13}"
      f"{'FP per TP':>11}  vs capacity {CAPACITY}/day")
for target in (0.5, 0.7, 0.9):
    p, achieved, thr, flagged = precision_at_recall(target)
    fp_per_tp = (1 - p) / p if p > 0 else float("inf")
    daily = flagged / 30                              # assume a month of transactions
    fits = "fits" if daily <= CAPACITY else f"NEEDS {daily/CAPACITY:.1f}x capacity"
    print(f"{achieved:>8.2f}{p:>11.3f}{thr:>11.3f}{daily:>13,.0f}{fp_per_tp:>11.1f}  {fits}")

mean_auc, lo, hi = bootstrap_ci(yf, sf, roc_auc, n_boot=200, seed=3)
print(f"\nROC AUC {mean_auc:.4f} 95% CI [{lo:.4f}, {hi:.4f}]")
def pr_auc(y_, s_):
    rc, pc = curve_points(y_, s_, "pr")
    return auc(rc, pc)
mean_pr, lo_pr, hi_pr = bootstrap_ci(yf, sf, pr_auc, n_boot=200, seed=3)
print(f"PR  AUC {mean_pr:.4f} 95% CI [{lo_pr:.4f}, {hi_pr:.4f}]  <- much wider: "
      f"only {yf.sum():,} positives carry it")
```

The insight: the recommendation is not "maximize F1", it is **the highest recall the review team
can actually absorb**. Here recall 0.70 gives a queue of 33 cases a day with 0.9 false alarms
per true fraud (precision 0.540, so about 1 in 2 flagged cases is wrong) — that fits 50 a day.
Recall 0.90 would need 123 a day, 2.5 times the capacity.

Capacity is the binding constraint, and it converts an abstract
precision–recall trade into a staffing question: at 90% recall the queue is several times larger
than the team can clear, so either recall comes down, the team grows, or the low-score tail gets a
cheaper treatment (an automated rule, a customer-facing challenge) instead of a human. Two
methodological notes. The PR AUC's confidence interval (about 0.056 wide) is far wider than the
ROC AUC's (about 0.004), because
it is determined almost entirely by the 760 positives — with rare events, **your effective
sample size is the positive count**, not the row count. And precision at a *fixed recall* is the
metric to report to stakeholders, because unlike AUC it survives translation: "we catch 70% of
fraud and about half of the flagged cases are real" is a sentence a business can act on.
