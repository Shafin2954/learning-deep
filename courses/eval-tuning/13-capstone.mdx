## The project

Build an evaluation-and-tuning harness that takes a dataset and a model family and produces a
**decision-ready report**: a validated CV protocol, a tuned and pruned Optuna study, calibrated
probabilities, a cost-optimal threshold, an interpretability section, an error-analysis work list,
and a champion-versus-challenger verdict backed by a corrected significance test. The deliverable
is not a notebook with a high score at the bottom — it is a document another person could use to
approve or reject shipping the model, and a harness they could re-run next quarter and get the
same answer. Everything in this course exists to make that document trustworthy; this is where you
prove you can produce one.

## Hard constraints (no vibe coding)

- **No AI assistants** for the code or the write-up. Read library documentation, not generated
  answers. The point is that you can defend every number in the report.
- **No copied notebooks.** You may use scikit-learn, Optuna, SHAP, pandas, NumPy, SciPy and a
  gradient-boosting library. You may not lift an end-to-end harness from a repository or a blog.
- **Implement from scratch**, using libraries only to check your work: the metric functions you
  optimize, the calibration fitters (Platt and isotonic/PAVA), the threshold optimizer, the
  permutation-importance routine, the slice finder, and the corrected paired significance test.
- **No fabricated numbers anywhere.** Every figure in the report comes from a run the harness can
  reproduce from its own manifest.
- **No metric without a protocol.** A score reported outside its CV scheme, seed, and data
  fingerprint does not count as a result.
- **The test set is touched once**, at the end, after every decision is made. If you look at it
  twice, you start over with a fresh split.
- **Determinism is a requirement, not a nicety.** Two runs of the harness with the same config and
  data must produce byte-identical fold scores.

## What it must contain (and the chapter each tests)

1. **A validation design step** that inspects the data and *chooses* the splitter — stratified,
   grouped, rolling-origin, or grouped-temporal — and records the reason in the manifest. Refuse
   to run if groups or a time column are present and unhandled. (ch. 5)
2. **A metric layer** built from first principles: confusion-matrix metrics, ROC and PR curves,
   and at least one ranking metric, each with a bootstrap confidence interval. Verify each against
   its scikit-learn counterpart to at least six decimals. (ch. 1–2)
3. **An Optuna study** over a conditional space spanning at least two model families, with a
   pruner, a seeded sampler, `enqueue_trial` warm-started from a trusted baseline, and a
   stale-study callback. Report the pruning saving in units of training work. (ch. 6–7)
4. **A multi-objective study** producing a Pareto front over quality against one real operational
   cost — latency, model size, or inference price per thousand calls. Pick a point from the front
   and justify the pick in one paragraph. (ch. 7)
5. **A calibration stage** that measures reliability (ECE and Brier), fits both Platt and isotonic
   on a held-out calibration split, selects between them on data neither was fitted on, and shows
   the before/after reliability table. Include the prior-correction adjustment if any resampling
   was used. (ch. 4)
6. **A decision layer** that converts a cost matrix into a threshold, compares the analytic
   optimum to the empirical sweep, and reports the expected cost per thousand decisions at the
   chosen threshold — plus a three-way triage variant with an explicit review budget. (ch. 3)
7. **An interpretability section** with permutation importance (test-set, with its spread),
   mean-|SHAP| with at least one local waterfall for a high-risk row, one dependence view, and a
   PDP-versus-ICE check that states whether each feature's effect is homogeneous enough to
   summarise. (ch. 8–10)
8. **An error-analysis work list** from an automatic slice finder, ranked by headroom, with a
   computed likely cause and a suggested action per slice, and an explicit note on slice overlap.
   (ch. 11)
9. **A tracking layer** recording data and config fingerprints, all seeds, per-fold scores, the
   protocol, the environment, the artefact hash, and the number of runs in the search — with a
   duplicate-fingerprint check that asserts reproducibility. (ch. 12)
10. **A champion-versus-challenger verdict** using a corrected paired test plus a pre-registered
    minimum effect size, vetoed by any slice regression beyond a stated tolerance. (ch. 11–12)

## Acceptance criteria

- **Reproducibility.** Running the harness twice on the same data and config yields identical
  per-fold scores and identical fingerprints. A reviewer can re-run it from the manifest alone.
- **Metric correctness.** Every hand-written metric matches its scikit-learn reference to $10^{-6}$
  on at least three datasets, including a degenerate one (single class present in a fold, all
  predictions identical, or a fold with no positives).
- **Leakage-free protocol.** All preprocessing, feature selection, calibration, and threshold
  choice happen inside the folds. Demonstrate this by showing that the harness scores a
  pure-noise dataset at chance, plus or minus its own confidence interval.
- **Tuning efficiency.** The pruned study reaches within 0.5% of the unpruned study's best value
  using at most 60% of the training work, and both numbers are reported.
- **Calibration improvement.** ECE on the final holdout drops by at least 50% relative to the
  uncalibrated model, with the reliability table shown before and after.
- **Threshold justification.** The chosen threshold's expected cost is within 2% of the empirical
  optimum on the holdout, and the report states what the cost matrix's entries mean in currency.
- **Honest comparison.** The final verdict reports the effect size, its confidence interval, the
  corrected p-value, and the number of challengers evaluated. A challenger that wins on average
  but regresses a slice is blocked, and the report says so.
- **The report stands alone.** A reader who has not seen your code can state what the model does,
  where it fails, what it costs to be wrong, and whether to ship it.

## Skills checklist (tick before you claim done)

- [ ] I can pick a cross-validation scheme from the structure of the data and defend it.
- [ ] I can show that a leaky pipeline scores above chance on pure noise, and that mine does not.
- [ ] I can implement precision, recall, F1, ROC-AUC, PR-AUC and NDCG from the definitions.
- [ ] I can put a confidence interval on any metric with the bootstrap.
- [ ] I can derive the cost-optimal threshold analytically and confirm it empirically.
- [ ] I can fit Platt scaling and isotonic regression by hand and choose between them honestly.
- [ ] I can explain why a resampled training set breaks calibration and how to correct the prior.
- [ ] I can size a random search from the volume of the region I want to hit.
- [ ] I can write an Optuna objective with a conditional space, a pruner, and a warm start.
- [ ] I can read a Pareto front as a menu of trade-offs and defend the point I picked.
- [ ] I can distinguish gain, permutation, and drop-column importance and say when each lies.
- [ ] I can compute a Shapley value by brute force and check TreeSHAP against it.
- [ ] I can tell when a PDP is safe to show and when only ICE curves are honest.
- [ ] I can rank error slices by headroom and attach a cause and an action to each.
- [ ] I can name what a run must log for its number to be reproducible.
- [ ] I can run a corrected paired test and explain why the naive one is overconfident.
- [ ] I can write a one-page recommendation that a non-modeller can act on.
